## Notes

- Fixed 5 real clippy findings surfaced while preparing this sign-off (not
  pre-existing — introduced by the v0.44 implementation): two unnecessary
  `as u64` casts on an already-`u64` `ObjectMeta::size` field
  (`delta_sink.rs`, `iceberg_sink.rs`), and `std::sync::MutexGuard`s held
  across `.await` points in three GC test functions (`delta_sink.rs`,
  `iceberg_sink.rs`, `cold_gc_safety_tests.rs`) — fixed by taking ownership
  of the sink out of the `Arc<Mutex<..>>` (dropping any other `Arc` holders
  first) before the final `.await`, rather than holding the lock across it.
  Also fixed one `assert_eq!(x > 0, true)` (literal-bool clippy lint) and
  added `#![allow(dead_code)]` to the shared `tests/common/mod.rs` helper
  module, whose functions are each used by only a subset of the LFS/MinIO/TC
  test binaries that include it.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
  warnings`, `cargo test --workspace` (1224 passed, 5 ignored, 84 suites),
  and `make e2e` all pass clean after the above fixes.
- `./scripts/check-exit-criteria.sh` passes with this sign-off file complete.
- Every user-visible sink DDL error path (malformed `WITH` options, missing
  view, unsupported format) uses an `RS-4007` error code with actionable
  text, verified by `server.rs` unit tests.
- Nothing deferred: all deliverables listed in the v0.44 roadmap row
  (Iceberg/Delta `CREATE SINK` DDL, partial-write fault-injection recovery,
  `docs/cold-tier-sinks.md`, `EXPLAIN INCREMENTAL` sink-target display, and
  the cold-snapshot GC scope — retention options, whichever-first expiry,
  shared-file safety, GC/commit non-overlap, and reclaim metrics — folded in
  during the >=v0.44 roadmap review) are implemented and verified in this
  sign-off.
