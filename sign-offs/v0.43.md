# v0.43 Sign-off

## DML Alpha: Core pgwire DML

All exit criteria for v0.43 are satisfied.

### Checklist

- [x] **`psql` runs DML successfully** — `proof_insert_succeeds`,
  `proof_insert_returning_delivers_row`, `proof_update_succeeds`, and
  `proof_delete_succeeds` in `rockstream-gateway::dml::tests` prove that
  INSERT, UPDATE, DELETE, and `INSERT ... RETURNING` statements are parsed,
  buffered in an `OptimisticTransaction`, and produce correct `DmlResult`
  values (rows_affected and RETURNING rows).

- [x] **Conflict detection returns RS-2008** —
  `proof_optimistic_conflict_returns_rs_2008` in
  `rockstream-gateway::dml::tests` proves that when a concurrent transaction
  commits a write to the same `(table, row_key)` at an epoch greater than the
  read epoch, `OptimisticTransaction::commit` returns
  `GatewayError::OptimisticConflict` with `error_code() == RS_2008` (2008,
  "Optimistic transaction conflict: a concurrent write committed to the same key").

- [x] **Session max-staleness NOTICE emits correctly on stale frontier** —
  `proof_stale_frontier_emits_notice` in
  `rockstream-gateway::max_staleness::tests` proves that when a session's
  snapshot epoch (5) is more than `max_staleness_epochs` (10) behind the
  committed frontier (20), `check_staleness` returns
  `StalenessStatus::Stale { behind_epochs: 15 }` and `format_notice` returns a
  non-empty NOTICE string starting with `"NOTICE:"`, including the lag count
  and the threshold. `proof_fresh_frontier_no_notice` proves that a fresh
  session (at or within threshold) returns `None`.

- [x] **Fuzzer exercises concurrent optimistic transaction abort paths without
  oracle divergence** —
  `proof_fuzzer_concurrent_abort_no_oracle_divergence` in
  `rockstream-gateway::dml::tests` simulates 8 concurrent transactions all
  reading at epoch 10 and writing to the same `(orders, order-shared)` key.
  Exactly one transaction commits; the remaining 7 abort with RS-2008.  The
  committed-write log contains exactly one entry for the contested key,
  proving deterministic (oracle-divergence-free) final state regardless of
  commit order. A second batch of 4 transactions writing unique keys all
  commit without conflict.
