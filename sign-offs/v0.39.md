## Scope

v0.39.0 implements **Clone, schema evolution, and law-version upgrade**:

### New types (`rockstream-types::schema_evolution`)

- `SchemaChangeKind` (`Compatible` / `Incompatible`) with `requires_blue_green()`.
- `CloneSpec` — captures source view ID, clone view name, **source offset epoch**
  (immutably preserved through the entire workflow), and clone reason.
- `CloneReason` enum:
  - `IncompatibleSchemaChange { description }`
  - `IncompatibleLawVersionUpgrade { law_id, from_version, to_version }`
  - `UserRequested { note }`
- `BlueGreenState` state machine:
  `Idle → Backfilling → ReadyToFlip → Flipped → Decommissioned`.
- `ColumnDescriptor` and `Schema = Vec<ColumnDescriptor>`.
- `classify_schema_change(old, new) -> SchemaChangeKind` — rules:
  - Compatible: add nullable column, widen type, bump law version (non-breaking).
  - Incompatible: remove/rename column, narrow type, add non-nullable column,
    nullable → non-nullable, breaking law-version bump.
- `classify_law_version_change(law_id, from, to, is_breaking) -> SchemaChangeKind`.

### Runtime module (`rockstream-runtime::clone`)

- `SchemaEvolutionChecker` — routes schema changes to in-place or blue/green path.
- `PipelineCloner` — creates a `CloneHandle` from a `CloneSpec`, preserving
  `source_offset_epoch` so backfill starts at the captured offset.
- `BlueGreenCoordinator` — drives the full state machine:
  - `begin()` — clone creation; rejects concurrent operations (RS-3608).
  - `report_backfill_progress()` — advances to `ReadyToFlip` when lag is zero.
  - `flip()` — atomic epoch-boundary cutover from blue to green.
  - `decommission()` — retires the original pipeline.
  - `simulate_full_cycle()` — deterministic full-cycle helper for proof tests.
- `LawVersionUpgradeCoordinator` — routes compatible upgrades in-place;
  routes breaking upgrades through a `BlueGreenCoordinator` clone.

### New error codes

| Code | Meaning |
|------|---------|
| `RS-3607` | Schema change requires blue/green clone; in-place apply rejected |
| `RS-3608` | A blue/green clone operation is already in progress for this view |
| `RS-3609` | Clone backfill lag exceeded the allowed threshold before flip |

## Proof Criteria

### Criterion 1: Breaking schema change goes through clone/backfill/flip without source offset loss

Verified by test `proof_schema_change_via_blue_green_no_source_offset_loss` in
`rockstream-runtime::clone::tests`:

1. Source offset is captured at epoch 100 in `CloneSpec::source_offset_epoch`.
2. `PipelineCloner::create_clone` starts backfill from the captured epoch — no gap.
3. `BlueGreenCoordinator` completes the full cycle; flip epoch 110 >= 100.
4. Invariant: `spec.source_offset_epoch == captured_epoch` throughout.

### Criterion 2: A forced MergeLaw version bump for an existing view re-encodes via clone without loss

Verified by test `proof_law_version_bump_via_blue_green_without_loss` in
`rockstream-runtime::clone::tests`:

1. `LawVersionUpgradeCoordinator::route_upgrade` with `is_breaking = true` returns
   `RequiresBlueGreen { spec }`.
2. The spec carries `CloneReason::IncompatibleLawVersionUpgrade { law_id, from, to }`.
3. `spec.source_offset_epoch == 300` (captured offset preserved).
4. Full blue/green cycle completes; flip epoch 350 >= 300 (no rewind).
