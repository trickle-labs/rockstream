# v0.5 Sign-off — Algebraic Aggregates and Epoch Commit (IVM-2)

**Signed off**: 2026-06-08

## Scope recap

v0.5 implements the DBSP algebraic aggregate operator and shard-level group
commit, satisfying IVM-2:

- `AggregateOp`: stateful incremental GROUP BY with SUM/COUNT/AVG using the
  DBSP delta rule — for each input delta `(k, v, w)`, compute `(Δsum, Δcount)`,
  look up old state, emit `(old, -1) ⊎ (new, +1)`, update in-memory
  arrangement. Uses checked arithmetic to detect i64 overflow (RS-1016).
- `AggState`: in-memory arrangement map `k → (sum, count)`, bounded by
  distinct group keys; fill-level metric via `entry_count()`; state serializes
  to/from `ShardDb` under the `op_state` namespace using scan-and-delete
  cleanup (no range deletion).
- `GroupCommit`: shard-level coalescer — N `WriteBatch` fragments from multiple
  operators per epoch are merged into **one** atomic `ShardDb::write_batch()`
  call. Bounded queue (`GROUP_COMMIT_MAX_BATCHES = 64`), fill-level metric,
  RS-1015 back-pressure error on overflow.
- `persist_frontier` / `load_frontier`: epoch frontier persisted to the
  `shard_meta` namespace (`ShardKeyEncoder::frontier_key()`), surviving
  close/reopen.
- `persist_agg_state`: scan-and-delete persistence that removes stale entries
  and writes all live groups atomically — no range deletion.
- New error codes: RS-1015 (group commit full) and RS-1016 (aggregate overflow),
  both registered in `rockstream-types` with descriptions and actionable
  `next_steps`.
- Oracle: `rockstream-oracle::aggregate_oracle` — pure-Rust batch reference +
  DataFusion validation + 100k-scenario proptest for
  `SELECT k, SUM(v), COUNT(*), SUM(v)/COUNT(*) AS avg_v FROM t GROUP BY k`.

New crates modified:
- `rockstream-ops`: `aggregate.rs`, `group_commit.rs` (new); `lib.rs`, `error.rs` updated.
- `rockstream-oracle`: `aggregate_oracle.rs` (new); `lib.rs` updated.
- `rockstream-types`: `error_code.rs` — added RS_1015, RS_1016 with descriptions and next_steps.
- `rockstream-ops` (Cargo.toml): added `sha2`, `hmac`, `hex` dev-dependencies for MinIO test.

## Notes

- `AggregateOp::process_delta` processes deltas sequentially within the Mutex,
  which is correct: each `(k, v, w)` triple updates the running arrangement so
  that the next triple in the same batch sees the updated state. This matches
  the DBSP delta-composition rule.
- `persist_agg_state` is a scan-and-delete function: it scans the existing
  `op_state` prefix for the operator, deletes stale keys, and writes all live
  groups. The MutexGuard is dropped before any `.await` to satisfy
  `clippy::await_holding_lock`.
- The proptest generates `k ∈ 0..5` (small key space) to force group churn —
  groups are created, updated, and deleted within the same test run. The
  `v ∈ -50..50` range exercises negative sums and negative averages.
- MinIO tests perform AWS4-HMAC-SHA256 bucket creation without external CLI
  tools; the signing code is embedded in the test file using the `sha2`, `hmac`,
  and `hex` crates (dev-dependencies only).
- New error codes RS-1015 and RS-1016 are added to the `description()` and
  `next_steps()` maps in `error_code.rs` and are included in the
  `all_codes_have_descriptions_and_actionable_next_steps` registry test.
- Deferred (out of scope for v0.5, by roadmap schedule): MIN/MAX non-invertible
  aggregates (v0.6); crash-replay (v0.6); multi-shard exchange over gRPC (v0.16).
