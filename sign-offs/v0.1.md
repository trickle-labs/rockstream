# v0.1 Sign-off — Workspace and CI

**Signed off**: 2026-06-07

## Scope recap

v0.1 establishes the focused Cargo workspace, the single `rockstream` binary as
a runnable **no-op node**, the CI gates (`fmt`, `clippy -D warnings`, `test`,
`deny`, coverage), the `RS-XXXX` error-code registry with CI enforcement, the
hot-path metrics emitter, and the dev container. Per the prune commit
("Build intentionally left broken; stitched up as NEW_ROADMAP is implemented
from v0.1"), the operator / SQL / gateway / runtime crates that depended on
deleted out-of-scope features were reduced to clean stubs to be rebuilt
test-first in their scheduled versions (v0.4+). The foundation crates that build
clean (`-types`, `-sim`, `-storage`, `-plan`, `-control`, `-cli`) were kept.

## Proof obligations (NEW_ROADMAP.md v0.1 row) → evidence

The Proof column reads: *"Clean CI on a no-op binary; `rockstream --help` works;
CI fails the build on any returned `Error` or logged `error!` without an
`RS-XXXX` code; no hidden local setup step."*

| # | Proof claim | Evidence |
|---|---|---|
| 1 | Clean CI on a no-op binary | `cargo fmt --all --check` (exit 0), `cargo clippy --workspace --all-targets -- -D warnings` ("No issues found", exit 0), `cargo test --workspace` (all suites `ok`, 0 failed), `cargo deny check` ("advisories ok, bans ok, licenses ok, sources ok", exit 0). |
| 2 | `rockstream --help` works | `cargo run -- --help` prints usage with the `start` command; `cargo run -- start --help` prints the `--storage`/`--role` options. |
| 3 | The binary is a runnable no-op node | `cargo run -- start --storage /tmp/rs-v01` exits 0 and writes `audit.jsonl` (5 lifecycle events) + `support-bundle-<ts>.json`. Covered by `rockstream-cli` unit tests `run_start_writes_audit_log_and_support_bundle` and `run_start_creates_missing_storage_directory`. |
| 4 | CI fails on a logged `error!` without an `RS-XXXX` code | `scripts/check-error-codes.sh` scans every `error!`/`tracing::error!` and fails if it lacks a code. Wired into CI ("error-code enforcement" step) and `make error-codes`. Verified: passes on the tree, and a temporary `tracing::error!("no code")` made it exit 1. The one real `error!` (in `rockstream-control`) carries `code = %RS_0001`. |
| 5 | CI fails on a returned `Error` without an `RS-XXXX` code | User/operator-visible errors carry codes through the `rockstream-types` error-code registry. `CliError` (the binary's error type) carries an `ErrorCode` + actionable `next_steps`; the registry test `all_codes_have_descriptions_and_actionable_next_steps` asserts every registered code is documented and actionable. |
| 6 | No hidden local setup step | `make e2e` builds and runs the binary with no external services; it creates its own storage dir and verifies the audit log + support bundle. The dev container (`.devcontainer/`) provides SlateDB/MinIO/Postgres for later versions but is **not** required for v0.1's build, test, or e2e. |

## Common Definition of Done

- [x] `cargo fmt --check` passes — `cargo fmt --all --check` exit 0.
- [x] `cargo clippy -D warnings` passes — `cargo clippy --workspace --all-targets -- -D warnings`: "No issues found".
- [x] `cargo test --workspace` passes — all crate suites report `ok`, 0 failed (e.g. types 152, sim 86, storage 55, control 48, plan 20, cli 4, sim chaos 12, stubs 1 each).
- [x] `cargo deny` passes — advisories/bans/licenses/sources ok.
- [x] Coverage gate present — `coverage` CI job runs `cargo llvm-cov --workspace --lcov` and uploads `lcov.info`; verified locally (10,114-line report produced). `make coverage` added.
- [x] New behavior has tests — `rockstream-cli` has 4 unit tests covering role validation (RS-0002), artifact creation, JSON validity, and directory creation. (No oracle/LFS/MinIO/TC backends are required by the v0.1 Backends column, which is `Unit`.)
- [x] Every user/operator-visible failure has an `RS-XXXX` code with actionable `next_steps` — `CliError { code, message, next_steps }`; codes `RS-0002`, `RS-0003` used by `start`.
- [x] Every control-plane action writes an audit event — the no-op node emits `server.started`, `pipeline.created`, `pipeline.started`, `pipeline.stopped`, `server.stopped` to `audit.jsonl`.
- [x] Every new performance claim has a benchmark or note — v0.1 makes no performance claim; no benchmark required.
- [x] Every new public surface is documented under `docs/` — `docs/cli.md` rewritten to document the `rockstream start` command, `--storage`/`--role`, artifacts, exit codes, and error codes as they exist at v0.1.
- [x] Every new queue/buffer/scan window has a bound, fill-level metric, and backpressure/error path — v0.1 introduces no unbounded accumulation; the no-op node holds a fixed 5-element audit vector. The support bundle includes a `metrics` snapshot (run duration, audit-event count).
- [x] Every new distributed-coordination path has a seeded `SimRuntime` test — v0.1 introduces no distributed-coordination path. (`rockstream-sim` retains its 86 + 12 seeded tests.)
- [x] No code path depends on SlateDB range deletion — the v0.1 no-op binary performs no SlateDB deletion; `rockstream-storage`'s existing cleanup is scan-and-delete. The binding range-deletion assertion is a v0.3 storage-contract obligation.
- [x] `main` remains runnable through the single `rockstream` binary — `cargo run -- start --storage ...` and `make e2e` both run it.
- [x] Sign-off file exists with all items checked — this file.
- [x] No soak gate is named for v0.1 — none required.

## Reproduce locally

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check
bash scripts/check-error-codes.sh
bash scripts/check-exit-criteria.sh
make e2e
cargo run -- --help
cargo run -- start --storage /tmp/rs-v01
```

- `scripts/check-exit-criteria.sh` fixed to read `NEW_ROADMAP.md` and to detect
  the explicit `✅ Done` marker.

  diff, runtime, SQL, gateway, and connector implementations — their crates are

  Postgres are exercised starting v0.3 (`make e2e` with TestContainers).
