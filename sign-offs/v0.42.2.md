## Proof Claims Verification

- [x] **Multi-row `INSERT ... VALUES (v1,v2),(v3,v4),...` is parsed correctly:
  each row becomes its own `DmlOp::Insert`, commas/parens inside string
  literals are not mistaken for row separators**
  - **Evidence**: `split_value_tuples` (`crates/rockstream-gateway/src/server.rs`)
    tracks paren depth and quote state to find each row tuple's boundaries,
    including a trailing `RETURNING ...` clause; `parse_insert` calls it and
    emits one `DmlOp::Insert` per row. Unit tests in `mod parse_insert_tests`
    (`server.rs`). Integration tests `multi_row_insert_values_writes_all_rows_correctly`
    and `multi_row_insert_values_returning_returns_all_rows`
    (`crates/rockstream-gateway/tests/gateway_proof_tests.rs`).
  - **Command**: `cargo test -p rockstream-gateway --lib parse_insert_tests`;
    `cargo test --test gateway_proof_tests multi_row_insert`

- [x] **A row whose arity doesn't match the declared column list (or the
  first row's arity) is a hard `RS-2056` parse error, not silent corruption**
  - **Evidence**: `multi_row_insert_malformed_row_returns_rs2056_not_silent_corruption`
    (`gateway_proof_tests.rs`) asserts the error path returns/contains
    `RS-2056` for a malformed row instead of silently dropping/corrupting
    columns (the pre-fix behavior: text was taken from the first `(` to the
    *last* `)` in the whole clause).
  - **Command**: `cargo test --test gateway_proof_tests multi_row_insert_malformed_row_returns_rs2056_not_silent_corruption`

- [x] **`INSERT ... RETURNING` returns every written row for a multi-row
  `VALUES` list**
  - **Evidence**: `multi_row_insert_values_returning_returns_all_rows`
    (`gateway_proof_tests.rs`) verifies all rows are present in the
    `RETURNING` result set.

## Notes

Per-row `INSERT` continues to work unchanged; only the multi-row `VALUES`
list parsing path was previously buggy. This closes the gap flagged by the
`<=v0.42` implementation review: ORM bulk-insert helpers (SQLAlchemy
`bulk_insert_mappings`, Prisma `createMany`) emit multi-row `VALUES` by
default, so the pre-fix silent corruption directly undermined the v0.39/v0.42
"any standard driver works without workarounds" claim.
