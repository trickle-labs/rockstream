# v0.67.1 Sign-off

Evidence is recorded in [v0.67.1 evidence](v0.67.1-evidence.md).

## Exit Criteria Verification

- [x] V0671-01: Every supported stateful operator and recovery path has a complete allocation/metadata audit and a bounded implementation or explicit rejection. Query planning matrix gates stateful operators; distributive aggregates (SUM, COUNT, MIN, MAX, AVG) and bounded joins/windows are supported beyond RAM; unsupported large-state operators (e.g., non-distributive MEDIAN, unbounded joins exceeding memory budget) fail closed before allocation with RS-4022 or RS-5003. Proven by `operator_support_matrix_tests` (7 passed).
- [x] V0671-02: Ordinary aggregate updates remain exact across eviction, reload, deletion, NULLs, signed weights, and arithmetic failure. `AggregateOp` supports demand-loading, LRU clean eviction, delta reduction, dirty-key persistence, and exact weighted multiset maintenance across evictions and reloads matching independent oracle. Proven by `arrangement_spill_correctness_tests` (7 passed) and `spillable_arrangement_tests` (4 passed).
- [x] V0671-03: Scans and restoration page to the real end without full-state vectors or unbounded spilled-key metadata. Storage layer streaming paged scan (`scan_prefix_page`) and `RecoveryDriver::recover_shard_paged` enforce page-bounded buffers (`MAX_RESTORE_SCAN_PAGE_ROWS = 1000`) without full-state vector materialization; cancelation and I/O interruption fail cleanly with RS-2003 without reporting false ready state. Proven by `paged_scan_tests` (3 passed) and `paged_recovery_tests` (6 passed).
- [x] V0671-04: Spill failure cannot discard authoritative dirty state or acknowledge an uncommitted epoch. Point tombstones and point deletes avoid SlateDB range-deletion data-loss bugs; dirty state survives restart; restart across process destruction reconstitutes exact aggregate and arrangement state across LocalFileSystem and MinIO object store backends. Proven by `spill_durability_lfs_tests` (4 passed), `spill_durability_minio_tests` (3 passed), `arrangement_spill_recovery_tests` (8 passed), and `spill_coordination_sim_tests` (3 passed).
- [x] V0671-05: Spill I/O, disk occupancy, checkpoint buffers, retries, and storage backlog obey named limits with truthful metrics and explicit pressure behavior. `SpillGovernor` bounds write buffers (16 MiB), total disk occupancy ceiling (1 GiB), concurrent spills (2), and protects foreground maintenance budget (32 MiB); disk full emits RS-2021 and concurrency saturation sheds excess with RS-2020. Proven by `spill_budget_governor_tests` (5 passed) and `many_shard_overload_tests` (3 passed).
- [x] V0671-06: State larger than the configured worker budget remains exact and within the frozen RSS/backlog limits through eviction, compaction, and restart. Real release-process measurement confirms maintained state exceeds worker memory budget while RSS stays strictly bounded; full recovery matches independent oracle across process restarts. Proven by `spillable_arrangement_tests` (4 passed), `spill_rss_soak_tests` (1 passed), and `tools/r1-local-harness` (65 passed).
- [x] V0671-07: Persistent format/schema mismatches and corrupt pages fail explicitly without partial successful recovery. Format versioning detects unsupported layouts, corrupt records, and corrupted magic bytes, immediately rejecting incomplete state with RS-3616 and RS-3617 while transitioning lifecycle cleanly to Fatal without falsely reporting ready. Proven by `paged_recovery_tests` (6 passed).
- [x] V0671-08: Operator limits and large-state claims are reproducible from published commands and evidence. Standard verification scripts, executable documentation, error-code checks, dispatch-wiring checks, and R1 local evidence contract verify reproducibility. Proven by `python3 scripts/check-r1-local-evidence.py .`, `bash scripts/check-documentation.sh`, `bash scripts/check-error-codes.sh`, and `python3 scripts/check-dispatch-wiring.py`.
