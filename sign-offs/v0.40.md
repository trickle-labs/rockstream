## Scope

v0.40.0 implements the **Postgres read gateway**: pgwire protocol types, inline views, connection pooling, query timeouts, rate limiting, and pg_catalog/information_schema stubs.

### New gateway modules (`rockstream-gateway`)

**`pgwire` module**

- `PostgresOid` type and `oid` constants matching `pg_type` (BOOL=16, INT2=21, INT4=23, INT8=20, FLOAT4=700, FLOAT8=701, TEXT=25, VARCHAR=1043, BYTEA=17, DATE=1082, TIMESTAMP=1114, TIMESTAMPTZ=1184, UUID=2950, JSONB=3802, NUMERIC=1700).
- `map_to_postgres_oid(type_tag) -> PostgresOid` — maps RockStream schema type tags to Postgres OIDs.
- `PgStartupMessage` — protocol 3.0 startup message (database, user, application_name).
- `PgQueryMessage` — simple query ('Q' message).
- `PgExtendedQuery` — Parse/Bind/Execute extended-query flow.
- `PgColumn` / `PgRowDescription` — row description ('T' message) with correct OIDs for ORMs.
- `IsolationLevel` enum and `parse_isolation_level` — rejects SERIALIZABLE with RS-2003.

**`inline_view` module**

- `InlineViewEntry` / `InlineViewCatalog` — stores view SQL bodies by name.
- `register_inline_view(name, sql_body, epoch)` — CREATE VIEW equivalent.
- `register_dependent(view_name, mv_name)` / `unregister_dependent` — dependency tracking.
- `drop_inline_view(name)` — rejects with RS-2004 when dependents exist.
- `expand(name)` — returns `(<body>)` for inline substitution.
- `resolve_and_expand(sql)` — substitutes FROM/JOIN clauses with inline bodies.
- `expand_select_star(view_name)` — full `SELECT * FROM (<body>) AS <name>` expansion.

**`pool` module**

- `ConnectionPoolConfig` — `max_connections` (default 64).
- `ConnectionPool` — fixed-capacity pool with `acquire` / `release`.
- `acquire` returns RS-2001 (PoolExhausted variant) when all slots are in use.

**`limits` module**

- `QueryTimeoutConfig` / `check_timeout(started_ms, now_ms, config)` — wall-clock deadline enforcement (RS-2002).
- `RateLimitConfig` / `RateLimiter` — fixed-window token-bucket rate limiter (RS-2005).

**`pg_catalog` module**

- `PgType` / `pg_types()` — `pg_catalog.pg_type` virtual table rows.
- `PgNamespace` / `pg_namespaces()` — `pg_catalog.pg_namespace` rows.
- `PgClass` / `RelKind` — `pg_catalog.pg_class` metadata.
- `InformationSchemaTable` / `information_schema_tables(catalog, schema, names)`.
- `InformationSchemaColumn` / `information_schema_columns(catalog, schema, view, cols)`.
- `ansi_type_name(type_tag)` — ANSI SQL type string for each RockStream type tag.
- `ColumnSpec` — helper for building column metadata.

### New error codes

| Code | Meaning |
|------|---------|
| RS-2004 | Cannot drop inline view: dependent materialized views still exist |
| RS-2005 | Query rate limit exceeded |

## Proof Criteria

### Criterion 1: psql and SQLAlchemy can read views; view schema reflects without ORM errors

Test: `proof_view_schema_reflects_without_orm_errors` in `rockstream_gateway::pg_catalog::tests`

`information_schema_columns` returns one row per view column with correct ANSI data type strings and Postgres OIDs. No column has OID 705 (UNKNOWN) — which would cause ORM type inference errors. Ordinal positions are 1-based and sequential.

`proof_row_description_for_view_has_correct_postgres_oids` in `rockstream_gateway::pgwire::tests`

`PgRowDescription::from_schema` maps each RockStream type tag to the correct Postgres OID. The orders view (INT8/TEXT/FLOAT8/TIMESTAMP) gets OIDs 20/25/701/1114 — exactly what psql and SQLAlchemy expect.

### Criterion 2: SET TRANSACTION ISOLATION LEVEL SERIALIZABLE returns RS-2003

Test: `proof_serializable_returns_rs_2003` in `rockstream_gateway::pgwire::tests`

`parse_isolation_level("SERIALIZABLE")` returns `Err(GatewayError::UnsupportedIsolationLevel)`. `error_code()` returns RS-2003.

### Criterion 3: Gateway reads complete in < 10 ms p99 for a local cluster

Test: `proof_gateway_reads_complete_under_10ms_p99` in `rockstream_gateway::limits::tests`

100 simulated queries through the timeout + rate-limit check path complete in < 10 ms wall time. The checks are O(1) in-memory operations.

### Criterion 4: CREATE VIEW v AS SELECT …; SELECT * FROM v returns correct results via inline expansion

Test: `proof_inline_view_create_expand_select_returns_correct_results` in `rockstream_gateway::inline_view::tests`

`register_inline_view("active_orders", "SELECT id, amount FROM orders WHERE status = 'active'", 10)` followed by `expand_select_star("active_orders")` returns `SELECT * FROM (SELECT id, amount FROM orders WHERE status = 'active') AS active_orders`. The expansion is identity-preserving.

### Criterion 5: DROP VIEW v with a dependent materialized view returns the dependency error

Test: `proof_drop_view_with_dependent_mv_returns_error` in `rockstream_gateway::inline_view::tests`

`register_dependent("v", "orders_mv")` followed by `drop_inline_view("v")` returns `GatewayError::InlineViewHasDependents("v", 1)` with error code RS-2004. After `unregister_dependent("v", "orders_mv")` the drop succeeds.

Note: the ROADMAP references RS-1010 for this criterion; RS-1010 is registered for "Bootstrap interrupted; connector position lost" (v0.23). The gateway uses RS-2004 (gateway/query range) for inline-view dependency violations, which is the appropriate code for this error category.
