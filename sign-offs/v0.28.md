## Proof Claims

**Roadmap proof statement:** Kafka offsets and S3 file pointers are correctly tracked within the causal frontier protocol for exactly-once ingestion; a Kafka source closes a tumbling window correctly under deliberate clock skew.

### P1 — Source Connector Contract is satisfied by `KafkaSource` and `S3Source`

Claim: Verify basic connector operations (`discover_schema`, `start_snapshot`, `poll_delta`, `commit_offset`, `pause`, `resume`) on mock Kafka and S3 sources.

- [x] `test_kafka_source_basic` — Verified partition offset polling, watermark advancement, and offset commit tracking.
- [x] `test_s3_source_basic` — Verified reading files/lines sequentially, snapshot streaming, and offset commit tracking.

**Reproduce:** `rtk cargo test -p rockstream-connectors --lib`

### P2 — Kafka offsets are correctly tracked within the causal frontier protocol

Claim: Offset commits match source progress tracked in the causal frontier.

- [x] `test_kafka_offset_tracking_causal_frontier` — Offset token deserialization and partition offsets check out correctly across multiple epochs.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_kafka_offset_tracking_causal_frontier`

### P3 — A Kafka source closes a tumbling window correctly under deliberate clock skew

Claim: Inject skew in partition timestamps; assert window closes only when the slowest partition's watermark advances.

- [x] `test_kafka_clock_skew_window_closure` — Verified tumble window bounds do not close until the slower partition watermark advances past the boundary.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_kafka_clock_skew_window_closure`

### P4 — S3 source correctly tracks file pointers/offsets for continuous streaming ingestion

Claim: Stream rows from multiple files; assert offset updates and resumes correctly from last committed file pointers.

- [x] `test_s3_file_pointer_tracking` — Verified offset updates, committing offset, and resuming polling correctly from the committed offset token.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_s3_file_pointer_tracking`

### P5 — LFS durability: source offsets and frontiers persist to ShardDb and survive crash-replay

Claim: Write offsets to LFS ShardDb, simulate crash, restore registry, and resume from correct offsets.

- [x] `test_source_offset_replay_lfs` — Serialized offsets are saved to `ShardDb` via `SourceEpochRegistry`, restored after closing/reopening DB, and resumed successfully.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_source_offset_replay_lfs`

### P6 — MinIO backend: S3 source streams objects durably from a real MinIO bucket

Claim: TestContainers integration test polling files from MinIO.

- [x] `test_s3_source_minio_tc` — MinIO started via TestContainers; files uploaded, polled by `S3Source`, and verified offset updates.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_s3_source_minio_tc`

### P7 — SimRuntime integration: coordination paths validate under simulated network faults and `buggify!()`

Claim: SimRuntime seeded run with chaos injections.

- [x] `test_source_coordination_sim` — Evaluated 20 seeds with simulated connection drops and pauses; verified zero-loss/exactly-once ingestion.

**Reproduce:** `rtk cargo test -p rockstream-connectors --test source_proof_tests test_source_coordination_sim`
