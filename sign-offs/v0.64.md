## Exit Criteria Verification

All exit criteria from [v0.64 implementation plan](../docs/implementation-plans/v0.64.md) have been verified:

- [x] V064-01: Every SQL statement follows shared AST parsing, typed validation, logical operation, and execution; textual DML dispatch no longer owns semantics; eliminated string-prefix routing (`starts_with("update ")`, `starts_with("delete from ")`), textual parsing helpers (`parse_update`, `parse_delete`), and naive parameter string replacement (`substitute_params`); routed all statements through `sqlparser` with `PostgreSqlDialect` in `crates/rockstream-sql/src/frontend.rs` and typed `DmlStatement` in `crates/rockstream-sql/src/dml.rs`; proven by `dml_ast_parser_tests::test_dml_ast_parser_recognizes_insert_update_delete`, `dml_ast_parser_tests::test_dml_ast_parser_multi_row_insert`, `dml_ast_parser_tests::test_dml_ast_parser_rejects_malformed_syntax`, `dml_ast_parser_tests::test_dml_schema_validation_unknown_table_and_column`, and `pgwire_dml_parity_tests::test_no_textual_prefix_dispatch_used`.
- [x] V064-02: Typed INSERT, UPDATE, and DELETE honor the documented predicate subset, including multi-column AND, and reject unsupported expressions without writes; implemented general predicate evaluation supporting conjunctions (`AND`), disjunctions (`OR`), negation (`NOT`), binary comparisons (`=`, `<>`, `<`, `<=`, `>`, `>=`), and nullability checks (`IS NULL`, `IS NOT NULL`) with SQL 3-valued logic; unsupported expressions (correlated subqueries, non-deterministic UDFs in DML predicates) fail fast with `RS-1013` (SQLSTATE `0A000`) before any writes occur; proven by `dml_predicate_eval_tests::test_predicate_and_three_valued_logic`, `dml_predicate_eval_tests::test_predicate_or_three_valued_logic`, `dml_predicate_eval_tests::test_predicate_not_three_valued_logic`, `dml_predicate_eval_tests::test_multi_column_and_predicate`, `dml_predicate_eval_tests::test_dml_without_where_clause`, `dml_predicate_eval_tests::test_unsupported_subquery_predicate_rejection`, and `dml_predicate_eval_tests::test_unsupported_udf_predicate_rejection`.
- [x] V064-03: Multi-row UPDATE and key changes commit complete old/new deltas atomically; readers never see half-maintained dependencies; updates formulate atomic retraction (`-old`) and insertion (`+new`) records applied in a single transactional epoch; view materialization occurs at epoch commit, isolating uncommitted state from concurrent readers; injected failures roll back base tables and views completely; proven by `dml_atomicity_and_view_tests::test_atomic_single_row_update_view_propagation`, `dml_atomicity_and_view_tests::test_atomic_multi_row_update_view_propagation`, `dml_atomicity_and_view_tests::test_multi_row_update_failure_rolls_back_completely`, `dml_atomicity_and_view_tests::test_pk_update_retraction_and_insertion`, `dml_atomicity_and_view_tests::test_transaction_rollback_discards_all_dml`, `dml_atomicity_and_view_tests::test_transaction_commit_publishes_atomic_epoch`, and `dml_atomicity_and_view_tests::test_view_reader_isolation_during_dml`.
- [x] V064-04: Durable primary-key or explicitly selected heap identity semantics survive restart and duplicate-key errors leave prior state intact; parsed and persisted `pk_cols` through `CatalogStore` and `CatalogStubs`; enforced uniqueness on `INSERT` and `UPDATE` against committed storage and session write buffers with atomic rejection code `RS-2057` (`23505`); heap tables maintain unique row identities; primary key definitions survive crash and restart; proven by `primary_key_dml_tests::test_single_pk_duplicate_insert_rejected`, `primary_key_dml_tests::test_single_pk_duplicate_update_rejected`, `primary_key_dml_tests::test_composite_pk_duplicate_insert_rejected`, `primary_key_dml_tests::test_composite_pk_duplicate_update_rejected`, `primary_key_dml_tests::test_heap_table_duplicate_row_insertion`, and `primary_key_dml_tests::test_pk_durability_across_process_restart`.
- [x] V064-05: NULL, NULL predicates, numeric coercion, escaped text, UUID, timestamps, decimals, booleans, and typed parameters obey the frozen contract; coerced numeric types (`Int16`, `Int32`, `Int64`, `Float64`), checked overflow with `RS-1016` (`22003`), validated UTF-8 escaping with `RS-1003` (`22021`), and bound typed parameters directly into AST parameter placeholders during extended protocol execution; proven by `type_coercion_dml_tests::test_int16_dml_and_coercion`, `type_coercion_dml_tests::test_int32_dml_and_coercion`, `type_coercion_dml_tests::test_int64_dml_and_coercion`, `type_coercion_dml_tests::test_float64_dml_and_coercion`, `type_coercion_dml_tests::test_decimal_dml_and_overflow`, `type_coercion_dml_tests::test_utf8_escaping_and_nulls`, `type_coercion_dml_tests::test_boolean_dml_and_null_logic`, `type_coercion_dml_tests::test_timestamp_dml_and_zones`, and `type_coercion_dml_tests::test_uuid_dml_roundtrip`.
- [x] V064-06: Simple, prepared, and bound forms agree through tokio-postgres and the selected external client (psycopg3); validated against `tokio-postgres` and Python `psycopg3` via TestContainers, verifying identical full row shapes, wire types, multiplicities, command tags (`INSERT 0 <n>`, `UPDATE <n>`, `DELETE <n>`), and exact SQLSTATE error codes; proven by `postgres_dml_compatibility_tests::test_simple_prepared_bound_parity_tokio_postgres`, `postgres_dml_compatibility_tests::test_psycopg3_conformance_suite`, and `postgres_dml_compatibility_tests::test_postgres_compatibility_corpus_e2e`.
- [x] V064-07: UPDATE RETURNING, DELETE, DELETE RETURNING, no-match UPDATE, prepared UPDATE, rollback, commit, and view propagation return exact expected results; verified all 10 roadmap DML scenarios across both simple and extended query protocols, returning projected columns or `*` on `RETURNING` and accurate command tags including 0-count on no-match; proven by `postgres_dml_compatibility_tests::test_ten_required_dml_scenarios`, `pgwire_dml_parity_tests::test_extended_protocol_parameter_binding_and_returning_parity`, `pgwire_dml_parity_tests::test_delete_returning_pre_image`, `pgwire_dml_parity_tests::test_update_returning_multi_row`, and `pgwire_dml_parity_tests::test_prepared_update_execution`.
- [x] V064-08: A hard process restart preserves complete committed base/view state and excludes rolled-back or failed changes; verified via SIGKILL black-box crash proof where process is terminated abruptly after committed DML, restarted from identical storage, and asserted bit-identical state and maintained view query results against an independent batch oracle (`incremental == batch`); proven by `dml_crash_recovery_tests::test_sigkill_crash_proof_after_committed_dml`, `dml_durability_lfs_tests::test_dml_persistence_lfs_lifecycle`, and `dml_durability_minio_tests::test_dml_persistence_minio_lifecycle`.
- [x] V064-09: Oversized statements, excessive expression depth, and result or mutation limits fail with bounded work and no partial commits; enforced bounds on statement size (`MAX_SQL_STATEMENT_BYTES` = 1 MiB -> `RS-1012`), AST depth (`MAX_EXPR_DEPTH` = 64 -> `RS-1012`), mutation count (`MAX_DML_MUTATIONS_PER_STATEMENT` = 10,000 -> `RS-2002`), scan window (`MAX_DML_SCAN_WINDOW_ROWS` = 1,024), and write buffer memory (`WRITE_BUFFER_LIMIT_BYTES` = 64 MiB -> `RS-2019`); proven by `dml_bounding_and_negative_tests::test_oversized_sql_statement_rejected`, `dml_bounding_and_negative_tests::test_excessive_expression_depth_rejected`, `dml_bounding_and_negative_tests::test_mutation_limit_per_statement_enforced`, `dml_bounding_and_negative_tests::test_write_buffer_memory_limit_enforced`, and `dml_bounding_and_negative_tests::test_dml_scan_page_window_continues_to_completion`.
