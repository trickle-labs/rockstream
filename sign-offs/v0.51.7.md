## Notes

v0.51.7 closes the three front-door blockers (Blockers 1, 3, and 4 of `IMPLEMENTATION_STATUS_20260803.md`) preventing standard clients from reaching and executing queries safely over the wire interface:

1. **Protocol 3.2 negotiation (Blocker 1)**: `psql 18.4` and `libpq >= 18` open with wire protocol 3.2 (`196610`). The gateway intercepts initial startup messages and returns a standard `NegotiateProtocolVersion` ('v') message setting minor version 0 and echoing unsupported `_pq_.*` extension parameters back, continuing the protocol 3.0 handshake cleanly without socket EOF disconnects. Existing protocol 3.0 clients are unaffected.
2. **Honest relation semantics (Blocker 3)**: Queries targeting non-existent relations or views whose `CREATE` failed now pre-resolve against the catalog and return PostgreSQL error code `42P01` (`RS-1004`), replacing silent empty `OK` responses.
3. **CLI Auth Mode routing & enforcement (Blocker 4)**: `rockstream start --auth <mode>` options are properly evaluated and routed to `GatewayServer` auth constructors instead of hardcoding `AuthMode::Off`. Misconfigured auth strings fail closed on startup with exit code 2 (`RS-0002`), and valid auth modes are logged at server startup.

Per the plan's deferred-item audit and ground-rules statement, no items have been deferred to a later version.
