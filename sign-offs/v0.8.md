# v0.8 Sign-off — Inner Equi-Join (IVM-4)

**Signed off**: 2026-06-08

## Scope recap

v0.8 implements the DBSP inner equi-join operator, completing IVM-4.  All work
from the NEW_ROADMAP.md v0.8 row is implemented in full.

### PlanNode upgrade (`rockstream-plan`)

- `PlanNode::InnerJoin { left, right, left_keys, right_keys, left_arr_id, right_arr_id, semantics }` replaces the old stub `PlanNode::Join`.
- `JoinSemantics { inside_semijoin, is_join_child, r_old_materialize }` — EC-01/Q07/Q21 metadata.
- `OpKind::InnerJoin { left_keys, right_keys, left_arr_id, right_arr_id }` replaces stub `OpKind::Join`.
- `DiffCtx` updated: `InnerJoin` is now a supported operator (emits two-input `OpNode`); the "unsupported" test uses `Window` instead.
- `explain_incremental.rs` renders `InnerJoin` with `dual_arrangement` annotation.

### Storage key encoders (`rockstream-storage`)

- `JoinSide { Left, Right }` enum with `disc_bytes()`.
- `JOIN_LEFT_DISC = [0x4A, 0x4C]` ("JL") and `JOIN_RIGHT_DISC = [0x4A, 0x52]` ("JR").
- `ShardKeyEncoder::join_arr_key(side, op_id, join_key, row_id)` — full entry key.
- `ShardKeyEncoder::join_arr_prefix(side, op_id, join_key)` — group scan prefix.
- `ShardKeyEncoder::join_arr_op_prefix(side, op_id)` — operator scan prefix.
- 4 unit tests: left/right distinct, prefix hierarchy, disc byte values.

### `JoinOp` — bilinear inner equi-join (`rockstream-ops`)

- Two weight-tracking in-memory arrangements: `HashMap<JoinKey, HashMap<RowId, ArrRow>>`.
  - `ArrRow { row_bytes, weight: i64 }` — net Z-set weight per row, removed at 0.
- Bilinear expansion: `Δ(L⋈R) = ΔL⋈R₀ + L₀⋈ΔR + ΔL⋈ΔR`.
- `stable_row_id(op_id, join_key, row_bytes)` — FNV-1a 128-bit deterministic row identity.
- `JoinOp::with_schema(op_id, left_key_cols, right_key_cols, left_n_cols, right_n_cols)` — variable-schema constructor for 3-way join chaining.
- `persist_state(&db)` — point puts only, no range deletion.
- `load_from_storage(&db, op_id)` — crash-replay from `scan_prefix`.
- `left_entry_count()` / `right_entry_count()` — fill-level metrics.
- 9 unit tests in `join::tests`.

### Oracle property tests (`rockstream-oracle`)

- `join_oracle.rs`:
  - `batch_reference_join` and `batch_reference_3way` — pure-math references.
  - `incremental_join_output` / `incremental_3way_join_output` — incremental side.
  - `assert_oracle_join` — asserts `incremental == batch`.
  - Proptest `oracle_join_100k` (≥100k 2-way scenarios) + `oracle_3way_join_10k` (≥10k 3-way scenarios).
  - 12 total tests.

### SQL lowering (`rockstream-sql`)

- `lower.rs`: `LogicalPlan::Join(Inner)` → `PlanNode::InnerJoin` with `(left_keys, right_keys)` column indices; `RS-1013` for non-inner; `RS-1014` for no equi-condition.
- `distribution.rs`: `InnerJoin` inserts Loopback exchanges; output partitioned by left keys.
- `explain_incremental.rs`: `InnerJoin` rendered as `✓ InnerJoin[L=..., R=...]  dual_arrangement`.

### Error codes

- `RS-1014`: "JOIN has no equi-join condition; required for incremental maintenance."

### TPC-H plan-level parity (`rockstream-sql/tests/tpch_plans.rs`)

- 7 tests: Q1, Q3, Q5, Q6, key-index correctness, equi-join success, outer-join RS-1013.

### LFS crash-replay (`rockstream-ops/tests/lfs_join.rs`)

- 3 tests: state persists across close/reopen, crash-replay bit-identical output, no-range-delete.

## Notes

- `JoinOp` uses a weight-tracking arrangement (`HashMap<RowId, ArrRow>` with `ArrRow.weight: i64`) to correctly handle Z-set deltas with arbitrary weights. Bilinear output weight = `delta_weight * arr_weight`.
- The 3-way oracle chains two `JoinOp::with_schema` instances: LM join (2×2 → 4-col) feeds LMR join (4×2 → 6-col). Output decoded at columns 0, 1, 3, 5 for (k, l_v, m_v, r_v).
- DataFusion 53 populates equi-join `on` field only after optimization. TPC-H tests use `sql_to_plan_node` (optimized plan).
- No items deferred from this version.
