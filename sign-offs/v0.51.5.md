## Notes

v0.51.5 closes the gap where `--auth=mtls` (`Principal::CertCn`) was
wired but unreachable: every connection's `SSLRequest` was unconditionally
answered `'N'` (`server.rs`, both `serve()`/`serve_background()` accept
loops), so no TLS handshake — and therefore no client certificate — could
ever be presented, and the mTLS "CN" was actually read verbatim from a
client-supplied, spoofable startup parameter.

This version adds:
1. **Real TLS termination** — `GatewayConfig` gains `tls_cert_path`/
   `tls_key_path`/`tls_ca_cert_path` (`rockstream-types::config`, with
   matching CLI flags and a `docs/configuration.md` entry kept in sync by
   `test_configuration_doc_matches_rockstream_config_defaults`).
   `GatewayServer::with_tls(...)` builds a real `rustls::ServerConfig`/
   `TlsAcceptor` and is passed through to pgwire's own (previously dead,
   since our manual `SSLRequest` interception always raced and won)
   `Option<Arc<TlsAcceptor>>` parameter, deleting the manual peek/`'N'`-reply
   code in favor of pgwire's built-in SSL negotiation.
2. **Real mTLS** — the negotiated `rustls::ServerConnection`'s verified
   peer certificate's CN is extracted post-handshake and used as
   `Principal::CertCn`, replacing the old spoofable startup-parameter stub.
   Requesting mTLS without a CA cert path fails fast at startup instead of
   silently degrading.
3. **Real binary wire-format encoding** for every currently-text-supported
   OID (previously only int2/int4/int8/float4/float8/bool were correctly
   binary-encoded per v0.38; every other type — text, timestamp(tz), date,
   time, uuid, numeric, json/jsonb, interval, and all 6 array types —
   silently mislabeled raw text bytes as binary, corrupting values for any
   binary-format client). `INTERVAL` required a small hand-rolled `ToSql`
   impl (16-byte microseconds+days+months format); all other types use
   `postgres_types`' existing built-in binary `ToSql` implementations
   (already transitive dependencies of pgwire's `server-api` feature), and
   array types reuse the blanket `Vec<Option<T>>` binary-array impl once
   each scalar element's encoder exists.

Per the plan's deferred-item audit (§1) and ground-rules statement (§4/§5),
this version introduces no new IVM operator and no new durability path, so
the oracle/property, LFS/MinIO durability, deterministic-simulation/chaos,
and benchmark/soak proof rungs are N/A for this version's scope — TLS is a
pre-commit transport concern and binary encoding is a post-commit
presentation-layer transform, neither of which touches commit/replay/
crash-recovery or persisted state.

No item from `sign-offs/v0.1.md` through `sign-offs/v0.51.4.md` recorded an
explicit deferral overlapping this version's scope (TLS/SSL/mTLS/CertCn/
binary wire format/FormatCode) — the gaps closed here (fake SSL downgrade,
spoofable CN stub, partial binary encoding) were latent bugs from earlier
versions' narrower proof scope, not named deferrals.
