## Scope

v0.41.0 implements **gateway introspection and law-driven read performance**:
cross-shard partial aggregation pushdown driven by `LawBundle::gateway_combiner`,
the `rockstream_catalog` system schema virtual tables, and the per-worker
arrangement segment cache.

### Changes to `rockstream-types`

**`merge_law.rs`**

- `GatewayAggCombinerDesc` struct — describes partial aggregation pushdown for
  a law: `law_id`, `law_name`, `is_associative`, `is_commutative`.
- `LawBundle::gateway_combiner()` default method — returns `None`; laws that
  support cross-shard partial aggregation override to return `Some(desc)`.

**`laws/sum_count.rs`**

- `SumCountV1::gateway_combiner()` returns `Some(GatewayAggCombinerDesc)` —
  `SumCount/v1` is an abelian group (associative + commutative), so partial
  aggregation can be safely pushed to individual shards.

**`laws/weight_add.rs`**

- `WeightAddV1::gateway_combiner()` returns `Some(GatewayAggCombinerDesc)` —
  same reasoning as SumCount.

### New modules in `rockstream-gateway`

**`partial_agg` module**

- `PartialAggRow` — one partial result row per shard per group-by key.
- `CombinedAggRow` — result of merging partial rows across shards.
- `PartialAggPlan` — plan built from a law's `GatewayAggCombinerDesc`.
- `PartialAggExplainRow` — EXPLAIN output row for pushdown steps.
- `build_partial_agg_plan(group_by_cols, agg_col, law)` — returns `Some(plan)`
  if the law supports gateway combining.
- `combine_partial_results(plan, partial_rows, law)` — merges O(shards) partial
  rows per group into one combined row per group using `law.merge`.
- `explain_partial_agg(plan, shard_count, group_count)` — EXPLAIN rows including
  the merge law name.

**`rockstream_catalog` module**

- `CatalogMergeLaw` / `catalog_merge_laws(registry)` — `rockstream_catalog.merge_laws`
  virtual table rows with `(id, name, version, class, idempotent, associative,
  commutative, has_inverse, has_identity, supports_gateway_pushdown)`.
- `CatalogEpoch` / `catalog_epochs(pipeline_ids)` — epoch frontier stubs.
- `CatalogPipeline` / `catalog_pipelines(names)` — pipeline registry stubs.
- `CatalogShard` / `catalog_shards(pipeline_id, count)` — shard placement stubs.
- `CatalogAuditEntry` / `catalog_audit_log(entries)` — audit log stubs.
- `resolve_catalog_alias(schema_prefix)` / `resolve_catalog_table(schema, table)`
  — rewrite the legacy `rockstream.*` prefix to `rockstream_catalog.*`.

**`segment_cache` module**

- `ShardSegmentKey { shard_id: u32, segment_id: u64 }` — cache key.
- `SegmentCacheConfig { max_segments: usize }` — default 256.
- `SegmentCacheStats { hits, misses }` + `hit_ratio()`.
- `SegmentCache` — hash-map + LRU eviction; `get`, `insert`, `invalidate`,
  `invalidate_shard`.

## Proof Criteria

### Criterion 1: Partial agg to shards; gateway receives O(groups) rows, explain reports merge law

Test: `proof_partial_agg_pushdown_reduces_row_count` in
`rockstream_gateway::partial_agg::tests`

Simulation: 3 shards × 4 view rows = 12 total view rows, 2 distinct groups
("us-east", "eu-west"). Each shard returns 2 partial rows; the gateway
combines 6 partial rows into 2 combined rows. Combined count == 2, NOT 12.
Correctness: us-east (sum=1000, count=6), eu-west (sum=300, count=6).
EXPLAIN rows include `merge_law = "SumCount"` and `step = "gateway_combine"`.

Test: `proof_weight_add_partial_agg_pushdown` in
`rockstream_gateway::partial_agg::tests`

WeightAdd: 4 shards × 5 view rows = 20 view rows, 3 groups. Gateway sees 3
combined rows, not 20.

### Criterion 2: SELECT * FROM rockstream_catalog.merge_laws returns registered catalog

Test: `proof_catalog_merge_laws_returns_all_registered` in
`rockstream_gateway::rockstream_catalog::tests`

`LawRegistry::with_builtins()` contains 7 laws (WeightAdd, SumCount,
MaxRegister, MinRegister, HyperLogLog, BloomUnion, OrSet). Each row has
non-empty name, version ≥ 1, valid class string, correct idempotent flag,
and correct `supports_gateway_pushdown` flag (true for WeightAdd and SumCount).
Rows are sorted by law ID for deterministic output.

### Criterion 3: Segment cache hit ratio > 80% for hot-join workloads

Test: `proof_segment_cache_hit_ratio_exceeds_80_percent` in
`rockstream_gateway::segment_cache::tests`

200 total segments, 20 hot segments, cache capacity 32. After cold scan and
re-warming the hot set, 5000 hot replays achieve > 80% hit ratio. The cache
fits the entire hot set (20 ≤ 32) so all hot accesses hit after warm-up.
