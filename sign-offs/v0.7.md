# v0.7 Sign-off — SQL Frontend and Catalog

**Signed off**: 2026-06-08

## Scope recap

v0.7 implements the SQL frontend for RockStream, completing Phase 2 milestone
entry.  All work from the NEW_ROADMAP.md v0.7 row is implemented in full.

### SQL frontend (`rockstream-sql`)

- `SqlFrontend`: DataFusion-based parse/bind using `SessionContext`; exposes
  `sql_to_plan_node()` (optimized) and `sql_to_unoptimized_plan_node()` (deterministic).
- Table registration: `register_table(name, schema)` — empty `MemTable` for
  schema-only planning; column names resolve to 0-based indices.
- `CREATE VIEW` support via `SqlFrontend::create_view()` — lowering + catalog write.

### Custom extension nodes (`IncAggregate` / `IncJoin` / `IncDistinct`)

Three `UserDefinedLogicalNodeCore` implementations establish the extension
infrastructure for v0.8+ incremental operators:
- `IncAggregate`: GROUP BY aggregate marked for DBSP arrangement maintenance.
- `IncJoin`: equi-join stub with dual-arrangement marker (v0.8).
- `IncDistinct`: DISTINCT/set-op stub (v0.10).
All three implement `PartialOrd` (required by DataFusion 53 trait bound) via a
stub returning `None` (not ordered, just required by bound).

### Lowering pass (`lower.rs`): `LogicalPlan → PlanNode`

Supported plan nodes: `TableScan → Source`, `Filter → Filter`,
`Projection → Project`, `Aggregate → Aggregate`, `SubqueryAlias → transparent`,
`Extension (1 child) → lower child`.

Expression lowering: `Column → Column(idx)`, `Literal → Literal(bytes)` (integers
as 8-byte big-endian i64), `BinaryExpr → BinaryOp`, `Alias → transparent`,
`Cast → transparent`.

Aggregate function lowering: SUM/COUNT/AVG/MIN/MAX via `func.name().to_lowercase()`.
DataFusion 53 `AggregateFunction` uses `{func, params}` structure; `params.args`
and `params.distinct` are used.

### Distribution pass (`distribution.rs`)

Walks the `PlanNode` tree and inserts `Exchange { kind: Loopback }` no-ops:
- `Aggregate` always requires hash-partitioned input → Loopback exchange inserted.
- All other operators preserve input partitioning.
- In single-shard mode all exchanges are Loopback (zero network calls).

### Schema-version catalog (`catalog.rs` + `SchemaCatalog`)

Backed by `ShardDb` under `CatalogType::View` keys
(`CatalogKeyEncoder::encode(View, namespace_id=0, view_object_id(name))`).
Stores `ViewEntry` as JSON bytes (via `serde_json`).

Schema-change classification:
- Compatible: same schema or new nullable columns at end → accepted, `schema_version++`.
- Incompatible: renamed/removed/retyped/reordered column → `RS-1002`.

### `EXPLAIN INCREMENTAL` (`explain_incremental.rs`)

Formats the `PlanNode` tree with merge-law annotations:
- Stateless ops: `⚠ stateless`
- Algebraic aggregates: `✓ merge_law=WeightAdd/v1`
- MIN/MAX aggregates: `✗ extremum_requires_rmw`

### `EXPLAIN INCREMENTAL ESTIMATE` (`estimate.rs`)

Static cost model — **no operators deployed, no storage accessed**:
- Filter / Project / Map: 5 M rows/s, 0 state bytes.
- Aggregate SUM/COUNT/AVG: 1 M rows/s, 24 bytes/group.
- Aggregate MIN/MAX: 100 k rows/s, 32 bytes/group.
- Returns `Vec<EstimateRow> { operator_kind, predicted_state_bytes, epoch_ms }`.

### New error codes

- `RS-1012`: SQL parse error — registered with description and actionable
  `next_steps`. Included in `all_codes_have_descriptions_and_actionable_next_steps`.
- `RS-1013`: Unsupported plan node for incremental lowering — registered with
  description and actionable `next_steps`. Included in the registry test.

### Serde on `PlanNode` types

All public types in `rockstream-plan` (`PlanNode`, `Expr`, `BinaryOp`,
`AggregateExpr`, `AggregateFunc`, `ExchangeKind`, `LateDataPolicy`,
`LateralFunc`, `UdafSpec`, `WindowExpr`, `WindowFunc`, `WindowStrategy`,
`OpNode`, `OpKind`) now derive `Serialize, Deserialize`, enabling catalog
storage and cross-process serialization.

## Notes

- DataFusion 53 API differences from assumed:
  - `DfExpr::Literal` is now a 2-tuple `Literal(ScalarValue, Option<FieldMetadata>)`; lowered with `DfExpr::Literal(scalar, _)`.
  - `AggregateFunction` uses `{func, params}` structure; args/distinct accessed via `params.args` / `params.distinct`.
  - `UserDefinedLogicalNodeCore` requires `PartialOrd`; implemented for extension nodes via a stub returning `None`.
  - `MemTable::try_new` requires at least one partition: `vec![vec![]]` not `vec![]`.
  - No `CrossJoin` variant in `LogicalPlan` (all joins are `Join`).
- DataFusion's unoptimized plan for aggregate queries adds an outer `Projection` node above `Aggregate`. The "identical physical plans" proof tests account for this: hand-coded expected plans include the outer `Project([Col(0), Col(1), ...])` wrapper.
- No items deferred from this version.
