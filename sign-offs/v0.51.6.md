## Notes

v0.51.6 closes three independent gaps found in the <=v0.51.5 serving-path
hardening: unbounded per-connection prepared-statement/portal cache state,
an unenforced-but-silently-accepted `REPEATABLE READ` isolation level, and
a truncated-integer `avg` aggregate.

This version adds:

1. **Bounded prepared-statement/portal cache with LRU eviction** — a new
   `MAX_PREPARED_STATEMENTS_PER_CONN` bound with LRU eviction and a
   `PREPARED_STATEMENTS_EVICTED_COUNT` metric replaces the previous
   unbounded per-connection cache, so a client that never issues
   `DISCARD ALL` (today's only bounding mechanism, v0.37) cannot leak memory
   proportional to the number of statements it has ever prepared.
2. **Guaranteed cleanup on abnormal (TCP-level) disconnect** — all five
   per-connection `DashMap`s (`prepared_statements`, `active_portals`,
   `portal_states`, `sessions`, `write_buffers`, `copy_states`) and their
   fill-level metrics are now proven to return to baseline even when a
   connection is killed at the raw-socket level with no `Terminate` message,
   closing the gap where only the graceful path was covered.
3. **Honest `REPEATABLE READ` rejection** — `BEGIN`/`SET TRANSACTION
   ISOLATION LEVEL REPEATABLE READ` now return the new, documented
   `RS-2004` error instead of silently accepting a request they never
   enforced, mirroring `SERIALIZABLE`'s existing `RS-2003` honesty
   contract. Dead frontier-pinning plumbing that was never wired to any
   enforcement was removed rather than left as latent, misleading code.
4. **Correct fractional `avg`** — the `avg` aggregate's row encoding changed
   from a truncating `Int64` to `Float64` (`TAG_FLOAT64` `avg_v`), matching
   PostgreSQL's `avg()` semantics for non-integer means, proven across
   in-memory, live-wire, oracle (incremental==batch), LFS durability, real
   MinIO/TestContainers durability, and Nexmark regression paths.

**Regressions found and fixed during Prove (schema-change fallout, not
deferred)**: changing `avg_v`'s output type broke two pre-existing tests
that hard-coded the old `Int64` column type for `AggregateOp`'s output
column 3 — `crates/rockstream-ops/tests/virtual_bucket_state_durability_tests.rs`
and `crates/rockstream-sql/tests/tpch_soak_e2e.rs`. Both were fixed in this
version (not left broken, not deferred) and re-verified green; see
`.claude/v0.51.6-evidence.md` for full detail.

Per the plan's deferred-item audit and ground-rules statement, this version
introduces no new distributed-coordination path, so the `SimRuntime`
deterministic-simulation/chaos proof rung is N/A for this version's scope
(bounded per-connection cache state, a gateway-local error-code honesty
fix, and an aggregate-encoding correctness fix are all single-connection/
single-shard concerns, not distributed-coordination concerns). No item from
`sign-offs/v0.1.md` through `sign-offs/v0.51.5.md` recorded an explicit
deferral overlapping this version's scope (prepared-statement bounding,
abnormal-disconnect cleanup, `REPEATABLE READ` enforcement, `avg`
precision) — the gaps closed here were latent bugs/omissions from earlier
versions' narrower proof scope, not named deferrals.
