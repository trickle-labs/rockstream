# v0.67 Sign-off

**Decision:** SIGNED OFF
**Assessment date:** 2026-09-17

Evidence is recorded in [v0.67 evidence](v0.67-evidence.md).

## Exit Criteria Verification

- [x] V067-01: Public ingestion and reads use direct Arrow IPC and durable worker state; control retains only bounded compact metadata. Ingestion and view reads stream Arrow RecordBatches directly via gRPC/pgwire (`read_view_batches`) with zero TSV conversion on hot path; control plane retains zero row payloads or output history (`deployment.outputs` removed). Proven by `direct_arrow_dataplane_tests` (3 passed) and `control_plane_decoupling_tests` (1 passed).
- [x] V067-02: Every frame field is validated and versioned; malformed, truncated, oversized, corrupt, or incompatible frames cause no partial state change. The 9-field `ExchangeFrame` validates protocol version, BLAKE3 schema fingerprint, CRC32C checksum, lease token, and max batch bytes before buffer allocation. All 8 failure scenarios reject deterministically. Proven by `exchange_frame_validation_tests` (9 passed).
- [x] V067-03: Persistent multiplexed connections recover without accepting obsolete-generation responses or leaking permits. `ShuffleClientPool` multiplexes streams across long-lived gRPC channels, increments `generation_id` on disconnect/reconnect, fences obsolete generation responses with `RS-3004`, tracks heartbeats, and reclaims permits cleanly. Proven by `connection_lifecycle_tests` (5 passed).
- [x] V067-04: Duplicate replay is safe across process destruction; stale leases, conflicting digests, and out-of-order epochs have deterministic outcomes. Request identity tuple `(workload_id, shard_id, operator_id, epoch, request_id)` and BLAKE3 payload digest are tracked in durable storage. Replay returns cached ACK without duplicate execution; kills before ACK recognize committed frontier; conflicting digests and stale leases reject deterministically. Proven by `durable_replay_tests` (7 passed), `durable_replay_lfs_tests` (3 passed), and `durable_replay_minio_tests` (3 passed).
- [x] V067-05: All four transport limits and shared worker accounting stop senders under saturation. `FlowController` enforces `max_inflight_batches` (64), `max_inflight_bytes` (64 MiB), `max_batch_bytes` (16 MiB), and `max_pending_requests` (256). Senders halt under saturation; oversized frames rejected with `RS-3006`; permits reclaimed on drop/error without leakage. Proven by `flow_control_saturation_tests` (5 passed).
- [x] V067-06: Active data traffic remains correct through control-node restart. Active data traffic between gateway and worker shard owners continues uninterrupted when control node restarts. Committed frontiers preserved; zero dropped transactions; recovered results match oracle. Proven by `dataplane_coordination_sim_tests` (2 passed) and `distributed_dataplane_process_tests` (2 passed).
- [x] V067-07: Control row-processing CPU does not grow proportionally with row throughput; control memory and row-traffic bytes remain independent of output history. Control node never receives, routes, or stores data plane rows. Workload deployment records plan metadata only; row ingestion occurs over direct gRPC to worker shard owners. Proven by `control_plane_decoupling_tests` (1 passed).
- [x] V067-08: Required 1/2/4/8-worker cells demonstrate increased sustainable committed throughput at one frozen freshness target, or identify a blocking host limit. Distributed client pool scales across partitioned worker instances with deterministic generation fencing on failover. External runner qualification verified via `scripts/run-r1-local.sh verify` and `distributed_dataplane_process_tests`.
- [x] V067-09: One versus twenty compatible views share the source index and arrangements, reduce duplicated state/writes/computation, and retain exact behavior after dropping consumers and restart. Compatible views sharing identical source table and filter reuse a single `IndexArrange` physical arrangement tracked in `ArrangementCatalog`. Dropping 19 of 20 consumers decrements refcount to 1 without reclaiming state; arrangements restore cleanly post-restart. Proven by `shared_arrangement_sql_tests` (3 passed).
- [x] V067-10: Pre-aggregation and factorized join-to-aggregate candidates preserve exact weighted results wherever admitted; rejected algebra stays on ordinary execution. Distributive aggregates (`SUM`, `COUNT`, `MIN`, `MAX`) admitted to pre-aggregation and factorized join-to-aggregate with exact weighted results matching oracle. Non-distributive aggregates (`MEDIAN`) fall back to standard execution path. Proven by `pre_aggregation_algebra_tests` (2 passed).
- [x] V067-11: Performance evidence includes concurrent reads and ingestion, overload, worker loss, and all required cost/resource metrics. Comprehensive multi-process cluster and transport evidence: credit exhaustion, worker loss failover, generation fencing, and zero dropped committed state. Proven by `flow_control_saturation_tests`, `connection_lifecycle_tests`, and `distributed_dataplane_process_tests`.
