# v0.6 Sign-off — MIN / MAX and crash-replay (IVM-3)

**Signed off**: 2026-06-08

## Scope recap

v0.6 implements non-invertible MIN/MAX aggregates and proves crash-replay
correctness on both LFS and MinIO backends, completing Phase 1 of the roadmap.

### IVM-3: Indexed-multiset arrangement and cached extremum

- `MinMaxOp`: stateful incremental GROUP BY MIN/MAX operator.
  - `MinMaxKind::Min` / `MinMaxKind::Max` — separate sort-key encoding per mode.
  - In-memory state: `HashMap<group_key, BTreeMap<sort_key, weight>>` +
    `HashMap<group_key, extremum>` (cached); bounded by distinct (group, value)
    pairs with `live_entries()` and `live_groups()` fill-level metrics.
  - Sort key: `(v as u64 ^ 0x8000_0000_0000_0000).to_be_bytes()` for MIN (smallest
    value → smallest key → `BTreeMap.keys().next()` returns extremum); bitwise NOT
    of MIN encoding for MAX (largest value → smallest key).
  - `process_delta`: row-by-row DBSP delta rule — update multiset, recompute
    extremum, emit `(k, old_extremum, -1) ⊎ (k, new_extremum, +1)` when extremum
    changes. Returns `RS-1017` on retraction underflow.
  - `persist_minmax_state(db, op)`: scan-and-delete persistence for multiset
    (under `ShardPrefix::OpState / 0x4D`) and extremum cache (under
    `ShardPrefix::OpIndex / 0x4D`); no range deletion.
  - `MinMaxOp::load_from_storage(db, op_id, kind)`: restore from ShardDb at shard
    startup.

### Crash-replay

- `persist_frontier` / `load_frontier` (from v0.5) used with `persist_minmax_state`
  to commit epoch state. Crash before persist leaves frontier at last committed
  epoch; replay from that frontier re-produces bit-identical output.
- Proved on LFS and MinIO backends.

### WAL listing cache validated on hot path

- `WalListingCache::populate()` (one LIST call) + repeated `get_cached_entries()`
  (zero additional LIST calls) — verified by `lfs_wal_cache_hot_path_avoids_list_calls`.
  Rotation increments count by 1; hot-path accesses after rotation also incur zero
  additional LIST calls.

### New error code

- `RS-1017`: MIN/MAX multiset retraction underflow — retraction for a value with no
  positive weight. Registered in `rockstream-types` with description and actionable
  `next_steps`. Included in `all_codes_have_descriptions_and_actionable_next_steps`.

### New key encoders

In `ShardKeyEncoder`:
- `minmax_multiset_key`, `minmax_group_prefix`, `minmax_operator_prefix`,
  `minmax_extremum_key`, `minmax_extremum_op_prefix`.

Free functions:
- `minmax_sort_key(v: i64, invert: bool) -> [u8; 8]`
- `minmax_sort_key_decode(sort_key: [u8; 8], invert: bool) -> i64`

## Notes

- Sort key encoding maps i64 to u64 with sign-aware byte ordering
  (`v as u64 ^ 0x8000_0000_0000_0000`) so lexicographic scan order matches signed
  integer order. For MAX, bitwise complement (`!raw`) reverses the order, so both
  MIN and MAX find the extremum with a single `BTreeMap.keys().next()` / O(1) call.
- `apply_delta` returns `Err(RS-1017)` on retraction underflow (never silently
  produces incorrect extrema from malformed input).
- Crash-replay uses two independent `TempDir` instances to prove hermetic isolation.
- `persist_minmax_state` drops `MutexGuard` before any `.await` (satisfies
  `clippy::await_holding_lock`).
- Phase 1 complete: v0.4 (filter/project/map) + v0.5 (algebraic aggregates +
  group commit) + v0.6 (MIN/MAX + crash-replay) all pass.
- No items deferred from this version.
