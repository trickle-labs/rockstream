## Incremental changes in this PR
- Workload definition carries a persisted numeric revision; older records without one decode at revision 1.
- Conditional `ALTER WORKLOAD <name> IF REVISION <n> SET (...)` compares revision at the actual producer catalog update, returning SQLSTATE `40001` on conflict.
- The in-memory catalog compare-and-swap checks and updates under a single write lock. Conflict and overflow leave the requested definition unchanged; concurrent callers cannot both win a stale revision.
- Async conditional updates are serialized and apply the persisted definition before publication in the gateway catalog.
- Regression fixtures: revision serialization, concurrent conflict, overflow, SQL-wire conflict and restart persistence.

## Incomplete requirements that **block #137 sign-off**
- Legacy `ALTER WORKLOAD ... SET (...)` still exists for backward compatibility and is **not** revision-conditioned. Operators must explicitly use `IF REVISION` for this path. Migration/restriction is outstanding.
- No verified live-owner acknowledgement protocol, effective-vs-requested policy status, frozen acknowledgement deadline, restart/outage/failure evidence, or reduction-below-live-use rejection.
- The async catalog backend does not provide a distributed transactional CAS; a concurrent external writer can race independently of this gateway. Multi-owner and multi-leader checks are outstanding.
