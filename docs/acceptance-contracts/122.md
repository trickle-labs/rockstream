## Implementation disposition

R1–R4 use `rockstream_ops::kafka_sink::KafkaViewSink` over the production
`ViewSinkOp` log and existing transactional `KafkaSink`. The LFS/Kafka test
`view_snapshot_changes_and_recovery_match_exact_consumer_stream` compares
independent complete consumer records and the final relation for uninterrupted
delivery and crashes before snapshot/update/delete commit and after broker
commit before progress finalization. It closes and reopens shard storage and
reconnects the producer; pending payload bytes and cursors survive recovery.

R5's exact stream oracle rejects equal-count value substitution, omission of a
deletion, duplication of a change, and marker-only output. R6 keeps `sink.kafka`
Experimental: the full Core proof-level matrix remains unqualified. Marker
transport tests retain their narrower scope. The runtime adapter requires one
owner, fixed view identity/schema, a retained monotonic log, and a dedicated
Kafka topic with retained delivery records. It rejects envelopes above 900 KiB
and reads above 64 MiB instead of truncating them.
