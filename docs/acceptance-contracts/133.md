## Initial implementation contribution

`v072_quota_lifecycle` exercises the existing production memory-wait future through unpolled drop, immediate success, repeated pending-future cancellation, waiter overflow, timeout, delayed success and task abort. Each completed path checks the entire category ledger and waiter usage.

`v072_worker_budget_tests` checks all eight existing categories, cross-category atomic admission, zero/full-reservation bounds, foreground capacity, retryable shared-cache reservations, concurrent cache initialization, overflow-safe accounting and empty-category release. The worker total is the admission counter; individual category observations reconcile after acquisition/release operations complete, not as a transactionally sampled live snapshot. These tests reserve accounting bytes, not physical large-state allocations.

Reproduce:

```sh
rtk cargo test -p rockstream-runtime --test v072_quota_lifecycle
rtk cargo test -p rockstream-types --test v072_worker_budget_tests
rtk cargo test -p rockstream-types state_budget
```

These are R2/R3/R4 regression contributions. They do not establish complete owner accounting, producer soft-pressure behavior, RSS reconciliation, shard/restart behavior or the consolidated resource inventory. Unit tests do not replace release-process evidence. No prerequisite sign-off or parent obligation is marked complete here.


## Follow-up zero-memory hard-bound regression (#195)

`v072_zero_workload_budget` exercises `WorkloadBudget` with a directly configured hard memory ceiling of 0 and verifies that both direct and operator-scoped positive reservations fail with exact `StateBudgetError` values and unchanged accounting. The intentionally absent workload limit remains represented by `WorkloadDef.memory_limit = None`; an explicit `Some(MemoryLimit { bytes: 0 })` must never become unlimited. A nonzero shared-operator limit/release boundary is also covered.

These targeted tests are additional regression evidence, **not** RSS reconciliation, physical beyond-RAM state coverage, complete source throttling, or final #133/#132 acceptance.

## Checked recovery accounting (#195 follow-up)

`StateBudget::force_acquire` now returns `Result<(), StateBudgetError>` and accounts restored state using checked atomic additions. Over-limit durable state is still charged after restart (so future admissions remain blocked); a counter overflow fails explicitly without wrapping the workload or operator charge back to zero. The tests verify exact ledger state at the `u64::MAX` overflow boundary and after a zero-limit policy is restored from nonzero durable state.

These are two additional code-level tests. Physical restart recovery, per-owner effective limit acknowledgements, and real-process evidence are not yet qualified. No v0.72 criterion is marked complete.

## Queued exchange-credit waiter bound (partial R4 contribution)

The `FlowController` has two asynchronous producers of exchange-credit waiters: legacy row credits (`acquire_credit`) and batch-byte credits (`acquire_batch_permit`). Both now register a drop-owned `CreditWaiterSlot` **only after** immediate admission has failed. Queued futures have an atomic, prospective ceiling of `max_pending_requests`; rejection is `RS-3006 RESOURCE_EXHAUSTED` before a waiter is installed. The `queued_credit_waiters()` method exposes the queue fill level. Legacy per-channel notifier entries are now ref-counted and released when their final live waiter leaves; `queued_notifier_channels()` exposes that fill. Teardown cannot decrement a replacement notifier generation because cleanup checks notifier pointer identity. Cancellation/abort, successful wakeup and early errors free the exact slot. This quota is **separate** from previously counted in-flight batch permits; it does not assert a unified cross-class sum or bound per-channel notifier-map cardinality.

`crates/rockstream-runtime/tests/v072_exchange_credit_waiters.rs` validates six exact transitions: uncontended admission, saturation without over-admission, task-abort cleanup, wakeup cleanup and failure before waiter ownership, and 32 distinct aborted channels without retained notifier keys. Production read/maintenance/control lane fairness, scheduler queue age, global waiter inventory, other transient-buffer cleanup, physical RSS and full resource-owner reconciliation remain outstanding.

Do not mark #133 or #132 accepted based on these code-level tests.
