# #135 — Producer-bound interactive execution (proposed child contract)

**Status:** partial implementation proposal, not approved acceptance or v0.72 sign-off.

Parent [#132](https://github.com/trickle-labs/rockstream/issues/132) v2:R23–R26,R29 (plus resource bound R6). Authoritative parent contract: `docs/acceptance-contracts/132.md` at `7a73050dbb28fdf61584d052b9521b2e7dce9835`; immutable plan `6442838183ffd913b6a24860072575aacaa9c96a`.

## Progress in the bounded-legacy-read PR

- Limited legacy view-prefix reads do **not** invoke the eager `scan_prefix()` path. They use `ShardReader::scan_prefix_pages` with bounded pages and a capacity-1 channel.
- The scanner task is abort-owned; reaching LIMIT, error, cancellation and disconnect drop the abort guard rather than draining the entire keyspace.
- The producer rejects a prospective response over the frozen 64 MiB interactive intermediate budget before returning rows; the wire-facing COPY OUT path in merged PR #181 retains its stricter 10,000-row/8 MiB output preflight.
- Focused storage-backed tests cover exact sorted LIMIT results, missing prefixes, zero rows, and rejection without partial results after exceeding a byte budget.

## Incomplete child acceptance

- **This is not all of #135.** Compiled-view state materialization, default unbounded requests, typed SQL validation/diagnostics, query compilation/CPU/queue/concurrency and snapshot-lifetime admission, scoped actor-bound handles, complete cancellation/revocation, read tokens and bounded typed result pages remain to be integrated.

## Follow-up: bounded COPY OUT producer-read time (#196)

The read stage of `COPY <view> TO STDOUT` is bounded by the frozen v0.72
interactive `max_wall_ms = 5000` budget. The gateway wraps the cancel-safe
`ViewReader::read_view` future in an explicit deadline; timeout returns
SQLSTATE `57014`, `[RS-9001] copy_out.read_timeout` before sending any
`CopyOutResponse`, `CopyData` or `CopyDone` frame. The dropped future
must release its owned permits. Two isolated tests check ready/error behavior
and release on timeout; one PgWire integration test checks the real timeout,
preframing SQL error, and reader cleanup.

This limits the **reader phase only**. It does not enforce a complete end-to-end
5-second producer/request/network deadline, compiled intermediate state bytes,
concurrency, snapshot lifetime, remote detached-task cancellation, handle
binding, or all eight interactive budgets. Actual process evidence and #135/#132
acceptance remain open.

## Read-only compiled delta-scan budget contribution

The read-only `ShardReader` previously exposed `scan_prefix` as the only way to read compiled `ViewSinkOp` history: it returned the entire delta log before result admission, even though the same-process `ShardDb` read already rejected output larger than 64 MiB. This exceeded the #135 producer-intermediate-state envelope before the query result ceiling was enforced.

`ShardReader::scan_prefix_bounded` now has a byte-checked cumulative payload bound, fails closed with a `truncated` signal, and handles v1, v2, and mixed-format migration reads without retaining unbounded input. It discards partial accumulated entries on overflow. The compiled-view read-only sink path now uses the existing named `VIEW_OUTPUT_READ_MAX_BYTES` limit and errors instead of decoding incomplete results.

`snapshot_bounded_scan_never_retains_partial_overflow_entries` checks exact-bound success and overflow/zero/absent handling using actual storage. `bounded_entry_accounting_rejects_size_overflow` guards against arithmetic wraparound. These are source and unit-level checks, not proof of full compiled-view state/output limits, cancellation, restart, snapshot freshness or producer query session budgets.

No #135 or #132 acceptance criterion is checked off by this contribution; real-process qualification and complete independent result oracles remain necessary.

## Streamed page-parameter hardening

`ShardReader::scan_prefix_pages` has a separate consumer-supplied page budget. A zero-row capacity previously disabled the page-count flush condition, and unbounded `Vec::with_capacity(max_rows)` could allocate beyond any documented envelope before reading a single storage row. The new producer preflight rejects row capacities outside 1–4096 and byte capacities outside 1–16 MiB. It also uses checked per-entry byte summation and emits an explicit error instead of wrapping counters. These limits encompass the existing control migration and gateway bounded-scan page configurations.

The corresponding unit test exercises zero/oversized row/byte bounds against an actual `ShardReader` and verifies the producer emits no data pages on error. This protects page-memory limits but does not yet prove correct streaming of mixed-format migration pages or complete intermediate-result cardinality bounds, and is not a capacity sign-off.

## Follow-up: subscription producer authorization

`GatewayHandler::dispatch_async_with_conn` now forwards the authenticated
connection identity to `handle_subscribe`, which invokes the same
`select_access_error_response` policy as SELECT before any stream permit,
catalog snapshot, or retained-epoch replay. The checker enforces a Viewer
grant and namespace visibility; denied requests return SQLSTATE 42501 with
RS-2401 (role) or RS-2402 (namespace).

`v072_subscription_authorization_tests` checks snapshot and epoch denial
before any reader call or stream reservation, successful viewer-granted
subscription followed by drop-owned cleanup, cross-namespace rejection even with a view-level Viewer grant in the
session namespace, and rejection of subscriptions in failed SQL transactions
before any snapshot read or stream reservation.

These code-level checks are **not** independent production authentication
or release-process validation, and they do not replace typed validation,
scoped handles, cancellation cleanup, and actual committed read-token
requirements under #135. No child or parent acceptance state changes.
