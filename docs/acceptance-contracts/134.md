## Incremental helper hardening (#189)

`AdmissionController::evaluate_and_admit` now plans priority preemption before mutating any competing view state. A request that still cannot fit after all eligible lower-priority estimates is rejected with only a rejection audit event; it may not leave other views spuriously paused. For successful requests, only the needed lowest-priority running views with non-zero accounted state are selected. Unknown workloads fail closed, while a u128 demand total and subtraction-based capacity check avoid u64 overflow/saturation being interpreted as free capacity.

Six regression tests exercise rejection side effects and audit, minimal preemption, unknown identity, overflow, multiple huge views, and wrapped backfill reservation accounting. The backfill controller now rejects a reservation that would overflow its capacity instead of accepting a saturated u64 sum. These are **code-level safety tests**, not proof of fair queue age or physical memory reclamation.

## Unmet prerequisites and scope

#133 full resource-owner reconciliation and producer memory-pressure integration are prerequisites for actual fair admission. The admission helper is not itself a production worker dispatch loop: serializable capacity reservations across concurrent callers, actual read/maintenance/control lane reservation, freshness/parallelism inputs, shard ordering, and producer-facing rollout remain to be implemented. Existing `EpochCompactionConfig` adaptation is a foundation, not the complete durable epoch protocol. No criterion or sign-off is marked complete.

## Follow-up bounded exchange waits

`FlowController` now uses a drop-owned `ExchangeWaiterSlot` for both
row-credit and async batch-permit wait paths, reserving a shared
`max_pending_requests`-sized waiter envelope only after uncontended
admission fails. `exchange_waiters()` exposes the current wait fill
separately from the existing `pending_requests()` count of in-flight
batch permits. Saturation returns `[RS-3006] RESOURCE_EXHAUSTED` without
creating another waiting task. Success, cancellation and task abort release
the same slot.

Three focused regression tests cover both wait paths at a limit of one,
cancellation/retry cleanup, and zero waiter ownership on the common
uncontended fast path.

This is a bound on exchange waiters, **not** integration of fair
cross-workload dispatch, reserved read/maintenance/control lanes, ordered
durable commits, or independent release-process fairness and RSS evidence.
Parent #132 remains unqualified.
