# v0.62 Unified configuration and node lifecycle

Status: Done

Source: [ROADMAP section 8](../../ROADMAP.md#v0-62). Apply the [shared implementation and evidence rules](README.md).

## Prerequisites and scope

Require v0.61's working local project. The v0.62.1 worker budget patch follows NodeConfig and does not block this base milestone. Keep standalone and separate roles on the same component implementations.

## Goal and public behavior

One versioned configuration describes every service the process starts. Effective configuration explains each value's origin. A node remains alive until shutdown or fatal failure and cannot report Ready before recovery finishes.

## Implementation steps

1. Replace overlapping startup configuration with NodeConfig in the types crate. Reuse `crates/rockstream-types/src/config.rs`, `config_resolver.rs`, and `config_validation.rs`. Include version, node, gateway, control, worker, storage, metrics, auth, logging, and runtime sections. Inventory every existing startup option and either map it to one field or explicitly deprecate it. Resolve old-config compatibility before changing deserialization.
2. Preserve one resolution path through `ConfigResolver::resolve`: compiled defaults, file, environment, then CLI. Make listening addresses properties of their services. Implement complete, redacted `config print-effective --origins` output through existing CLI dispatch. No startup path may recompute different defaults after resolution.
3. Reject unknown keys for the new format. Diagnostics identify the source file, unknown key, nearby valid keys, and line and column when the parser provides them. Validate version, role requirements, addresses, authentication, resource settings, and storage before binding any port. Define migration errors for unsupported prior versions.
4. Parse explicit storage URLs, including the roadmap's file and S3 forms only when their implementation is actually available. Reject unimplemented schemes. Resolve relative file URLs consistently with the documented config base directory; define this rule before coding. Verify inaccessible storage fails startup rather than falling back to ephemeral state.
5. Refactor `run_start` and gateway startup in `crates/rockstream-cli/src/lib.rs` around the planned NodeRuntime, Component, and ComponentState types. Compose ControlComponent, WorkerComponent, GatewayComponent, MetricsComponent, and ConnectorSupervisor according to the role. Reuse existing runtime services and `shutdown.rs`; do not build parallel standalone implementations.
6. Enforce Created, Starting, Recovering, Ready, Draining, Stopping, Stopped, and Fatal transitions. Specify startup dependency order, mandatory recovery completion, component failure propagation, drain deadlines, and cancellation before implementation. Bound startup requests, drain waiters, retry loops, and health response buffers. Report state and limit occupancy.
7. Remove production sleep-based or no-op startup completion. Each server role must remain running until explicit shutdown, fatal failure, or process termination. Move fast-exit behavior into tests and make startup failure clean up already-started components.

## Documentation changes

Update `docs/configuration.md`, `docs/reference/configuration.md`, project generation, and deployment examples. Document the one precedence order, origins, supported URLs, lifecycle states, readiness, shutdown limits, and config-version migration. Execute primary configuration examples with the release binary in CI.
