# v0.67: Direct distributed data plane

Status: Planned

Roadmap sources: [13. v0.67: Direct Distributed Data Plane](../../ROADMAP.md#v0-67) and [5.2: External performance baseline](../../ROADMAP.md#52-v0611-external-performance-baseline).
Follow the [shared implementation and evidence rules](README.md). Direct transport and measured shared execution are both required for this release.

## Prerequisites and scope

Require v0.66 management, v0.65 durable recovery, v0.62.1 worker budgets, and the v0.61.1 measured baseline. Preserve v0.61.2 delta semantics and v0.65.1 durable concurrency where integrated. v0.68 owns durable movement; this release must already reject stale owners and replay safely.

Reuse `crates/rockstream-runtime/proto/shuffle.proto`, `crates/rockstream-runtime/src/exchange/serialization.rs`, `pool.rs`, `service.rs`, `flow_control.rs`, `durable.rs`, and `persistence.rs`. `ShuffleClientPool` and Arrow IPC serialization already exist. `FlowController::acquire_credit` currently admits by row budget; extend accounting where required for bytes and request waiters. Gateway ownership starts in `crates/rockstream-gateway/src/server.rs`, `multi_shard_reader.rs`, and `view_reader.rs`. Shared planning and arrangement ownership start in `crates/rockstream-plan/src/dag.rs`, `crates/rockstream-control/src/arrangement.rs`, and `crates/rockstream-runtime/src/arrangement_attach.rs`.

## Goal and public behavior

Public gateway ingestion sends Arrow batches directly to current workers. Public reads query durable indexed worker view state at the requested committed frontier. Control handles membership, leases, placement, deployment metadata, frontiers, and operations. Record batches, operator exchange, source deltas, and query results travel on the data plane.

## Implementation steps

1. Inventory public ingestion and read callers, control forwarding, TSV conversions, and output accumulators. Assign each message to the roadmap 13.1 boundary. Remove row payloads and query output history from control ownership while retaining compact execution metadata. Bound metadata retention independently of workload history.
2. Version the 13.2 frame contract with `protocol_version`, `workload_id`, `shard_id`, `operator_id`, `epoch`, `lease_token`, `schema_fingerprint`, `payload`, and `checksum`. Define checksum coverage, digest identity, compatible versions, and encoding limits before implementing receivers. Validate headers, lengths, checksum, schema, and lease before allocating or mutating state. Unsupported versions and malformed IPC must return registered deterministic errors.
3. Wire 13.3 through existing Arrow IPC serializers and pooled gRPC clients. Resolve current placement/lease metadata, send gateway batches directly, and query durable indexed shard state. Reads must wait boundedly for the requested committed frontier or fail explicitly. Preserve NULLs, schema types, signed multiplicities, and complete results across multiple batches; no Arrow-to-text round trip on the hot path.
4. Complete 13.4 connection lifecycle using the existing pool: multiplexing, heartbeats, deadlines, reconnection, and connection generation IDs. Fence delayed responses from obsolete generations. Bound connection count, pending requests, reconnect retries, and response accumulation; release permits on cancellation, timeout, disconnect, and decode failure.
5. Implement 13.5 limits `max_inflight_batches`, `max_inflight_bytes`, `max_batch_bytes`, and `max_pending_requests` under the worker budget. Acquire credits before allocation; reject single oversized frames and propagate saturation to source admission. Expose fill levels and queue age. Reserve foreground/read capacity, and prove that multiple streams cannot evade the aggregate limit.
6. Persist 13.6 execution identity using `request_id`, epoch, shard, lease, operator, and payload digest. Exact replay returns the original durable outcome without a duplicate logical write. Conflicting identity/payload combinations, stale leases, and invalid epoch order fail predictably. Acknowledgement follows durable writes and frontier advancement, never receipt alone. Define replay retention against durable frontiers before garbage collection.
7. Implement 13.8 shared work on public SQL plans. Compatible views reuse one source index and existing arrangements with explicit owners, reference retention, drop behavior, and recovery identity. Verify actual shared plan selection and restore it after restart; identical result output alone cannot prove sharing.
8. Evaluate pre-aggregation and existing factorized join-to-aggregate execution only for algebraically valid plans. Compare against ordinary execution using weighted updates, deletions, NULLs, and cancellation. Record eligibility and rejection rules; do not add a new optimizer framework without measured duplicated work.
9. Extend the external runner with real public gateway workloads. Freeze targets and regression tolerances before measurement. Require one versus twenty compatible views and 1, 2, 4, and 8 actual workers at the same freshness target, payload/state size, durability, offered-load schedule, and query load. Check every worker processes workload rows. Record blocked cells as release blockers, never synthetic results.
