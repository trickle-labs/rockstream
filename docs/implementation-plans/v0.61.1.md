# v0.61.1 External performance baseline

Status: Planned

Source: [ROADMAP section 5.2](../../ROADMAP.md#52-v0611-external-performance-baseline). Apply the [shared implementation and evidence rules](README.md).

## Prerequisites and scope

Begin alongside v0.61 once its public standalone ingestion and query path is usable. This patch requires a measured standalone baseline. Distributed, large-state, and migration cells become mandatory at v0.67, v0.67.1, and v0.68 respectively. Record unavailable cells as blocked with the owning milestone. They cannot support performance claims.

## Goal and public behavior

Publish reproducible external measurements of correct committed work. Read latency, durable commit latency, and event-to-correct-committed-result freshness have separate budgets.

## Implementation steps

1. Extend `scripts/run-r1-local.sh`, `benchmarks/r1-local/README.md`, and the existing harness under `tools/r1-local-harness/src/`. Reuse its process, load, oracle, metrics, and evidence modules. Create a new versioned workload profile; preserve frozen profiles and evidence. Keep `sample_reference_run` restricted to qualification-logic tests.
2. Before measurement, freeze payload size, state size, view count, durability, offered-load schedule, separate p99 targets, regression tolerances, run duration, repetition policy, and sustainable-throughput rule. Define the allowed write-amplification variation for “approximately constant” from the workload contract, not after seeing results. Record hardware, storage backend, revision, binary hashes, and commands.
3. Drive release processes only through public ingestion and query interfaces. Timestamp scheduled event generation and keep offered load independent of response completion. Retain generator delay, backpressure, errors, timeouts, and unfinished requests. Bound generator queues and record drops or admission failures instead of silently reducing offered load.
4. Compare complete result multisets against an independent oracle at the relevant committed epoch. A visibility marker alone cannot establish freshness. Validate the oracle with deliberate wrong-value, duplicate, missing-row, and stale-epoch results.
5. Implement the experiment matrix below as separately identifiable cells. Observe actual worker PIDs and activity; reject inactive or fake workers. Do not score a partially populated required matrix as complete.
6. Record state writes, intermediate rows, network bytes, and object-store requests per committed input change. Include RSS, queue age, control-node load, physical flushes per logical epoch, all three p99 measures, and repeated-run variation. Preserve raw samples and failed runs.
7. Report cost per million changes using `total hourly infrastructure cost * 1_000_000 / (sustainable committed changes per second * 3600)`. Include gateways, control nodes, workers, storage requests, retained storage, transfer, and compaction. Local performance cannot establish cloud cost; cloud claims require measured deployments and dated prices.

A future cell may remain blocked only with a concrete blocker and mandatory owning milestone. Closing these baseline IDs does not qualify the blocked capability or waive its later measured gate.
