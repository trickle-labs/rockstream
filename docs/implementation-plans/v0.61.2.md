# v0.61.2 Aggregate delta reduction

Status: Planned

Source: [ROADMAP section 5.3](../../ROADMAP.md#53-v0612-aggregate-delta-reduction). Apply the [shared implementation and evidence rules](README.md).

## Prerequisites and scope

Start alongside v0.61 and use v0.61.1 measurements as they become available. Restrict changes to epoch-visible SUM and COUNT. Preserve dirty-key persistence and existing supported aggregate semantics. Do not create a new aggregate framework or merge distinct observable epochs.

## Goal and public behavior

Repeated changes to a group produce at most its old and final output values within one logical epoch. An unchanged result produces no output delta. Durable results remain identical.

## Implementation steps

1. Trace every caller of `AggregateOp::process_delta_with_result` in `crates/rockstream-ops/src/aggregate.rs` through operator execution and compilation. Identify how one logical epoch spans input batches. Record the consolidation boundary before editing; a transport batch must not accidentally redefine user-visible epoch boundaries.
2. Reuse `AggState`, `encode_mutations_for_keys`, and `OperatorEpochResult`. Capture each touched group's old state once, consolidate signed inputs, and compute its final state before emitting retraction and insertion rows. Preserve schema and multiplicity, NULL rules, empty groups, and deletion mutations. Compare complete output values when deciding whether a result changed.
3. Preserve checked arithmetic for both aggregation and multiplicity. Stage changes until validation succeeds so overflow or invalid input cannot leave earlier groups mutated. Decide and document how intermediate arithmetic ordering interacts with cancellation before implementation; do not silently weaken the existing overflow contract.
4. Keep persistence proportional to touched keys and avoid a full-state walk. Bound the epoch accumulator by bytes and group count with observable usage and explicit pressure or error behavior. Do not acknowledge a partial epoch if the bound is exceeded.
5. Extend existing `delta_native_aggregate_tests.rs`, `constant_write_amplification_scale_tests.rs`, and `r1_execution_counter_tests.rs` in the ops tests directory. Cover both exact intermediate deltas and persisted mutations, then verify complete results through a public release node and process restart.
6. Compare intermediate-row amplification and dirty-key writes under repeated-key workloads. Freeze load, state size, tolerances, and freshness targets in the versioned baseline before comparing candidates. Publish results even when dirty-key writes stay unchanged.

## Documentation changes

Document epoch consolidation and unchanged-result suppression beside the aggregate behavior and benchmark contract. State that this patch changes work per epoch, not aggregate availability or durability semantics.

## Exit criteria

| ID | Acceptance condition | Intended proof |
|---|---|---|
| V0612-01 | SUM and COUNT emit exactly the old negative row and final positive row for a changed group, and no rows for unchanged output. | Exact schema, values, signed multiplicities, and mutation assertions for repeated-key and cancellation fixtures. |
| V0612-02 | Deletions, NULL-only groups, signed multiplicities, and group recreation retain existing SQL results. | Independent complete expected deltas and full output multisets, including deletion tombstones. |
| V0612-03 | Overflow, invalid input, and accumulator exhaustion leave the whole epoch uncommitted and previous state intact. | Multi-group failure injection followed by exact state reads and retry. |
| V0612-04 | Multiple observable epochs remain separate even when physically batched, and input batch boundaries do not change one epoch's result. | Equivalent partitionings of one epoch plus distinct-epoch public visibility checks. |
| V0612-05 | Dirty-key writes remain proportional to affected keys and intermediate rows decrease for repeated-key updates. | Frozen baseline comparison records both measures and lookup cost with unchanged full-result oracle. |
| V0612-06 | Crash and retry recover the exact acknowledged results without duplicate deltas or resurrected groups. | Planned release-process aggregate crash test, with complete before and after multisets. |
| V0612-07 | Consolidation memory has named limits, observable occupancy, and deterministic overflow behavior. | Boundary workload reaches each limit and proves no partial mutation or unbounded waiter growth. |
