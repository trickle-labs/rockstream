# v0.67.1: State beyond RAM

Status: Planned

Roadmap sources: [5.6: State beyond RAM](../../ROADMAP.md#56-v0671-state-beyond-ram) and [5.2: External performance baseline](../../ROADMAP.md#52-v0611-external-performance-baseline).
Follow the [shared implementation and evidence rules](README.md). This release must qualify the full supported stateful execution path, including recovery metadata.

## Prerequisites and scope

Require v0.67 public distributed execution, v0.62.1 worker budgets, and v0.65 complete recovery. A truncated scan is already a recovery correctness failure under v0.65; this milestone adds bounded operation when maintained state exceeds RAM. v0.68 must extend this proof to migration before v0.69 expands the connector workload envelope.

Reuse `SpillableArrangement` in `crates/rockstream-ops/src/spill.rs`, storage in `crates/rockstream-storage`, arrangement attachment in `crates/rockstream-runtime/src/arrangement_attach.rs`, and `RecoveryDriver` in `crates/rockstream-runtime/src/recovery.rs`. Existing `scan_all` returns an accumulated vector; `populate_spilled_keys_from_db` scans and retains key metadata. Both require a public-caller audit before claiming bounded state. Existing spill tests prove components, not the release-process workload.

## Goal and public behavior

Supported materialized views continue to return exact results when their maintained state exceeds the configured worker memory budget. Eviction, compaction, checkpointing, and restart remain bounded. Unsupported operator/workload combinations fail explicitly before unsafe allocation or visibility.

## Implementation steps

1. Inventory every supported stateful operator and its production call path, including ordinary aggregates, joins, shared arrangements, distinct/retention state where supported, and all snapshot/recovery readers. Record state values, key indexes, dirty-key sets, access queues, replay/dedup metadata, query accumulators, temporary merge data, and checkpoint buffers. For each, specify bounded implementation or explicit workload rejection. Freeze this support matrix before dependent work.
2. Make ordinary aggregate state demand-loaded or spillable through existing arrangement/storage mechanisms. Preserve dirty-key persistence and epoch-visible old/final deltas, checked arithmetic, NULL behavior, signed multiplicities, deletion, and atomic failure. Persist dirty state safely before eviction; a spill write failure must preserve authoritative data and prevent false durable acknowledgement.
3. Replace full-state reads on supported production paths with byte- and row-bounded paging or demand loads. Do not retain a complete spilled-key registry merely because values are on disk. Bound access metadata and deduplication for scans without missing or repeating keys. Determine continuation, snapshot consistency, and oversized-entry behavior before implementing paged readers.
4. Restore every page to completion using the v0.65 recovery contract. Persist or safely reconstruct progress across process loss. End-of-scan must be distinguishable from quota exhaustion, cancellation, corruption, and I/O failure; only verified completion permits ready/healthy state. Check schema and persistent format versions before loading state, and reject unsupported combinations with recovery instructions.
5. Integrate spill with the worker-owned budget, including shared caches counted once, operator memory, I/O buffers, disk occupancy, checkpoints, concurrent reads, and storage backlog. Use named byte/concurrency limits, observable fill levels, bounded retries, and admission before allocation. When disk or I/O limits are reached, propagate backpressure or an explicit error instead of accumulating memory. Preserve foreground maintenance capacity.
6. Exercise eviction and reload during updates/deletions, checkpoint and compaction overlap, and storage failures. Audit restart paths that construct vectors, maps, or key registries. A larger scan limit is not a fix. Reuse existing storage paging and spill tests; add only the missing public-process and operator-specific proofs.
7. Freeze a measured large-state profile in the external baseline before qualification: serialized maintained state above the configured worker budget, actual worker RSS ceiling including documented non-state overhead, disk/I/O/backlog limits, read/commit/freshness p99, offered load, and restart completion budget. Load all state through public ingestion, verify all results independently, and retain raw evidence through eviction, compaction, and full process restart.

## Documentation changes

Publish the operator support/audit matrix, limits and overflow behavior, eviction durability, complete recovery conditions, disk-full recovery, and workload rejection errors. Extend the R1 contract with the frozen large-state profile and runnable release-process examples. Document v0.68 as the additional migration gate, not as permission to omit full recovery here.

## Exit criteria

| ID | Acceptance condition | Required proof |
|---|---|---|
| V0671-01 | Every supported stateful operator and recovery path has a complete allocation/metadata audit and a bounded implementation or explicit rejection. | Reviewed production caller matrix plus exact public acceptance/rejection tests; no unclassified supported path. |
| V0671-02 | Ordinary aggregate updates remain exact across eviction, reload, deletion, NULLs, signed weights, and arithmetic failure. | Full output-delta and committed-result assertions against the independent oracle, including failure with unchanged authoritative state. |
| V0671-03 | Scans and restoration page to the real end without full-state vectors or unbounded spilled-key metadata. | Dataset beyond several scan pages and beyond budget, exact full recovered multiset, allocation/RSS evidence, and injected continuation/I/O errors that never report ready. |
| V0671-04 | Spill failure cannot discard authoritative dirty state or acknowledge an uncommitted epoch. | Disk/storage write failure before eviction, crash after spill before checkpoint, and crash during recovery; full restart restores exactly the committed history. |
| V0671-05 | Spill I/O, disk occupancy, checkpoint buffers, retries, and storage backlog obey named limits with truthful metrics and explicit pressure behavior. | Sustained overload and disk-full tests, concurrent reads and checkpoints, complete error outputs, bounded observed peaks, and successful exact recovery after pressure clears. |
| V0671-06 | State larger than the configured worker budget remains exact and within the frozen RSS/backlog limits through eviction, compaction, and restart. | Real release-process measurement, actual budget/state-size evidence, full oracle comparison, restart completion time, and read/commit/freshness p99 under fixed offered load. |
| V0671-07 | Persistent format/schema mismatches and corrupt pages fail explicitly without partial successful recovery. | Supported/rejected version tests and corrupt-record/page tests assert complete errors and unchanged committed state. |
| V0671-08 | Operator limits and large-state claims are reproducible from published commands and evidence. | Executable documentation, versioned profile, revision/hardware/storage/raw samples/repeated variation, and criterion-by-criterion sign-off mapping. |

Step coverage: steps 1 through 7 are checked by criteria 01, 02/04, 03, 03/04/07, 05, 02 through 07, and 06/08 respectively. Documentation is checked by 08.

## Verification instructions

Existing baselines are `rtk cargo test -p rockstream-ops --test arrangement_spill_correctness_tests`, `rtk cargo test -p rockstream-ops --test arrangement_spill_recovery_tests`, and `rtk cargo test -p rockstream-ops --test spill_rss_soak_tests`. Inspect test prerequisites and confirm cases actually execute; a skipped soak is not qualification.

Build real processes with `rtk cargo build --release -p rockstream-cli`. The complete operator audit, public large-state driver, corruption matrix, and extended R1 profile are planned additions. Record their exact commands before qualification. Existing component passes cannot replace full process destruction, complete output comparison, or measured RSS/backlog proof.
