# v0.61 Golden path and project tooling

Status: Planned

Source: [ROADMAP section 7](../../ROADMAP.md#v0-61). Apply the [shared implementation and evidence rules](README.md).

## Prerequisites and scope

Require v0.60 product truth before sign-off. Start v0.61.1 baseline collection and v0.61.2 aggregate work alongside this milestone; neither patch blocks the base golden path. Support the local template only. Kafka, PostgreSQL CDC, clustering, GUI, and cloud automation remain outside this release.

## Goal and public behavior

A user creates a sales project, starts its node, applies its schema and seed data, and verifies a maintained view without installing psql. Every command uses the live PostgreSQL protocol.

## Implementation steps

1. Extend project generation in `crates/rockstream-cli/src/init.rs` and dispatch in `cli_args.rs` and `main.rs` in that directory. Reuse `scaffold_project` and its destination checks. Generate exactly `rockstream.toml`, `project.toml`, `schema.sql`, `data/seed.csv`, `queries/verify.sql`, and `README.md`. Add a versioned project manifest with ordered apply files, table and format seed declarations, and query expectations. Validate version, referenced paths, file availability, and supported formats before execution. Specify overwrite and relative-path behavior before implementing the loader.
2. Add a shared embedded pgwire client for `rockstream query`, `rockstream shell`, and project operations. Reuse the workspace PostgreSQL client dependency after checking its enabled features. Implement simple and extended queries, typed parameters, multiline input, timing, tabular, JSON, and CSV output, SQL files, and RockStream error codes. Define escaping, NULL representation, and type-preserving output before golden fixtures. Put client code in the CLI crate; do not call gateway Rust handlers directly.
3. Implement `project apply` using a real connection. Execute schema files in manifest order, then stream seed input. Stop on the first unexpected SQL error and record successfully applied project metadata only after the corresponding operation succeeds. Decide the supported idempotency unit, metadata location, and interrupted-apply replay behavior before coding. Do not promise all-file atomicity unless the server supports it. Test repeat apply and failure after an earlier successful step.
4. Implement `project verify` with structured expected values and complete ordered rows or multisets as declared by each query. A row-count match cannot pass a wrong value, type, NULL, or multiplicity. Report the named verification and exact differences. Missing files, queries, objects, or server connections fail nonzero.
5. Remove Kafka and PostgreSQL CDC from supported template selection. Move their examples to the planned `examples/experimental/` directory and mark them experimental. Keep generated local commands consistent with actual CLI options.
6. Bound SQL-file buffering, seed batches, shell input, query result accumulation, timeouts, and client retries. Name limits and expose progress or fill levels. Stream output where possible, and fail explicitly if a complete verification exceeds its configured budget.

## Documentation changes

Update `README.md`, `docs/README.md`, and the generated local README with the exact supported workflow and error recovery. Document manifest versioning, repeat-apply guarantees, parameter use, and output encodings. Execute generated README commands in CI.

## Exit criteria

| ID | Acceptance condition | Intended proof |
|---|---|---|
| V061-01 | Project generation emits the complete six-file contract with valid references and config; occupied destinations and malformed manifests fail without unintended overwrites. | Extend existing `init_tests.rs` and `template_verification_tests.rs` with complete file and diagnostic assertions. |
| V061-02 | Release commands complete new, start, apply, and verify without psql or direct Rust APIs. | Planned golden-path process test executes generated README commands against a temporary local node. |
| V061-03 | CREATE TABLE, CREATE MATERIALIZED VIEW, seed INSERT or import, UPDATE, and DELETE produce the exact expected view contents after every committed step. | Public pgwire transcript plus independently calculated complete row expectations. |
| V061-04 | Simple, prepared, SQL-file, and multiline shell paths support timing and all three formats with equivalent values and explicit RockStream errors. | Planned client corpus covers quoting, NULL, malformed SQL, connection loss, and complete encoded output. |
| V061-05 | Apply stops at the first failure, metadata describes only completed work, and documented repeat apply does not duplicate seed data. | Inject a middle schema or seed error, interrupt the client, retry, and compare complete metadata and table state. |
| V061-06 | Verify rejects wrong values, extra rows, duplicate rows, missing dependencies, and unavailable service; no missing case is treated as success. | Negative process fixtures assert exact failures and exit status. |
| V061-07 | Only local is supported, and client buffers and waiters obey documented limits under oversized files or slow servers. | Template selection and pressure tests plus observed fill levels and overflow errors. |
