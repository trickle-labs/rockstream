The ENOSPC test belongs in the normal `rockstream-storage` integration-test suite. Its bounded adapter avoids runner-wide disk pressure. A local execution took 0.15 seconds after compilation, so it runs in the existing PR `storage-sql` leg; CI retains the test log with the source revision, injected errno, write response at the fault, and complete recovered state. The `post_ack_enospc_v1` line records these values.

The block crash scenario is isolated in the `Post-ACK block crash qualification` PR workflow. Its 256 MiB loop images are disposable; the compressed write log, exact ACK/recovery transcript, and SHA-256 of the test executable are retained for 90 days. The replay log records writes completed at flush boundaries, so this test covers the Linux filesystem and block ordering contract exercised by that runner, not physical power interruption.

The real-cluster chaos workflow containing the MinIO ENOSPC case took 11 minutes 31 seconds end to end in [run 41163469564](https://github.com/trickle-labs/rockstream/actions/runs/41163469564). Keep it in its existing relevant-PR and weekly lane; the separate block-replay scenario remains in its PR qualification workflow.

## Unqualified failure models

No lane here cuts power to the test medium. The remaining hardware capability is an isolated, power-cuttable Linux device with documented write-cache, flush/barrier, and power-loss-protection settings: cut the medium immediately after a successful ACK without guest or OS shutdown, then reboot and recover from that same medium. Until that model is run, host power-loss and volatile device/controller-cache claims remain unqualified.

The MinIO run proves ENOSPC at its bounded `/data` tmpfs and rejected WAL `PutObject`; it does not force ENOSPC through Rockstream's local filesystem syscall path. Local `LocalFileSystem`/SlateDB flush behavior on real hardware and other ObjectStore providers' atomic-write, flush, and crash-recovery guarantees remain assumptions under [ADR 0006](../adr/0006-persistence-replay-compaction.md).
