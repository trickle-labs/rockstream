## 1. Resolved Contract Choices

1. **Protocol Envelope & Frame Schema (`ExchangeFrame`)**:
   - Proto package: `rockstream.shuffle`. Message name: `ExchangeFrame`.
   - Fields:
     ```protobuf
     message ExchangeFrame {
       uint32 protocol_version = 1;
       uint64 workload_id = 2;
       uint64 shard_id = 3;
       uint64 operator_id = 4;
       uint64 epoch = 5;
       uint64 lease_token = 6;
       bytes schema_fingerprint = 7;
       bytes payload = 8;
       bytes checksum = 9;
     }
     ```
   - `protocol_version`: Must be `1`. Unsupported versions fail deterministically with `RS-3001` / `FAILED_PRECONDITION` naming both supported and received versions.
   - `schema_fingerprint`: 32-byte BLAKE3 digest of the canonical Arrow IPC schema. Frames with unexpected schema fingerprints are rejected before allocating record batches (`RS-3018` / `INVALID_ARGUMENT`).
   - `checksum`: 4-byte CRC32C (or 16-byte BLAKE3) over fields 1 through 8. Corrupt frames fail with `RS-3019` / `DATA_LOSS`.
   - `lease_token`: Validated against active worker shard lease. Stale lease tokens are fenced with `RS-3004` / `FAILED_PRECONDITION`.

2. **Decoupled Plane Boundaries (Roadmap 13.1 & 13.7)**:
   - **Control Plane owns**: membership, leases, placement, deployment metadata, frontiers, operations. Control plane never buffers, routes, or stores row payloads or query output histories (`deployment.outputs` removed from memory).
   - **Data Plane owns**: record batches, operator exchange, source delta delivery, query result delivery.
   - Gateway directly resolves current placement and lease metadata from control plane, then streams Arrow batches directly to worker shard owners over gRPC.

3. **Arrow IPC on Hot Path (No TSV Round-Trip)**:
   - All gateway DML ingestion and CDC source deltas are serialized directly to Arrow IPC record batches (`ArrowZSet`).
   - Materialized view reads query durable indexed worker shard state directly via `ViewReader::read_view_batches`, returning Arrow `RecordBatch` streams directly to the pgwire row encoder without TSV string splitting.
   - Preserves NULLs, exact Arrow data types, signed multiplicities, and multi-batch boundaries.

4. **Connection Lifecycle & Multiplexing**:
   - `ShuffleClientPool` maintains persistent, long-lived multiplexed gRPC channels per peer worker.
   - Monotonic `generation_id: u64` assigned per connection. On disconnect or reconnect, generation ID increments.
   - Delayed responses or ACKs from obsolete connection generations are explicitly fenced and dropped; permits are reclaimed.
   - Idle keep-alive heartbeats every 5 seconds; RPC deadline 10 seconds; reconnection backoff capped at 2 seconds.

5. **Transport Flow Control & Worker Budget Bounds (Roadmap 13.5)**:
   - `FlowController` enforces four explicit upper bounds:
     - `max_inflight_batches`: 64 per channel (default).
     - `max_inflight_bytes`: 64 MiB aggregate per worker (default).
     - `max_batch_bytes`: 16 MiB maximum single frame size (default). Oversized frames rejected before allocation.
     - `max_pending_requests`: 256 concurrent pending RPC calls.
   - Credits are acquired before frame serialization or channel allocation. Saturation halts senders and propagates backpressure to upstream sources.
   - Permit acquisition releases permits on normal ACK, channel drop, timeout, cancellation, or decode error.

6. **Durable Execution Identity & Replay Safety (Roadmap 13.6)**:
   - Request identity tuple: `(workload_id, shard_id, operator_id, epoch, request_id)`.
   - Combined with 32-byte BLAKE3 `payload_digest`.
   - Stored in durable shard metadata during commit.
   - Replay with matching digest returns cached durable outcome/ACK without duplicate execution or state mutation.
   - Conflicting payload with identical request ID returns `RS-3008` (`ALREADY_EXISTS`).
   - ACKs are dispatched **strictly after** durable storage flush and monotonic frontier advancement; receipt alone never triggers ACK.

7. **Shared Execution on Public SQL Path (Roadmap 13.8)**:
   - DAG planner detects compatible views sharing identical source relations and filters.
   - Reuses a single shared source index and existing `IndexArrange` arrangements.
   - `ArrangementCatalog` tracks reference counts and owner identities. Dropping a view decrements ref count; arrangement persists until ref count reaches 0 and compaction frontier advances.
   - Pre-aggregation and factorized join-to-aggregate are admitted only for algebraically distributive aggregations (`SUM`, `COUNT`, `MIN`, `MAX`); non-distributive expressions fall back to standard incremental execution.

8. **Workload Benchmarking Contract (R1 Local Matrix)**:
   - Unblocks and measures the 5 previously blocked matrix cells:
     - `views-shared-execution-benefit` (Area 2: 1 vs 20 views).
     - `worker-scaling-2-workers`, `worker-scaling-4-workers`, `worker-scaling-8-workers` (Area 3: 1, 2, 4, 8 workers).
     - `overload-worker-loss-failover` (Area 6: worker loss and failover).
   - Preserves frozen p99 targets: `read_p99 <= 10.0 ms`, `commit_p99 <= 25.0 ms`, `freshness_p99 <= 100.0 ms`.
   - Compares complete result multisets with independent oracle engine.
