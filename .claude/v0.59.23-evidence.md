## 2. Capacity Model & Physical Strategy Modeling Verification

The calibrated capacity planning estimator replaces heuristic estimates with physical arrangement accounting:

- **Canonical Arrangement Sharing**: Estimator recognizes maintained arrangements by `ArrangementId`. When 20 views consume 3 canonical arrangements, the report computes 3 maintained arrangement states + 20 view consumers + shared byte savings, rather than 20 independent full-state copies.
- **Factorized vs Classic Physical Join Strategies**:
  - `Classic Join`: Reports materialized intermediate state and intermediate row growth.
  - `Factorized Join`: Reports compact payload state (left and right factor representations), avoiding flat intermediate cardinality ballooning.
- **Source Statistic Provenance**: Distinguishes input confidence:
  - `Connector`: Live statistics sampled directly from active source connectors.
  - `Catalog`: Historical statistics registered in the catalog.
  - `Fallback`: Heuristic fallback marked with low-confidence indicator.

## 3. Threshold Manifest, Guidance Determinism & Durability Verification

- **Immutable Threshold Manifest (`CapacityThresholdManifest`)**:
  - Encapsulates calibrated small, medium, and large reference profiles.
  - Seals candidate identity, hardware specifications, worker concurrency, workload digests, absolute floors (throughput, update rate), ceilings (CPU-seconds, request counts, query latency), and error ranges.
  - Generates deterministic SHA-256 payload digest. Any mutation to floors, ceilings, or workload digests invalidates the cryptographic signature.
- **Deterministic Guidance Generation**:
  - Raw measurement records stream into bounded immutable chunks (`CAPACITY_SAMPLE_BATCH_MAX` = 10,000 records, `CAPACITY_SAMPLE_BATCH_BYTES_MAX` = 32 MiB).
  - Published sizing guidance and error-range tables regenerate bit-identically from raw chunks, linking each error range to its raw chunk SHA-256 digest.
- **Durable Create-Only Store (`CapacityThresholdStore`)**:
  - Implements create-only storage across LocalFileSystem (`LFS`) and MinIO (`S3`).
  - Prohibits overwrite of existing sealed manifests.
  - Enforces scan-and-delete for chunk cleanup, strictly avoiding SlateDB range-deletion calls.

## 4. Negative Tests & Release Gate Verification

Release gate validations ensure strict verification before qualifying v0.59.24:

- **`complete_signed_profile_set_is_required`**: Rejects manifest bundles missing any of `Small`, `Medium`, or `Large` reference profiles.
- **`gate_rejects_altered_workload_digest`**: Fails closed if test workload parameters or source digests deviate from the frozen corpus.
- **`gate_rejects_missing_observed_metrics`**: Rejects profile runs where any declared capacity dimension (private state, shared state, RSS, spill, cache, epoch/commit duration, freshness, shuffle, writes, object-store requests, checkpoint cost, compaction debt) was unobserved.
- **`gate_rejects_candidate_identity_mismatch`**: Fails if the measured profile was produced by a different commit SHA or compiler toolchain.
