# v0.59.10 Plan — Runtime Introspection & Operator Clarity

## Scope and Boundary

v0.59.10 implements the Runtime Introspection and Operator Clarity milestone of the Pre-v1 Product Polish track (`NEW_ROADMAP.md` v0.59.10):

1. **Embedded Runtime Capability Registry & `SHOW ROCKSTREAM CAPABILITIES` (`OBS-01`)**:
   - Embed the authoritative `capabilities.toml` specification directly into the runtime binary as an immutable, compiled-in `CapabilityRegistry`.
   - Implement `SHOW ROCKSTREAM CAPABILITIES` (and `SHOW CAPABILITIES`) over pgwire, returning all registered capabilities with tier (`Core`, `Maintain`, `Experimental`), category/kind (`language`, `connector`, `sink`), reachability, dispatch symbols, proof test identifiers, and documentation anchors.
   - Guarantee zero drift between `SHOW ROCKSTREAM CAPABILITIES` output and `capabilities.toml`.

2. **Candidate Identity Function `SELECT rockstream_version()` (`OBS-02`)**:
   - Add `SELECT rockstream_version()` exposing `product_version`, `candidate_id`, `source_sha`, and `artifact_digest` from `CandidateIdentity` over the PostgreSQL wire protocol.
   - Ensure the returned values match `CandidateIdentity::current()` and the immutable candidate manifest with exact SHA-256 digests and Git commit metadata.

3. **Stable Engine Raw Facts in `SHOW VIEW STATUS` & `EXPLAIN INCREMENTAL` (`OBS-03`)**:
   - Enrich `SHOW VIEW STATUS` and `EXPLAIN INCREMENTAL` with stable raw engine facts from the final v0.59.5–v0.59.9 architecture:
     - Shared arrangement facts: `arrangement_id`, `arrangement_consumer_count` (`consumer_count`), `shared_state_bytes`, `bytes_saved_by_sharing`, and `compaction_frontier`.
     - Amplification & write metrics: `delta_amplification`, `join_amplification`, `merge_operand_count`, `dirty_key_count`, `logical_write_bytes`, and `physical_write_amplification`.
     - Operator & execution strategy: `hot_key_bucket_count`, `factorization_strategy`, `predicate_filter_selectivity`, `cache_hit_rate`, and `epoch_group_size`.
     - Storage & checkpoint status: `checkpoint_mode`, `compaction_debt`, `checkpoint_id`, `frontier`, and `spill_bytes`.
     - Freshness & health attribution: `degradation_reason`, `reason_code`, `dominant_contributor`, `source_lag_ms`, `compute_lag_ms`, and `recommended_action_key`.
   - Reconcile arrangement and operator facts with immutable v0.59.5–v0.59.9 benchmark artifacts and independently counted consumers, mutations, and state bytes.
   - Strictly avoid handcrafted human advice strings; v0.59.16 owns diagnostic interpretation and rendering.

4. **Bounded Read-Only `rockstream_catalog` System Schema Tables (`CAT-01`)**:
   - Implement bounded read-only virtual tables in `rockstream_catalog`:
     - `rockstream_catalog.nodes`: Active cluster nodes/workers, node roles (`all`, `worker`, `control`, `gateway`), `WorkerId`, address, heartbeat timestamp, lease counts, and memory budget.
     - `rockstream_catalog.sources`: Registered sources, connectors, ingestion status, committed offsets, live lag, buffer fill, and schema versions.
     - `rockstream_catalog.views`: Materialized and inline view definitions, namespace, state, arrangement refcounts, shared bytes, and resolved `workload_source`.
     - `rockstream_catalog.operators`: Deployed physical operators, operator IDs, operator kinds, parent/child linkages, merge law IDs, and dirty key counts.
     - `rockstream_catalog.arrangements`: Durable shared arrangements, canonical `ArrangementId`, consumer count, shared trace bytes, compaction frontier, and partitioning.
     - `rockstream_catalog.checkpoints`: Committed cluster checkpoints, checkpoint IDs, commit timestamps, epoch numbers, frontier vector, and storage paths.
     - `rockstream_catalog.capabilities`: Virtual table projection of the capability registry with filterable SQL columns.
   - Enforce bounded cardinality and scan ceilings on every catalog query (fail-safe pagination / scan limits).
   - Redact all sensitive fields (passwords, connection strings, auth tokens, secret values) before returning catalog rows.
   - Ensure all stable identifiers (`ArrangementId`, `OperatorId`, `WorkerId`, `CheckpointId`) survive node and cluster restarts.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
