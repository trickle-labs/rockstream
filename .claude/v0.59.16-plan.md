# v0.59.16 Plan: Structured Diagnostics Everywhere

## Scope and boundary

v0.59.16 consumes the static catalog delivered by v0.59.12. It adds one runtime diagnostic model and makes every public failure renderer consume that model.

`DiagnosticOccurrence` lives in `rockstream-types`. It stores an `ErrorCode` descriptor reference, a UUID correlation ID, the catalog-derived message, a sorted safe context map, an optional retry-after duration, and one optional causal occurrence. Renderers resolve the descriptor through `ErrorDescriptor::lookup`. They do not copy catalog titles, SQLSTATEs, severities, retry classes, next steps, or documentation anchors into error producers.

The version adds these lookup surfaces:

- `SHOW DIAGNOSTIC RS-XXXX` returns one static descriptor.
- `SHOW DIAGNOSTICS [LIMIT n]` returns recent runtime occurrences.
- `rockstream support diagnose --code RS-XXXX` and `--correlation-id UUID` render the same occurrence and write its support bundle.

The CLI, JSON, pgwire, structured log, and support-bundle renderers read one occurrence representation. Public producers pass a catalog code and safe values only. This removes manual user-facing error strings from gateway, CLI, control, runtime, storage, SQL, and connector paths.

No new error catalog code, SQL operator, aggregate, join, window, storage protocol, or distributed protocol is in scope. `uuid` is already a workspace dependency. Do not add a dependency for this work.

### Bounds

| Bound | Value | Behaviour and proof |
|---|---:|---|
| `MAX_DIAGNOSTIC_CONTEXT_ENTRIES` | 32 | Reject extra context entries before rendering. `diagnostic_context_rejected_total` records the rejected entries. |
| `MAX_DIAGNOSTIC_CONTEXT_KEY_BYTES` | 64 | Reject an oversized key. |
| `MAX_DIAGNOSTIC_CONTEXT_VALUE_BYTES` | 1,024 | Redact and truncate an oversized value before storage. |
| `MAX_DIAGNOSTIC_CONTEXT_BYTES` | 8 KiB | Stop accepting context once the total reaches the bound. |
| `MAX_DIAGNOSTIC_OCCURRENCES` | 256 per process | The journal evicts its oldest item and increments `diagnostic_occurrences_evicted_total`. `rockstream_diagnostic_occurrences_retained` reports fill level. |
| `MAX_DIAGNOSTIC_BUNDLE_OCCURRENCES` | 256 | `support diagnose` writes at most this many records. |
| `MAX_DIAGNOSTIC_BUNDLE_BYTES` | 1 MiB | The writer stops at the limit and records a redacted truncation record. |

The causal field has one direct occurrence and cannot nest. This preserves the causal diagnostic without creating an unbounded chain. The context map uses `BTreeMap` so JSON, text, logs, and bundles have stable field order. Redact values at construction and before every renderer. Reuse the secret patterns in `crates/rockstream-cli/src/doctor.rs:149`; move the shared logic to `rockstream-types` rather than maintaining a second redactor.

## 4. Vertical slices

1. **Runtime diagnostic core.** Add the bounded `DiagnosticOccurrence`, direct cause, redactor, deterministic correlation source for tests, and catalog-only descriptor resolution in `rockstream-types`. Add exact fixture tests before callers change.

2. **Journal and lookup commands.** Add the bounded per-process journal, metrics, `SHOW DIAGNOSTIC`, and `SHOW DIAGNOSTICS`. Exercise simple and extended pgwire paths with exact rows and the fixed fixture correlation ID.

3. **Renderer migration.** Replace manual error strings in gateway errors, session notices, CLI errors, control responses, runtime logs, storage adapters, SQL errors, and connector errors with occurrence construction and the common renderers. Add a source audit gate that rejects public `#[error(...)]`, `ErrorInfo::new(...)`, `CliError::new(...)`, and `tracing` failure output that bypasses an occurrence.

4. **Support diagnosis.** Add `rockstream support diagnose` code and correlation lookup. Reuse `StorageClient::generate_support_bundle` for output writing. Include only redacted, bounded occurrence records and the existing candidate identity.

5. **Cross-surface proof.** Induce stale-view, lag, and dependency failures through real pgwire. Assert the complete expected text, JSON, query rows, structured log event, and support-bundle JSON fixture. Run mutation cases for every redactor rule and every bound.

## 6. Durability and coordination commitments

This version adds no commit, replay, checkpoint, compaction, WAL, or distributed-coordination path. LFS, MinIO, and SimRuntime slices are not required.

The diagnostic journal is process-local and bounded. The support bundle is an explicit CLI artifact, not durable engine state. Its writer needs local filesystem tests only. It must not introduce a SlateDB key, a checkpoint field, a range deletion, or a cross-node protocol.
