## 2. Role-Specific Shutdown, Drain & Signal Interception Verification

Graceful shutdown workflows and signal handlers are verified across all node roles:

- **Unified Shutdown Coordinator**: `crates/rockstream-cli/src/shutdown.rs` implements `ShutdownCoordinator` managing multi-signal interception (`SIGTERM`, `SIGINT`), role-specific phase ordering, component unregistration, and watchdog timeout handling.
- **Configurable Timeout**: Configurable via `--shutdown-timeout-secs` CLI flag and `ClusterConfig.shutdown_timeout_secs` (default 30s).
- **Gateway Drain**: Drops listener socket to refuse new TCP connections, broadcasts PostgreSQL Notice `57P01` (`admin_shutdown` / `RS-2056`), awaits active queries, terminates background subscription tailers, and closes sockets.
- **Worker Drain**: Transitions to `Draining` state, refuses new shard allocations (`RS-3010`), completes active micro-batch epoch, commits/aborts dirty state, releases shard leases to control plane, and purges exchange client pools.
- **Control Plane Drain**: Steps down Raft leadership, snapshots topology and shard lease allocations to shared storage, and stops RPC servers.

## 3. Structured HTTP Management Endpoints & Dynamic Readiness Verification

Management HTTP server (`crates/rockstream-cli/src/metrics_server.rs`) co-located with `/metrics` serves:

- **`/live` (Liveness Probe)**: Returns HTTP 200 OK `{"status":"alive"}` as long as the process is alive.
- **`/ready` (Readiness Probe)**: Returns HTTP 200 OK `{"status":"ready"}` when ready to serve; returns HTTP 503 Service Unavailable `{"status":"not_ready","reason":"..."}` during `Starting`, `Draining`, `ShuttingDown`, `Terminated`, or `DependencyLoss`.
- **`/health` (System Health Probe)**: Returns HTTP 200/503 with structured JSON:
  - `status`: `"healthy"`, `"degraded"`, `"unhealthy"`, `"starting"`, `"draining"`, or `"shutting_down"`
  - `role`: `"gateway"`, `"worker"`, `"control"`, `"frontier"`, or `"all"`
  - `version`: `"0.59.21"`
  - `commit`: Git commit SHA
  - `uptime_secs`: Process uptime
  - `dependencies`: Individual dependency health (`storage`, `control`, `raft`, `sinks`)
  - `active_shards`: Count of currently owned and active shards
  - `replication_lag_ms`: Replication / consumer lag
  - `reasons`: Actionable enumerated degradation reasons (`RS-XXXX` codes with dominant causes).

## 5. Durability, Shard Lease Mobility & Crash Recovery Verification (LFS & MinIO)

Durable state preservation and lease mobility under graceful and abrupt termination were verified:

- **Graceful Lease Release**: When a worker receives `SIGTERM`, it flushes its active epoch to SlateDB storage, commits 2PC sink batches, and explicitly relinquishes its shard leases to the control plane. Peer workers acquire the released leases immediately without waiting for heartbeat timeout.
- **Ungraceful Termination (`SIGKILL`)**: When a worker crashes abruptly, committed SlateDB SSTs and WAL records remain durable on LFS and MinIO. The control plane detects heartbeat timeout (5s), reassigns shard ownership, and the new worker recovers the shard state bit-identically from storage.
- **Binary Qualification**: `crates/rockstream-cli/tests/binary_lifecycle_integration_tests.rs` validates live multi-process binary execution, continuous SQL queries, graceful `SIGTERM` drain, and ungraceful crash recovery against real SlateDB storage.
