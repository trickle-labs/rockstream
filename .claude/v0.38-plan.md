## Vertical Slices

### S1 — Type System Mapping Extensions

**What:**
- Extend `arrow_type_to_pg_oid` in `catalog_stubs.rs` and `pg_type_from_name` in `protocol.rs` for:
  - `INT2` (21)
  - `FLOAT4` (700)
  - `DATE` (1082)
  - `TIME` (1083)
  - `TIMESTAMPTZ` (1184)
  - `UUID` (2950)
  - `NUMERIC`/`DECIMAL` (1700)
  - `JSON` (114)
  - `JSONB` (3802)
  - `VARCHAR`/`CHAR` (1043/1042)
  - `INTERVAL` (1186)
  - array variants `_int4` (1007), `_int8` (1016), `_text` (1009), `_float8` (1022), `_bool` (1000), `_uuid` (2951).
- Extend `arrow_type_to_pg_data_type` in `catalog_stubs.rs` to return correct string representations.
- Extend `pg_type_from_arrow_datatype` and `map_data_type_to_pg_type` in `server.rs`.
- Extend `pg_catalog.pg_type` stub in `catalog_stubs.rs` to return OIDs, names, and lengths for all the new OIDs.

**Exit test (green):**
- Unit tests in `crates/rockstream-gateway/tests/type_system_tests.rs` asserting correct OID mapping and round-trips for every new type.

---

### S2 — Binary Encoding of Numeric Types

**What:**
- Update `read_view_data_stream` (and other query result formatting loops) in `server.rs` to parse string representations of numeric values (`INT2`, `INT4`, `INT8`, `FLOAT4`, `FLOAT8`, `BOOL`) and call `encoder.encode_field` on them when binary format is requested.

**Exit test (green):**
- Unit tests in `type_system_tests.rs` validating that binary serialization matches network byte order (big-endian) compared to expected format.
- An integration test comparing binary values of the 6 numeric types against a real PostgreSQL 14 instance launched via `testcontainers` (generic image `postgres:14-alpine`).

---

### S3 — `pg_catalog` & `information_schema` Stub Additions

**What:**
- Implement dynamic stubs for:
  - `pg_proc` (pre-populated with built-in aggregates COUNT, SUM, AVG, MIN, MAX).
  - `pg_constraint` (empty table).
  - `pg_index` (mapping entries from registered indexes).
  - `pg_class` (extending it to include index entries with `relkind = 'i'`).
  - `pg_description`, `pg_enum` (empty tables).
  - `pg_roles` and `pg_user` stubs returning one row for the authenticated user.
  - `information_schema.key_column_usage`, `table_constraints`, `column_privileges`, and `referential_constraints` stubs.
- Route queries for these tables/views in `route_catalog_query` in `catalog_stubs.rs` case-insensitively.

**Exit test (green):**
- Integration tests in `gateway_proof_tests.rs` querying these catalog tables and verifying expected columns and rows are returned.

---

### S4 — ORM Conformance E2E Tests

**What:**
- Implement client-level reflection conformance tests simulating queries generated by ORMs:
  - SQLAlchemy 2.x `inspect(engine).get_columns('my_view')`
  - Prisma `db pull`
  - jOOQ/Hibernate `DatabaseMetaData.getColumns()`.
- Use Node, Python, and JDBC TestContainers to execute actual clients against our running gateway in integration tests.

**Exit test (green):**
- Integration tests in `crates/rockstream-gateway/tests/type_system_tests.rs` gated behind `#[cfg(feature = "testcontainers")]` passing successfully.
