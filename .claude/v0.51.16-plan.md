Roadmap: `NEW_ROADMAP.md:1061`. This version completes the PostgreSQL 18 logical replication CDC connector and HTTP webhook source on top of the durable source runtime foundation established in v0.51.15.

## 1. Deferred-Item Audit

### Must implement this version

All prior `sign-offs/v*.md` files were scanned for items marked `deferred`, `postponed`, or `out-of-scope`.
- `v0.51.15` signed off with **zero items deferred** (`sign-offs/v0.51.15.md:70`).
- `v0.51.14` was superseded by `v0.51.15` and `v0.51.16` (`NEW_ROADMAP.md:1063`). Its unshipped source surface is an undocumented deferral carried forward and **must be implemented in this version**:
  1. PostgreSQL 18 logical replication snapshot and subscription workers for `pgoutput` and `wal2json`.
  2. Keyed `INSERT`, `UPDATE`, `DELETE` Z-set deltas using `row_id = hash(source_id, table_id, primary_key)`.
  3. LSN-backed durable offset token restart and commit tracking.
  4. Automatic resnapshot recovery upon replication slot invalidation or WAL retention loss.
  5. Slow-subscriber backpressure based on credit budget and `wal_lag_bytes`.
  6. Authenticated `json` and `csv` HTTP webhook ingestion (`POST /webhook/<source>`).
  7. HTTP 429 Too Many Requests response when `local_buffer_max_epochs` is exceeded.
  8. Durable M3 commit requirement before HTTP 202 Accepted response.
  9. End-to-end DDL integration for `CREATE SOURCE`, `ALTER SOURCE PAUSE|RESUME|DROP`, and `SHOW SOURCE STATUS`.

## 4. Vertical Slices

1. **PostgreSQL 18 Replication Worker & Snapshot Engine.** Implement `tokio-postgres` replication stream worker supporting both `pgoutput` and `wal2json` decoders, initial table snapshot stream, and LSN offset token mapping. Exit: `postgres_cdc_format_matrix_tests`.
2. **Keyed CDC Z-Set Delta Generation & LSN Checkpointing.** Construct keyed Z-set deltas using `row_id_for(table_id, pk)` for `INSERT`, `UPDATE` (retract old + insert new), and `DELETE` (retract old). Bind LSN offset tokens to durable source checkpoints. Exit: `postgres_cdc_exactly_once_tests`.
3. **Slot Invalidation Auto-Resnapshot & Slow-Subscriber WAL Backpressure.** Detect slot invalidation / WAL removal, transition state to `Resnapshotting` (up to 3 attempts before `BLOCKED RS-4011`), and pause replication reading when `wal_lag_bytes >= POSTGRES_CDC_MAX_WAL_LAG_BYTES`. Exit: `postgres_cdc_failure_and_slow_subscriber_tests`.
4. **Authenticated HTTP Webhook Ingestion & Bounded 429 Backpressure.** Wire `POST /webhook/<source>` with token authentication (`credential_ref`), `json`/`csv` body parsing, `local_buffer_max_epochs` bounded queue returning HTTP 429 when full, and M3 input commit confirmation before returning HTTP 202. Exit: `http_webhook_ingestion_tests` and `http_webhook_backpressure_tests`.
5. **Durable Control Plane & Live Status Integration.** Wire `CREATE SOURCE`, `ALTER SOURCE PAUSE|RESUME|DROP`, and `SHOW SOURCE STATUS` to drive CDC worker loops and webhook endpoint state live. Scrub credentials in status output. Exit: `source_ddl_postgres_webhook_tests`.
6. **Multi-Backend Durability & Seeded Fault Sweep.** Execute all CDC and webhook test scenarios against SlateDB LFS, MinIO S3, seeded `SimRuntime` with `buggify!()`, and real PostgreSQL 18 Testcontainers. Exit: all 6 proof claims verified green across backends.

## 5. Operator and Durability Commitments

### CDC Oracle Property Test
For every PostgreSQL table mutation sequence `(INSERT, UPDATE, DELETE)`, the incremental Z-set delta stream accumulated by `PostgresCdcSource` bit-identically matches a full table snapshot oracle query (`SELECT * FROM table`) evaluated at the same LSN boundary.

### Webhook Oracle Property Test
For every batch of webhook requests `POST /webhook/<source>`, the processed Z-set batch output matches the expected batch oracle bit-identically, and re-submitting an already-committed delivery token results in deduplication with zero duplicate output rows.

All new durability paths (LSN checkpoints, webhook M3 transactions, slot resnapshot states) have explicit LFS and MinIO TestContainers coverage. All coordination paths have seeded `SimRuntime` tests with active `buggify!()` annotations.
