# v0.52.2 plan — Transaction-Preserving PostgreSQL CDC & Upstream Schema Evolution

## Scope and non-negotiable invariants

This version makes `pgoutput` the canonical PostgreSQL CDC path while keeping
all roles on the single `rockstream` binary. It changes neither the M3
protocol nor SlateDB's API: atomic source-transaction visibility is obtained
by placing the entire upstream transaction in one existing M3 epoch commit.

- A `pgoutput` `BEGIN` opens a bounded transaction envelope containing the
  upstream xid, final commit LSN, and every decoded row for every imported
  relation. `COMMIT` closes it. No row is dispatched, checkpointed, or made
  visible before its enclosing envelope closes.
- An upstream PostgreSQL transaction maps to exactly one RockStream epoch.
  Its base-table mutations, IVM state/output, source checkpoint, and frontier
  share one M3 `WriteBatch`; recovery replays the whole envelope or none of it.
- One upstream PostgreSQL source owns one shared logical slot/connection and
  routes relation IDs to all imported tables. Runtime/slot ownership is keyed
  by source identity, not `(source, view)`.
- Large envelopes use the existing `rockstream_ops::SpillableArrangement`
  rather than a second spill implementation. `POSTGRES_CDC_MAX_TRANSACTION_BYTES`
  is the named bound; `postgres_cdc_transaction_buffer_fill_ratio` and
  `postgres_cdc_transaction_spilled_bytes` are emitted. A full bound pauses
  upstream reading or returns a coded error; it never accumulates unbounded
  rows in memory.
- `Relation` is decoded before the next row. A nullable/defaulted added column
  or lossless widening is applied and appended to durable schema-evolution
  history. Rename, drop, narrowing, reordered/key-type change, or unsupported
  conversion stops the source in `BLOCKED` with `RS-1002`; no row is decoded
  against a stale ordinal layout.
- The supported schema contract is the bounded current pgoutput types
  (`INT`, `BIGINT`, `TEXT`, `DECIMAL`) plus compatible additions/widenings.
  Unsupported input fails closed. `wal2json` remains Maintain-only and gains
  no new behavior.
- Durable cleanup continues to use bounded scans and point deletes only. No
  new path uses SlateDB range deletion; tests assert this directly.

`DESIGN.md:831-894` supplies the compatible/breaking classification and
`DESIGN.md:1984-2049` supplies the one-epoch atomicity contract. `IVM.md:528-530`
requires same-epoch deltas to be staged before commit, which this envelope
preserves.

## Vertical slices

1. **Decode one transaction envelope.** Replace ignored pgoutput `BEGIN` /
   `COMMIT` with an envelope carrying xid, end LSN, and routed changes. Reject
   orphan/nested/malformed frames at the decode boundary. Green test:
   `pgoutput_begin_commit_envelope_has_exact_xid_lsn_and_rows`.

2. **Apply one envelope atomically.** Route all table changes from one
   envelope through one gateway M3 epoch so tables, compiled IVM output,
   frontier, and checkpoint become visible together. Green TC test:
   `cdc_tx_mixed_two_tables_exact_atomic_batch_oracle`, polling both imported
   tables across worker restarts and asserting the complete result transcript.

3. **Share the physical replication stream.** Replace the per-(source, view)
   `build_postgres_cdc_source` runtime with one keyed shared pgoutput runtime
   that owns a single slot/connection and relation map. Green TC test:
   `pgoutput_shared_slot_two_tables_real_server_slot_count_is_one` asserts
   `pg_replication_slots` directly and verifies both tables' exact rows.

4. **Bound large transactions with existing spill.** Stage an envelope in
   `SpillableArrangement`, flush the first over-budget bytes durably, and
   replay spill before acknowledge. Expose fill/spill metrics and pause/error
   at the named maximum. Green tests:
   `cdc_tx_spilled_two_tables_exact_atomic_batch_oracle` and
   `cdc_tx_transaction_buffer_full_returns_coded_backpressure`.

5. **Classify `Relation` and persist history.** Decode relation metadata into
   a source schema version; apply compatible additions/widenings before a
   following tuple, append a durable history entry in the same M3 commit, and
   make every incompatible change block with `RS-1002` before decoding rows.
   Green tests are every schema-matrix cell above.

6. **Wire operational status.** Project shared-slot ownership, committed LSN,
   buffer fill/spill, schema version/history, and `BLOCKED(RS-1002)` through
   existing `SHOW SOURCES` / `SHOW SOURCE STATUS` and the pgwire encoder.
   Green raw-pgwire test:
   `pgoutput_schema_incompatible_show_source_status_reports_exact_rs1002`.

7. **Recovery and faults.** Complete LFS, MinIO, real-Postgres TC, and seeded
   SimRuntime coverage for every named matrix/durability cell. Include
   `buggify!()` at `BEGIN` acceptance, spill handoff, M3 commit, upstream
   acknowledgement, connection disconnect, and relation classification.
