## Vertical Slices

Each slice ends in a green `cargo test` run.

### Slice 1 — PlanNode IR: Distinct / Intersect / Except variants

**Files:** `crates/rockstream-plan/src/lib.rs`

- Add `PlanNode::Distinct { input, arr_id: OperatorId }` — arrangement
  `row_hash → i64 weight`, zero-crossing emission.
- Add `PlanNode::Intersect { left, right, all: bool, arr_id }` — min-weight of
  two distinct-style arrangements (set); min(l,r) for bag (`INTERSECT ALL`).
- Add `PlanNode::Except { left, right, all: bool, arr_id }` — (l − r).max(0)
  for set; clamp-at-zero subtraction for bag (`EXCEPT ALL`).
- Add `OpKind::Distinct`, `OpKind::Intersect { all: bool }`,
  `OpKind::Except { all: bool }` to the `OpKind` enum.
- **Green gate:** existing `cargo test -p rockstream-plan` still passes (no
  behaviour change, only additive).

### Slice 2 — DistinctOp operator

**File:** `crates/rockstream-ops/src/distinct.rs`  
**Storage key format:** `0x01 0xDS op_id(16) row_hash(16) → i64 weight`  
(DESIGN.md §6.6, keys.rs `op_state/distinct`)

- Weight accumulation via `MergeOperator` (associative i64-add; registered in
  `merge_registry.rs`).
- Emit output delta only on zero-crossings:
  - weight `0 → positive`: emit `(row, +1)`
  - weight `positive → 0`: emit `(row, -1)`
- Write an explicit tombstone (not just a zero merge operand) when a row must
  disappear immediately; compaction filters clean up obsolete operands after the
  frontier proves no snapshot can need them.
- **Bound:** arrangement is bounded by the cardinality of the input relation;
  each distinct row occupies one SlateDB entry. No unbounded accumulation.
- **Green gate:** unit tests in `distinct.rs` for basic insert/retract sequences.

### Slice 3 — Distinct oracle property test (pre-commit to test before operator)

**File:** `crates/rockstream-oracle/src/distinct_oracle.rs`

- `oracle_distinct_50k` — proptest: random Z-set deltas over a synthetic
  schema; incremental `DistinctOp` output must match batch `DISTINCT` oracle
  at every epoch boundary.
- **Green gate:** test passes with the operator implemented in Slice 2.

### Slice 4 — IntersectOp / ExceptOp operators

**Files:** `crates/rockstream-ops/src/intersect.rs`,
`crates/rockstream-ops/src/except.rs`

- `IntersectOp` — maintains two distinct-style arrangements (one per input
  side). Emits deltas at `min(left_weight, right_weight)` transitions.
  For `INTERSECT ALL` (bag): uses raw weights, `min(l, r)`.
  For `INTERSECT` (set): clamps both sides to `{0,1}` before min.
- `ExceptOp` — emits deltas at `(left_weight − right_weight).max(0)`
  transitions.
  For `EXCEPT ALL` (bag): uses raw weights.
  For `EXCEPT` (set): clamps to `{0,1}`.
- **Bound:** arrangements bounded by cardinality of each input relation.
- **Green gate:** unit tests for basic sequences (insert/retract each side).

### Slice 7 — SQL lowering: Distinct / Intersect / Except

**File:** `crates/rockstream-sql/src/lower.rs`

- `LogicalPlan::Distinct(d)` → lower inner plan, wrap in `PlanNode::Distinct`.
  DataFusion represents `SELECT DISTINCT` as `Distinct` wrapping a `Projection`.
- `INTERSECT` / `EXCEPT`: DataFusion emits `Distinct(Union(...))` or
  `Distinct(Except(...))` depending on version. Detect the pattern and route
  to `PlanNode::Intersect` / `PlanNode::Except` with `all = false`. Detect the
  `UNION ALL` / `INTERSECT ALL` / `EXCEPT ALL` variants (`all = true`).
- `LogicalPlan::Union` that is NOT part of a set-op pattern → `PlanNode::Union`
  (existing stateless union, no arrangement needed — passthrough).
- **Green gate:** unit tests in `lower.rs` assert `SELECT DISTINCT id FROM t`,
  `SELECT … INTERSECT SELECT …`, `SELECT … EXCEPT SELECT …` each lower to the
  correct `PlanNode` variant.

### Slice 8 — EXPLAIN INCREMENTAL: Distinct / Intersect / Except rendering

**File:** `crates/rockstream-sql/src/explain_incremental.rs`

- Add `PlanNode::Distinct` arm:
  `"✓ Distinct  merge_law=WeightAdd/v1  zero_crossing"`
- Add `PlanNode::Intersect { all, .. }` arm:
  `"✓ Intersect[{semantics}]  dual_arrangement  min_weight"` where
  `semantics = if all { "ALL" } else { "SET" }`.
- Add `PlanNode::Except { all, .. }` arm:
  `"✓ Except[{semantics}]  dual_arrangement  subtract_weight"`.
- **Green gate:** unit tests in `explain_incremental.rs` assert the strings.

### Slice 9 — distribution.rs: Distinct / Intersect / Except annotation

**File:** `crates/rockstream-sql/src/distribution.rs`

- `PlanNode::Distinct` — partition key = hash of all output columns (the
  distinct key is the full row, so it must be co-located).
- `PlanNode::Intersect` / `PlanNode::Except` — left and right inputs must have
  the same partition key (hash of all columns); annotate output with that key.
- **Green gate:** `cargo test -p rockstream-sql` passes.

### Slice 10 — LFS durability: Distinct crash-replay and state persistence

**File:** `crates/rockstream-ops/tests/lfs_distinct.rs`

- `lfs_distinct_crash_replay_bit_identical` — run Distinct over LFS, crash
  mid-epoch via `ShardDb::inject_fault`, replay, assert bit-identical output.
- `lfs_distinct_state_persists_across_reopen` — arrangement survives
  `ShardDb` close/reopen; hit-ratio and weight values match.
- `lfs_distinct_no_range_delete` — assert `WriteBatch` API has no
  `delete_range` call in the Distinct code path (grep-level assertion in the
  test or structural proof via the type system).
- **Green gate:** all three pass on LFS.

### Slice 11 — End-to-end SQL Engine milestone

**File:** `crates/rockstream-sql/tests/sql_engine_e2e.rs` (new integration test)

- `sql_engine_create_view_join_group_by` — using the embedded runtime:
  1. Parse and compile `CREATE VIEW revenue AS SELECT o.region, SUM(l.amount) FROM orders o JOIN lineitem l ON o.id = l.order_id GROUP BY o.region`.
  2. Deploy the view.
  3. Insert batches of `(orders, lineitem)` rows, tick the epoch.
  4. Assert incremental output matches `datafusion::SessionContext` batch query
     at every epoch boundary.
- **Green gate:** test passes end-to-end.

### Slice 12 — Storage Budget Gate: WAL listing cache hit ratio (MinIO)

**File:** `crates/rockstream-storage/tests/minio_budget.rs`

- `minio_wal_listing_cache_hit_ratio` — spin up MinIO via TestContainers,
  mount a `ShardDb`, run 100 epochs with WAL writes, assert
  `list_call_count / (total hot-path accesses + list_call_count) < 0.01`
  (i.e., >99% cache hits).
- `minio_manifest_cadence_bounded` — assert manifest writes ≤ `epochs + 2`
  (at most one per epoch plus compaction; never burst-writes on high input rate).
- **Green gate:** both pass against real MinIO.

### Slice 13 — Storage Budget Gate: latency and write amplification (MinIO)

**File:** `crates/rockstream-storage/tests/minio_budget.rs` (extend Slice 12)

- `minio_latency_p99_1gb` — seed ShardDb with ~1 GB of state, run 1000 random
  GET/PUT/LIST ops, assert p99 ≤ defined budget (document the measured value;
  any breach of 2× budget triggers `RS-5022` and must be recorded as a
  mitigation item in `sign-offs/v0.10.md`).
- `minio_write_amplification` — track logical bytes written vs. SlateDB
  physical bytes written over 50 epochs; assert ratio ≤ 20 (2× the
  `target_write_amplification = 10` budget); document the measured ratio.
- **Green gate:** both pass. If either metric exceeds 2× budget, the test
  still passes but records a `RS-5022` mitigation item.
