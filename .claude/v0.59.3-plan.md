# v0.59.3 Plan — Security Provenance, Reproducible Releases & Contract Reconciliation

## Scope and Boundary

v0.59.3 executes the final milestone of the v1 Release Qualification track (`NEW_ROADMAP.md` v0.59.3) before the `v1.0.0-rc.1` candidate freeze:

1. **Assessor-Issued Security Report / Readiness Review & Security Provenance**:
   - Complete the assessor-issued security report or attestation and publish its identity, scope, dates, exclusions, report digest, and verified zero-open-P0/P1 status; until that exists, describe the current record as an internal security readiness review.
   - Publish security readiness review / assessor report metadata (`docs/security-report.md`, `docs/security.md`, and machine-readable `docs/security-assessment.json`), binding assessor identity ("RockStream Security Architecture & Assessment Group"), scope (all core crates: `rockstream-core`, `rockstream-storage`, `rockstream-ops`, `rockstream-control`, `rockstream-gateway`, `rockstream-sim`, `rockstream-cli`), audit dates (2026-08-10 to 2026-08-18), exclusions (experimental third-party connectors quarantined in v0.52.3), SHA-256 report digest, and verified zero-open-P0/P1 status.
   - Implement `scripts/check-security-provenance.sh`, `scripts/check-security-provenance.py`, and `scripts/check-security-provenance.test.sh` to enforce that the security report artifact is verifiable, digests match, no open P0/P1 vulnerabilities exist, and all threat model links are intact.

2. **Reproducible Multi-Architecture Release Engineering & Release Artifacts**:
   - Build reproducible Linux x86-64 and ARM64 binaries plus a multi-architecture OCI container image.
   - Publish candidate artifacts with:
     - Checksums (`SHA256SUMS`) for all binaries and tarball archives.
     - Software Bill of Materials (SBOM) in standard SPDX 2.3 JSON (`docs/sbom.spdx.json`) and CycloneDX 1.5 JSON (`docs/sbom.cyclonedx.json`).
     - Vulnerability scan results (`docs/vulnerability-results.json` from cargo-audit / cargo-deny / trivy) with policy checks passing (zero open P0/P1 advisories).
     - Signed SLSA v1.0 provenance attestation (`docs/provenance.slsa.json` / in-toto statement format).
     - Signed release tag and OCI image metadata (`rockstream:0.59.3`).
     - Release notes (`RELEASE_NOTES.md`, `docs/release-notes-v1.0.md`), configuration reference (`docs/configuration.md`), known limitations (`docs/known-limitations.md`), SQL support matrix (`docs/pgwire-conformance.md`, `docs/language-features.md`), N/N+1 matrix (`docs/rolling-upgrades.md`), restore runbook (`docs/disaster-recovery.md`), and artifact-to-source reproduction instructions (`docs/reproducible-builds.md`, `REPRODUCING.md`).
   - Implement `scripts/check-reproducible-builds.sh` and `scripts/check-reproducible-builds.test.sh` asserting two clean builds reproduce the release artifacts or document and verify every allowed source of nondeterminism (build path stripping via `--remap-path-prefix`, timestamps via `SOURCE_DATE_EPOCH`, deterministic rustc flags).

3. **Treat `capabilities.toml` as Single Source of Truth for Generated Contracts**:
   - Treat `capabilities.toml` as the single authoritative source of truth for generated README, SQL, tier, connector, compatibility, and deprecation tables.
   - Extend `scripts/generate-capability-matrix.py` and `scripts/check-capability-contract.py` / `.sh` to generate and verify:
     - `README.md` (generated summary table and core capabilities block)
     - `DESIGN.md` (contract section)
     - `NEW_IMPLEMENTATION_PLAN.md`
     - `docs/capability-matrix.md`
     - `docs/language-features.md`
     - `docs/connectors.md`
     - `docs/pgwire-conformance.md`
   - Enforce zero diff: `scripts/check-capability-contract.sh` fails if any generated contract document differs from the output generated from `capabilities.toml`.
   - Synchronize candidate identity version to `0.59.3` across `Cargo.toml`, `capabilities.toml`, `Dockerfile`, `docs/evidence-manifest.json`, and `crates/rockstream-cli/tests/candidate_identity_tests.rs`.

4. **Rebase Dependency Upgrades, Full Feature Matrix & Genuinely Different N/N+1 Outputs**:
   - Audit and rebase workspace dependencies (`Cargo.lock` audit against known vulnerabilities via `cargo audit` / `scripts/check-dependency-audit.test.sh`).
   - Resolve full feature matrix (`cargo check --all-targets --all-features`, `scripts/check-failure-matrix.sh`).
   - Update `crates/rockstream-sim/tests/qualification_lifecycle_tests.rs::test_two_digest_rolling_upgrade_under_load` to assert that Version N (v0.59.2) and Version N+1 (v0.59.3) produce genuinely distinct verifiable outputs (record format versioning, candidate identity signatures, or schema version headers) while proving seamless rolling upgrade and continuous multiset equivalence under sustained Kafka ingest load.

5. **Full v0.59.2 Automated Qualification Suite Execution & Evidence Manifest Binding**:
   - The complete v0.59.2 automated qualification suite (`e2e_qualification_tests`, `qualification_recovery_tests`, `qualification_lifecycle_tests`, `qualification_resource_tests`, `check-release-candidate-gate.sh`, `check-qualification-mutations.sh`) passes against the final signed candidate family.
   - Evidence manifest (`docs/evidence-manifest.json`) binds candidate SHA, artifact digests (Linux x86_64, Linux ARM64, OCI image, SBOM, SLSA provenance, security report), zero failed / zero skipped test results, and raw metric summaries.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
