# v0.54.1 Plan — Enumerated Degradation Reasons, Dominant-Cause Attribution & Live Progress

## Scope and Non-Negotiable Invariants

This version turns v0.54's per-stage measurements into one actionable, stable
answer on every existing status surface. It adds no service, configuration, or
SQL family.

1. Replace free-text blocked/degraded state with exactly eight documented
   reasons: `waiting_on_source`, `quota_admission_rejected`, `spilling`,
   `over_budget_relaxed`, `checkpoint_alignment_stalled`, `sink_blocked`,
   `topology_transition_in_progress` (with `shard_migration` or
   `worker_drain` progress), and `recovering`. Each has a stable `RS-XXXX`
   code and a linked remediation entry.
2. Derive exactly one dominant contributor from the v0.54
   `StageLagBreakdown`, with a documented total ordering for ties; no result
   may be `unknown`, free text, or iteration-order dependent.
3. Return reason, code, dominant contributor, and optional live-progress data
   from `SHOW VIEW STATUS [FOR <view>] [FOR NAMESPACE <namespace>]` and
   `rockstream view status [<view>]` in text and JSON.
4. Expose topology-transition phase, bytes remaining, rows remaining, and a
   bounded estimate for active drain/migration work. Expose per-shard
   checkpoint-alignment state and the shard/operator currently holding a
   barrier through `rockstream checkpoint show <checkpoint_id>`.

The existing single `rockstream` binary and CLI remain runnable. Read paths
must use existing point-get or bounded-prefix-scan state; no path may depend on
SlateDB range deletion. Status snapshots, progress registries, and
per-checkpoint holder maps need named capacities, fill-level metrics, and a
defined rejection/backpressure result. The implementation must not invent a
second checkpoint, migration, or drain architecture.

## Oracle, Durability, and Coordination Commitments

The central property oracle is:

```text
dominant(snapshot) == argmax_stable(snapshot.active_contributor_values)
```

where `argmax_stable` applies the documented fixed priority on equal values.
Every reason test asserts an exact complete typed result, and the two-cause
property runs all insertion orders to prove it is not map iteration order.
Progress oracles assert phase legality, bytes/rows remaining never increase
between observations of the same operation, and a completed operation reports
zero remaining work. They do not assert only that a command did not crash.

No new commit, replay, checkpoint, compaction, or WAL format is introduced.
Because progress is read from existing durable migration/drain/checkpoint
records, the version nevertheless commits both SlateDB LFS and MinIO
(TestContainers) restart proof for each new exposed durability projection:
`test_interrupted_migration_progress_survives_restart_lfs_and_minio` and
`test_interrupted_drain_progress_survives_restart_lfs_and_minio`. These tests
assert point-get/bounded-prefix cleanup and zero range deletions.

The new cross-worker holder/progress read path has a seeded `SimRuntime`
commitment: `test_explainability_progress_simruntime_faults` uses `buggify!()`
at barrier delivery, drain acknowledgement, migration copy, restart, and
confirmation boundaries. It proves the status never names an unknown reason,
never regresses durable progress, clears stale holders, and preserves the
deterministic dominant result.
