## Proof Claim 2 — Partition-recompute cost is measured and documented

**Claim**: Cost per epoch = Σ O(|P| × log|P|) over affected partitions only; cost is measured and documented.

**Evidence sources**:

### 2a. Unit test: `window_partition_recompute_cost_bounded`

```
cargo test -p rockstream-ops window_partition_recompute_cost_bounded -- --nocapture
```
Result: ✅ PASS (1 passed, 131 filtered out)

### 2b. Oracle harness cost-ratio assertions (50k random epochs)

The oracle harness logs `recomputed_rows / delta_rows` ratio and asserts it stays bounded by `n_partitions × max_partition_size / delta_size`. Sample output from 50k runs:

```
oracle cost: recomputed_rows=39  delta_rows=21  ratio=1.86  max_part=8
oracle cost: recomputed_rows=59  delta_rows=29  ratio=2.03  max_part=12
oracle cost: recomputed_rows=57  delta_rows=25  ratio=2.28  max_part=15
oracle cost: recomputed_rows=68  delta_rows=33  ratio=2.06  max_part=13
oracle cost: recomputed_rows=66  delta_rows=25  ratio=2.64  max_part=13
oracle cost: recomputed_rows=0   delta_rows=1   ratio=0.00  max_part=0
```

All 50k cases passed the cost assertion — ratio bounded by affected partition sizes, not total relation size. Unchanged partitions are not recomputed (ratio = 0 when delta touches an empty partition).

### 2c. Module docstring in `crates/rockstream-ops/src/window.rs`

The `WindowOp` module documents the cost model:
- Recomputation cost per epoch = Σ_{affected P} O(|P| × log|P|)
- Only partitions with at least one row in the input delta recompute
- `WINDOW_PARTITION_THRESHOLD = 10_000` rows
- `fill_level()` and `oversized_partition_keys()` expose metrics
