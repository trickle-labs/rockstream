# v0.51.17 Plan — Panic Safety on Untrusted-Input Paths & a First Fuzzing Harness

Roadmap: `NEW_ROADMAP.md:1119` (Phase 15.7). This version audits and eliminates every reachable panic (`.unwrap()`, `.expect()`, panicking slice/index access, integer-cast panics) on the four untrusted byte-parsing boundaries (pgwire startup/extended-query decoding, SQL statement parser entry point, Postgres CDC `pgoutput`/`wal2json` decoders, and JSON/CSV HTTP webhook body decoders), mapping every error to an `RS-XXXX` / `RS-4XXX` error code. It also adds a `cargo-fuzz` harness workspace, permanent corpus regression replay suite, scoped `#![deny(clippy::unwrap_used, clippy::expect_used)]` module lints, and a scheduled CI fuzz soak workflow.

## 5. Operator and Durability Commitments

### Oracle Property Test for Fuzzing & Untrusted Input Safety
For any arbitrary byte sequence $B \in \{0, 1\}^*$ passed to any of the four decoder boundaries:
1. The decoder either succeeds in returning a valid parsed object OR returns a structured `RS-XXXX` / `RS-4XXX` error code.
2. The decoder NEVER panics (`panic!`, `.unwrap()`, `.expect()`, index out-of-bounds, or integer overflow panic).
3. The underlying connection or worker remains fully operational and able to process subsequent valid requests without process restart or lock poisoning.

### Durability & Fault Commitments
- Fuzzing regression inputs checked into `fuzz/corpus/` are permanent regression artifacts.
- Multi-backend tests verify that malformed payloads rejected on LFS or MinIO storage paths cause zero state corruptions in underlying SlateDB checkpoints.
