## ⚡ 1. Ground Rules & Constraints

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable through it at the end of this version.
- No code path may depend on SlateDB range deletion. Cleanup is point-write, scan-and-delete, or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is strictly forbidden. Stateful operator arrangements exceeding allocated `memory_limit_bytes` must spill the coldest entries to SlateDB (`ShardDb`) and transparently fault them back on lookup.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`.
- Make only changes this version requires: no speculative features, no drive-by refactors, scope limited strictly to the IVM spill engine and durability substrate.
- **Nothing may be deferred to a later version.**

## 🍰 5. Thin Vertical Slices

1. **Slice 1: `SpillableArrangement` Generic Core Primitive**
   - Create `crates/rockstream-ops/src/spill.rs` providing `SpillableArrangement<K, V>` backed by LRU memory cache + `ShardDb` cold tier.
   - Verify eviction threshold triggers point write to `ShardDb` and lookup faults back entries cleanly.
   - *Test*: `rtk cargo test -p rockstream-ops --test spillable_arrangement_tests`

2. **Slice 2: `TopKOp` Buffer Overflow Resolution**
   - Replace `TOPK_BUFFER_LIMIT` hard overflow error in `crates/rockstream-ops/src/topk.rs` with `SpillableArrangement`.
   - Publish `rockstream_ops_spill_faults_total` metric when entries are faulted from SlateDB shard.
   - *Test*: `rtk cargo test -p rockstream-ops --test arrangement_spill_correctness_tests test_topk_spill_buffer_overflow_resolved`

3. **Slice 3: `JoinOp` & `AggregateOp` 10× Memory Budget Spill Integration**
   - Integrate `JoinState` and `AggState` with `SpillableArrangement`.
   - When operator live state exceeds share of `memory_limit_bytes`, evict cold keys to `ShardDb`.
   - Verify outputs driven to 10× budget are **bit-identical** to unspilled execution and DataFusion batch oracle.
   - *Test*: `rtk cargo test -p rockstream-ops --test arrangement_spill_correctness_tests`

4. **Slice 4: Mid-Spill Durability & Checkpoint Recovery (LFS + MinIO)**
   - Wire spilled SlateDB key-value prefixes into checkpoint snapshotting.
   - Verify mid-spill process restart recovers identical arrangement contents under both local filesystem (LFS) and MinIO (S3 object store via TestContainers).
   - *Test*: `rtk cargo test -p rockstream-ops --test arrangement_spill_recovery_tests`

5. **Slice 5: Benchmarking, RSS Budget Enforcement & SimRuntime Verification**
   - Implement `benches/spill_latency.rs` (Criterion benchmark) measuring spilled vs in-memory throughput/latency.
   - Verify process RSS remains bounded within configured budget under `v0.51.20` soak harness.
   - Seeded `SimRuntime` test with `buggify!()` fault injection for distributed spill coordination under network faults.
   - *Test*: `rtk cargo bench -p rockstream-ops --bench spill_latency` & `rtk cargo test -p rockstream-sim --test spill_coordination_sim_tests --features simulation`
