## Vertical Slices

### S1 — `AutoTuner` struct: epoch-sizing control loop

**New file**: `crates/rockstream-control/src/auto_tuner.rs`

Implement `AutoTuner::adjust_epoch_sizing(write_rate_ops_per_ms: f64, slo_compliance_ratio: f64) -> (u64, u64)`:
- Returns new `(min_epoch_ms, max_epoch_ms)`.
- Floor: 10 ms; ceiling: 5 000 ms (DESIGN.md §14.5).
- If `write_rate` trends above quota OR `slo_compliance_ratio < target`, widen epoch window.
- Writes an `AuditEvent` on every adjustment via `FileAuditLog`.
- Upper bound: adjustment deltas clamped to ±50 % per call; no unbounded accumulation.

**Ends green**: unit test `proof_epoch_sizer_settles_within_3_adjustments_under_10x_spike`.

### S2 — `AutoTuner` struct: parallelism control loop

**Same file**: add `AutoTuner::adjust_parallelism(epoch_ms_p95: u64) -> usize`:
- Reads `AutotunerConfig` (already in `rockstream-types/src/config.rs`):
  - `hysteresis_scale_up_windows: 3` — must see p95 above threshold for 3 consecutive calls before scaling up.
  - `hysteresis_scale_down_windows: 12` — must see p95 below threshold for 12 consecutive calls before scaling down.
  - Bounds: `min_parallelism ≤ N ≤ max_parallelism`.
- Maintains internal `up_window_count` and `down_window_count` counters (both bounded by their respective config values; no unbounded accumulation).
- Adds `buggify!("auto_tuner.parallelism.between_counters_and_emit", 0.05)` between counter update and parallelism emit, so the fault model can inject a crash mid-adjustment.

**Ends green**: unit test `proof_parallelism_loop_settles_within_3_adjustments_no_oscillation`.

### S3 — `AutoTuner` struct: source-throttle control loop

**Same file**: add `AutoTuner::adjust_source_throttle(frontier_lag_ms: u64, freshness_target_ms: u64, current_max_poll_bytes: u64) -> u64`:
- Trigger: `frontier_lag_ms > freshness_target_ms * 1.5` for > 20 simulated seconds (≈ 20 epochs at 1 s/epoch) → reduce by 50 %.
- Floor: 1 row/epoch (encoded as `MIN_THROTTLE_BYTES = 64` bytes); ceiling: `MAX_THROTTLE_BYTES = 1 << 26` (64 MiB, connector native ceiling).
- Never returns 0 (deadlock prevention invariant, asserted in code).
- Adds `buggify!("auto_tuner.throttle.between_lag_check_and_emit", 0.05)`.

**Ends green**: unit test `proof_source_throttle_settles_within_3_adjustments_no_deadlock`.

### S4 — `SpikeScenario` step-function driver and combined settling proof

**New file**: `crates/rockstream-sim/src/spike.rs`

`SpikeScenario` struct:
- `SpikeScenario::baseline(epochs: usize) -> SpikeScenario` — low steady-state load.
- `SpikeScenario::ten_x_spike(baseline_epochs: usize, spike_epochs: usize) -> SpikeScenario` — applies 10× step-function on top of baseline; measures auto-tuner state per epoch.
- Internally bounded: `epochs` ≤ 10 000 hard cap; no unbounded growth.
- Tracks `SpikeResult { parallelism_trace: Vec<usize>, epoch_ms_trace: Vec<u64>, throttle_trace: Vec<u64>, epochs_to_settle: Option<usize> }`.
- `epochs_to_settle` = number of epochs from spike onset until all three loop outputs stop changing by more than a 5 % threshold.

`spike.rs` also exports `OscillationDetector::detect(samples: &[f64]) -> bool`:
- Returns `true` if there are more than 1 direction reversal within any window of 5 consecutive samples.

**Oracle property test for S4**: `proof_incremental_spike_equals_batch_spike` — applying auto-tuner epoch-by-epoch for 10 epochs vs recomputing target from 10× state directly (batch oracle); both must reach the same steady-state `(min_epoch_ms, max_epoch_ms)` and `parallelism`. This is the `incremental == batch` oracle.

**Ends green**: two tests:
1. `proof_auto_tuner_combined_settles_within_3_epochs` — runs `SpikeScenario::ten_x_spike()` and asserts `epochs_to_settle.unwrap() <= 3`.
2. `proof_incremental_spike_equals_batch_spike` — oracle property test.

### S5 — Oscillation-detection oracle

**In `spike.rs`** (exported from `rockstream-sim`):

`OscillationDetector::detect(samples: &[f64]) -> bool`:
- Counts direction reversals in a sliding window of 5.
- Returns `true` if any window has > 1 reversal (i.e., oscillating).

**Ends green**: two tests in a new `crates/rockstream-sim/tests/auto_tuner_chaos_tests.rs`:
1. `proof_oscillation_detector_catches_synthetic_oscillation` — feeds [1.0, 3.0, 1.0, 3.0] → must return `true`.
2. `proof_oscillation_detector_passes_monotone_series` — feeds [1.0, 2.0, 3.0, 4.0] → must return `false`.
3. `proof_parallelism_trace_no_oscillation` — feeds the `parallelism_trace` from S4 `SpikeScenario` into `OscillationDetector::detect`; must return `false`.

### S6 — SimRuntime + buggify chaos soak (1 000 seeds)

**New file**: `crates/rockstream-sim/tests/auto_tuner_chaos_tests.rs` (same file as S5 tests).

`proof_auto_tuner_buggify_chaos_1000_seeds_all_settle`:
- Calls `buggify_init(seed)` for each of 1 000 seeds (0..1000).
- Runs `SpikeScenario::ten_x_spike(baseline_epochs=5, spike_epochs=10)` against each seed.
- Asserts: (a) no panic, (b) `epochs_to_settle.unwrap_or(999) <= 3` for every seed.
- Calls `buggify_disable()` after each run.

**Also adds law seed** `"AutoTuner/v1"` to `build_initial_corpus()` in `crates/rockstream-sim/src/soak.rs`:
- Seed `0xA0_B0_C0_D0_E0_F0_A0_B0` covering `"auto_tuner.epoch_sizer.10x_spike"`.
- Seed `0xF0_E0_D0_C0_B0_A0_F0_E0` covering `"auto_tuner.parallelism.hysteresis"`.
- Seed `0xA1_B1_C1_D1_E1_F1_A1_B1` covering `"auto_tuner.throttle.deadlock_prevention"`.

**Updates** `proof_seed_corpus_covers_all_registered_laws` in `chaos_tests.rs` to include `"AutoTuner/v1"`.

**Ends green**: `proof_auto_tuner_buggify_chaos_1000_seeds_all_settle` + updated seed corpus test.

### S7 — LFS durability slice: auto-tuner audit survives crash-replay

**New test** in `crates/rockstream-sim/tests/auto_tuner_chaos_tests.rs`:

`proof_auto_tuner_audit_survives_crash_replay`:
- Creates a `SimObjectStore` (LFS equivalent).
- Runs `AutoTuner` through one 10× spike, logging all adjustment events to a `FileAuditLog` backed by the `SimObjectStore` (write path).
- Simulates crash: drops the `AutoTuner` and log handle.
- Re-opens the log from the `SimObjectStore`.
- Asserts: all adjustment events are present in the re-opened log (count matches pre-crash count).
- Uses the `SimRuntime`'s object store, so this is an LFS-equivalent test (same store used by LFS path in v0.27–v0.29 proofs).

**Ends green**: `proof_auto_tuner_audit_survives_crash_replay`.
