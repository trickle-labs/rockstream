# v0.61.2 Plan — Aggregate Delta Reduction

**Version**: v0.61.2  
**Phase**: Phase 2 — Plan  
**Target Scope**: Keep existing dirty-key persistence. For epoch-visible `SUM` and `COUNT`, consolidate each group's inputs and emit its old and final values once. ## Scope and Boundary

Roadmap reference (`ROADMAP.md` §5.3: `v0.61.2: Aggregate delta reduction`):
> **Focus**: Keep the existing dirty-key persistence. For epoch-visible `SUM` and `COUNT`, consolidate each group's inputs and emit its old and final values once. Emit nothing when the result is unchanged. Preserve checked arithmetic, NULL behavior, signed multiplicities, group deletion, and atomic failure behavior. Do not coalesce across observable epoch boundaries.
> **Required Proof**: Prove exact output deltas and recovered results for repeated-key updates, cancellations, deletions, NULLs, and overflow. Measure intermediate rows as well as dirty-key writes. This is a bounded optimization of supported aggregates, not a new aggregate framework.

Committed implementation plan reference: `docs/implementation-plans/v0.61.2.md`.  
Shared implementation and evidence rules: `docs/implementation-plans/README.md`.

v0.61.2 establishes aggregate delta reduction across operator consolidation, atomic staging, persistence bounds, and public release verification:

1. **Epoch Group Input Consolidation & Old/Final Value Emission**:
   - Consolidate inputs by group key `k` within a logical epoch before evaluating aggregate transitions.
   - For any modified group, capture its old state once and compute its final state once.
   - Emit at most:
     - One retraction row (weight = -1) for the old group aggregate state (if previously non-empty).
     - One insertion row (weight = +1) for the final group aggregate state (if non-empty).
   - If the group's net result is unchanged between the start and end of the logical epoch (e.g. offsetting insertions and retractions, or net-zero updates), emit **zero output rows**.
   - If a group is created in this epoch (no prior state), emit only the final positive insertion row.
   - If a group is completely deleted in this epoch (count drops to zero), emit only the retraction of the old state.

2. **Atomic Staged Validation & Checked Arithmetic**:
   - Accumulate and validate all group updates within an epoch in a staged accumulator before applying any mutations to operator state (`AggState`) or registering dirty keys.
   - If any arithmetic overflow occurs (`checked_add`, `checked_mul`), or if input is malformed, or if memory limits are exceeded, reject the entire epoch immediately with `Err(OpError)`.
   - Ensure zero partial mutations: earlier groups in the batch remain strictly unmodified in memory and in storage write batches.
   - Decision on intermediate arithmetic ordering and cancellation:
     - SumCount is an abelian group over mathematical integers.
     - Per-row multiplication `v_i.checked_mul(w_i)` is checked strictly upon ingestion.
     - Net contribution per group is accumulated in `i128` during epoch consolidation to ensure mathematical commutativity and cancellation of offsetting deltas within the epoch regardless of input arrival order.
     - Transition to final `i64` sum (`old_sum.checked_add(delta_sum)`) and count (`old_count.checked_add(delta_count)`) enforces checked bounds. True mathematical overflow beyond `[i64::MIN, i64::MAX]` fails closed atomically.

3. **Strict Resource Bounding & Consolidation Limits**:
   - Bound the epoch consolidation accumulator by named constants:
     - `MAX_EPOCH_CONSOLIDATION_GROUPS = 1_000_000` (maximum distinct group keys touched in one epoch).
     - `MAX_EPOCH_CONSOLIDATION_BYTES = 64 * 1024 * 1024` (64 MiB maximum memory for epoch staging).
   - Expose observable occupancy and fill-level telemetry (`consolidation_groups`, `consolidation_bytes`).
   - If limits are reached, reject the epoch fail-closed without acknowledging partial work or leaking memory.

4. **Preservation of Dirty-Key Persistence & Proportionality**:
   - State persistence remains strictly proportional to touched dirty keys (O(dirty keys)), never performing a full-state walk over unchanged keys.
   - State mutations continue to produce `StateMutation::Put` for active groups and `StateMutation::Delete` for deleted groups (tombstones).
   - If a group's state is unchanged over the epoch, do not mark it dirty and do not emit unnecessary storage mutations.

5. **Epoch Boundary Integrity & Transport Batch Decoupling**:
   - Physical transport batches within the same logical epoch are consolidated cleanly into that epoch's net result.
   - Never coalesce across distinct observable epoch boundaries: separate epochs must emit distinct, observable public deltas and advance frontiers independently.

6. **Durability & Crash Recovery Verification**:
   - Persisted aggregate arrangements survive node restart and crash-recovery drills without duplicate deltas, stale values, or resurrected deleted groups.
   - Verify durability across both SlateDB LocalFileSystem (LFS) and MinIO (S3) backends.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).

  - Tracks approximate byte memory usage and distinct group key count.
  - Enforces `MAX_EPOCH_CONSOLIDATION_GROUPS` and `MAX_EPOCH_CONSOLIDATION_BYTES`.

### Slice 2: Group Consolidation, Net State Computation, and Unchanged Suppression
- Refactor `AggregateOp::process_delta_with_result`:
  - First pass: aggregate all input rows for each group into `StagedEpochAggregator`.
  - Second pass: for each touched group, look up its existing `(old_sum, old_count)` in `AggState`.
  - Compute `new_sum` and `new_count` using checked arithmetic.
  - Compare `(old_sum, old_count)` with `(new_sum, new_count)`:
    - If identical: emit **zero output deltas**, do not add key to `dirty_keys`.
    - If different:
      - If old state existed (`old_count > 0`): emit retraction row `(k, old_sum, old_count, old_avg, weight = -1)`.
      - If new state exists (`new_count > 0`): emit insertion row `(k, new_sum, new_count, new_avg, weight = +1)`.
      - Add key `k` to `dirty_keys`.
- **Oracle property test commitment**:
  - Compare incremental output against `MultisetOracle` batch recalculation across 1,000 randomized events.
