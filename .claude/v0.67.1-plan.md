## 1. Resolved Contract Choices

1. **Stateful Operator Support Boundary & Workload Rejection Gate (Step 1, V0671-01)**:
   - **Supported Operators for State Beyond RAM in v0.67.1**:
     - Ordinary distributive aggregates: `SUM`, `COUNT`, `MIN`, `MAX`, and `AVG` (maintained as `SUM` and `COUNT` pair) with group keys of type `i64`, `int32`, and `Vec<u8>` (text/bytes). Implemented with demand loading and spillable arrangement backing.
     - Single-source shared arrangements (`IndexArrange` / `SharedArrangementTrace`): bounded demand-paging.
     - Materialized view point-lookups and bounded prefix scans (`scan_prefix_paginated`).
   - **Unsupported Operator/Workload Combinations**:
     - Non-distributive aggregates beyond RAM (e.g. `MEDIAN`, `PERCENTILE_CONT`, `ARRAY_AGG` without bounded window).
     - Multi-way hash joins requiring full-state dual materialization when estimated join state exceeds the worker operator memory budget.
     - Recursive queries / TCO beyond RAM.
     - Sliding windows without watermarks or with unbounded retention.
   - **Rejection Behavior**:
     - Unsupported combinations fail during query compilation / view creation with explicit error code `RS-5003` (`state_budget_exceeded`) or `RS-4022` (`unsupported_large_state_operator`) naming the unsupported operator, required budget, and recovery instructions.
     - Never allocate unbounded in-memory buffers or permit silent OOM crashes.

2. **Demand-Loaded Aggregate State & Dirty-Key Tracking (Step 2, V0671-02, V0671-04)**:
   - `AggregateOp` replaces full in-memory `AggState::HashMap<i64, (i64, i64)>` with demand-loaded cache backed by `ShardDb`.
   - On incoming delta for group key `K`:
     - Look up `old_state`: check in-memory cache first; on cache miss, demand-load `(sum, count)` from `ShardDb` via point read.
     - Compute transition: `new_sum = checked_add(old_sum, delta_sum)`, `new_count = checked_add(old_count, delta_count)`.
     - Output delta calculation: emit `(-old_state, +new_state)` downstream. If `new_count == 0`, group is retracted; emit retraction and mark storage key for tombstone/deletion.
     - Mark key in `dirty_keys: BTreeSet<K>` for the current epoch.
     - Dirty state remains authoritative and pinned in memory until epoch commit. Cold clean entries are evicted when memory exceeds the operator quota.
     - Arithmetic overflow/underflow or division-by-zero triggers atomic rollback with `RS-1201` (`numeric_value_out_of_range`) without corrupting committed state.

3. **Bounded Streaming Scans & Paging Contract (Step 3, V0671-03)**:
   - Fix `ShardDb::scan_prefix_paginated`: replace current eager `self.scan_prefix(prefix).await?` (which buffers all entries into a `Vec`) with a true streaming cursor over SlateDB's `iter = self.db.scan_prefix(&physical_prefix).await?`.
   - Page boundaries enforced by two orthogonal limits:
     - `page_size`: maximum rows per page (default: 1,024 rows).
     - `max_buffer_bytes`: maximum serialized bytes accumulated per page (default: 1 MiB).
   - Deterministic continuation: scans use the last returned key as a continuation token for resumed cursor positioning.
   - Eliminate `spilled_keys: HashSet<K>` in `SpillableArrangement`: maintaining 10M keys in memory consumes hundreds of megabytes. Replace with direct SlateDB key lookups, a bounded negative-lookup cache (LRU, max 16,384 entries), and prefix bloom filter.

4. **Complete Page Restoration Contract (Step 4, V0671-03, V0671-07)**:
   - View restoration across process restarts (`AggregateOp::restore_in_place` and `RecoveryDriver::recover_shard`) pages through persisted state in bounded chunks.
   - Distinguish end-of-scan from intermediate states:
     - Normal EOF: iterator depleted cleanly; mark restoration phase complete.
     - Quota exhaustion: fails with `RS-5003` / `RS-9001`.
     - Cancellation: returns `RS-2003` (`scan_cancelled`).
     - Corrupt page / checksum mismatch: returns `RS-2024` (`corrupt_storage_page`).
     - Persistent format version mismatch: returns `RS-2025` (`unsupported_storage_format_version`).
   - Only verified complete scan permits transitioning `RecoveryDriver` to `Healthy` / `Ready`.

5. **Worker Budget Ledger Integration & Pressure Governors (Step 5, V0671-05)**:
   - Spill buffers and I/O queues are accounted against the `WorkerBudgetLedger`:
     - Category 3 (`OperatorState`): in-memory cache and pinned dirty keys.
     - Category 7 (`CheckpointStaging`): serialized spill pages and flush batches.
     - Category 8 (`StorageBacklog`): pending spill write bytes.
   - Named limits enforced in `WorkerBudgetConfig`:
     - `max_spill_write_buffer_bytes`: 16 MiB default upper bound per shard.
     - `max_disk_occupancy_bytes`: 50 GiB default disk ceiling.
     - `max_concurrent_spill_io`: 4 concurrent asynchronous spill flushes.
     - `max_spill_retries`: 5 attempts with bounded exponential backoff before failing.
   - When limits are reached:
     - Ingestion sources are throttled via existing `SourcePressureController` (poll credits reduced at 80% utilization, paused at 95%).
     - Disk-full condition rejects writes cleanly with `RS-2021` (`disk_space_exhausted`) instead of unbounded memory accumulation.
     - Dedicated foreground capacity (`foreground_reservation_bytes`, default 20%) is preserved for ad-hoc reads and maintenance commits.

6. **External R1 Baseline Qualification & Matrix Cells (Step 7, V0671-06, V0671-08)**:
   - Unblock and qualify the 2 blocked matrix cells in `tools/r1-local-harness/src/matrix.rs`:
     - `one-key-10m-beyond-ram` (Area 1: One-key updates with 10M groups).
     - `state-beyond-ram-spillable` (Area 5: State larger than RAM spillable arrangements).
   - Workload profile:
     - Serialized maintained state: >= 500 MiB (1M to 10M groups) with worker budget configured to 64 MiB or 128 MiB.
     - Actual worker process RSS ceiling: strictly bounded <= `worker_budget_bytes + 25%` headroom under sustained updates, eviction, compaction, and full restart.
     - p99 targets: `read_p99 <= 10.0 ms`, `commit_p99 <= 25.0 ms`, `freshness_p99 <= 100.0 ms`.
     - Bit-identical result multiset compared with independent oracle engine.
