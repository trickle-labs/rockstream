## Vertical Slices

### S1 — `docs/configuration.md` regeneration + conformance lock (P2, P3)
Rewrite the reference table directly from `crates/rockstream-types/src/
config.rs`'s `RockstreamConfig`/`Default` impl: correct section placement
(`state_budget_gb` moves from a nonexistent `[memory]` section into
`[cluster]`), correct every default (`min_epoch_ms=10`,
`checkpoint_retention_count=128`, `state_budget_gb=10`,
`segment_cache_bytes=536870912`, `max_rows_per_quantum=1000`,
`dlq_warn_threshold=100`, `dlq_retention_days=7`), remove the phantom
`checkpoint_retention_duration_sec` key, and add any currently-undocumented
fields (`autotuner`, `index_prefer_selectivity_threshold`,
`index_max_lag_ms`, `tiering`, optional `pricing`). Add a new test
`crates/rockstream-types/tests/docs_conformance_tests.rs`:
`test_configuration_doc_matches_rockstream_config_defaults` — parses
`docs/configuration.md`'s reference table (key + default value pairs) and
diffs it, at test time, against `RockstreamConfig::default()`'s real field
values (via `Debug`/serialization, not hand-copied numbers in the test
itself). Ends green when `cargo test -p rockstream-types
docs_conformance` passes and fails if a docs value or the struct default
diverges.

### S2 — `docs/cli.md` regeneration (P3)
Rewrite the flags table directly from `crates/rockstream-cli/src/main.rs`'s
`clap` `Command` definition, covering every flag including the seven
missing v0.45.2 M7 flags (`--raft_peers`, `--raft_node_id`, `--raft_bind`,
`--raft_bootstrap`, `--daemon`, `--control_bind`,
`--control_shared_storage`) with their real defaults/required-ness, and add
`RS-1731` to the error-code table alongside `RS-0002`/`RS-0003`. Ends green
when `cargo test --workspace` still passes (no test currently parses
cli.md, so this slice's "green test" is the full suite staying green plus a
human diff read against `main.rs` recorded in the evidence file — see P3
proof mapping) and a manual re-run of `rockstream --help` (or the
equivalent `clap` usage string) matches the doc flag-for-flag.

### S3 — `docs/language-features.md` full audit + conformance lock (P1, P3)
Line-by-line re-verify every "Implemented Today" bullet (not the prior
sample) against `crates/rockstream-sql`'s parser, correcting any found
drift in place. Add a new test `crates/rockstream-sql/tests/
docs_conformance_tests.rs`: `test_language_features_doc_keywords_are_
parseable` — mirrors `conformance_doc_tests.rs`'s parsing style: reads
`docs/language-features.md`, extracts every backtick-quoted keyword/clause
listed under "Implemented Today", and asserts each one is recognized by
`rockstream-sql`'s parser/keyword table (constructing a minimal valid
statement per keyword where needed, or checking the keyword against the
parser's reserved/keyword enum directly — whichever is less brittle without
inventing a parallel keyword list; use the parser's own tokenizer/keyword
recognition, not a hand-copied list in the test). Ends green when `cargo
test -p rockstream-sql docs_conformance` passes and fails if a future PR
adds an "Implemented Today" keyword the parser doesn't recognize.

### S4 — `docs/concepts.md` full audit (P3)
Full line-by-line re-verification of every remaining "Implemented Today" /
worked-example claim in the document (§32 already carries its caveat from
the round-3 fix; the rest of the ~1400+ lines have never been audited).
Correct any drift found in place. Ends green when `cargo test --workspace`
stays green and the per-section audit checklist in the evidence file shows
every claim checked.

### S5 — `docs/sre-operations.md` support-bundle fix (P4)
Rewrite the "Support Bundle Parsing" section to match
`write_support_bundle()` (`crates/rockstream-cli/src/lib.rs`): the bundle
is generated automatically on node start (not via a `rockstream
support-bundle` command, which does not exist), written as a single
pretty-printed JSON file `support-bundle-<generated_at_ms>.json`, with a
worked example showing the real top-level shape (`generated_at_ms`,
`system_info{version,os,arch,role}`,
`metrics{uptime_ms,audit_events_emitted}`, `audit_events`) instead of the
fictitious tarball/`audit.jsonl`/`config.toml`/`metrics.json` triple. Add
an explicit note that the two-word `rockstream support bundle` CLI command
is roadmapped for v0.55 and is not yet available. Ends green when `cargo
test --workspace` stays green and the worked example is produced by
actually running a node and inspecting the real emitted JSON file
(recorded verbatim, field-for-field, in the evidence file) rather than
hand-typed.

### S6 — `docs/distributed-architecture.md` full component re-verification (P5)
Confirm (regression-check, not a fix) that `WorkerAggregator` →
`FrontierAggregator` and `RS-1601` → `RS-3601` remain corrected. Then
re-verify the previously-unchecked sections component-by-component against

against `crates/rockstream-control`, and §5 Shuffle Transport's
`ExchangeClassifier`/`DurableShuffleWriter` against
`crates/rockstream-runtime`. Correct any further drift found in place.
Ends green when `cargo test --workspace` stays green and the evidence file
records a component-by-component checklist (type/error-code name → source
file:line) for every section of the document, with zero remaining

### S7 — `docs/grafana-dashboard.json` metric-name fix (P6)
Fix the "Memory / State Budget Utilization" panel (replace the `memory_
limit` denominator with a real metric or a documented static config value,
whichever the panel's actual Grafana template variable mechanism supports)

`exchange_queue_depth` with a real existing metric — no new metric is
implemented by this docs-only version, so a fabricated metric's panel
cannot be kept as-is). Re-verify every other panel's metric name against
`crates/rockstream-types/src/metrics.rs`'s registered metric names. Ends
green when `cargo test --workspace` stays green (no test currently parses
this file) and the evidence file records a panel-by-panel checklist
(panel → metric name → source file:line) with zero remaining mismatches.
