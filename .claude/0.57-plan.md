# v0.57 Plan — The v1 Public Contract: Tiering & the Machine-Checked Substrate

## Scope and guardrails

This version is contract data, generated documentation, and CI enforcement only:
it adds no IVM, storage, durability, coordination, pgwire, parser, dispatcher,
or executor behavior. `main` remains runnable solely through `rockstream`.
No cleanup may use SlateDB range deletion.

The product-promise text is exactly:

> RockStream ingests changing data, continuously maintains a documented SQL subset as durable materialized views, and serves globally committed results to PostgreSQL-compatible clients while surviving ordinary distributed-system failures without losing or silently corrupting committed state.

## 3. Coverage matrices and test commitments

### Aggregate/type/join/window matrix

No aggregate, type, join, or window feature is added or changed in v0.57.
Therefore this version introduces **zero matrix cells**. Existing cells are
inventory inputs only; their exact named e2e proof is required in each
`capabilities.toml` Core record and is checked by
`scripts/check-capability-contract.sh`. v0.57.1, not v0.57, owns the five
per-operator semantic matrices.

| Feature family | New cells | Required v0.57 test commitment |
|---|---:|---|
| Aggregates (key type × value type × function) | 0 | No new oracle property test; the gate rejects any Core aggregate record without its existing named e2e proof link. |
| Joins (join type × key type) | 0 | No new oracle property test; the gate rejects any Core join record without its existing named e2e proof link. |
| Windows (function × key type) | 0 | No new oracle property test; the gate rejects any Core window record without its existing named e2e proof link. |

This is not permission to leave a Core cell unproven: the generator emits every
Core record into the matrix, and the checker fails on a missing or unresolvable
proof link. Existing proof suites used by records include
`rockstream-sql/tests/tpch_plans.rs`, `rockstream-oracle` aggregate/join/window
oracles, `rockstream-gateway/tests/unified_data_plane_tests.rs`, and the named
PostgreSQL CDC/Kafka matrix tests in `docs/connectors.md`.

1. **S1 — Structured source and deterministic matrix.** Add
   `capabilities.toml`, a deterministic generator, and generated capability

   `README.md`, `DESIGN.md`, and `NEW_IMPLEMENTATION_PLAN.md`; add strategic

   `docs/connector-migration.md`; publish the Maintain deprecation and future

   `scripts/check-capability-contract.test.sh` byte-compares the three promise
   copies and validates every generated/documented record.
3. **S3 — Contract gate and inventory audit.** Implement
   `scripts/check-capability-contract.sh` plus its paired self-test. It must
   reject a missing tier, missing Core proof link, unresolvable proof target,
   Core entry without dispatch-derived inventory evidence, unknown connector or
   sink, and generated-matrix/roadmap drift. Green:
   `scripts/check-capability-contract.test.sh`.
4. **S4 — Future-surface admission enforcement.** Extend
   `scripts/check-exit-criteria.sh` to require the §8 admission checklist for

   `scripts/check-capability-contract.test.sh` proves CI-ready contract checks.

test is required. If implementation discovers that a record would introduce or
change an operator, that work is out of this plan until its oracle property
test is added before the operator code.
