# v0.58 Plan — Failure Matrix: Enumeration & Deterministic Simulation Coverage

## Scope and Boundary

v0.58 implements the comprehensive, published failure matrix and deterministic `SimRuntime` coverage across all production failure modes required for an object-storage-native IVM system (per `ROCKSTREAM_PROJECT_FOCUS.md` §5.5 and `NEW_ROADMAP.md` v0.58).

Per the 2026-08-12 realism review split:
- **v0.58 (this version)**: Enumerates and publishes the matrix in `docs/failure-matrix.md`, pairs every cell with an in-tree programmatic definition in `crates/rockstream-sim`, covers every cell deterministically in `SimRuntime` with a permanent seed corpus, asserts explicit recovery properties (no loss, no duplicates, bounded recovery time against v0.22/v0.31 SLOs — never merely "did not crash"), and enforces matrix coverage and assertion quality via a new CI gate (`scripts/check-failure-matrix.sh` + self-test). Replays all historical FizzBee counterexample seeds and chaos seeds clean.
- **v0.58.1**: Real-backend counterparts in `real-cluster-chaos.yml` and published recovery numbers.
- **v0.58.2**: Storage-pressure admission signals and the SLO auto-tuning lock.
- **v0.58.3**: Unscoped reachability, dispatch-wiring & silent-wrong-answer sweep.

### Non-Negotiable Ground Rules
- `rockstream` remains the sole production binary and `main` remains runnable.
- Prefix all commands with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- No code path may depend on SlateDB range deletion; cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is prohibited: every buffer/queue/window has a named upper bound, fill metric, and backpressure/error path.
- No test may be weakened, skipped (`#[ignore]`), or deleted.
- **Nothing may be deferred to a later version.**

## Vertical Slices

### Slice 1: Failure Matrix Specification & Programmatic Model
- **Deliverables**:
  - `docs/failure-matrix.md`: Checked-in documentation defining all 11 failure modes, scenarios, fault injection mechanisms, permanent seeds, asserted recovery properties, and owning versions.
  - `crates/rockstream-sim/src/failure_matrix.rs`: Structured Rust registry and types (`FailureModeId`, `FailureMatrixCell`, `RecoveryOutcome`, `FAILURE_MATRIX_CELLS`) with metadata verification.
  - Export module in `crates/rockstream-sim/src/lib.rs`.
- **Test**: `crates/rockstream-sim/tests/failure_matrix_tests.rs::test_failure_matrix_registry_complete_and_consistent`

### Slice 2: Matrix-Coverage CI Gate & Self-Test
- **Deliverables**:
  - `scripts/check-failure-matrix.py`: Parser and validator for `docs/failure-matrix.md` and the codebase. Validates:
    1. Every named failure mode FM-001..FM-011 is present.
    2. Every cell has a non-vacuous asserted recovery property (rejects "did not crash", "passes without panic", "no error", etc.).
    3. Every cell links to an existing, resolvable Rust test (`path::test_name`).
    4. Every cell names its permanent seed corpus.
  - `scripts/check-failure-matrix.sh`: Shell wrapper.
  - `scripts/check-failure-matrix.test.sh`: Self-test with mutation tests verifying rejection of:
    - Missing cell / deleted scenario.
    - Vacuous assertion ("did not crash").
    - Missing or unresolvable test link.
    - Missing seed reference.
  - Integration into `Makefile` (`check` target) and `scripts/check-exit-criteria.sh`.
- **Test**: `rtk bash scripts/check-failure-matrix.test.sh`

### Slice 3: Deterministic SimRuntime Failure Scenarios & Seed Corpus
- **Deliverables**:
  - Extend `crates/rockstream-sim/src/soak.rs` (`build_initial_corpus`) and `crates/rockstream-sim/src/failure_matrix.rs` with permanent seeds for each of the 11 failure modes.
  - Ensure all 11 deterministic scenarios pass under `SimRuntime` with their permanent seeds.
  - Verify that historical FizzBee counterexample seeds and chaos seeds replay clean.
- **Test**: `crates/rockstream-sim/tests/failure_matrix_tests.rs` (all 11 FM tests pass) & `crates/rockstream-sim/tests/chaos_tests.rs` & `crates/rockstream-sim/tests/recovery_slo_tests.rs`

### Slice 4: Durability and Coordination Slices
- **Deliverables**:
  - Durability assertions (LFS and MinIO) verified for checkpoint recovery, spill under compaction, and crash recovery.
  - Coordination assertions verified with `buggify!()` fault injection points in `coord_faults.rs`.
- **Test**: `crates/rockstream-storage/tests/lfs_backend.rs`, `crates/rockstream-sim/tests/checkpoint_recovery.rs`, `crates/rockstream-sim/tests/az_aware_exchange_sim_tests.rs`
