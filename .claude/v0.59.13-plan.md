# v0.59.13 Plan — Single-Source Product Surface

## Scope and Boundary

v0.59.13 implements the Single-Source Product Surface milestone of the Pre-v1 Product Polish track (`NEW_ROADMAP.md` v0.59.13):

1. **`rockstream-docgen` Tooling & Architecture (`DOC-001`, `DOC-004`)**:
   - Introduce `rockstream-docgen` (as a dedicated workspace crate / engine component) that extracts, validates, normalizes, and generates unified product surface metadata across all RockStream components.
   - Define canonical data structures for `ProductSurfaceManifest` (`DOC-001`) capturing:
     - `manifest_metadata`: Schema version, engine version, candidate identity digest, generator version, and timestamp.
     - `cli_surface`: Commands, subcommands, arguments, options/flags, exit codes, and error code mappings from `rockstream-cli`.
     - `config_surface`: Configuration keys, types, defaults, descriptions, deprecated keys, env var mappings, and source origins from `rockstream-runtime`.
     - `function_surface`: SQL scalar and aggregate functions, signatures, argument types, return types, null-handling semantics, categories, and examples from `rockstream-sql` and `rockstream-ops`.
     - `catalog_surface`: System catalog schemas, tables (`rockstream_catalog.*`), columns, data types, nullability, cardinality bounds, and descriptions from `rockstream-gateway`.
     - `metric_surface`: Prometheus metrics, names, types (Counter, Gauge, Histogram), units, labels, stability levels, and descriptions across all subsystem crates.
     - `error_surface`: Authoritative error descriptors from `contracts/errors.toml` / `rockstream-types` (`code`, `key`, `title`, `severity`, `sqlstate`, `retry_class`, `default_next_steps`, `doc_anchor`).
     - `sql_contract_surface`: Complete multi-dimensional SQL type compatibility matrix consumed from `contracts/sql-type-matrix.toml`.

2. **Authoritative SQL Type Contract (`contracts/sql-type-matrix.toml`)**:
   - Establish `contracts/sql-type-matrix.toml` as the single authoritative, machine-readable declaration of all supported, experimental, and unsupported SQL type combinations across expressions, aggregates, joins, windows, DML, and prepared statements.
   - Cover standard SQL types (`INT2`, `INT4`, `INT8`, `FLOAT4`, `FLOAT8`, `NUMERIC`/`DECIMAL`, `BOOLEAN`, `TEXT`, `VARCHAR`, `BYTEA`, `DATE`, `TIMESTAMP`, `TIMESTAMPTZ`, `INTERVAL`, `UUID`, `ARRAY`).
   - Define exact status for every cell: `Core` (fully implemented and proven), `Supported`, `Experimental`, `Unsupported` (with mandatory documented rejection error code e.g. `RS-1019`).

3. **Product Surface Contributors (`DOC-001`)**:
   - Implement modular contributors that extract surface definitions directly from source code and contract files:
     - `CliContributor`: Extracts CLI tree structure from `rockstream-cli` definition.
     - `ConfigContributor`: Extracts configuration schemas and metadata from `rockstream-runtime`.
     - `FunctionContributor`: Extracts built-in scalar and aggregate functions from `rockstream-sql` and `rockstream-ops`.
     - `CatalogContributor`: Extracts system catalog tables and column schemas from `rockstream-gateway`.
     - `MetricContributor`: Extracts registered telemetry metrics across all crates.
     - `ErrorContributor`: Ingests `contracts/errors.toml` / `rockstream-types`.
     - `SqlContractContributor`: Parses and normalizes `contracts/sql-type-matrix.toml`.

4. **Deterministic Generated JSON & Output (`DOC-001`, `DOC-004`)**:
   - Generate deterministic canonical JSON `docs/product-surface.json` representing the complete, unified product surface.
   - Enforce deterministic serialization (canonical key ordering, stable array sorting, uniform formatting) guaranteeing bit-for-bit identical outputs across environments.

5. **Automated Drift Gates & Mutation Verification (`DOC-004` foundation)**:
   - Provide `scripts/check-product-surface.sh` / `scripts/check-product-surface.py` to enforce zero drift between live code/contracts and `docs/product-surface.json`.
   - Verify 100% ID and matrix cell resolution (zero broken references between CLI error codes, function types, catalog types, and error catalog entries).
   - Implement `scripts/check-product-surface.test.sh` mutation suite validating that unauthorized changes to CLI flags, config options, functions, catalog tables, metrics, error codes, or SQL matrix cells immediately fail the CI drift gate.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
