## Error Codes Needed (new)

Auth/RBAC errors belong in `RS-2400–2499` ("Reserved (gateway expansion)") per
DESIGN.md §14.14 range table — auth is gateway-enforced.

| Code | Slug | Description |
|------|------|-------------|
| RS-2400 | `auth.unauthenticated` | Request missing or carrying invalid credentials; rejected at gateway before any shard or control-plane access |
| RS-2401 | `auth.permission_denied` | Authenticated principal lacks the required RBAC role for this view/namespace |
| RS-2402 | `auth.namespace_access_denied` | Cross-namespace access attempt by a non-admin principal |

## Buffer Bound Declarations

| Buffer / Queue / Window | Upper Bound | Fill Metric | Backpressure / Error |
|-------------------------|-------------|-------------|----------------------|
| JWKS key cache | `MAX_JWKS_ENTRIES` (default 100 keys); LRU eviction on full | `jwks_cache_size` gauge | On validation miss after full eviction: re-fetch from OIDC endpoint; RS-2400 on repeated failure |
| ACL decision cache | `MAX_ACL_CACHE_ENTRIES` (default 10,000 entries); TTL 60 s | `acl_cache_size` gauge | On TTL expiry: re-fetch from `catalog/acl/`; RS-2401 if re-check denies |
| Per-shard partial-agg result buffer | `MAX_PARTIAL_AGG_RESULT_ROWS` (default 1,000,000 rows/shard) | `partial_agg_result_rows` gauge | RS-2002 `view.state_budget_exceeded` when a shard returns > limit |
| Key-refresh interval | `AUTH_KEY_REFRESH_INTERVAL_MS` (default 300,000 ms = 5 min) | `auth_key_refresh_total` counter | Background refresh; stale key triggers foreground re-fetch on first miss |

### S2 — `Principal` type + auth verification (bearer / mTLS / off)

**Files:**
- `crates/rockstream-gateway/src/auth.rs` (new)
- `crates/rockstream-gateway/src/server.rs` — replace `NoopStartupHandler`

**What:**
```rust
#[derive(Debug, Clone, PartialEq)]
pub enum Principal {
    System,                     // --auth=off or internal paths
    Jwt { sub: String },        // OIDC bearer token, verified against JWKS
    CertCn { cn: String },      // mTLS client cert CN
}
impl Principal {
    pub fn identity(&self) -> &str { ... }
    pub fn is_anonymous(&self) -> bool { ... }
}
```

- When `--auth=off`: `current_principal()` always returns `Principal::System`.
- When `--auth=oidc`: extract `Authorization: Bearer <jwt>` from pgwire startup
  params; validate signature against JWKS fetched from `--oidc-issuer`; extract
  `sub`; cache up to `MAX_JWKS_ENTRIES` keys LRU.
- When `--auth=mtls`: extract CN from TLS peer certificate (uses existing
  `TlsConfig` scaffolding in `rockstream-control`).
- Missing/invalid credentials → RS-2400 in a pgwire `ErrorResponse`, connection
  closed before any query.
- `OidcStartupHandler` implements `StartupHandler` and enforces this; replaces
  `NoopStartupHandler` when auth ≠ off.
- Bound: JWKS cache ≤ `MAX_JWKS_ENTRIES`; fill metric `jwks_cache_size`.

**Green gate:**
- `auth_off_bypasses_all_checks` — with `--auth=off`, any startup params produce
  `Principal::System` with no network calls.
- `jwt_bearer_token_validates_sub` — a mock-signed JWT with `sub = "alice"` is
  verified and returns `Principal::Jwt { sub: "alice" }`.
- `jwt_missing_or_invalid_returns_rs2400` — no `Authorization` header / expired
  token → `GatewayError` carrying RS-2400.

### S3 — RBAC catalog + ACL enforcement at the gateway

**Files:**
- `crates/rockstream-control/src/acl.rs` (new)
- `crates/rockstream-types/src/acl.rs` (new — `Role`, `AclEntry` types)
- `crates/rockstream-gateway/src/server.rs` — call `AclStore::check` before
  SELECT / SUBSCRIBE / DML

**What:**
```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub enum Role { Viewer, PipelineOwner, Admin }

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct AclEntry {
    pub principal: String,        // JWT sub or cert CN
    pub namespace: String,
    pub view_name: Option<String>, // None = namespace-level grant
    pub role: Role,
}
```

`AclStore` persisted under `catalog/acl/<namespace>/<principal>` in the
control-plane `ShardDb`. Exposes:
- `grant(entry: AclEntry) -> Result<()>`
- `revoke(principal, namespace, view_name) -> Result<()>`
- `check(principal: &Principal, namespace: &str, view_name: Option<&str>, required: Role) -> Result<(), GatewayError>`

Cache up to `MAX_ACL_CACHE_ENTRIES` entries with 60 s TTL; fill metric
`acl_cache_size`.

`Principal::System` always passes all ACL checks (used by internal paths and
`--auth=off`).

RS-2401 on permission denied.

**Green gate:**
- `acl_grant_viewer_allows_select` — grant viewer, check viewer → OK.
- `acl_check_denies_insufficient_role` — grant viewer, check pipeline_owner →
  GatewayError RS-2401.
- `admin_role_passes_all_checks` — admin principal passes viewer, pipeline_owner,
  and admin checks.

### S6 — Shard partial-query interface

**Files:**
- `crates/rockstream-storage/src/shard_db.rs` (or `view_reader.rs`)
- New method: `partial_query`

**What:**
```rust
/// Execute a DataFusion partial-aggregate plan against this shard's
/// `view_output/<view_name>/` snapshot and return a compact RecordBatch.
/// Bound: result rows ≤ MAX_PARTIAL_AGG_RESULT_ROWS.
pub async fn partial_query(
    &self,
    view_name: &str,
    partial_plan_bytes: &[u8],   // Substrait fragment
    frontier: u64,
) -> Result<RecordBatch, ShardError>;
```

Internally:
1. Open a `DbReader` snapshot pinned to `frontier`.
2. Deserialize the Substrait fragment via DataFusion's Substrait reader.
3. Execute against the in-memory scan of `view_output/<view_name>/`.
4. Return a `RecordBatch` with at most `MAX_PARTIAL_AGG_RESULT_ROWS` rows;
   return `ShardError::ResultTooLarge` (RS-2002) if exceeded.

Named bound: `MAX_PARTIAL_AGG_RESULT_ROWS` (const, default 1,000,000);
fill metric: `partial_agg_result_rows` gauge per call.

**Green gate:**
- `partial_agg_shard_query_returns_compact_batch` — write 100 rows across 5
  groups, call `partial_query` with a `GROUP BY key, SUM(val)` plan, assert
  result has exactly 5 rows.
- `partial_agg_shard_query_too_large_returns_rs2002` — set limit to 3, write
  10 distinct groups, assert RS-2002 is returned.

### S7 — Gateway partial-aggregation planner + `scatter_read_partial_agg`

**Files:**
- `crates/rockstream-gateway/src/multi_shard_reader.rs`
- `crates/rockstream-gateway/src/server.rs` — wire up for `GROUP BY` queries

**What:**
- `can_pushdown_partial_agg(plan: &LogicalPlan) -> bool`: returns true when the
  plan is a simple `Aggregate(group_exprs, agg_exprs)` over a `TableScan` of a
  materialized view, where every aggregate is in `{SUM, COUNT, COUNT(*), AVG}`.
- `scatter_read_partial_agg(view_name, partial_plan_bytes, merge_plan, frontier)`:
  1. Fan out `partial_query(partial_plan_bytes)` to every shard in parallel.
  2. Collect all partial `RecordBatch`es.
  3. Execute `merge_plan` (gateway-side final aggregation via DataFusion) over
     the collected batches.
  4. Return the merged final `RecordBatch`.
- Gateway SELECT handler: if `can_pushdown_partial_agg(plan)`, use
  `scatter_read_partial_agg`; otherwise fall back to `scatter_read` (full scan).
- Named bound: existing `MAX_IN_FLIGHT_ROWS` on the fan-out; `MAX_PARTIAL_AGG_RESULT_ROWS`
  on each shard response.

**Green gate:**
- `partial_agg_gateway_planner_detects_pushdown_query` — `SELECT k, SUM(v) FROM mv GROUP BY k` → `can_pushdown = true`.
- `partial_agg_gateway_planner_rejects_non_pushdown` — `SELECT * FROM mv WHERE id > 5` → `can_pushdown = false`.
- `oracle_partial_agg_pushdown_equals_full_scan` (oracle property test) — run
  the same `GROUP BY` query via pushdown and via full scan on a 3-shard in-memory
  ShardDb; assert identical results for 1,000 random insert/update/delete sequences.

## Coordination Slices

Auth, RBAC, and pushdown are all gateway-local or control-plane-catalog operations.
No new consensus protocol is introduced. The existing M1–M4 FizzBee models cover
the underlying epoch-commit, frontier-advance, and exactly-once protocols that
all new paths reuse. No new FizzBee model is required for v0.26. Paired runtime
`assert!`s from M4 (self-fencing, single-writer) and M1 (idempotent replay) guard
all paths that RBAC or pushdown may touch.

The JWKS refresh and ACL cache invalidation are gateway-local, single-process
state with simple TTL bounds — no consensus path.
