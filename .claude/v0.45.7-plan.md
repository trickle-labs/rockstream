## 2. Live-Codebase Audit (why this plan's scope is precise, not exploratory)

Before slicing the work, every `Err(format!(...))` / `Err(String::from(...))`
/ bare-string `Result` construction site in `crates/` was enumerated (not just
the three files the roadmap names) to determine exactly what the extended
`check-error-codes.sh` will flag once activated, and to make sure CI stays
green on the real tree immediately after this version lands.

**Finding**: the vast majority of `crates/`'s `Err(format!(...))`/
`.ok_or_else(|| format!(...))` sites (`view_materializer.rs`, `secret.rs`,
`pool.rs`, `persistence.rs`, `loopback.rs`, `raft.rs`,
`catalog_registrar.rs`, most of `serialization.rs`) are **context-wrapping a
foreign error and re-raising it via a trailing `?`** — e.g.
`.map_err(|e| format!("context: {:?}", e))?`. These are propagation idioms,
not fresh ad hoc errors, and are unaffected. `server.rs`'s VALUES-list parser
(`split_value_tuples`, lines ~7264–7369) already embeds `RS-2056` inline at
every site — fully compliant already, no fix needed there.

**Genuine gaps** (bare terminal construction — no trailing `?`, no inline
code):
- `copy_state.rs::parse_copy_from_stmt` — 8 sites, zero codes (exactly what
  the roadmap names).
- `server.rs`'s CREATE SINK option parser (`parse_create_sink_ddl`,
  `parse_create_sink_options`, `parse_create_sink_option_value`,
  `parse_optional_u64_option`, `parse_sql_single_quoted_string`,
  `split_top_level_comma_list`) — ~20 sites. These are *not* bare at the
  point the client sees them today (the sole caller, `handle_create_sink`,
  wraps every message via `create_sink_error_response` which prefixes
  `[RS-4007]`), but the construction sites themselves carry no inline code —
  a textual checker cannot see through the wrapping call, so these must be
  fixed at the source to satisfy both the new automated check and direct
  unit-testability of the parser functions in isolation.
- `durable.rs` — the named `RS_3010` overload (8 call sites across rate-limit
  exhaustion, generic object-store I/O failure, buffer-capacity-exceeded,
  footer serialize, 3×footer-corruption checks, footer deserialize).
- `multiplexer.rs` — 2 sites reusing `RS_3010` for frame-coalescing failures
  during compaction (tightly coupled to the `durable.rs` split; same
  subsystem, same overloaded code, must move in lock-step or CI's new check
  finds a stale/removed constant reference).
- `serialization.rs::deserialize_zset` — 2 *terminal* sites (`return
  Err(format!(...))` / `return Err("...".to_string())`, no trailing `?`,
  unlike the rest of the file) — genuinely bare, not named by the roadmap but
  caught by the extended check the moment it activates; tightly coupled to
  the "extend the script" work item, must be fixed to keep CI green.
- `crates/rockstream-types/src/laws/sum_count.rs` and `weight_add.rs` — 1
  terminal site each (accumulator wire-size mismatch), same situation as
  above.

**Explicitly out of scope, confirmed correct to leave alone**: the
CLI-argument-parsing `Err(format!("unknown argument: {arg}"))` sites in
`crates/rockstream-ops/src/bin/{nexmark,bench}_regression_gate.rs`. These are
standalone CI benchmark-gate binaries (not the `rockstream` product binary
per the "one binary, one CLI" ground rule), and their errors are developer/CI
console output, never an operator- or user-visible pipeline failure. The
extended check's file-selection will exclude `crates/*/src/bin/*.rs` for
this reason (documented in the script's header comment).

## 3. New/Changed Error Codes

Ranges taken from DESIGN.md §14.14's reserved-range table, picking numbers
that don't collide with anything DESIGN.md already reserves for future work
(notably `RS-2501`–`RS-2504`, reserved there for a *different*, later
coordinator-error renumbering effort, and `RS-3001`/`RS-3002`, reserved for
future shard-runtime codes) — new numbers here are the next free slots after
today's real, already-registered numbers in each owner range.

| Code | Slug (informal) | Range owner | Replaces |
|---|---|---|---|
| `RS-2021` | `copy.malformed_stdin_statement` | Gateway/SQL (2000–2099) | — (new) |
| `RS-3011` | `durable.rate_limit_exhausted` | Shard/runtime (3000–3499) | part of `RS-3010` |
| `RS-3012` | `durable.object_store_io_failure` | Shard/runtime | part of `RS-3010` |
| `RS-3013` | `durable.buffer_capacity_exceeded` | Shard/runtime | part of `RS-3010` |
| `RS-3014` | `durable.footer_serialization_failed` | Shard/runtime | part of `RS-3010` |
| `RS-3015` | `durable.footer_deserialization_failed` | Shard/runtime | part of `RS-3010` |
| `RS-3016` | `durable.footer_corrupt_or_undersized` | Shard/runtime | part of `RS-3010` |
| `RS-3017` | `exchange.ipc_shuffle_decode_error` | Shard/runtime | — (new) |
| `RS-3501` | `merge.law_accumulator_decode_error` | Merge laws (3500–3999) | — (new) |

`RS-3010` is **retired** (constant, description/severity/next_steps match
arms, and the `all_codes_have_descriptions_and_actionable_next_steps` test
list entry all removed) — its six failure modes move to `RS-3011`–`RS-3016`
above. Only `sign-offs/v0.29.md` mentions `RS-3010` in the whole repo besides
`error_code.rs`/`durable.rs`/`multiplexer.rs` themselves, and that is a
historical, point-in-time sign-off record which is never edited after the
fact — no doc update needed there.

`RS-4007` ("CREATE SINK DDL parse or validation failed") already exists and
is reused (not replaced) — it is inlined directly into every CREATE-SINK
parser construction site instead of only being applied by the
`create_sink_error_response` wrapper.

`RS-1003` ("Record decode error") was considered for `serialization.rs`'s two
Arrow-IPC decode sites and the two merge-law accumulator-decode sites, but
rejected: `RS-1003`'s registered `next_steps` ("Inspect the dead-letter queue
for malformed records") is specific to connector/source record ingestion
(DESIGN.md documents it as `connector.decode_error (DLQ routed)`); these four
sites decode internal shuffle/arrangement wire formats that never touch a
DLQ, so reusing it would give operators actively misleading remediation
guidance. `RS-3017`/`RS-3501` are minted instead with accurate next_steps.

## 4. Vertical Slices

Each slice ends in a green test (`cargo test --workspace`, plus the new
`check-error-codes.sh`/`.test.sh` where noted).

- **S1 — Registry updates in `error_code.rs`.** Add `RS_2021`, `RS_3011`–
  `RS_3017`, `RS_3501` (const + `description`/`severity`/`next_steps` match
  arms, each with actionable, code-specific remediation text); remove
  `RS_3010` entirely (const + all four match-arm entries); update the
  `all_codes_have_descriptions_and_actionable_next_steps` test list
  (drop `RS_3010`, add the nine new codes). Green gate: `cargo test -p
  rockstream-types`.
- **S2 — `copy_state.rs::parse_copy_from_stmt`.** Inline `[RS-2021]` +
  actionable `next_steps` text into all 8 error sites (not-a-COPY-statement,
  missing-FROM-STDIN, 3×missing-table-name, unmatched-paren,
  empty-column-list). Existing `parse_copy_from_stmt_variants` test keeps
  passing unchanged (`is_err()`-only assertions); new assertions land in S9.
- **S3 — `server.rs` CREATE SINK option parser.** Inline `[RS-4007]` +
  `next_steps` text into every bare site in `parse_create_sink_ddl`,
  `parse_create_sink_options`, `parse_create_sink_option_value`,
  `parse_optional_u64_option`, `parse_sql_single_quoted_string`,
  `split_top_level_comma_list` (~20 sites). Simplify
  `create_sink_error_response` to stop hardcoding a `[RS-4007]` prefix (the
  message now always self-carries its code) — it only builds the
  `ErrorInfo`/`42601` envelope. The two call sites at `handle_create_sink`
  (unknown view, invalid catalog) get `[RS-4007]` embedded directly in their
  own `format!` calls too, for consistency and to keep the wrapper dumb.
- **S4 — `durable.rs` code split.** Replace all 8 `RS_3010` references with
  the matching new code from §3's table: `retry_op!`'s rate-limited branch →
  `RS_3011`; its generic-failure branch → `RS_3012`; `add_frame`'s capacity
  check → `RS_3013`; `finish`'s footer-serialize `map_err` → `RS_3014`;
  `read_footer`'s three size/length sanity checks → `RS_3016`;
  `read_footer`'s deserialize `map_err` → `RS_3015`. Existing
  `test_durable_shuffle_buffer_limit` updated to assert `"RS-3013"` instead
  of `"RS-3010"`.
- **S5 — `multiplexer.rs` coalescing errors.** Update its two `RS_3010`
  references (frame-add-during-coalescing → `RS_3013`; frame-read-during-
  coalescing → `RS_3012`), keeping them coupled to the same subsystem's new
  codes rather than inventing separate ones.
- **S6 — `serialization.rs::deserialize_zset` terminal sites.** Inline
  `[RS-3017]` into the two genuinely-bare `return Err(...)` sites (failed to
  read IPC batch; empty Arrow IPC stream).
- **S7 — Merge-law accumulator decode errors.** Inline `[RS-3501]` into
  `sum_count.rs::parse_sum_count`'s and `weight_add.rs`'s single bare
  size-mismatch sites.
- **S8 — Extend `scripts/check-error-codes.sh`.** Add a second awk pass
  (same accumulate-until-`;` technique already used for the `error!()` macro
  scan) that additionally matches `Err(format!(`, `Err(String::from(`,
  `Err("..."` + `.to_string()`/`.into()`, and `.ok_or_else(|| format!(`/
  `.ok_or_else(|| "..."` construction sites. A site is a violation unless
  either (a) its accumulated text already contains `RS-[0-9]{4}` /
  `error_code::` / `ErrorCode` (mirrors the existing macro-scan rule), or (b)
  the accumulated text's last non-whitespace token before the terminating
  `;` is `?` (i.e. the constructed value is immediately re-raised via the
  `?`-operator — "propagated ... errors ... remain exempt" taken at its most
  literal reading, which is also what keeps every context-wrapping
  `.map_err(|e| format!(...))?` idiom elsewhere in the codebase — untouched
  by this version — from becoming a false positive). File selection walks
  `crates/**/*.rs` but excludes `crates/*/src/bin/*.rs` (CI tooling
  binaries, not operator-facing — see §2's audit finding) and anything under
  a `#[cfg(test)]` module. Wired into `.github/workflows/ci.yml`'s existing
  `check` job step (extends the existing `check-error-codes.sh` invocation
  in place; no new CI step needed for the check itself).
- **S9 — Self-test harness, `scripts/check-error-codes.test.sh`.** Mirrors
  `scripts/check-invariant-pairs.test.sh`'s exact pattern: give
  `check-error-codes.sh` an optional `ROOT_DIR` argument (defaults to `git
  rev-parse --show-toplevel`, exactly like `check-invariant-pairs.sh`
  already does); the test script copies `crates/` into a temp dir, appends a
  new function containing a deliberately bare `Err(format!("boom"))` (with
  no trailing `?`) to a copied source file, runs the checker against the
  mutated copy and asserts exit code 1 with `"boom"`'s file named in the
  output; then runs the checker against the real, unmodified tree and
  asserts exit code 0. Wired into `.github/workflows/ci.yml` as its own step
  immediately after the `check-error-codes.sh` step, matching the
  `check-invariant-pairs.sh`/`.test.sh` pairing precedent exactly.
- **S10 — New test file `crates/rockstream-gateway/tests/
  copy_error_code_tests.rs`.** Integration tests (full pgwire client
  against a real test-harness server, matching the existing `RS-2056`/
  `RS-2500` assertion pattern already used in `gateway_proof_tests.rs`) for:
  every `parse_copy_from_stmt` malformed-statement variant returns `RS-2021`
  with non-empty, actionable `next_steps` text; every CREATE SINK malformed-
  DDL variant (missing FOR VIEW, missing sink name, missing TO, bad format,
  missing WITH, malformed WITH-options: bad key=value, bad ARRAY literal,
  bad string literal, non-numeric numeric option, wrong-typed
  `partition_by`/`catalog`) returns `RS-4007` with non-empty `next_steps`.
- **S11 — New test file `crates/rockstream-runtime/tests/
  durable_shuffle_error_code_tests.rs`.** One test per newly-split failure
  mode, each driving the real code path (not just constructing the error by
  hand) and asserting the specific new code appears and that all six codes
  are pairwise distinct: rate-limit exhaustion (`RS-3011`, via a fake
  `ObjectStore` that always returns a `429`-flavored error), generic
  object-store I/O failure (`RS-3012`, non-429 error), buffer-capacity
  exceeded (`RS-3013`, oversized frame — supersedes/extends the existing
  `test_durable_shuffle_buffer_limit`), footer serialization failure
  (`RS-3014` — not directly triggerable without a custom un-serializable
  type, so this sub-test documents the code's existence/next_steps text via
  `error_code::description`/`next_steps` rather than a live trigger, noted
  inline as such), footer deserialization failure (`RS-3015`, corrupt JSON
  footer bytes written directly to the `InMemory` store), corrupt/undersized
  footer (`RS-3016`, truncated object / bad footer-length bytes / footer
  claiming a length larger than the object).
- **S12 — Full workspace regression.** `cargo test --workspace` green;
  `scripts/check-error-codes.sh` and `scripts/check-error-codes.test.sh`
  green; existing `check-invariant-pairs.sh`/`check-path-coupling.sh`/
  `check-exit-criteria.sh` unaffected (no regression from the stricter
  check).
- **S13 — Documentation.** DESIGN.md §14.14's illustrative registry sample
  gets a few new lines for `RS-2021`, `RS-3011`–`RS-3017`, `RS-3501` (it is
  explicitly "illustrative; full list maintained in
  `crates/rockstream-types/src/error_code.rs`", so this is additive
  consistency, not a completeness requirement).

## 6. Durability Slices

**No new durability path.** `durable.rs`'s coalesced-shuffle object-store
writer/reader already exists (introduced in an earlier version, with its own
existing `test_durable_shuffle_writer_reader_roundtrip` and
`test_durable_shuffle_buffer_limit` unit tests using an `InMemory` store).
This version only refines *which error code* its existing failure branches
report — it adds no new commit/replay/checkpoint/compaction/WAL semantics
and touches no new durable state. Per the Phase 2 rule this only requires a
durability *test pair* (SlateDB LFS + MinIO) when a *new* durability path is
introduced; none is here, so none is owed. S11's unit tests (against the
already-covered `InMemory`/`ObjectStore` trait object) are the correct-sized
proof for a pure error-taxonomy change to an existing path.
