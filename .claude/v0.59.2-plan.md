# v0.59.2 Plan — True Automated End-to-End Release Qualification

## Scope and Boundary

v0.59.2 executes the second milestone of the v1 Release Qualification track (`NEW_ROADMAP.md` v0.59.2):
1. **Automated End-to-End Distributed Qualification Topology**:
   - Replace nominal high-level proofs and placeholder skips with one bounded, repeatable qualification suite.
   - Run a multi-node distributed topology: separate control nodes (HA cluster), frontier/compute workers, PostgreSQL wire gateway, real Kafka/Redpanda broker, PostgreSQL CDC instance, and MinIO S3 object store.
   - Fail-closed prerequisite check: missing Docker, images, credentials, backends, or test selection is an immediate failure, never a successful or skipped return.
2. **End-to-End Workload Ingestion & External Batch Oracle Auditor**:
   - Drive schema DDL, sources, views, and Kafka sink transactions through public pgwire and CLI interfaces.
   - Ingest inserts, updates, deletes, out-of-order timestamps, skewed keys, and high-cardinality state through real Kafka and PostgreSQL CDC paths.
   - Compare full result multisets, committed frontiers, and independently consumed Kafka sink egress with an external batch oracle (`rockstream-oracle`).
3. **Explicit Fault Injection & Recovery State Observation**:
   - Observe actual heartbeat loss, worker shard ownership reassignment, fencing epoch advancement, selected checkpoint recovery, source offset/LSN resume, view frontier advancement, sink transaction 2PC atomicity, and first correct post-recovery query.
   - Mutation self-test proves that each recovery observation and SLO check fails when mutated.
4. **Lifecycle, Disaster Recovery & Rolling Upgrade**:
   - Two-digest N→N+1 rolling upgrade under active ingestion load across distinct immutable images with differing digests.
   - Fail-closed rejection of incompatible storage formats (`RS-4019`).
   - Fresh-cluster disaster restore: destroy all original cluster-local and primary store state, restore from an independent export bucket into a freshly provisioned cluster, and assert bit-identical view reproduction.
   - Corrupt-export rejection (`RS-4020`).
5. **Declared-Hardware Performance Envelope & Raw Metric Separation**:
   - Measure throughput, latency (p50, p95, p99), RSS memory, open file descriptors, sockets, queue depth, state size, and object-store request counts.
   - All summary metrics are mathematically regenerated from raw time-series samples; checked-in baselines define targets only and cannot satisfy measured fields.
   - Produce a single SHA- and digest-bound `evidence-manifest.json` with 0 failed and 0 skipped mandatory scenarios.
6. **Pre-Release Formal Verification Relaxed-Bounds Sweep**:
   - Re-run the relaxed-bounds sweep across all M1–M7 FizzBee models against the candidate SHA.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
