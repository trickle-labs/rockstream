### Slice 1 — `docs/pgwire-conformance.md`

Create `docs/pgwire-conformance.md` enumerating every supported PostgreSQL wire
message type (both frontend → backend and backend → frontend) and every SQL
statement class, each with a linked proof test. Sections:

- **Authentication messages**: AuthenticationSASL, AuthenticationSASLContinue,
  AuthenticationSASLFinal, AuthenticationMD5Password, AuthenticationOk
- **Session startup**: StartupMessage, SSLRequest, ParameterStatus, BackendKeyData,
  ReadyForQuery
- **Simple Query**: Query, CommandComplete, DataRow, RowDescription, EmptyQueryResponse
- **Extended Query**: Parse, Bind, Execute, Describe, Close, Flush, Sync,
  ParseComplete, BindComplete, CloseComplete, PortalSuspended, NoData,
  ParameterDescription
- **Copy**: CopyInResponse, CopyOutResponse, CopyData, CopyDone, CopyFail
- **Async / Notifications**: NotificationResponse, NoticeResponse
- **Errors**: ErrorResponse
- **Cancellation**: CancelRequest
- **Transaction**: BEGIN, COMMIT, ROLLBACK, SAVEPOINT, RELEASE SAVEPOINT,
  ROLLBACK TO SAVEPOINT (status bytes `I`/`T`/`E`)
- **Named Cursors**: DECLARE CURSOR FOR, FETCH, CLOSE cursor
- **Statement classes**: SELECT, INSERT, UPDATE, DELETE, CREATE TABLE, CREATE VIEW,
  CREATE MATERIALIZED VIEW, REFRESH MATERIALIZED VIEW, LISTEN, NOTIFY, UNLISTEN,
  SUBSCRIBE, SET, SHOW

For each entry: message name / statement, direction, linked test (file::function).

Add unit test `test_conformance_doc_has_linked_tests` in a new
`tests/conformance_doc_tests.rs` that reads `docs/pgwire-conformance.md`, extracts
every `file::function` link, and asserts the named function exists in the test
corpus (grep-based check).

**Green gate**: `test_conformance_doc_has_linked_tests` passes.

### Slice 2 — Golden Wire-Byte Snapshots (`tests/golden_wire_tests.rs`)

Create `crates/rockstream-gateway/tests/goldens/` directory with checked-in binary
blobs and `tests/golden_wire_tests.rs` with ≥8 golden exchanges:

| Golden | Blob file | What it captures |
|---|---|---|
| `test_golden_wire_startup_scram` | `goldens/startup_scram.bin` | StartupMessage → AuthenticationSASL → SASL exchange → AuthenticationOk → ParameterStatus×N → BackendKeyData → ReadyForQuery |
| `test_golden_wire_simple_query` | `goldens/simple_query.bin` | Query("SELECT 1") → RowDescription → DataRow → CommandComplete → ReadyForQuery |
| `test_golden_wire_extended_query` | `goldens/extended_query.bin` | Parse+Bind+Execute+Sync → ParseComplete+BindComplete+DataRow+CommandComplete+ReadyForQuery |
| `test_golden_wire_error_flow` | `goldens/error_flow.bin` | Query with syntax error → ErrorResponse → ReadyForQuery |
| `test_golden_wire_transaction` | `goldens/transaction.bin` | BEGIN→CommandComplete / INSERT→CommandComplete / COMMIT→CommandComplete; status byte transitions |
| `test_golden_wire_copy_in` | `goldens/copy_in.bin` | COPY t FROM STDIN → CopyInResponse → CopyData rows → CopyDone → CommandComplete |
| `test_golden_wire_listen_notify` | `goldens/listen_notify.bin` | LISTEN ch → CommandComplete / NOTIFY ch → CommandComplete / NotificationResponse delivery |
| `test_golden_wire_cancel` | `goldens/cancel.bin` | CancelRequest → no response / next ReadyForQuery |

Each test:
1. Runs an in-process gateway (no Docker)
2. Captures the full server→client byte stream with a `CaptureSink` wrapper
3. On first run (when golden absent): writes the blob; on subsequent runs: asserts
   byte-exact equality against the checked-in blob
4. Uses a `--bless` env var pattern: `BLESS_GOLDENS=1 cargo test` regenerates blobs

**Green gate**: all 8 golden tests pass; goldens are checked in to the repo.

### Slice 4 — Driver Conformance Smoke-Suite Harness (`tests/driver_matrix_tests.rs`)

Create `tests/driver_matrix_tests.rs` defining the nine conformance smoke
tests, all gated by `#[cfg(feature = "testcontainers")]`. The file contains:

- A `SmokeSuite` helper that starts an in-process RockStream gateway on a random
  port and provides the DSN to the container under test.
- Nine `#[tokio::test]` functions (one per driver).
- Each test runs the same 9-check conformance suite via a container:
  1. **connect+SCRAM auth** — plain connect with MD5 disabled; assert auth succeeds
  2. **simple query** — `SELECT 42` via the simple query protocol
  3. **extended query** — prepared `SELECT $1::int + $2::int` with typed parameters
  4. **typed params** — bind `TEXT`, `INT4`, `FLOAT8`, `BOOL`, `TIMESTAMP`
  5. **transactions + savepoints** — BEGIN; INSERT; SAVEPOINT s1; INSERT; ROLLBACK TO s1; COMMIT; verify final state
  6. **named cursors** — DECLARE c1 CURSOR FOR SELECT ...; FETCH 10 FROM c1; CLOSE c1
  7. **COPY** — COPY t FROM STDIN for 100 rows; verify COUNT(*)
  8. **LISTEN/NOTIFY** — LISTEN ch; NOTIFY ch 'payload'; assert notification received
  9. **CancelRequest** — issue a slow query; send CancelRequest; assert cancellation

**Slice 4a — psql 14 + psql 16 + libpq**

Tests: `test_psql14_smoke`, `test_psql16_smoke`, `test_libpq_smoke`

Use `GenericImage::new("postgres", "14-alpine")` / `"16-alpine"` for the client
tools. Run a shell script inside the container that drives `psql` against the
in-process gateway.

**Green gate**: all three psql/libpq tests pass under `--features testcontainers`.

### Slice 5 — Reference Application: Prisma Variant (`tests/reference_app/prisma/`)

Directory structure:
```
crates/rockstream-gateway/tests/reference_app/prisma/
  schema.prisma          — Customer, Order, OrderItem, SalesSummary (MV)
  migrations/            — Prisma migration files
  seed.js                — Seeds 100 customers, 1000 orders
  app.js                 — Full application: migrations, seed, MV read,
                           SUBSCRIBE feed, transactional workflow, pooled conns
  Dockerfile             — FROM node:20-alpine; COPY .; RUN npm install
```

`schema.prisma` defines:
- `Customer`, `Order`, `OrderItem` tables
- `SalesSummary` as a raw-SQL materialized view (via `prisma db execute`)
- `EventLog` for LISTEN/NOTIFY feed

`app.js` workflow:
1. `prisma migrate deploy` — runs all migrations
2. Seed: insert 100 customers, 1000 orders in a transaction with a SAVEPOINT mid-batch
3. Read materialized view: `SELECT * FROM SalesSummary LIMIT 5`
4. Subscribe/Listen: `LISTEN order_events`; insert an order; assert notification received
5. Transactional workflow: BEGIN; INSERT Customer; SAVEPOINT s1; INSERT Order (bad FK);
   ROLLBACK TO s1; INSERT Order (good FK); COMMIT; verify final state
6. Pooled: open 5 concurrent connections; each runs SELECT COUNT(*)

TestContainers test `test_prisma_reference_app` in
`tests/reference_app_tests.rs`:
1. Start in-process RockStream gateway on random port
2. Build + run the Prisma Dockerfile against gateway DSN
3. Assert container exits 0

**Green gate**: `test_prisma_reference_app` passes under `--features testcontainers`.
