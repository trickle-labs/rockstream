# v0.51.18 Plan — Arithmetic Overflow Safety in Release Builds

## Contract

**Focus:** Arithmetic Overflow Safety in Release Builds.

**Scope:** Enable release overflow checks; benchmark hot commit/ingest cost;
make epoch, connector LSN/offset, checkpoint-index, and hot-ingest quota
arithmetic explicit and overflow-safe with dedicated `RS-XXXX` failures; add
numeric-boundary property tests.

**Proof assertions:**

1. `rtk cargo test --workspace --release` passes with release overflow checks.
2. The committed Criterion baseline at
   `crates/rockstream-runtime/benches/baseline/v0.51-runtime.json` documents the
   checked-ingest measurement and accepted regression threshold against the
   prior v0.51.18 measurement.
3. A proptest suite drives all four counter classes to `u32::MAX` or
   `u64::MAX - delta` and proves a dedicated RS rejection or benign no-op—never
   wrapping, panicking, or leaking admission credits.

**Backends:** Unit, LFS. No SQL command, parser, wire request, response encoder,
new durability path, or distributed-coordination path is in scope.

## Prerequisite and deferred-item audit

`sign-offs/v0.51.17.md` is complete and explicitly confirms that no item was
deferred. The prior-sign-off audit found no overlapping deferred, postponed, or
out-of-scope item. Historical v0.51.3/v0.50 markers concern unrelated IVM work;
the CLI drain stub and gateway catalog placeholders are also out of scope.

The counter-path audit found no overlapping TODO/stub/placeholder. It did find
an undocumented overlapping gap: `CheckpointCoordinator::begin_checkpoint`
acquires credits before `CheckpointId::checked_next`; exhaustion returns
`RS-3604` without releasing those credits. This is **MUST IMPLEMENT** in this
version: move exhaustion checking before credit acquisition or release every
acquired credit, then prove the exact post-error credit state. A stale
`# Panics` comment and a nonmonotone-epoch assertion in `source_epoch.rs` are
also reviewed in the connector slice; no uncontrolled panic may remain on the
counter API's reachable error path.

Although `sign-offs/v0.51.18.md` currently marks the version done, it does not
name the promised boundary-property tests, map exact RS outputs, supply the LFS
proof, or compare the benchmark with a prior baseline and accepted percentage.
Those documentary and proof gaps overlap this version and are **MUST IMPLEMENT**
before a valid sign-off; they are not deferrable.
