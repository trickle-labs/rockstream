# v0.51.18 Plan — Arithmetic Overflow Safety in Release Builds

## Contract

**Focus:** Arithmetic Overflow Safety in Release Builds.

**Scope:** Enable release overflow checks; measure the hot commit/ingest cost using
Criterion; make epoch numbers, connector LSN/offset tokens, checkpoint indices, and
hot-ingest admission byte/row quotas explicit overflow-safe operations with dedicated
`RS-XXXX` errors; add numeric-boundary property tests.

**Proof assertions:**

1. `cargo test --workspace --release` succeeds with `overflow-checks = true`.
2. Criterion emits a committed baseline and a documented acceptance percentage for
   the hot commit/ingest path.
3. Boundary tests drive each counter to `u32::MAX` or `u64::MAX - delta`; every
   outcome is a dedicated RS rejection or benign no-op, never wrapping or panicking.

**Backends:** Unit, LFS. No SQL or wire surface is in scope.
