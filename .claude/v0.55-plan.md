# v0.55 Plan — Internal mTLS & Node Identity

## Scope and Non-Negotiable Invariants

This version ships the internal node-identity and mutual TLS (mTLS) substrate for RockStream, closing the internal implicit-trust security gap identified in the `<=v0.42.3` review and required as a prerequisite for v0.55.1 secrets management and production readiness (DESIGN.md §3.1, §14.18; [ROCKSTREAM_PROJECT_FOCUS.md](ROCKSTREAM_PROJECT_FOCUS.md) §5.3).

1. **Internal mTLS on Every Internal Channel**:
   - `control ↔ worker`: TCP control plane framing for worker registration, heartbeats, shard leases, drain, and migration commands wrapped in TLS with mutual certificate verification.
   - `worker ↔ worker`: gRPC shuffle streams and frame transfer (`ShuffleServer` and `ShuffleClientPool`) wrapped in TLS with mutual certificate verification.
   - `CLI ↔ control-plane`: CLI control transport wired into the v0.53 identity-pluggable transport seam with client certificate presentation.
2. **Node Identity**:
   - Node identity (`NodeRole`, `node_id`, `cluster_id`) derived directly from the presented client certificate (X.509 Common Name / SAN).
   - Strict verification: untrusted CA, expired certificate, malformed identity, or identity mismatch against registered worker ID is rejected immediately.
3. **Audited Denial for Every Rejected Peer**:
   - Any peer connection presenting an invalid, expired, untrusted, or absent certificate is rejected immediately with an audited denial (`security.internal_mtls_denied`) and an actionable `RS-2410`, `RS-2411`, or `RS-2412` error code, and is never granted leases or allowed to process shard data.
4. **Dynamic Certificate Issuance & Rotation Under Load**:
   - Dynamic reloading of certificates and keys via atomic configuration reloader without process restart.
   - Live certificate rotation proven under load on a 3-worker cluster with zero epoch loss, zero pipeline restarts, and no window in which an authenticated peer is spuriously refused.
5. **CLI Transport Seam Integrity**:
   - The v0.53 CLI reaches the control plane with a client certificate and is refused without one when internal mTLS is enabled, with zero changes to its user-facing command surface.
6. **One Binary & Durability**:
   - Single `rockstream` binary remains runnable across all roles.
   - No SlateDB range deletions. Durability verified across SlateDB LFS and MinIO (TestContainers).
   - Coordination verified with seeded `SimRuntime` tests with `buggify!()` annotations.

## Vertical Slices

### Slice 1: Node Identity, Internal TLS Types, Error Codes & PKI Test Utilities
- **Crates**: `rockstream-types`, `rockstream-test-support`

## Test Commitments & Oracle Invariants

1. **Identity & Auth Invariance**:
   - $\forall c \in \text{Connections}$, $c$ is admitted $\iff$ $\text{verify\_cert}(c) = \text{Ok}(\text{identity}) \land \text{identity.matches}(c.\text{payload})$.
   - $\forall c \in \text{Connections}$, $\neg \text{admitted}(c) \implies \text{leases\_granted}(c) = 0 \land \text{data\_processed}(c) = 0 \land \exists e \in \text{AuditLog}: e.\text{action} = \text{"security.internal\_mtls\_denied"}$.
2. **Rotation Invariance Under Load**:
   - $\text{epochs\_lost}(\text{rotation\_window}) = 0$.
   - $\text{pipeline\_restarts}(\text{rotation\_window}) = 0$.
   - $\text{spurious\_rejections}(\text{rotation\_window}) = 0$.
3. **Transport Seam Invariance**:
   - $\forall \text{cmd} \in \text{CliCommands}$, $\text{output}(\text{cmd}_{\text{plaintext}}) \equiv \text{output}(\text{cmd}_{\text{mtls}})$.
4. **SlateDB Range Deletion Prohibition**:
   - Zero code paths use SlateDB range deletion; cleanup uses scan-and-delete.
