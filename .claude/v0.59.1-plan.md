# v0.59.1 Plan — Evidence Integrity & Honest Release State

## Scope and Boundary

v0.59.1 executes the first milestone of the v1 Release Qualification track (`NEW_ROADMAP.md` v0.59.1):
1. **Public Reclassification & Sign-off Amendment**:
   - Reclassify v0.59 publicly as an engineering-complete technical preview.
   - Separate implementation, short-CI, security-review, artifact-publication, and final-authorization status in project records.
2. **Unified Candidate Identity**:
   - Establish one immutable candidate identity across the workspace package, `rockstream --version`, image labels, support bundles, build-info metrics (`rockstream_build_info`), documentation, manifests, and tags.
   - Embed the semantic version, commit SHA, build timestamp (RFC 3339 / ISO 8601), compiler version, Cargo lockfile digest (SHA-256), and enabled Cargo features.
3. **Release History & Governance Protection**:
   - Enforce branch and tag protection policies: required checks, no force pushes, signed release tags.
   - Require ownership review (`.github/CODEOWNERS`) for release workflows, formal specifications (`formal/`), security policy (`SECURITY.md`, threat models), and capability contracts (`capabilities.toml`).
4. **Machine-Readable Evidence Manifest & RC Validator Mutation Suite**:
   - Replace checked-in self-attestation with a machine-readable evidence manifest (`evidence-manifest.json`).
   - Manifest binds candidate SHA, artifact digests (SHA-256), workflow run ID, environment and workload digests, test pass/fail/skip counts, raw metrics, and regenerated summaries.
   - RC validator mutation suite enforces: rejection of changed SHA or artifact digest, rejection of skipped mandatory prerequisites, rejection of missing raw data, and rejection of summaries that cannot be regenerated from raw artifacts. Checked-in baselines define targets only and cannot satisfy measured-result fields.
   - Branch and tag policy is machine-verified before release authorization.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

    - `workflow_run`: ID, URL, trigger event, runner environment
