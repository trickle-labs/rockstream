# v0.60 Plan — Product Truth

## Scope and Boundary

Roadmap reference (`ROADMAP.md` §6: `v0.60 — Product Truth`):
> **Focus**: Remove the distinction between what RockStream appears to do and what it actually does. This version is intentionally subtractive. No substantial new database functionality should be added.
> **User outcome**: When a production `rockstream` command reports something, the result comes from a live RockStream server, durable RockStream state, or an explicitly labeled demo environment. Unavailable functionality fails rather than returning plausible sample data.
> **Required Proof**:
> 1. Start no RockStream services.
> 2. Run `rockstream status`.
> 3. Command fails nonzero.
> 4. No worker/shard/status data is printed.
> 5. Start a one-node RockStream instance.
> 6. Run `rockstream status`.
> 7. Returned values correspond to the live node.
> 8. Shut the node down.
> 9. Run the same command.
> 10. It fails rather than retaining or fabricating previous values.
> A repository search gate should fail CI if known fixture constructors become reachable from production CLI dispatch.

v0.60 establishes product truthfulness across the entire CLI surface and client architecture:

1. **Client Interface Separation (`Api` Traits vs Clients)**:
   - Introduce internal API traits: `CatalogApi`, `TopologyApi`, `OperationApi`, and `StorageAdminApi` in `crates/rockstream-cli/src/transport.rs` (or a dedicated client module).
   - Implement production remote clients: `RemoteCatalogClient`, `RemoteTopologyClient`, `RemoteOperationClient` that connect exclusively to live endpoints via HTTP/TCP/gRPC/pgwire with zero fallback data.
   - Separate test mock implementations: `MockCatalogClient`, `MockTopologyClient`, `MockOperationClient` into `crates/rockstream-test-support` (and `#[cfg(test)]` harness), strictly prohibiting their instantiation in production CLI binaries.
   - Move fixture/default constructors (`with_defaults()`, `with_mock_data()`, etc.) out of production crates to `rockstream-test-support`.

2. **Elimination of Predefined Topology Responses & Production Mock Fallbacks**:
   - Eliminate all production fallbacks in `ControlClient`, `CatalogClient`, and CLI handlers that fabricate workers, shards, resource quotas, leader identities, migration duration, cluster size, or view definitions when `control_addr` is `None` or connection fails.
   - A failed or missing control connection fails closed with error code `RS-0004`:
     ```text
     RS-0004: cannot reach RockStream control service at 127.0.0.1:9200

     Next steps:
       - verify `rockstream start` is running
       - check `rockstream config print-effective`
       - verify the configured control endpoint
     ```

3. **Separation and Explicit Labeling of Demo Behavior**:
   - Distinct `rockstream demo` / `rockstream demo orders` commands with unambiguous self-identification on every response:
     ```text
     Mode: demo
     Durability: ephemeral
     Topology: simulated
     ```
   - Ensure demo mode and simulated state can never be triggered accidentally from production commands (`rockstream status`, `rockstream view list`, `rockstream shard list`, etc.).

4. **CLI Command Hierarchy Simplification**:
   - Establish target top-level hierarchy:
     - `rockstream start`
     - `rockstream shell`
     - `rockstream query`
     - `rockstream status`
     - `rockstream project ...`
     - `rockstream config ...`
     - `rockstream admin ...` (`worker drain`, `shard migration`, `Raft inspection`, `checkpoint administration`)
     - `rockstream dev ...` (`manifest`, `qualify`, `debug`, `simulation helpers`, `offline SQL compilation`, `evidence generation`)
     - `rockstream demo ...`
   - Relocate specialized/developer commands under `rockstream dev`.
   - Relocate operator/cluster administration commands under `rockstream admin`.

5. **Typed CLI Values via Clap Enums**:
   - Replace stringly-typed CLI options with type-safe Clap enums:
     - `Role`: `All`, `Gateway`, `Worker`, `Control` (reusing domain definitions from `rockstream-types`).
     - `AuthMode`: `Off`, `Scram`, `Md5`, `Oidc`, `Mtls`.
     - Align other CLI arguments with typed domain structures rather than raw strings.

6. **Repository Anti-Fixture Gate (`scripts/check-no-fixture-dispatch.sh`)**:
   - Implement an automated CI gate verifying that no fixture constructors (`with_defaults`, `with_mock_data`, `MockCatalogClient`, `MockTopologyClient`) are reachable from production CLI dispatch in `crates/rockstream-cli/src/main.rs`.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters, asserted by test.
- Unbounded in-memory accumulation is never acceptable: all buffers, queues, metrics batches, and sample streams have named bounds and metrics.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass; no `--no-verify`. Fix root causes.
- Make only changes this version requires. Subtractive milestone: no new SQL, no new connectors, no new operators.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

### Explicitly Out of Scope

- Durable catalog (scheduled for v0.63).
- New SQL features or dialect additions (scheduled for v0.64 SQL execution integrity).
- New connector families beyond PostgreSQL CDC and Kafka (governed by Extensibility Policy).
- Distributed performance work and tuning (preserved from frozen v0.59.24 baselines).
- New authentication modes (scheduled for v0.73 Security).
- Future research queue programs: richer type semantics, temporal analytics, recursion, serializable transactions, multi-region execution (moved to research queue per `ROADMAP.md` §23).
