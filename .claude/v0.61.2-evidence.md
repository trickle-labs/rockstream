## 2. Exit Criteria Verification Details

### V0612-01: Old/Final Row Emission & Unchanged Result Suppression
- **Requirement**: SUM and COUNT emit exactly the old negative row and final positive row for a changed group, and no rows for unchanged output.
- **Evidence**:
  - `delta_native_aggregate_tests::test_v0612_repeated_updates_emit_old_and_final_only`: Group initialized to `(sum=10, count=1)`. Receives updates `(-10, +1)` and `(+40, +1)` in the same epoch. Emits exactly `[(k=1, sum=10, count=1, -1), (k=1, sum=40, count=1, +1)]` (2 rows instead of 4 intermediate rows).
  - `delta_native_aggregate_tests::test_v0612_unchanged_aggregate_emits_no_delta`: Group initialized to `(sum=10, count=1)`. Receives offsetting updates `(5, +1)` and `(5, -1)`. Net delta is 0; emits an empty Z-set (`num_rows() == 0`), 0 dirty keys, and 0 state mutations.
  - `delta_native_aggregate_tests::test_v0612_multi_value_cancellation_emits_no_delta`: Group receives multiple cancelling insertions and retractions within the epoch. Output Z-set has 0 rows and key is not marked dirty.
- **Command Output**:

### V0612-03: Staged Validation & Checked Arithmetic Atomicity
- **Requirement**: Overflow, invalid input, and accumulator exhaustion leave the whole epoch uncommitted and previous state intact.
- **Evidence**:
  - `delta_native_aggregate_tests::test_v0612_multiplication_overflow_atomicity`: Row 2 in a batch triggers `v.checked_mul(w)` overflow with `i64::MAX * 2`. Staging returns `Err(OpError::AggregateOverflow)`. Verifies earlier row 1 was not committed to operator state.
  - `delta_native_aggregate_tests::test_v0612_sum_overflow_atomicity`: Group total sum addition overflows `i64::MAX`. Transition validation rejects batch; internal `AggState` remains unchanged.
  - `delta_native_aggregate_tests::test_v0612_invalid_multiplicity_atomicity`: Group count drops below 0 (`old_count + w < 0`). Staging rejects with `OpError::InvalidMultiplicity`; previous state remains intact.
  - `delta_native_aggregate_tests::test_v0612_malformed_schema_atomicity`: Batch with missing columns returns `OpError::ColumnOutOfBounds`; state remains unmodified.
