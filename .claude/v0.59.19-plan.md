# v0.59.19 Plan — SQL Semantics, PostgreSQL Compatibility & System Limits

## Scope and Boundary

Roadmap row (`NEW_ROADMAP.md:1843`): *"Define and publish the exact v1 SQL contract before type-completeness implementation: numeric precision/scale, overflow and casts, NULL propagation and three-valued logic, duplicate rows, unmatched DML, transaction visibility, timestamp precision/time zones/DST, identifier folding, deterministic collation and string ordering, text and temporal key behavior, prepared-statement arrays and `ANY($1)`, and PostgreSQL compatibility boundaries. Select the versioned `rockstream_binary_v1` collation, whose byte ordering is explicitly defined and independent of host libc and locale; define the admitted decimal bounds and temporal time-zone policy. Generate `docs/sql-semantics.md` and `docs/sql-type-matrix.md` from the authoritative `contracts/sql-type-matrix.toml` contributor, and generate `docs/limits.md` from authoritative limit metadata. Pin PostgreSQL 18.0 as the differential reference using `postgres:18.0@sha256:41fc5342eefba6cc2ccda736aaf034bbbb7c3df0fdb81516eba1ba33f360162c` in that contract source, with architecture-specific digests recorded for each tested platform."* Proof: *"Every admitted semantic has executable conformance coverage against the batch oracle and the pinned PostgreSQL reference; every published limit comes from runtime/configuration metadata or an explicitly measured bound; exceeding a bound fails with its documented `RS-XXXX` code; generated documents, manifest contribution, and the checked-in type matrix are drift-checked; unsupported locale-sensitive collations, unadmitted temporal keys, and floating-point equality joins fail clearly rather than producing an unverified result."* Backends: `Unit, LFS, TC`. Dependencies: `v0.59.13, v0.59.17` (`NEW_ROADMAP.md:74`).

v0.59.19 defines, standardizes, and freezes the exact v1 SQL semantics and system boundaries before the type-completeness implementations in v0.59.20:

1. **Authoritative SQL Contract & Pinned Reference (`contracts/sql-type-matrix.toml`)**:
   - Pin PostgreSQL 18.0 as the differential reference standard:
     - Canonical image: `postgres:18.0@sha256:41fc5342eefba6cc2ccda736aaf034bbbb7c3df0fdb81516eba1ba33f360162c`.
     - Platform-specific digests recorded for `linux/amd64` and `linux/arm64`.
   - Formalize numeric precision/scale bounds (`DECIMAL(p,s)` where $1 \le p \le 38, 0 \le s \le p$), overflow behavior (fail closed with `RS-1016`), and explicit cast conversion matrix.
   - Specify ANSI three-valued logic (`TRUE`, `FALSE`, `UNKNOWN`), `NULL` propagation, `IS [NOT] NULL`, `COALESCE`, and `NULLS FIRST`/`NULLS LAST` sorting semantics.
   - Define multiset bag semantics under IVM, duplicate row preservation, retraction weights, and unmatched DML behavior (`UPDATE`/`DELETE` returning empty sets with 0 rows affected without error).
   - Standardize temporal precision (microsecond resolution, 6 fractional digits), time-zone offset parsing, UTC normalization policy, and DST transition behavior.
   - Enforce deterministic identifier folding (unquoted identifiers folded to lowercase, double-quoted identifiers preserved verbatim).
   - Select the versioned `rockstream_binary_v1` collation with explicitly defined byte-wise lexicographical UTF-8 ordering independent of OS/libc locale.
   - Specify prepared statement 1D array parameter binding and scalar-to-array membership comparison `col = ANY($1)` / `col IN (SELECT UNNEST($1))`.

2. **Operation-Specific Capability Cell Split (`NEW_ROADMAP.md:4030`, `capabilities.toml`)**:
   - Decompose broad umbrella capabilities (`language.aggregates`, `language.relational-operators`, `language.analytics-time`) into fine-grained operation-specific cells with honest tiers, reachabilities, and proof targets:
     - `language.aggregates.exact` (`Core`), `language.aggregates.text` (`Supported`), `language.aggregates.float` (`Experimental`).
     - `language.joins.equi-integer` (`Core`), `language.joins.equi-text` (`Supported`), `language.joins.cross` (`Experimental`), `language.joins.float` (`Unsupported`).
     - `language.window.ranking` (`Supported`), `language.window.tumble` (`Core`), `language.window.slide` (`Core`), `language.window.temporal-timestamp` (`Experimental`).
   - Update `scripts/check-capability-contract.py` to validate split capability declarations, proof levels, and reachability.

3. **System Limits & Measured Bounds Catalog (`docs/limits.md`)**:
   - Consolidate all architectural, protocol, engine, and query limits from runtime constants into authoritative metadata.
   - Define exact threshold values, enforcement sites, metrics, and fail-closed `RS-XXXX` rejection codes for:
     - Result set size limit (`max_in_flight_rows` = 10,000 -> `RS-2040`).
     - Per-connection memory limit (64 MiB -> `RS-2053`).
     - Server-wide connection limit (`max_connections` = 100 -> `RS-2055`).
     - Prepared statement cache limit (100 per connection -> `RS-2600`).
     - Portal limit (50 per connection -> `RS-2601`).
     - Cursor limit (64 per connection -> `RS-2052`).
     - Identifier length limit (63 bytes -> `RS-1012`).
     - Numeric precision limit (38 digits -> `RS-1016`).
     - View dependency DAG depth limit (16 levels -> `RS-1011`).

4. **Single-Source Documentation Generation (`rockstream-docgen`)**:
   - Implement docgen contributors for:
     - `docs/sql-semantics.md`: Complete SQL semantics, three-valued logic, time zones, collation, and PostgreSQL compatibility reference.
     - `docs/sql-type-matrix.md`: Markdown rendering of the exact type/operation matrix generated directly from `contracts/sql-type-matrix.toml`.
     - `docs/limits.md`: Generated system limits and bounds reference from authoritative metadata.
   - Integrate with `scripts/check-product-surface.py` and `scripts/check-documentation.sh` for strict zero-drift enforcement.

5. **Differential & Conformance Verification (`rockstream-oracle`)**:
   - Implement executable conformance suites comparing RockStream against the pinned PostgreSQL 18.0 reference container for all admitted semantics.
   - Implement fail-closed rejection tests verifying that unsupported features (locale-sensitive collations, floating-point equality joins, unadmitted temporal keys) fail immediately with documented `RS-XXXX` codes rather than silently producing incorrect results.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable: all buffers, limit checks, parameter arrays, and diagnostic occurrences have named bounds and metrics.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass; no `--no-verify`. Fix root causes.
- Make only changes this version requires.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

- No deployment profile / Helm / OCI packaging matrix — that is `v0.59.22` (`Supported Platforms & Deployment Profiles`).
- No capacity estimator calibration or threshold signing — that is `v0.59.23` (`Capacity Planning & Estimator Calibration`).

### Matrix A: Exact SQL Semantics & PostgreSQL Compatibility Matrix

| Semantic Domain | RockStream v1 Specification | PostgreSQL 18.0 Equivalence | Non-Compliance / Rejection Code | Conformance Target |
|---|---|---|---|---|
| Numeric / Decimal Bounds | `DECIMAL(p, s)`: $1 \le p \le 38$, $0 \le s \le p$. Signed fixed-point. | Exact match with standard SQL `NUMERIC(p, s)`. | Scale > precision or $p > 38$ -> `RS-1012`. Arithmetic overflow -> `RS-1016`. | `sql_semantics_numeric_tests::test_decimal_precision_overflow` |
| NULL Logic & 3-Valued Logic | ANSI three-valued logic (`TRUE`, `FALSE`, `UNKNOWN`). `NULL` is not equal to `NULL`. `IS NOT DISTINCT FROM` treats `NULL` == `NULL`. | Byte/row identical. | Misleading boolean fallback prohibited. | `sql_semantics_null_tests::test_three_valued_logic_truth_tables` |
| Duplicate Rows / Bag Semantics | Bag/multiset semantics under IVM with positive and negative weights. Monotone view frontier. | Multiset equivalent under `SELECT` / `UNION ALL`. | Retraction underflow -> `RS-1017`. | `sql_semantics_multiset_tests::test_duplicate_rows_and_retractions` |
| Unmatched DML | `UPDATE` or `DELETE` matching 0 rows succeeds with `UPDATE 0` / `DELETE 0`. | Byte-identical command tag and 0 rows affected. | Non-existent table -> `RS-2003`. | `sql_semantics_dml_tests::test_unmatched_dml_empty_result` |
| Identifier Folding | Unquoted identifiers folded to ASCII lowercase. Quoted `"Identifier"` preserves exact case. | Exact PostgreSQL folding equivalence. | Identifier byte length > 63 -> `RS-1012`. | `sql_semantics_identifier_tests::test_case_folding_and_quoting` |
| Collation & String Ordering | Versioned `rockstream_binary_v1`: raw UTF-8 byte-wise sorting independent of host libc/locale. | Equivalent to PostgreSQL `COLLATE "C"` / `"POSIX"`. | Locale-dependent collations (e.g. `COLLATE "en_US"`) rejected with `RS-1013`. | `sql_semantics_collation_tests::test_binary_v1_collation_ordering` |
| Temporal & Time Zones | Microsecond precision (`TIMESTAMP(6)`), ISO 8601 parsing, UTC internal normalization. | Timestamp arithmetic & UTC storage equivalent. | Unparseable timestamp -> `RS-1012`. | `sql_semantics_temporal_tests::test_timestamp_utc_normalization` |
| Array Parameters & `ANY($1)` | 1D typed arrays in prepared statements. `val = ANY($1)` evaluates scalar in array. | Exact `ANY(ARRAY[...])` semantics. | Multidimensional arrays in `ANY($1)` rejected with `RS-1012`. | `sql_semantics_array_param_tests::test_prepared_any_array_binding` |
