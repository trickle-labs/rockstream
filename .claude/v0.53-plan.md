# v0.53 Plan — Operator CLI: Substrate & Read-Only Inspection Surface

## Scope and Non-Negotiable Invariants

This version implements the operator CLI substrate and complete read-only inspection command surface, along with the SQL-native `SHOW VIEW STATUS` and `SHOW RESOURCE USAGE` wire equivalents. All roles and commands are built into the single `rockstream` binary.

- **One binary, one CLI, one config**: All subcommands are built into the `rockstream` binary using `clap`. `main` remains runnable through it across all roles.
- **Identity-pluggable transport seam**: The CLI communicates through a unified client transport trait (`CliTransport` / `ClientTransport`) capable of querying the control plane, catalog, and storage layers. The transport encapsulates authentication credentials (`ClientIdentity`) so v0.55's internal mTLS client certificates can plug in without redesigning the command surface.
- **Output contract & golden test harness**: Every inspection subcommand supports human-readable formatted text by default and structured `--json` output for automation. All `--json` outputs validate against checked-in JSON schemas, and every subcommand is backed by golden-output tests.
- **Read-only commands**:
  - `rockstream view {list,show,status}`
  - `rockstream source {list,show}`
  - `rockstream schema {list,show}`
  - `rockstream workload {list,show}`
  - `rockstream cluster {status,quotas}` and `rockstream cluster workers {list,status}`
  - `rockstream shard list`
  - `rockstream checkpoint list`
  - `rockstream resource {usage,usage --workload=<name>,cluster}`
  - `rockstream schema-evolution {status,history}`
  - `rockstream audit {tail,query}`
  - `rockstream explain <view> [--estimate]`
  - `rockstream sql "<query>"` (parse, lower to PlanNode IR, and run `EXPLAIN INCREMENTAL` without deploying).
- **PGWire SQL equivalents**: `SHOW VIEW STATUS` (global, per-view, per-namespace) and `SHOW RESOURCE USAGE` (global, per-workload, cluster-wide) are fully reachable and wire-compatible over PostgreSQL wire protocol.
- **Non-perturbing inspection**: Read-only commands and `SHOW` queries access catalog metadata and storage via read-only snapshot readers (`DbReader`), taking no pipeline locks and causing zero freshness-lag regression on active pipelines.
- **Bounded resources**: All CLI output, log tailing, and status collections use bounded buffers (`CLI_OUTPUT_MAX_ROWS`, `AUDIT_TAIL_MAX_EVENTS`) with fill metrics and explicit truncation/pagination, preventing unbounded in-memory accumulation.
- **No SlateDB range deletion**: Inspection and state reading never rely on range deletions.
- **Security review commissioning**: The independent third-party security review for v0.55.2 remediation is formally commissioned at the start of this version for lead time.

## Vertical Slices

1. **Slice 1 — Transport Seam & Identity-Pluggable Substrate**:
   - Define `CliTransport` trait in `crates/rockstream-cli/src/transport.rs` with `ClientIdentity` representation.
   - Implement `ControlClient`, `CatalogClient`, and `StorageClient` abstractions over local/remote transports.
   - Implement `--json` serialization and output contract formatting in `crates/rockstream-cli/src/output.rs`.
   - *Test*: `test_cli_transport_substrate_and_schema_validation`.

2. **Slice 2 — Catalog Read-Only Commands (`view`, `source`, `schema`, `workload`)**:
   - Add CLI subcommands for `view {list,show,status}`, `source {list,show}`, `schema {list,show}`, `workload {list,show}` in `main.rs` and `lib.rs`.
   - Wire each subcommand to query catalog structures and format text / JSON output.
   - *Tests*: `test_cli_catalog_commands_text_and_json_golden`, `test_cli_view_show_not_found_rs1001`.

3. **Slice 3 — Cluster, Worker, Shard & Checkpoint Inspection**:
   - Add CLI subcommands for `cluster {status,quotas}`, `cluster workers {list,status}`, `shard list`, and `checkpoint list`.
   - Expose active workers, AZ, health, owned shard ranges, and checkpoint manifest histories.
   - *Tests*: `test_cli_cluster_inspection_commands_golden`, `test_cli_shard_and_checkpoint_list_golden`.

4. **Slice 4 — Resource Usage, Schema Evolution & Audit Commands**:
   - Add CLI subcommands for `resource {usage,usage --workload=<name>,cluster}`, `schema-evolution {status,history}`, and `audit {tail,query}`.
   - Enforce bounded buffers on audit log reads (`AUDIT_TAIL_MAX_EVENTS`).
   - *Tests*: `test_cli_resource_evolution_audit_commands_golden`, `test_cli_audit_tail_bounded_cap`.

5. **Slice 5 — Explain & SQL Offline Compilation Commands**:
   - Add `rockstream explain <view> [--estimate]` and `rockstream sql "<query>"`.
   - Call `rockstream-sql::explain_incremental` / `explain_incremental_for_sql` and DataFusion lowering against the catalog without deploying.
   - *Tests*: `test_cli_explain_and_sql_offline_compilation_golden`, `test_cli_sql_compile_syntax_error_rs1012`.

6. **Slice 6 — PGWire `SHOW VIEW STATUS` & `SHOW RESOURCE USAGE`**:
   - Add `SHOW VIEW STATUS` (and `FOR <view>`, `FOR NAMESPACE <ns>`) parsing and catalog execution in `server.rs` and `catalog_stubs.rs`.
   - Verify `SHOW RESOURCE USAGE` parity with CLI `resource usage`.
   - *Tests*: `test_pgwire_show_view_status_all_views`, `test_pgwire_show_view_status_single_view`, `test_pgwire_show_resource_usage`.

7. **Slice 7 — Non-Perturbing Polling & TestContainers Multi-Worker Integration**:
   - Write comprehensive TestContainers integration test `crates/rockstream-cli/tests/cli_read_only_tests.rs`.
   - Run active continuous workload; assert CLI polling across all read-only commands does not degrade freshness lag compared to a baseline control run.
   - *Tests*: `test_cli_read_only_polling_non_perturbing_tc`, `test_cli_read_only_answers_stale_worker_shards_and_workload`.

8. **Slice 8 — Documentation, Conformance Locks & Security Review Commissioning**:
   - Regenerate and expand `docs/cli.md` covering all new commands, arguments, `--json` mode, exit codes, and error codes.
   - Add CLI doc-coverage conformance test `test_docs_cli_conformance_and_coverage` ensuring every `clap` subcommand is documented.
   - Formally record the commissioning of the v0.55.2 security review.
