## Infrastructure & Bounds

### ViewChangeLog (S1)

- **Structure**: VecDeque-based, bounded by `CHANGE_LOG_MAX_ENTRIES` (default 10,000)
- **Eviction**: Pop-front (FIFO) when capacity exceeded
- **Test**: `subscribe_no_range_delete_in_change_log` ✓ PASS — Capacity-3 log with 5 pushes retains exactly 3 entries (pop_front eviction, not range-delete)

### SubscribeRegistry (S2–S4)

- **Oracle property**: `oracle_subscribe_incremental_equals_batch` ✓ PASS — Sequential 1-row COMMITs produce identical Z-set as batch COMMIT
- **Live-tail poll interval**: 100 ms (tunable)
- **Backlog bound**: `SUBSCRIBE_BACKLOG_MAX` (default = `CHANGE_LOG_MAX_ENTRIES`), raises RS-2020 when exceeded

### Session wait-for (S8–S9)

- **Timeout bound**: `session_wait_for_timeout_ms` (default 5000 ms = 5s SLO)
- **Test**: `session_wait_for_bounded_by_timeout` ✓ PASS — 50 ms timeout with impossible epoch exits within 200 ms (never blocks indefinitely)
