# v0.59.4 Plan — CLI & Configuration Usability

## Scope and Boundary

v0.59.4 executes the first milestone of the Pre-v1 Product Polish track (`NEW_ROADMAP.md` v0.59.4, `rockstream-pre-v1-small-features-plan.md` Section 7):

1. **`rockstream demo` with Deterministic Embedded Orders Scenario (`UX-01`)**:
   - Provide a zero-external-dependency demonstration command proving that changes written through PostgreSQL-compatible SQL incrementally maintain a materialized view and return updated results over pgwire.
   - Implement built-in `orders` scenario (`examples/demo/orders.sql`) executing DDL (`CREATE TABLE orders`, `CREATE MATERIALIZED VIEW sales_by_store AS SELECT store_id, SUM(amount) AS total_amount FROM orders GROUP BY store_id`), DML (`INSERT`, `UPDATE`, `DELETE`), and view queries asserting incremental maintenance.
   - Support CLI arguments: `--scenario <name>` (default `orders`), `--storage <path>`, `--listen <addr>` (default `127.0.0.1:0` ephemeral port), `--keep` (retain data), `--step-delay-ms <n>` (presentation delay, capped at 5000 ms), `--output <text|json>`.
   - Embed single `role=all` gateway process with local SlateDB shard storage, connect via `tokio-postgres`, execute steps, assert results, shut down cleanly, and remove temporary storage unless `--keep` is specified.
   - Return structured outcome in text and JSON formats; fail closed with `RS-0001` on assertion mismatch, `RS-0002` on unsupported scenario.

2. **`rockstream doctor` Bounded Diagnostic Command (`UX-02`)**:
   - Provide a non-destructive, bounded diagnostic command probing binary candidate identity, configuration validity, local/remote storage accessibility, control plane connectivity, pgwire gateway reachability, TLS material validity, system host limits (memory, file descriptors, monotonic clock), and optional Docker availability.
   - Support CLI arguments: `--config <path>`, `--storage <path-or-url>`, `--control <url>`, `--gateway <host:port>`, `--deep` (bounded temporary write/read/delete probe at `_rockstream_doctor/<uuid>/probe`), `--include-docker`, `--timeout <duration>` (default 5s per check, max 30s), `--output <text|json>`.
   - Implement `DiagnosticCheckResult` with status (`Pass`, `Warn`, `Fail`, `Skip`), category, summary, details, `RS-XXXX` error code, next steps, and execution duration.
   - Enforce bounded deadlines (per-check and 30s global timeout), max 64 checks, and generic secret redaction in all outputs.
   - Exit codes: 0 if no Fail, 1 if one or more Fail, 2 on usage error.

3. **Semantic Validation & Unknown-Key Reporting in `rockstream config validate` (`CFG-01`)**:
   - Add multi-layered configuration validation to `rockstream config validate`:
     - Layer 1: TOML syntax validation with exact line/column reporting.
     - Layer 2: Unknown and deprecated key detection with full dotted path reporting, edit-distance typo suggestion, and `RS-0002` / `RS-4017` codes.
     - Layer 3: Semantic bounds validation across all configuration sections (`cluster`, `autotuner`, `skew`, `worker`, `connector`, `exchange`, `gateway_tls`, `internal_tls`, `pricing`, `tiering`).
     - Layer 4: Referenced file readability validation for TLS certificate and key paths (`--check-files`).
   - Support CLI arguments: `--file <path>`, `--strict` (default `true` for pre-v1 compatibility), `--check-files`, `--output <text|json>`.
   - Collect and return all diagnostics in stable path order rather than failing on the first error.

4. **Shared Configuration Resolver & Origin Reporting in `rockstream config print-effective` (`CFG-02`)**:
   - Establish one authoritative configuration resolver `ConfigResolver::resolve(...)` shared by `rockstream start`, `doctor`, `config validate`, and `config print-effective`.
   - Implement four-tier binding precedence: Compiled Defaults → Config File (`--config`/`--file`, `ROCKSTREAM_CONFIG`, `./rockstream.toml`) → Environment Variables (`ROCKSTREAM__<SECTION>__<KEY>` parsed as TOML scalars) → CLI Flag Overrides.
   - Refactor CLI argument structs (`CommonConfigArgs`, `ExchangeOverrideArgs`, etc.) so `start` and `config print-effective` accept the same configuration flags.
   - Support CLI arguments: `--file <path>`, `--show-origins`, `--output <text|json>`, and CLI override flags.
   - Track `ConfigOrigin` (`Default`, `File(PathBuf)`, `Environment(String)`, `Cli(String)`) for every configuration key, format origin comments in TOML and structured JSON, and redact sensitive fields.

5. **Uniform `--output json` & Streaming Behavior Across All CLI Commands (`CLI-01`)**:
   - Standardize global `--output <text|json>` (clap `ValueEnum`, default `text`) across the entire CLI command tree.
   - Retain hidden `--json` boolean flag as a backwards-compatible alias (reject conflicting flags with usage error).
   - Ensure all finite CLI commands emit a single valid JSON document to stdout, and streaming commands (`audit tail`, `view subscribe`) emit valid JSON Lines.
   - Direct all informational messages, progress, and logs to stderr; emit structured JSON error objects to stderr on failure with error code, message, retryable flag, next steps, and documentation links.
   - Enforce zero unformatted `println!` in command handlers, no ANSI escapes in JSON mode, and schema stability across all commands.

6. **Shell Completions for Bash, Zsh, and Fish (`CLI-02`)**:
   - Implement `rockstream completions <bash|zsh|fish>` using `clap_complete`.
   - Generate completions dynamically from the live `Cli::command()` AST so completions remain synchronized with all subcommands, arguments, and options.
   - Write generated completion scripts directly to stdout.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
