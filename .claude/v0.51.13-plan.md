# v0.51.13 Plan — Full Ad Hoc Query Support: Multi-Shard Scatter-Gather & Removal of Hard Result-Set Caps

## 1. Deferred-Item Audit

### Must implement this version

No prior sign-off contains an unfinished deferral that overlaps this scope. The
roadmap explicitly identifies the unplanned, existing correctness gap in the
v0.51.2 query-time path: `query_time_datafusion_select` reads only the local
`ShardDb` and rejects relations above `MAX_QUERY_TIME_ROWS` / 
`MAX_QUERY_TIME_SCAN_BYTES`. Both are therefore must-implement scope here, not
performance follow-ups:

1. scatter every referenced relation to every owning shard at one pinned
   frontier, then give DataFusion the complete logical relation;
2. replace one unbounded logical-relation materialization with bounded,
   streamed batch ingestion and a documented pathological-query error.

### Out-of-scope — flag for follow-up version

The historical out-of-scope items found in `sign-offs/v*.md` are per-operator
oracle/IVM, early multi-shard exchange/checkpoint/aggregate/min-max/replay
work, HOP/SESSION scheduling, v0.24 read-your-writes surface, transactional
LISTEN delivery, and v0.51.3 view refresh. They do not overlap this ad hoc
base-table/view read path. Later sign-offs through v0.51.12 explicitly defer
nothing. No item is silently dropped.

The scope adds no new SQL grammar: it completes `SELECT` with `WHERE`, `JOIN`,
and `GROUP BY`/aggregate when the existing query-time route is selected. Every
one of those forms must traverse the following complete path. If any entry
marked **MUST ADD** remains missing before commit, the feature is incomplete.

| Stage | Existing wire | Required v0.51.13 result |

provide incremental pages/batches instead of composing either whole-relation
return value into an unbounded collection.

## 4. Vertical Slices

1. **Topology and pinned reader injection.** Add the gateway constructor/runtime
   dependency that resolves all owning shard readers at one frontier, including
   the local shard. Make missing topology a fail-closed query-time error rather
   than a local-only fallback. Exit: seeded
   `query_time_scatter_sim_tests::scatter_reader_selection_is_complete_at_one_frontier`.

2. **Bounded relation batch source.** Add paged per-shard scanning and bounded
   merge scheduling. Define `QUERY_TIME_SCATTER_MAX_IN_FLIGHT_ROWS`,
   `QUERY_TIME_SCATTER_MAX_IN_FLIGHT_BYTES`, and
   `QUERY_TIME_SCATTER_MAX_CONCURRENT_SHARD_BATCHES`; publish the current
   rows/bytes/batches fill levels. Exit:
   `query_time_scatter_batches_never_exceed_row_or_byte_budget`.

3. **Query-time executor and all dispatch callers.** Feed every referenced
   relation's streamed batches into the DataFusion table provider, preserve
   aliases/schema conversion, wire `query_time_datafusion_response` and
   `EXPLAIN`, and remove the old local hard caps. Exit: the three `WHERE`
   matrix tests above.

4. **Cross-relation correctness.** Execute each join input through the same
   scatter source and prove the three JOIN matrix cells, then execute all GROUP
   BY/aggregate matrix cells. Exit: all six named JOIN/GROUP tests are green.

5. **Large relation and pathological limit.** Prove both former cap failures
   now complete correctly, then prove the new documented resource limit is an
   error with no partial response. Exit: all three capacity tests are green.

6. **Real distributed wire proof.** Add
   `crates/rockstream-gateway/tests/query_time_multi_shard_scatter_tests.rs` as
   a 3+ shard, real multi-process TestContainers gateway cluster. Run exact
   WHERE, JOIN, and GROUP BY comparisons through pgwire against the one-shard
   oracle. Exit: the complete matrices above are green in that fixture.

7. **Regression and safety proof.** Run the unmodified v0.51.2 query/index
   suites plus the seeded coordination and LFS/MinIO durability checks below.
   Confirm no query read or cleanup path uses SlateDB range deletion; cleanup,
   if needed for fixture data, is scan-and-delete or a snapshot-safe compaction
   filter and is asserted by the test.

## 5. Oracle, Durability, and Coordination Commitments

The new logical operator is scatter-backed relation ingestion. Before it is
implemented, every matrix test above commits to the oracle property:
`incremental/multi-shard query result == batch/DataFusion single-shard oracle`
for the complete sorted row set. The bounded-batch test additionally asserts
the full stream result and all three fill levels.

This version adds no commit, replay, checkpoint, compaction, or WAL durability
path; it only reads already durable shard outputs. The real read path is still
tested on both persistence substrates to prevent an accidental storage-specific
implementation:

| Substrate | Test commitment |
| --- | --- |
| Local filesystem SlateDB | `query_time_multi_shard_scatter_lfs_tests::multi_shard_scatter_lfs_where_join_group_by_exact_oracle` |
| MinIO/S3 via TestContainers | `query_time_multi_shard_scatter_minio_tests::multi_shard_scatter_minio_where_join_group_by_exact_oracle` |

Scatter selection/pinned-frontier fan-out is a distributed coordination path.
`query_time_scatter_sim_tests::scatter_frontier_buggify_preserves_complete_exact_result`
runs a seeded `SimRuntime` schedule with `buggify!()` annotations before reader
selection, between shard batch arrivals, and before final frontier validation.
It asserts the exact final rows, one common pinned frontier, no duplicated or
omitted row, and bounded fill levels; it prints a replayable failing seed.
