# v0.64 Plan — SQL Execution Integrity

## Scope and Boundary

Roadmap reference (`ROADMAP.md` §10: `v0.64 — SQL Execution Integrity`):
> **Focus**: Replace RockStream-specific textual DML shortcuts with standard SQL semantics.
> **User outcome**: Ordinary PostgreSQL clients can issue ordinary PostgreSQL-style `UPDATE` and `DELETE`. Simple and extended protocols produce equivalent typed results and transactional effects.
> **Required Proof**:
> Run a PostgreSQL compatibility corpus using `tokio-postgres` and at least one ordinary external ecosystem client (`psycopg3`).
> The test must verify resulting state rather than merely command completion.
> Required scenarios include:
> - multi-row UPDATE
> - UPDATE RETURNING
> - DELETE
> - DELETE RETURNING
> - no-match UPDATE
> - NULL predicate
> - prepared UPDATE
> - transaction rollback
> - transaction commit
> - materialized-view propagation
> - restart after DML

Committed implementation plan reference: `docs/implementation-plans/v0.64.md`.
Apply the shared implementation and evidence rules: `docs/implementation-plans/README.md`.

v0.64 eliminates legacy string-slicing and prefix-based DML handling, replacing it with a unified AST-driven, typed semantic, and transactionally atomic execution pipeline:

1. **Shared PostgreSQL AST Parsing Path (`crates/rockstream-sql/src/frontend.rs`, `extension.rs`)**:
   - Route every SQL statement (`INSERT`, `UPDATE`, `DELETE`, `SELECT`, `CREATE`, `DROP`) through `sqlparser::parser::Parser` with `PostgreSqlDialect`.
   - Eliminate execution decisions based on string prefixes such as `starts_with("update ")` or `starts_with("delete from ")`.
   - Remove legacy string parsers (`parse_update`, `parse_delete`, `parse_insert`) and naive text parameter substitution (`substitute_params`) from `crates/rockstream-gateway/src/server.rs`.
   - Retain special syntax only through explicit parsed extensions.

2. **Typed DML Representation & Semantic Lowering (`crates/rockstream-sql/src/dml.rs`, `lower.rs`)**:
   - Introduce strongly-typed DML AST and IR:
     ```rust
     pub enum DmlStatement {
         Insert(InsertStatement),
         Update(UpdateStatement),
         Delete(DeleteStatement),
     }
     ```
   - Lower typed predicates, assignments, and expressions to logical operations using existing schema and type infrastructure.
   - Validate target relation existence, column names, column types, permissions, and supported expressions before modifying state.
   - Unsupported expressions return explicit capability errors (`RS-1013` / SQLSTATE `0A000`) with zero writes or state mutations.

3. **Standard General-Predicate Evaluation & SQL Three-Valued Logic (`crates/rockstream-sql/`, `crates/rockstream-ops/`)**:
   - Replace comma-separated key/value string matching (`WHERE id = 1, val = 'b'`) with standard SQL predicate trees (`WHERE order_id = 1 AND store_id = 100`).
   - Implement documented general-predicate subset: `AND`, `OR`, `NOT`, binary comparisons (`=`, `<>`, `!=`, `<`, `<=`, `>`, `>=`), and nullability checks (`IS NULL`, `IS NOT NULL`).
   - Honor operator precedence and SQL three-valued logic (`TRUE`, `FALSE`, `NULL`).
   - Evaluate predicates against live table rows and uncommitted session write buffer overlays.

4. **Atomic DML Deltas (-old/+new) & Materialized View Isolation (`crates/rockstream-gateway/`, `crates/rockstream-ops/`)**:
   - Execute each `UPDATE` as an atomic retraction of the complete old row (`-old`) plus insertion of the complete new row (`+new`) in one logical commit.
   - Multi-row updates and primary key modifications commit atomically or fail completely.
   - Defer maintained-view visibility until the full epoch is committed; readers never observe partial or half-maintained view dependencies.
   - Explicit `ROLLBACK` completely discards all buffered mutations; injected write failures leave base tables and views intact.

5. **First-Class Durable Primary Key Semantics (`crates/rockstream-storage/`, `crates/rockstream-gateway/`)**:
   - Persist first-class `pk_cols` metadata through `CatalogStore` (`CatalogTable`).
   - Parse and enforce `PRIMARY KEY` in `CREATE TABLE` DDL.
   - For tables with primary keys, enforce uniqueness atomically on `INSERT` and `UPDATE`. Duplicate key violations fail with `RS-2057` (`write.duplicate_key`, SQLSTATE `23505`) and leave prior state unchanged.
   - Primary key definitions and row identities remain invariant across process crash and restart.

6. **Type Coercion, NULL Semantics, Text Escaping & Parameter Binding (`crates/rockstream-gateway/`, `crates/rockstream-types/`)**:
   - Define and enforce frozen type representations: `NULL`, `IS NULL`, `IS NOT NULL`, numeric coercion (e.g. `Int16` -> `Int32` -> `Int64` -> `Float64`), escaped text, `UUID`, timestamps/time-zones, `DECIMAL(p, s)`, and `BOOLEAN`.
   - Bind typed parameters (`$1`, `$2`, ...) directly into the execution AST rather than text substitution.
   - Prevent numeric and decimal overflow with explicit errors (`RS-1016` / SQLSTATE `22003`).

7. **Simple and Extended Protocol Parity (`crates/rockstream-gateway/src/server.rs`)**:
   - Unify execution semantics across Simple Query protocol, Prepared Statements (`PREPARE` / `EXECUTE`), and Bound Parameters (Extended Query `Parse` / `Bind` / `Execute`).
   - Implement complete `UPDATE RETURNING` and `DELETE RETURNING` results returning projected columns or `*`.
   - Return accurate command completion tags: `UPDATE <count>` and `DELETE <count>`, correctly reflecting 0 rows matched/updated.

8. **Compatibility Corpus, Crash Verification & Hard Process Restart (`crates/rockstream-gateway/tests/`)**:
   - Validate against `tokio-postgres` and an external client (`psycopg3` via TestContainers).
   - Verify all 10 required roadmap scenarios: multi-row UPDATE, UPDATE RETURNING, DELETE, DELETE RETURNING, no-match UPDATE, NULL predicate, prepared UPDATE, transaction rollback, transaction commit, and materialized-view propagation.
   - Execute black-box crash proof: SIGKILL after committed DML, restart fresh process from identical storage, assert bit-identical state and maintained view query results against an independent oracle (`incremental == batch`).
   - Enforce resource bounds: statement size (`MAX_SQL_STATEMENT_BYTES`), AST depth (`MAX_EXPR_DEPTH`), mutation limit (`MAX_DML_MUTATIONS_PER_STATEMENT`), and scan windows (`MAX_DML_SCAN_WINDOW_ROWS`).

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag or config property on the same `rockstream` binary. `main` remains runnable through it.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters, asserted by test.
- Unbounded in-memory accumulation is never acceptable. Every new queue, buffer, or scan window needs a named upper bound, a fill-level metric, and a backpressure or error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix root causes.
- Make only changes this version requires. No speculative features outside IVM engine + Postgres wire layer.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals.**

**Stage 1: Parser** (`crates/rockstream-sql/src/frontend.rs`, `sqlparser`)

**Stage 3: Executor** (`crates/rockstream-gateway/src/write_buffer.rs`, `server.rs`, `rockstream-storage`)
**Stage 4: Response Encoder** (`crates/rockstream-gateway/src/server.rs`, `DataRowEncoder`)

## 4. Vertical Slices & Test Commitments

### Slice 1: SQL AST DML Parser, `DmlStatement` IR & Bounded Parser Guards (`rockstream-sql`)
- Add `DmlStatement`, `InsertStatement`, `UpdateStatement`, `DeleteStatement`, and assignment representations in `crates/rockstream-sql/src/dml.rs`.
- Parse DML statements using `sqlparser::parser::Parser` with `PostgreSqlDialect`.
- Enforce parser bounds: `MAX_SQL_STATEMENT_BYTES` (1 MiB) and `MAX_EXPR_DEPTH` (64 levels), rejecting oversized input with `RS-1012` before execution.
- Validate target table name, column lists, and assignment expressions against catalog schema.
- Pre-committed test: `crates/rockstream-sql/tests/dml_ast_parser_tests.rs::test_dml_ast_parser_recognizes_insert_update_delete`.

### Slice 2: General Predicate Expression Evaluator, 3-Valued Logic & Type Coercion (`rockstream-sql`, `rockstream-ops`)
- Implement general predicate lowering and evaluation in `crates/rockstream-sql/src/lower.rs` and `crates/rockstream-ops/src/expr.rs`.
- Support multi-column `AND` conjunctions (`col1 = 1 AND col2 = 100`), `OR`, `NOT`, comparisons (`=`, `<>`, `<`, `<=`, `>`, `>=`), and nullability checks (`IS NULL`, `IS NOT NULL`).
- Strictly adhere to SQL three-valued logic.
- Reject unsupported predicate expressions (correlated subqueries, non-deterministic UDFs) with `RS-1013` (SQLSTATE `0A000`) without modifying table or view state.
- Pre-committed test: `crates/rockstream-sql/tests/dml_predicate_eval_tests.rs::test_predicate_evaluator_general_subset_and_capability_errors`.

### Slice 3: First-Class Primary Key Metadata, Storage Persistence & Duplicate Key Rejection (`rockstream-storage`, `rockstream-gateway`)
- Parse and capture `PRIMARY KEY` in `CREATE TABLE` statements in `crates/rockstream-gateway/src/server.rs`.
- Persist `pk_cols` through `CatalogStore` (`CatalogTable`) into durable storage.
- Bridge primary key metadata into gateway `CatalogStubs`.
- Implement uniqueness check on `INSERT` and `UPDATE` against live storage and uncommitted write buffer.
- Colliding keys fail atomically with `RS-2057` (`write.duplicate_key`, SQLSTATE `23505`), preserving prior state intact.
- Pre-committed test: `crates/rockstream-gateway/tests/primary_key_dml_tests.rs::test_primary_key_uniqueness_and_durability`.

### Slice 4: Atomic DML Deltas (-old/+new), Multi-Row Execution & Materialized View Propagation (`rockstream-gateway`, `rockstream-ops`)
- Refactor `handle_update` and `handle_delete` in `crates/rockstream-gateway/src/server.rs`:
  - Locate matching rows using AST predicate evaluator over live shard data and write buffer overlay.
  - Formulate updates as an atomic batch of retraction (`-old`) and insertion (`+new`) records.
  - Ensure multi-row updates apply within a single committed epoch.
  - Defer view maintenance visibility until the transaction epoch commits.
  - Injected write failures roll back base tables and views completely.
- Pre-committed test: `crates/rockstream-gateway/tests/dml_atomicity_and_view_tests.rs::test_atomic_update_deltas_and_view_propagation`.

### Slice 5: Parameter Binding, Typed Extended Protocol Parity & RETURNING Semantics (`crates/rockstream-gateway`)
- Replace string-replacement `substitute_params` with typed parameter binding directly into AST parameter placeholders.
- Ensure Simple Query and Extended Query protocol (`Parse` / `Bind` / `Describe` / `Execute`) execute identical logic.
- Implement complete `UPDATE RETURNING` and `DELETE RETURNING` returning requested columns or `*`.
- Ensure accurate command tags (`UPDATE <count>`, `DELETE <count>`), including 0-count on no-match.
- Pre-committed test: `crates/rockstream-gateway/tests/pgwire_dml_parity_tests.rs::test_extended_protocol_parameter_binding_and_returning_parity`.

### Slice 6: PostgreSQL Compatibility Corpus with `tokio-postgres` & `psycopg3` (`crates/rockstream-gateway/tests`)
- Build a comprehensive PostgreSQL compatibility corpus executing against a release-mode RockStream binary.
- Test across `tokio-postgres` and an ordinary ecosystem client (`psycopg3` via TestContainers).
- Exercise all 10 required scenarios:
  1. multi-row UPDATE
  2. UPDATE RETURNING
  3. DELETE
  4. DELETE RETURNING
  5. no-match UPDATE
  6. NULL predicate
  7. prepared UPDATE
  8. transaction rollback
  9. transaction commit
  10. materialized-view propagation
- Compare full result rows, data types, multiplicities, command tags, and exact SQLSTATE error codes.
- Pre-committed test: `crates/rockstream-gateway/tests/postgres_dml_compatibility_tests.rs::test_postgres_compatibility_corpus_e2e`.

### Slice 7: Hard Process Restart, Crash/Recovery Integrity & Oracle Verification (`crates/rockstream-gateway/tests`)
- Black-box crash proof: Start server, execute table creation with PK, insert initial rows, issue DML mutations and transaction commits/rollbacks, verify state, SIGKILL the process, start a completely fresh process pointing to identical storage.
- Query base tables and materialized views, asserting bit-identical state against an independent batch oracle (`incremental == batch`).
- Verify uncommitted or rolled-back DML mutations leave zero phantom traces.
- Pre-committed test: `crates/rockstream-gateway/tests/dml_crash_recovery_tests.rs::test_sigkill_crash_proof_after_committed_dml`.

### Slice 8: Negative Boundary, Resource Limits & Malformed Statement Containment (`crates/rockstream-gateway/tests`)
- Enforce strict bounds on statement size (`MAX_SQL_STATEMENT_BYTES`), AST depth (`MAX_EXPR_DEPTH`), mutation count per statement (`MAX_DML_MUTATIONS_PER_STATEMENT`), scan window (`MAX_DML_SCAN_WINDOW_ROWS`), and write buffer memory (`WRITE_BUFFER_LIMIT_BYTES`).
- Malformed statements, malformed RETURNING clauses (`RS-2022`), malformed INSERT lists (`RS-2056`), and numeric overflows (`RS-1016`) fail closed with zero partial commits.
- Pre-committed test: `crates/rockstream-gateway/tests/dml_bounding_and_negative_tests.rs::test_dml_limits_and_negative_error_containment`.
