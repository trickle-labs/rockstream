## 2. Vertical Slices

### Slice 1: Protocol 3.2 Wire Negotiation & Handshake Downgrade (Blocker 1)
- **Goal**: Allow modern PostgreSQL clients (e.g. `psql 18.4`, `libpq >= 18`) advertising wire protocol 3.2 (`196610`) to connect successfully rather than being abruptly disconnected with an EOF.
- **Implementation**:
  - Intercept client startup handshake messages in `crates/rockstream-gateway/src/server.rs`.
  - When a startup message specifies a minor version > 0 (e.g., protocol 3.2 / `196610`), construct and send a `NegotiateProtocolVersion` (`'v'`) backend response specifying protocol 3.0 (`196608`) and listing any unrecognized `_pq_.*` extension parameters.
  - Proceed with the protocol 3.0 handshake matching standard PostgreSQL server behavior.
  - Ensure existing protocol 3.0 clients continue to connect without any behavioral change.
- **Verification**: Green test in `protocol_negotiation_tests.rs` (hand-written 3.2 wire client asserting `NegotiateProtocolVersion` reply, and `psql 18` container test).

### Slice 2: Catalog Pre-Resolution & Honest Relation Error Semantics (Blocker 3)
- **Goal**: Prevent `SELECT` or DML against non-existent or failed-to-create relations from returning a silent empty `CommandComplete` / `OK`.
- **Implementation**:
  - Update query dispatch in `crates/rockstream-gateway/src/server.rs` to validate referenced target relations against `CatalogStubs` (`get_view`, `get_table`) and the active `search_path`.
  - If a relation is absent from the catalog (including views whose `CREATE` failed), fail immediately with PostgreSQL error code `42P01` (`RS-1004` / "relation does not exist") `ErrorResponse`.
- **Verification**: Green test in `absent_relation_error_tests.rs` asserting `SELECT * FROM does_not_exist` and `SELECT` from a view whose `CREATE` failed both return `42P01` `ErrorResponse`.

### Slice 3: CLI Auth Mode Routing & Fail-Closed Enforcement (Blocker 4)
- **Goal**: Ensure `--auth` CLI flags are honored and misconfigured auth options cause startup failure rather than running insecurely in `AuthMode::Off`.
- **Implementation**:
  - Modify `crates/rockstream-cli/src/lib.rs` (`start_gateway_with_shard` and `run_start`) to evaluate `opts.auth_mode`.
  - Route parsed modes (`off`, `scram`, `md5`, `oidc`, `mtls`) to `GatewayServer::with_shard_db_and_auth` or `with_shard_db_and_mtls_auth`.
  - Fail closed with documented `RS-0002` / `RS-2401` error on unknown or unsupported auth mode string.
  - Log active auth mode at startup: `tracing::info!("Gateway server starting with auth mode: {}", auth_mode)`.
- **Verification**: Green test in `cli_auth_enforcement_tests.rs` asserting `--auth scram` enforces credentials, invalid `--auth` string aborts startup, and startup log names the active mode.
