# v0.59 Plan — v1.0 Release Candidate (RC1)

## Scope and Boundary

v0.59 executes the v1.0 Release Candidate (RC1) release gate per `ROCKSTREAM_PROJECT_FOCUS.md` §10 Stage 5 and `NEW_ROADMAP.md` v0.59.

Per the 2026-08-12 realism review:
- **v0.59 is a pure release gate, not a feature sprint.**
- **Entry criteria**:
  1. `scripts/check-dispatch-wiring.sh` re-runs clean (0 `MISSING` paths).
  2. `scripts/check-no-unreachable.sh` re-runs clean (0 `unreachable!()` calls in production crates).
  3. `scripts/check-failure-matrix.sh` re-runs clean (0 uncovered or unbudgeted cells).
  4. `scripts/check-exit-criteria.sh` confirms all prior versions from v0.1 through v0.58.3 are fully signed off.
- **The Gate is the v0.57 Contract, Not Feature Completeness** (`ROCKSTREAM_PROJECT_FOCUS.md` §10 Stage 5):
  - Correctness.
  - Recovery.
  - Bounded resources.
  - Operability.
  - Upgradeability.
  - Security.
  - Performance stability of core maintained-view workloads.
- **Continuous 2-Week Automated Chaos Soak & Restart Clock Rule**:
  - The soak cycle runs under maximum cluster pressure within a single cloud region.
  - The clock is wall-clock bound and restarts on any P0/P1 fix or merged change.
- **Pre-Release Formal Verification Gate (DC.4)**:
  - Relaxed-bounds sweep across coordination models (M1–M7) in `formal/*.fizz` and `FIZZBEE_TEST_PLAN.md`.
- **Single-Region Product Boundary**:
  - v1 is explicitly a single-region product. Multi-region active/active serving is permanently out of scope for v1.
- **v1.0 Milestone**: Tag `v1.0.0`.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.
