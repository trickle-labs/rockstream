# v0.54 Plan — Per-Stage Freshness Lag Accounting & Barrier Flight Time

## Scope and Non-Negotiable Invariants

This version implements **Per-Stage Freshness Lag Accounting & Barrier Flight Time** split by the 2026-08-12 realism review (NEW_ROADMAP.md row v0.54, ROCKSTREAM_PROJECT_FOCUS.md §5.2 and §10 Stage 2). It provides the measurement and timestamp propagation engine that makes freshness lag explainable and attributable:

1. **Per-Stage Timestamp Propagation & Lag Decomposition**:
   - Decompose end-to-end view freshness lag into separately-attributable components:
     1. `source_lag_ms`: source watermark/event lag (source event time to ingestion arrival)
     2. `decode_ingest_lag_ms`: record decoding, schema adaptation, and ingest buffer time
     3. `compute_lag_ms`: IVM operator delta evaluation / differential compute execution time
     4. `checkpoint_alignment_lag_ms`: barrier alignment wait time across shards
     5. `sink_commit_lag_ms`: transactional sink staging and batch commit latency
     6. `spill_activity_ms`: spill activity / storage paging delay
     7. `storage_compaction_pressure_ms`: object-store and L0 compaction backpressure delay
   - End-to-end freshness lag (`freshness_lag_ms`) is measured independently and equals the sum of the decomposed components within a tolerance published from this version's empirical measurements.
   - Stage isolation invariant: under an induced source stall, spill, or sink block, only the affected stage's lag increases; no component silently absorbs or masks another stage's time.

2. **Barrier Flight Time vs Checkpoint Completion Time**:
   - Measure `barrier_flight_time_ms` (time elapsed from coordinator barrier injection until all shard operators receive the barrier) separately from `checkpoint_completion_time_ms` (time elapsed from barrier injection until all shard SlateDB checkpoints confirm and the cluster manifest commits).
   - Under a deliberately saturated data channel, prove that `barrier_flight_time_ms` diverges from checkpoint completion time due to control messages queuing behind data packets on shared channels — the empirical measurement that informs whether reserved channels are required.

3. **Public Surfaces & Observability**:
   - Prometheus `/metrics` export: export all 7 stage lag gauges, total freshness lag gauge, barrier flight time gauge/summary, and checkpoint completion time gauge/summary. Every metric has a documented unit (milliseconds), is non-negative, and is monotonic where required.
   - PGWire SQL: `SHOW VIEW STATUS`, `SHOW VIEW STATUS FOR <view>`, and `SHOW VIEW STATUS FOR NAMESPACE <namespace>` return decomposed lag columns alongside lifecycle status.
   - Operator CLI: `rockstream view status [<view>]` formats stage lag breakdown in human-readable tables and structured `--json` output (`ViewStatusInfo` with `StageLagBreakdown`).

### Ground Rules & Engine Constraints
- **One binary, one CLI, one config**: All subcommands and roles remain in the single `rockstream` binary. `main` remains runnable across all roles.
- **Prefix every shell command with `rtk`**: Enforced in all workflows.
- **No SlateDB range deletion**: All storage scans and checkpoint reads use point-get or bounded prefix scans.
- **Bounded buffers & metrics**: Stage timestamp queues and metrics registries have named upper bounds (`MAX_STAGE_TIMESTAMPS_PER_VIEW` = 1024, `MAX_BARRIER_FLIGHT_SAMPLES` = 4096), fill-level metrics, and backpressure/error paths.
- **No deferrals**: All scoped items are implemented this version.

## Test Commitments (Oracle Property Tests)

- **Summation Tolerance Commitment**: Under sustained load without stalls, the sum of decomposed lag components ($\sum_{i=1}^7 \text{lag}_i$) matches the independently measured end-to-end freshness lag within the published tolerance:
  $$\left| \text{freshness\_lag\_ms} - \sum \text{stage\_lags} \right| \le \text{PUBLISHED\_SUMMATION\_TOLERANCE\_MS}$$
  Pre-committed test: `crates/rockstream-cli/tests/lag_attribution_tests.rs::test_lag_attribution_summation_tolerance_published`.
- **Non-Absorption / Isolation Commitment**: An induced delay in stage $k$ increases $\text{lag}_k$ by $\Delta$, increases $\text{freshness\_lag\_ms}$ by $\Delta$, and leaves all $\text{lag}_{j \ne k}$ invariant ($\pm \epsilon$).
  Pre-committed tests: `test_lag_attribution_induced_source_stall`, `test_lag_attribution_induced_spill`, `test_lag_attribution_induced_sink_block`.
- **Barrier Flight Divergence Commitment**: Under channel saturation, $\text{barrier\_flight\_time\_ms}$ grows in proportion to channel backlog, while local SlateDB shard checkpoint time remains bounded.
  Pre-committed test: `test_barrier_flight_time_divergence_under_channel_saturation`.
