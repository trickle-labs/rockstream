## Vertical Slices

Each slice ends in one or more green tests. All changes live in
`crates/rockstream-gateway/`.

### Slice 1 — SQLSTATE Full Mapping (foundation, no new deps)
**Files**: `src/error.rs`

- Add every missing `GatewayError` variant with a proper RS-XXXX code.
- Map every variant to a 5-char Postgres SQLSTATE in `From<GatewayError> for PgWireError`.
- Populate `Detail`, `Hint`, `Position`, `Where` fields in `ErrorInfo` for query-level errors.
- New variants needed: `QueryCancelled` (RS-2050/57014), `CursorNotFound` (RS-2051/34000),
  `CursorAlreadyExists` (RS-2052/42P03), `MemoryLimitExceeded` (RS-2053/53200),
  `StatementTimeout` (RS-2054/57014), `ConnectionLimitExceeded` (RS-2055/53300).
- **Green gate**: `tests/gateway_proof_tests.rs` — unit test asserting SQLSTATE for every RS code.

### Slice 2 — BackendKeyData & CancelRequest
**Files**: `src/server.rs`, `src/session.rs`

- `SessionState` gains `backend_pid: u32` (connection counter, atomic) and `cancel_secret: u32`
  (random, per-connection).
- `GatewayServer::on_startup` sends `BackendKeyData { pid, secret }` after `AuthenticationOk`.
- Add a `CancellationRegistry`: `Arc<DashMap<(u32, u32), tokio::sync::CancellationToken>>` on
  `GatewayServer`; each connection registers at startup and deregisters on drop.
- `GatewayServer` listens for raw `CancelRequest` packets on the same port (pgwire dispatches
  these before the startup handshake); looks up `(pid, secret)` in the registry and calls
  `token.cancel()`.
- `do_query_single` wraps every `ViewReader::read_view` and DML dispatch inside
  `tokio::select! { _ = token.cancelled() => ... }`, returning `RS-2050`/SQLSTATE `57014`.
- Connection re-accepts new queries after cancellation with `ReadyForQuery('I')`.
- Memory bound: `CancellationRegistry` is bounded by `MAX_CONNECTIONS = 10_000`.
- **Green gate**: `tests/gateway_proof_tests.rs::test_cancel_request_aborts_query` — unit test
  (mocked slow ViewReader with a 500 ms sleep); verifies RS-2050 and connection reuse.

### Slice 3 — Named Cursors (DECLARE / FETCH / MOVE / CLOSE)
**Files**: `src/session.rs`, `src/server.rs`

- `SessionState` gains `cursors: HashMap<String, CursorState>` where:
  ```rust
  struct CursorState {
      rows: Vec<Vec<u8>>,
      position: usize,
  }
  ```
  Bound: max 100 open cursors per connection; fill-level metric = `cursors.len()`.
- Parse `DECLARE <name> CURSOR FOR <query>` in `dispatch_sync`: execute the query once
  (collecting all rows into `CursorState.rows`), insert into `session.cursors`.
- Parse `FETCH [FORWARD] n FROM <name>` / `FETCH ALL FROM <name>` / `MOVE n FROM <name>` /
  `CLOSE <name>` / `CLOSE ALL`.
- Cleanup on `ROLLBACK` and connection drop (drop `SessionState`).
- **Green gate**: `tests/gateway_proof_tests.rs::test_named_cursor_lifecycle` — unit test
  covering DECLARE/FETCH 100/FETCH ALL/MOVE/CLOSE with correct row counts and cleanup.

### Slice 4 — Streaming Row Delivery (bounded memory)
**Files**: `src/view_reader.rs`, `src/server.rs`

- Add `ViewReader::read_view_stream` returning `Pin<Box<dyn Stream<Item = Result<Vec<u8>, GatewayError>> + Send>>`.
- `HotOnlyViewReader::read_view_stream`: scan in chunks via `shard_reader.scan_prefix`, yield
  rows as they arrive from storage.
- `read_view_response` in `server.rs` switches to the stream interface: pumps rows in batches
  of 1 000, sending each `DataRow` as soon as it is ready.
- Per-connection peak memory bound: 64 MiB (named constant `STREAM_BATCH_BYTES = 64 * 1024 * 1024`);
  a fill-level metric `ROWS_IN_FLIGHT_BATCH = 1_000` is a named constant.
- `CancelRequest` token is checked between batches.
- **Green gate**: `tests/gateway_proof_tests.rs::test_streaming_peak_memory_bounded` — writes
  2 000 000 rows into a shard, reads through `read_view_stream`, asserts no single batch
  exceeds the limit and the stream completes without collecting all rows up front.

### Slice 5 — PgBouncer Compatibility
**Files**: `src/server.rs`, `src/session.rs`

- `ReadyForQuery` transaction-status byte: `'I'` (idle), `'T'` (in transaction), `'E'`
  (in failed transaction). `SessionState` gains `TxStatus` enum; `SimpleQueryHandler` and
  `ExtendedQueryHandler` set correct byte on every `ReadyForQuery` send.
- `DISCARD ALL`: clear `cursors`, `prepared statements`, `portals`, `search_path`, `idempotency_key`,
  `source_epoch_envelope`, reset `TxStatus` to Idle.
- `RESET ALL`: reset all GUC settings (`search_path`, `wait_for_timeout_ms`, etc.) without
  clearing cursors or prepared statements.
- `application_name` tracked in `SessionState`; accepted as a startup parameter.
- Portal and cursor cleanup on `Sync` outside a transaction.
- **Green gate**: `tests/gateway_proof_tests.rs::test_pgbouncer_compat_status_bytes`,
  `test_discard_all_clears_session`, `test_reset_all_preserves_cursors`.

### Slice 6 — `pg_stat_activity` Virtual Table
**Files**: `src/catalog_stubs.rs`, `src/server.rs`

- `ConnectionRegistry`: `Arc<RwLock<HashMap<u32, ActivityRow>>>` where:
  ```rust
  struct ActivityRow {
      usename: String,
      application_name: String,
      state: String,          // "idle" | "active"
      query: String,
      query_start: Option<DateTime<Utc>>,
      client_addr: Option<String>,
  }
  ```
  Bound: capped at `MAX_CONNECTIONS = 10_000` entries; fill-level = `registry.len()`.
- Each connection registers on startup, updates `state`/`query`/`query_start` at query start,
  resets to `state="idle"` on `ReadyForQuery`.
- `SELECT * FROM pg_stat_activity` handled in `dispatch_sync` by reading the registry snapshot.
- **Green gate**: `tests/gateway_proof_tests.rs::test_pg_stat_activity_shows_connection`.

### Slice 7 — Protocol Fuzzer
**Files**: `tests/protocol_fuzzer_tests.rs` (new)

- `proptest`-driven structured fuzzer generating random well-formed pgwire message byte
  sequences (Parse/Bind/Execute/Describe/Close/Sync/Flush/Query in random order, random
  names/SQL strings).
- Each sequence wrapped in `tokio::time::timeout(Duration::from_secs(5))`.
- Assert: no panics (via `catch_unwind` or proptest harness), no hangs, no malformed responses.
- Runs 50 000 random sequences under `proptest` with a deterministic seed in CI.
- **Green gate**: `tests/protocol_fuzzer_tests.rs::protocol_fuzzer_no_panics_no_hangs`.

### Slice 8 — Concurrent-Connection Stress Test
**Files**: `tests/gateway_integration_tests.rs` (extend)

- Spawn 1 000 `tokio-postgres` connections simultaneously against a local `GatewayServer`.
- Each connection runs 100 `SELECT 1` queries.
- Assert: zero connection-level errors; peak RSS < 2 GiB.
- **Green gate**: `test_concurrent_1000_connections_no_errors`.
