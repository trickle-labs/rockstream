## Proof obligations (restated as checkable assertions)

1. `WITH RECURSIVE` SQL compiles end-to-end: DataFusion's
   `LogicalPlan::RecursiveQuery` lowers to `rockstream-plan`'s existing
   `PlanNode::Recursion { base, step, max_iterations, monotone }`
   (`crates/rockstream-plan/src/lib.rs:203-213`, already defined since an
   earlier version but never wired to a lowering path or a runtime operator).
2. Monotone, insert-only recursive terms (transitive closure / graph
   reachability) run semi-naive fixed-point iteration and incrementally
   maintain state correctly: `incremental(query, Δ) == batch(query,
   accumulated)` against the correctness oracle, including a 1M-edge
   transitive-closure graph and a recursive employee-hierarchy query
   (IVM.md:1191).
3. Non-monotone recursive terms (`EXCEPT`, aggregate, `DISTINCT`, window,
   `INTERSECT`, or unsupported multiple self-reference in the recursive term)
   fall back to full recomputation, exactly as DESIGN.md §6.8/IVM.md §11
   specify; a genuinely non-monotone *delta* under a monotone-classified query
   is rejected at runtime with a registered error code (closing the
   RS-1009/RS-1509 numbering gap below), never silently miscomputed.
4. Convergence is enforced by both data and progress: iteration stops when
   the recursive delta distinct-collapses to empty AND the inner frontier
   advances; a configured `max_iterations` cap and an inner-frontier-stall
   timeout each fail the epoch conservatively (never loop forever), reusing
   the already-registered `RS_1512`/`RS_1513` (stall / max-iteration
   exceeded, `crates/rockstream-types/src/error_code.rs:96,98`).
5. Distributed recursion works: the recursive scope may span shards via
   `Exchange` operators re-partitioning `Arr` once per iteration, with a
   per-iteration inner frontier aggregated cluster-wide (IVM.md §11.1); a
   seeded `SimRuntime` test proves this survives inner-frontier stalls and
   per-shard cost spikes without incorrect results.
6. Lateral joins for nested JSON/arrays compile and execute: DataFusion's
   `LogicalPlan::Unnest` lowers to the existing `PlanNode::Lateral { input,
   func: LateralFunc::Unnest }` (`crates/rockstream-plan/src/lib.rs:260-265,
   465-480`, currently unreachable — falls through to `RS-1013` at
   `crates/rockstream-sql/src/lower.rs:354`); the operator is stateless,
   row-scoped, and a retracted input row retracts exactly the output rows it
   produced (IVM.md §7.12).
7. Hopping windows are implemented and pass the oracle: overlapping,
   fixed-size windows advancing by a `slide_ms < window_size_ms` interval
   assign each row to every window it falls in, using the same state-key
   format, watermark policy, and frontier-aware compaction filter as
   `TumbleWindowOp` (DESIGN.md §6.9 documents TUMBLE/HOP/SESSION as one
   family sharing the `0x01 0xTW op_id(16) window_id(16) key(var)` layout).
8. Session windows are implemented and pass the oracle: dynamic,
   gap-delimited windows that merge when two sessions' events fall within
   `gap_ms` of each other, with correct retraction of a previously-emitted
   session when a late/early row causes two sessions to merge or split.
9. Nexmark q11 (sessionization) is added to the Nexmark suite and its output
   is bit-identical to the DataFusion batch oracle on static snapshots and
   correct under retraction storms, closing the long-standing gap noted in
   NEW_ROADMAP.md:161 ("q11 session windows: v0.50") — `crates/
   rockstream-sql/tests/nexmark/main.rs` currently has no `q11` entry in any
   of its `views` arrays.
10. Ground rules hold: no new code path depends on SlateDB range deletion
    (recursion state cleanup, hop/session window expiry are all
    scan-and-delete or frontier-gated compaction filters, same as
    `TumbleWindowOp::CompactionFilter`); every new state map (recursion
    arrangement, hop-window state, session-window state) has a named upper
    bound, a fill-level metric, and a backpressure/error path; no existing
    test is weakened or `#[ignore]`d; `cargo fmt --check`, `cargo clippy
    --workspace --all-targets -- -D warnings`, `cargo test --workspace`,
    `bash scripts/check-error-codes.sh`, `bash scripts/check-invariant-pairs.sh`,
    and `make e2e` all pass.

### Track A — Recursive CTEs (`WITH RECURSIVE`) and Fixed-Point IVM

#### Slice A1 — Lower `WITH RECURSIVE` SQL into `PlanNode::Recursion`
- Add a `LogicalPlan::RecursiveQuery` match arm to
  `crates/rockstream-sql/src/lower.rs` (before the line-354 catch-all),
  lowering `static_term` → `PlanNode::Recursion.base` and `recursive_term` →
  `.step`, with a compiler-side monotonicity classifier that scans the step
  subtree for `EXCEPT`/aggregate/`DISTINCT`/window/`INTERSECT`/a second
  self-reference and sets `monotone = false` (full-recomputation path) when
  found, `monotone = true` (semi-naive path) otherwise. `max_iterations`
  defaults from a new `RockstreamConfig` field (`recursion_max_iterations`,
  default e.g. 1024, matching DESIGN.md's "typically 1024" comment at
  `crates/rockstream-plan/src/lib.rs:191`).
- Reject unsupported shapes (mismatched recursive-term/stored-output column
  count, multiple co-recursive self-references) with a registered error code
  instead of miscompiling, per IVM.md §11's classification rules.
- Tests: `lower_with_recursive_transitive_closure_to_recursion_node`,
  `lower_with_recursive_classifies_except_term_as_non_monotone`,
  `lower_with_recursive_rejects_column_count_mismatch`.

#### Slice A2 — Semi-naive fixed-point recursion operator
- New `crates/rockstream-ops/src/recursion.rs` implementing `RecursionOp`
  per IVM.md §11's runtime shape (`apply(P_base, Δ)` at iteration 0, then
  `apply(P_step, [Arr@iter-1, Δ@0])` → `distinct` → emit-or-break loop).
  State keyed by a new `RC_DISCRIMINATOR` in
  `crates/rockstream-storage/src/keys.rs` (next unused 2-byte discriminator
  after `TK_DISCRIMINATOR`), matching DESIGN.md §6.8's
  `0x01 0xRC op_id(16) row_hash(16) iteration(4 BE) → i64 weight` layout.
- Bound: named `RECURSION_STATE_LIMIT` (arrangement rows across all
  in-flight iterations of one operator) with a `fill_level()` metric and an
  epoch-backpressure path when exceeded, mirroring
  `TUMBLE_WINDOW_STATE_LIMIT` (`crates/rockstream-ops/src/
  time_window.rs:35`).
- Wire the real non-monotone-delta rejection at its actual call site using
  the already-registered `RS_1009` (see Deferred-Item Audit above); fix the
  four stale `RS-1509` doc references to `RS-1009` in the same slice.
- Tests: `recursion_semi_naive_matches_batch_transitive_closure`,
  `recursion_converges_and_stops_on_empty_delta`,
  `recursion_max_iterations_cap_fails_epoch_conservatively`,
  `recursion_non_monotone_delta_rejected_with_rs_1009`,
  `recursion_state_bound_triggers_backpressure`.

#### Slice A3 — Distributed (cross-shard) recursion

### Track D — Session Windows

#### Slice D8 — Session window operator with gap-based dynamic merging
- Add `PlanNode::SessionWindow { input, time_col, gap_ms,
  late_data_policy }` and `OpNode::SessionWindow { gap_ms,
  late_data_policy }` to `crates/rockstream-plan/src/lib.rs`.
- Extend `time_window.rs` with `SessionWindowOp`: unlike TUMBLE/HOP,
  session-window boundaries are data-dependent — a new event either extends
  an open session (event within `gap_ms` of the session's current end) or
  starts a new one; two sessions merge when an intervening event or
  window-boundary correction closes the gap between them. On merge, the
  operator must retract the two previously-emitted (now-stale) sessions and
  emit one replacement — this is the operator's core correctness property,
  analogous to Top-K's delete-refill delta swap
  (`crates/rockstream-ops/src/topk.rs` pattern) but keyed on dynamic
  boundaries instead of a fixed K.
- Bound: `SESSION_WINDOW_STATE_LIMIT` (open-session count × group-key) with
  its own fill-level metric and backpressure path.
- Tests: `session_window_extends_open_session_within_gap`,
  `session_window_starts_new_session_after_gap`,
  `session_window_merge_retracts_both_and_emits_replacement`,
  `session_window_matches_batch_oracle_under_retraction_storm`,
  `session_window_state_bound_backpressures`.

Resolved SQL surface note (2026-07-19, Track C Slice C6): vendored DataFusion
53.1 in this repo does not expose a native `HOP(...)` TVF/streaming-window
surface we can lower directly. The working HOP surface is:
`... FROM <input> CROSS JOIN generate_series(0, overlap-1) AS slide(slide_idx)
GROUP BY date_bin(INTERVAL '<window>', to_timestamp_millis(event_time_ms -
slide_idx * slide_ms))` where `overlap = window_size_ms / slide_ms`. We use
`to_timestamp_millis(...)` because `slide_idx * INTERVAL '<slide>'` does not
type-check in this DataFusion build.
