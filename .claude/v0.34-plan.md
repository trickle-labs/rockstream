## Vertical Slices

### S1 — Extend SQL Compiler for Time Windows and Top-K

**What:**
- Extend the SQL compiler lowering support in `crates/rockstream-sql/src/lower.rs` to recognize and compile tumbling time window expressions (e.g. using `date_bin` or custom window functions) into `PlanNode::TumbleWindow`.
- Support pattern matching and lowering of rank-filtering query structures (e.g., `ROW_NUMBER() / RANK() OVER (...)` combined with a `rank <= K` filter) into `PlanNode::TopK`.
- Add SQL planner tests to verify that these SQL queries are correctly compiled into their physical plan equivalents.

**Exit test (green):**
- Unit test `test_compile_tumble_window` in `crates/rockstream-sql/src/frontend.rs` — asserts a query with tumbling time windows lowers to `PlanNode::TumbleWindow`.
- Unit test `test_compile_topk` in `crates/rockstream-sql/src/frontend.rs` — asserts a rank-filtering query lowers to `PlanNode::TopK`.

### S2 — Implement q0–q3 Nexmark queries end-to-end (LFS)

**What:**
- Define standard `CREATE VIEW` statements for Nexmark queries q0–q3:
  - `q0` (pass-through `SELECT *` on `bid`)
  - `q1` (currency conversion on `bid` — multiply price)
  - `q2` (selection filter — `MOD(auction, 123) = 0` on `bid`)
  - `q3` (local item suggestion — inner join Auction × Person filtered by state and category)
- In `crates/rockstream-sql/tests/nexmark/main.rs`, implement integration test `test_nexmark_q0_q3_lfs`.
- Bring up `GatewayServer` using LFS-backed `ShardDb`, run DDL `CREATE TABLE` and `CREATE VIEW` queries, insert events via pgwire `INSERT` transactions, and verify view results via `SELECT` and in-process `SUBSCRIBE` change log verification.
- Verify output results are bit-identical to the DataFusion batch oracle.

**Exit test (green):**
- Integration test `test_nexmark_q0_q3_lfs` — registers views q0–q3, ingests events, and verifies `SELECT` and `SUBSCRIBE` results against DataFusion batch oracle.

### S3 — Implement q4–q9 Nexmark queries end-to-end (LFS)

**What:**
- Define standard `CREATE VIEW` statements for Nexmark queries q4–q9:
  - `q4` (average price per category — windowed join + `AVG`)
  - `q5` (hot items — sliding-window bid `COUNT` + top-N)
  - `q6` (average selling price by seller — last-10-auctions window)
  - `q7` (highest bid — tumbling-window `MAX`)
  - `q8` (new-user monitoring — join Person × Auction within event-time window)
  - `q9` (winning bids — join Bid at closing price)
- In `crates/rockstream-sql/tests/nexmark/main.rs`, implement integration test `test_nexmark_q4_q9_lfs`.
- Verify the queries execute correctly under transaction boundary updates, and output matches batch oracle after every event batch.

**Exit test (green):**
- Integration test `test_nexmark_q4_q9_lfs` — registers views q4–q9, ingests event batches, and verifies results against DataFusion batch oracle.
