# v0.59.18 Plan — Lifecycle, Client, Documentation & Backend Test Closure

## Scope and Boundary

Roadmap row (`NEW_ROADMAP.md:1842`): *"Close the existing lifecycle race/restart/recovery, external-client, real-backend, documentation, golden-path, and high-level test program (`TST-007`–`TST-010`). Exercise real Kafka, PostgreSQL, and MinIO paths, run current docs and golden-path scenarios, complete the Core behavior ledger across required proof levels and backends, and enforce zero-hidden-skip behavior."* Proof: *"Lifecycle, client, and backend workflows pass through public surfaces; all golden paths and current docs run; the Core behavior ledger is complete; required tests fail when prerequisites are missing, skipped, or retried instead of reporting green; the public surfaces agree on the observed result."* Backends: `Unit, LFS, MinIO, Postgres, Kafka, TC`. Dependencies: `v0.59.14, v0.59.15, v0.59.16, v0.59.17` (`NEW_ROADMAP.md:73`).

v0.59.18 is the test and public-surface closure release that consolidates all preceding pre-v1 infrastructure (`v0.59.14` golden paths, `v0.59.15` executable docs, `v0.59.16` structured diagnostics, and `v0.59.17` scenario/differential framework) into a unified, fail-closed, zero-hidden-skip verification program:

1. **Lifecycle Race, Restart & Recovery across Real Backends (`TST-007`)**:
   - Close lifecycle race, restart, and recovery verification under real external backends: Apache Kafka / Redpanda, PostgreSQL logical replication (pgoutput), and MinIO (S3) alongside SlateDB on LocalFileSystem (LFS).
   - Exercise crash boundaries across uncommitted L0 SST discard, committed checkpoint restoration, replication slot LSN resumption, 2PC sink commit recovery, and control-plane leader failover.
   - Verify multi-worker lifecycle under shard reassignment, worker drain, and process termination with zero loss, zero duplicate deliveries, and monotone view frontiers.

2. **External-Client Conformance Closure (`TST-008`)**:
   - Execute real client drivers and ORMs against the compiled `rockstream` binary over public pgwire: `tokio-postgres` (Rust async), `psql` (libpq v14 & v16), `psycopg3` (Python 3.12 binary), `node-postgres` (Node 20), `PgJDBC` (Java 21), `SQLAlchemy` (Python async), and `Prisma` (Node ORM/generator).
   - Exercise full wire protocol paths: SCRAM-SHA-256 authentication, simple query protocol, extended query protocol (parse, bind, execute, describe, sync), server-side prepared statements, typed parameter encoding (`TEXT`, `INT4`, `FLOAT8`, `BOOL`), transactions and savepoint rollbacks, named cursors (`DECLARE`, `FETCH`, `CLOSE`), `COPY FROM STDIN` streaming wire path, `LISTEN`/`NOTIFY`, and graceful connection cleanup.
   - Enforce that in-process, pgwire-process, and containerized client drivers agree on identical results for equivalent operations.

3. **Executable Documentation & Golden-Path Scenario Closure (`TST-009`)**:
   - Execute all golden path templates (`local`, `kafka`, `postgres-cdc`) generated via `rockstream init` as end-to-end integration scenarios against the running `rockstream` binary.
   - Verify `rockstream demo` in-memory scenario execution, timing/storage bounds, and deterministic output schema.
   - Execute checked-in documentation snippets and transcripts (`README.md`, `docs/getting-started.md`, schema evolution cookbooks, reference docs) against the live binary and assert bit-identical agreement.
   - Enforce that public surfaces (CLI human output, CLI `--json`, pgwire query rows, system catalog tables, and structured diagnostic occurrences) present a coherent, agreed view of engine state.

4. **Core Behavior Ledger & Zero-Hidden-Skip Closure (`TST-010`)**:
   - Complete the Core behavior ledger in `capabilities.toml` for all 11 `tier = "Core"` capabilities (8 language + 3 connector/sink).
   - Extend the 3 connector/sink capabilities (`connector.postgres-cdc`, `connector.kafka-source`, `sink.kafka`) to define all 5 standard behaviors (`incremental`, `backfill`, `checkpoint_recovery`, `state_growth`, `failure`) with exact statements, proof targets, and paired durability proofs (LFS + MinIO).
   - Extend `scripts/check-capability-contract.py` / `.sh` to validate all 5 behaviors across both language and connector/sink Core capabilities under `--full-semantics`.
   - Implement strict Zero-Hidden-Skip enforcement:
     - In CI / qualification runs (`ROCKSTREAM_REQUIRE_DOCKER=1` / qualification mode), missing environment prerequisites (Docker daemon, container images, network ports, memory/FD limits) MUST fail closed with named `RS-XXXX` errors, never report green or exit 0.
     - In optional local runs where Docker is unavailable, tests must explicitly log a structured skip reason naming the missing prerequisite and capability ID, never silently pass.
     - Introduce `scripts/check-no-hidden-skips.sh` and CI validation gate ensuring no test target produces disguised passes on unexecuted suites.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable: all buffers, scenario event logs, diagnostic journals, and client queues have named bounds, fill-level metrics, and backpressure/error paths.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass; no `--no-verify`. Fix root causes.
- Make only changes this version requires.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

### Explicitly Out of Scope

- No new SQL data types or collation changes — that is `v0.59.19` (`SQL Semantics, PostgreSQL Compatibility & System Limits`) and `v0.59.20` (`Common SQL & Type Completeness`).
- No graceful shutdown daemon signal handlers or `/live`/`/ready`/`/health` HTTP endpoints — that is `v0.59.21` (`Graceful Lifecycle, Shutdown & Health Contract`).
- No deployment profile / Helm / OCI packaging matrix — that is `v0.59.22` (`Supported Platforms & Deployment Profiles`).
- No capacity estimator calibration or threshold signing — that is `v0.59.23` (`Capacity Planning & Estimator Calibration`).
- No final multi-worker RC qualification run — that is `v0.59.24` (`Final Horizontal Scale & Performance Qualification`).
- No new workspace crate.
