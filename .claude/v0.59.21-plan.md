# v0.59.21 Plan — Graceful Lifecycle, Shutdown & Health Contract

## Scope and Boundary

Roadmap row (`NEW_ROADMAP.md:1845`): *"Define SIGTERM/SIGINT, crash, eviction, drain, and role-shutdown behavior; stop new work, finish or abort epochs safely, flush durable state, release leases, close clients, enforce a configurable deadline, and expose structured `/live`, `/ready`, and `/health` endpoints with startup, draining, dependency, and degraded-state semantics."* Proof: *"Binary-level lifecycle tests start a workload, terminate gateway/control/worker roles, and verify committed rows survive, leases move, subscriptions close cleanly, and the old process exits within its deadline; readiness transitions are asserted during startup, dependency loss, and drain, while health responses include role, version, dependencies, and actionable reasons."* Backends: `Unit, LFS, MinIO, TC`. Dependencies: `v0.59.17` (proof deps: `v0.59.17`) (`NEW_ROADMAP.md:76`).

v0.59.21 delivers a complete, operator-grade graceful lifecycle, shutdown protocol, and health observation contract across all RockStream roles (`gateway`, `worker`, `control`, `frontier`, and standalone `all`):

1. **Role-Specific Graceful Shutdown State Machine & Signal Handling**:
   - Install robust OS signal handlers for `SIGTERM` and `SIGINT` (Ctrl-C) across all node roles in daemon and server modes.
   - Enforce explicit role lifecycle states: `Starting` -> `Ready` -> `Draining` -> `Stopping` -> `Terminated` (or `Degraded` / `Unhealthy`).
   - Coordinate role-specific shutdown sequences:
     - **Gateway**: Transition readiness probe to not-ready (`503`), stop accepting new TCP connections on pgwire and webhook listeners, send standard PostgreSQL `57P01` (`admin_shutdown` / `RS-2056`) notice to connected clients, drain in-flight queries and cursors within deadline, close subscriptions cleanly, and terminate.
     - **Worker**: Transition readiness probe to not-ready (`503`), refuse new shard assignments (`RS-3010`), finish current micro-batch epoch flush to durable SlateDB storage or safely abort uncommitted dirty state, flush 2PC sinks, explicitly release shard leases to the control plane, purge exchange channels/multiplexers, and terminate.
     - **Control Plane**: Transition readiness probe to not-ready (`503`), stop accepting worker registrations, cleanly transfer or step down Raft leadership if peers exist, flush topology/lease/migration store snapshots to shared storage, and terminate.
     - **Frontier**: Flush pending watermark updates, notify downstream subscribers, and terminate.
     - **Standalone / All**: Sequence gateway drain -> worker drain -> control shutdown -> metrics server teardown.

2. **Configurable Shutdown Deadline Enforcement & Self-Fencing**:
   - Add `shutdown_timeout_secs` to `ClusterConfig` / `RockstreamConfig` (default: 30s) and CLI flag `--shutdown-timeout-secs`.
   - Implement an asynchronous shutdown watchdog timer. If in-flight work, slow object-store flushes, or stubborn clients exceed the configured deadline, the node logs a fatal timeout occurrence (`RS-3023`), self-fences to prevent split-brain state mutations, and forces process termination without hanging indefinitely.

3. **Structured HTTP Management & Health Endpoints (`/live`, `/ready`, `/health`)**:
   - Expose standard health endpoints on the management HTTP listener (co-located with `/metrics`):
     - **`/live` (Liveness Probe)**: Returns HTTP 200 OK (`{"status":"alive"}`) as long as the process runtime is alive and not deadlocked.
     - **`/ready` (Readiness Probe)**: Returns HTTP 200 OK (`{"status":"ready"}`) only when the node can accept client queries or cluster traffic; returns HTTP 503 Service Unavailable (`{"status":"not_ready","reason":"..."}`) during startup, dependency loss, lease loss, or draining.
     - **`/health` (Structured System Health Probe)**: Returns comprehensive JSON detailing node status (`healthy`, `degraded`, `unhealthy`, `draining`), role, version, commit SHA, uptime, dependency health checks (LFS/MinIO storage, control plane connectivity, Raft quorum, sink availability), active shard counts, and actionable enumerated degradation reasons (`RS-XXXX` codes with dominant causes).

4. **Durable State Preservation & Shard Lease Mobility**:
   - Guarantee crash consistency and committed row survival: on graceful stop or abrupt termination (SIGKILL), all committed SlateDB SSTs and WAL records remain durable across LocalFileSystem (LFS) and MinIO (S3).
   - Verify that gracefully released shard leases become immediately acquirable by surviving workers without waiting for lease timeout.
   - Verify that abruptly terminated worker leases expire cleanly via control-plane heartbeat timeout and are reassigned without data loss or duplicate processing.

5. **Binary-Level Lifecycle & Failure Injection Qualification Suite**:
   - Implement end-to-end integration tests starting live `rockstream` binary processes with active workloads.
   - Inject lifecycle events: `SIGTERM` to gateway, `SIGTERM` to worker, `SIGKILL` ungraceful worker crash, control leader failover, and dependency loss.
   - Assert exact query survival, lease reallocation, subscription closure, readiness transitions, and clean exit within the deadline.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable: all buffers, client sessions, health history, and in-flight drains have named bounds and metrics.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass; no `--no-verify`. Fix root causes.
- Make only changes this version requires.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

- No capacity estimator calibration or threshold signing — that is `v0.59.23` (`Capacity Planning & Estimator Calibration`).

### Matrix C: Lifecycle Termination & Failure Semantics Matrix

| Failure / Lifecycle Scenario | Detection Mechanism | Immediate Invariant Enforced | Durability & State Guarantee | Recovery / Failover Path |
|---|---|---|---|---|
| Graceful Shutdown (`SIGTERM`) | OS signal caught by `ShutdownCoordinator` | Stop admitting new work; `/ready` returns 503 | Current epoch flushed or cleanly aborted; SlateDB WAL synced | Leases explicitly released; peers take over instantly with zero lease delay |
| Abrupt Termination (`SIGKILL` / Panic) | Process abruptly exits / dies | OS reclaims sockets and memory | Committed SlateDB SSTs and WAL records survive on LFS/MinIO | Control heartbeat timeout (5s) expires; leases reassigned; WAL replayed |
| Worker Drain Command | Operator CLI / RPC `run_cluster_workers_drain` | Worker marks lifecycle `Draining`; rejects new shards (`RS-3010`) | Shards migrated one-by-one with monotonic frontier preservation | Target workers acquire migrated shards; drained worker exits cleanly |
| Network Partition / Control Disconnect | Heartbeat timeout to control plane | Worker self-fences (`RS-3011`); rejects writes | Uncommitted dirty state discarded; committed SSTs intact | Control reassigns shards after lease expiry; partitioned worker halts writes |
| Shutdown Deadline Expiry | Asynchronous watchdog timer reaches deadline | Worker/Gateway logs `RS-3023` and calls `std::process::exit(1)` | Committed data already flushed survives; prevents stale split-brain writes | Orchestrator cleans up process; peer workers recover from durable state |

## 4. Vertical Slices

1. **Slice S1: Unified Lifecycle Coordinator, Signal Handling & Configurable Watchdog (`crates/rockstream-types`, `crates/rockstream-cli`)**:
   - Define `LifecycleState` enum (`Starting`, `Ready`, `Degraded`, `Draining`, `ShuttingDown`, `Terminated`) and `NodeHealthStatus` in `rockstream-types`.
   - Add `shutdown_timeout_secs: u64` (default: 30) to `ClusterConfig` and `--shutdown-timeout-secs` CLI override.
   - Implement `ShutdownCoordinator` in `rockstream-cli` installing multi-signal listeners (`SIGTERM`, `SIGINT`) and managing graceful drain ordering with an asynchronous timeout watchdog enforcing hard termination on deadline expiry.

2. **Slice S2: Structured Management HTTP Server (`/live`, `/ready`, `/health`) (`crates/rockstream-cli`, `crates/rockstream-types`)**:
   - Extend `metrics_server.rs` to serve `/live`, `/ready`, and `/health` alongside `/metrics` on the configured `--metrics-addr`.
   - Implement `HealthReporter` collecting component status (storage backend, control connectivity, Raft quorum, sink health, replication lag, active shard counts) and formatting structured JSON responses matching Matrix B.
   - Wire dynamic readiness transitions: `/ready` returns `200 OK` when healthy/degraded, and `503 Service Unavailable` when starting, dependency-lost, or draining.

3. **Slice S3: Gateway Server Connection Drain & Protocol Notice (`crates/rockstream-gateway`)**:
   - Implement graceful shutdown handler on `GatewayServer`:
     - Drop listener socket to reject new TCP connections immediately.
     - Send PostgreSQL Notice response `57P01` (`admin_shutdown` / `RS-2056`) to all active client sessions.
     - Await in-flight queries and cursors up to a per-query grace period.
     - Cleanly terminate background subscription listeners and close client channels.

4. **Slice S4: Worker Epoch Completion, Dirty State Abort, & Shard Lease Release (`crates/rockstream-runtime`, `crates/rockstream-storage`)**:
   - Implement graceful drain on `WorkerClient` and `DataPlane`:
     - Transition to `Draining` and reject new shard assignments (`RS-3010`).
     - Finish the currently active micro-batch epoch, flush memtables and WAL to SlateDB storage (LFS and MinIO), and update local frontiers; or cleanly discard uncommitted partial state without corrupting SSTs.
     - Flush 2PC sink commit batches.
     - Issue explicit shard lease release RPCs to the control plane, allowing peer workers to acquire shards immediately.
     - Purge and teardown exchange client pools and multiplexers.

5. **Slice S5: Control Plane Drain Handshake, Leader Stepdown & Store Durability (`crates/rockstream-control`)**:
   - Implement graceful shutdown on `ControlService`:
     - Refuse new worker registrations and DDL operations.
     - If running in a multi-node Raft group and currently leader, cleanly step down or transfer leadership to a follower.
     - Flush topology, shard lease, and migration stores to shared object storage (`--control-shared-storage`).
     - Persist audit log entries (`server.stopping`, `server.stopped`) and close RPC listeners.

6. **Slice S6: Binary-Level End-to-End Lifecycle & Fault Injection Qualification Suite (`crates/rockstream-cli/tests`, `crates/rockstream-gateway/tests`)**:
   - Implement comprehensive binary lifecycle tests:
     - Gateway `SIGTERM` test: Starts real `rockstream` binary, executes continuous SQL workload, issues `SIGTERM`, verifies existing queries complete or receive `57P01`, verifies `/ready` returns 503, and verifies process exits 0 within deadline.
     - Worker `SIGTERM` test: Starts worker binary with active streaming pipeline, issues `SIGTERM`, verifies committed rows are durable in SlateDB, leases are released to control, and surviving worker resumes without row loss or duplicates.
     - Worker `SIGKILL` test: Kills worker abruptly, verifies control detects lease expiry, reassigns shard, and committed state recovers on LFS and MinIO.
     - Health & Readiness endpoint test: Asserts `/live`, `/ready`, and `/health` JSON structure and HTTP codes across startup, steady-state, induced dependency loss, and drain.

7. **Slice S7: Single-Source Documentation Generation, Limits Update & Workspace Quality Gates (`rockstream-docgen`, `docs/`, `scripts/`)**:
   - Update `docs/limits.md`, `docs/architecture.md`, and generate `docs/lifecycle.md` documenting signal semantics, drain protocols, shutdown timeouts, and health endpoints.
   - Run all workspace quality gates (`scripts/check-capability-contract.sh --full-semantics`, `scripts/check-product-surface.sh`, `scripts/check-documentation.sh`, `scripts/check-no-hidden-skips.sh`, `scripts/check-dispatch-wiring.sh`, `scripts/check-exit-criteria.sh`).

## 6. Durability and Coordination Commitments

**Durability (LFS & MinIO)**:
- Every role shutdown (graceful `SIGTERM` or abrupt `SIGKILL`) must guarantee that all globally committed records, shard snapshots, arrangement SSTs, and WAL logs remain crash-consistent and bit-identical across LocalFileSystem (`LFS`) and MinIO (`S3` object storage).
- Shard recovery following graceful worker release or abrupt lease timeout must restore identical view state without duplicate row emission or lost updates.

**Coordination (`SimRuntime` / Deterministic Simulation & `buggify!()`)**:
- Node lifecycle transitions, heartbeat timeouts, lease reassignments, and drain progress must operate deterministically under `SimRuntime`.
- `buggify!()` fault injection must simulate delayed drain responses, dropped lease release RPCs, and slow storage flushes, verifying that watchdog timers enforce fail-closed self-fencing without split-brain anomalies.
