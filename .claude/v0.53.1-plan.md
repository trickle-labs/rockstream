# v0.53.1 Plan — Mutating Operator Commands: Lifecycle Control, Support Bundle & Safe-by-Default Semantics

## Scope and Non-Negotiable Invariants

This version implements the mutating operator CLI surface split out from v0.53 by the 2026-08-12 realism review. It delivers cluster lifecycle control, entity mutation, support bundle diagnostics, and safe-by-default operation semantics with authorization, confirmation, idempotency, and audit logging.

- **One binary, one CLI, one config**: All subcommands are built into the single `rockstream` binary. `main` remains runnable through it across all roles.
- **Mutating command surface**:
  - `rockstream view {pause, resume, query, subscribe}`
  - `rockstream source {pause, resume, drop}`
  - `rockstream schema {create, drop}`
  - `rockstream workload {create, alter, drop}`
  - `rockstream cluster workers drain <worker_id> [--yes]`
  - `rockstream shard migrate <shard_id> --to <worker_id> [--yes]`
  - `rockstream checkpoint restore <checkpoint_id> [--storage <dir>] [--yes]`
  - `rockstream support bundle [--view=<name>] [--since=<duration>] [--out=<path>]`
- **Identity & RBAC authorization**: Every mutating invocation authenticates using the identity presented by the transport (`ClientIdentity`), authorizes against the already-shipped RBAC (`Role::Viewer`, `Role::PipelineOwner`, `Role::Admin`), and fails closed with `RS-2401` on unauthorized access.
- **Audit trail**: Every mutating invocation (both successful mutations and denied attempts) emits exactly one durable `AuditEvent` naming the operator/actor, timestamp, action, target resource, and exact invocation arguments.
- **Idempotency & explicit refusal**:
  - Re-issuing an operation against an identical target reaches an identical state or returns a documented refusal code.
  - Re-issuing `shard migrate` against an in-flight migration returns an enumerated refusal (`RS-5030`), never a second parallel migration.
  - Re-issuing `cluster workers drain` against a draining worker returns idempotent progress status.
- **Safe-by-default confirmation**: Destructive commands (`view drop`, `source drop`, `schema drop`, `workload drop`, `cluster workers drain`, `shard migrate`, `checkpoint restore`) require interactive confirmation prompt (`[y/N]`) or explicit `--yes` flag. Non-interactive or unconfirmed destructive calls refuse with `RS-0005`.
- **Support bundle diagnostics**: `rockstream support bundle` produces the v0.45.5 diagnostic artifact on demand with secret redaction (passwords, tokens, keys masked as `[REDACTED]`) and a documented size cap (< 10MB), closing the stale `rockstream support-bundle` reference in `docs/sre-operations.md`.
- **View subscribe streaming**: `rockstream view subscribe` provides a long-lived streaming client inheriting `RS-2006` cursor and retention semantics (`--from-epoch <n>` / `--snapshot`).
- **No SlateDB range deletion**: All storage mutations and cleanup paths use point-delete or scan-and-delete.
- **Prefix every shell command with `rtk`**: Enforced throughout.

### 2. Error Code & Safeguard Matrix

| Error Code | Meaning | Trigger Scenario | Documented Remedy |
|---|---|---|---|
| `RS-0005` | Destructive command confirmation required | Destructive CLI command executed in non-interactive environment without `--yes` | Pass `--yes` for script execution or answer `y` at the prompt |
| `RS-1001` | Entity not found | Dropping or querying a non-existent view or schema | Check name with `rockstream view list` or `rockstream schema list` |
| `RS-1004` | Entity already exists | Creating schema/table that already exists | Use unique name or inspect with `rockstream schema show` |
| `RS-1005` | Workload not found | Altering or dropping non-existent workload | Inspect workloads with `rockstream workload list` |
| `RS-1006` | Workload already exists | Creating an existing workload | Use distinct name or modify existing with `workload alter` |
| `RS-1007` | View already paused | Pausing a view that is currently in PAUSED state | Check view status with `rockstream view status` |
| `RS-1008` | View not paused | Resuming a view that is already RUNNING | Check view status with `rockstream view status` |
| `RS-1014` | Workload drop rejected | Attempting to drop workload with assigned views | Reassign or drop dependent views first |
| `RS-2006` | Epoch before retention | Subscribing from epoch outside retention window | Subscribe with `--snapshot` or more recent epoch |
| `RS-2401` | Permission denied | Principal lacks required RBAC role | Request elevated RBAC role (PipelineOwner / Admin) |
| `RS-4009` | Source not found | Pausing, resuming, or dropping non-existent source | Inspect sources with `rockstream source list` |
| `RS-5030` | In-flight migration conflict | Re-issuing shard migration while migration is in progress | Wait for active migration to complete or inspect status |
