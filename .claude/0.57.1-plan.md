# v0.57.1 Phase 2 Plan — Core Operator Semantics

## Scope and boundary

v0.57.1 makes the existing v0.57 `Core` language inventory honest: every
retained Core item gets five precise, generated/documented statements
(incremental, backfill, checkpoint/recovery, state growth, and failure), each
linked to a passing end-to-end proof. An item without that evidence is demoted
with a recorded reason; no statement is weakened to retain a tier.

This is a contract/documentation/gate version, not an engine, SQL syntax,
pgwire, durability, or coordination implementation version. `capabilities.toml`
is the inventory authority (Core language records at lines 66–174);
`docs/language-features.md:77–87` is the human-facing inventory. The semantic
definitions must agree with `DESIGN.md:450–465` (Z-set deltas and `f^Δ`) and
`IVM.md:1056–1088,1232–1263` (snapshot-to-delta bootstrap, reconciliation, and
the incremental-equals-batch property).

No new queue, buffer, scan window, cleanup path, command, SQL keyword, or
binary is introduced. The resulting `main` remains the same `rockstream`
binary. Existing structural coverage remains the range-delete guard, including
`crates/rockstream-storage/src/shard_db.rs::no_range_delete_api_exposed` and
`crates/rockstream-gateway/tests/gateway_proof_tests.rs::commit_write_batch_uses_no_range_delete`;
this version must not add a SlateDB range-delete dependency.

## Semantic source and enforcement design

1. Extend each retained `kind = "language", tier = "Core"` record in
   `capabilities.toml` with a structured five-row semantic ledger:
   `incremental`, `backfill`, `checkpoint_recovery`, `state_growth`, and
   `failure`. Each row contains the exact bounded claim, a `proof` target in
   `path::test_name` form, and, where state is retained, the explicit bound,
   metric, and bound-hit error/backpressure outcome. Do not add a free-form
   hand-maintained inventory.
2. Update `scripts/generate-capability-matrix.py` to render the ledger into a
   generated Core-semantics block in both `docs/capability-matrix.md` and
   `docs/language-features.md`. The latter keeps explanatory prose outside the
   generated block; the extracted generated blocks must be byte-identical.
3. Extend `scripts/check-capability-contract.py` with `--full-semantics`.
   Full mode rejects: absent/duplicate behavior rows; empty statements or
   proofs; a proof target that does not resolve to a test; a Core language item
   missing any of the five rows; a generated-block mismatch; or a tier decision
   without an item, old/new tier, reason, and evidence. Normal v0.57 contract
   checks remain intact.
4. Change the contract version only as required for v0.57.1 and make
   `scripts/check-capability-contract.sh` invoke full mode. Expand
   `scripts/check-capability-contract.test.sh` with isolated mutation fixtures
   deleting one behavior, deleting its proof link, corrupting a generated
   semantics block, and omitting a tier-decision reason. Each must fail with
   the exact expected violation; the pristine tree must pass.
5. Record at least one actual audit outcome in the structured tier-decision
   ledger. It may be an up-tier or a demotion, but it must be evidence-led; a
   capability that cannot satisfy all five claims is demoted rather than
   documented aspirationally.

## Durability and coordination commitments

No new commit, replay, checkpoint, compaction, WAL, or distributed-coordination
path is introduced, so no new durability or seeded `SimRuntime` slice is
applicable. The documentation makes claims about existing stateful paths,
however, so it may link a checkpoint/recovery behavior only after both an LFS
test and a TestContainers MinIO test prove the same transcript. The plan's
required pairs are aggregate, join, window, view-DAG, subscription, and DML
whenever those entries retain a durable claim. The test name, store mode, and
exact output transcript are stored in the semantic ledger. No `buggify!()`
test is required unless implementation reveals a new coordination path; if it
does, add a seeded `SimRuntime` test with `buggify!()` before retaining the
claim.
