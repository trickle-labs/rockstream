# v0.59.17 Plan — Public-Path Scenario & Differential Framework

## Scope and Boundary

Roadmap row (`NEW_ROADMAP.md:1841`): *"Add typed scenario DSL (`TST-001`–`TST-006`), process/Docker drivers, typed transcripts, independent oracles, capability proof levels, differential and metamorphic suites, and reproducibility artifacts."* Proof: *"Every Core capability meets minimum proof level; differential corpus passes; injected mismatches produce minimized reproducible artifacts."* Backends: `Unit, LFS, MinIO, Postgres, Kafka, TC`. Dependency: `v0.59.13` only (`NEW_ROADMAP.md:72`).

This version is the one that **invents** "capability proof level" as a concept — no prior canonical definition exists anywhere in the repo (`ARCHITECTURE.md`/`DESIGN.md` have zero hits; the phrase appears only in the `NEW_ROADMAP.md:1841`/`1842` rows). Two *forward, unreconciled* draft enumerations exist later in the roadmap (§4.2's `proofs` list at `NEW_ROADMAP.md:2094-2155` — `unit/oracle/pgwire/lfs_recovery/minio_recovery/multi_worker/upgrade/performance`; §53's legend at `NEW_ROADMAP.md:3774-3808` — `U/O/L/M/S/F/P/D/Q`). v0.59.17 must define its own concrete, minimal level scheme now (Matrix A below) without waiting for or attempting to reconcile those later, still-abstract drafts — reconciliation is a v0.60+ concern, out of scope here.

1. **Typed scenario DSL (`TST-001`)**: `Scenario` / `ScenarioStep` / `ExpectedTranscript` types in a new `scenario` module of `crates/rockstream-oracle` (the existing home of independent-oracle harness code, already a normal — non-dev — dependency of `rockstream-gateway`, `rockstream-sim`, and `rockstream-sql`; see `crates/*/Cargo.toml` `rockstream-oracle = { ... }` lines). No new workspace crate — extending an existing test-support crate avoids workspace sprawl the Ground Rules forbid.
2. **Process/Docker drivers (`TST-002`)**: one `ScenarioDriver` trait with `InProcessDriver`, `PgwireProcessDriver` (generalizing the existing compiled-binary + real Postgres-client pattern in `crates/rockstream-gateway/tests/driver_matrix_tests.rs:471-566`), and `DockerDriver` (generalizing the existing `docker_available()`/`REQUIRED_CONTAINER_IMAGES` gating in `crates/rockstream-test-support` and `crates/rockstream-sim/src/qualification/env_check.rs`, plus the Postgres/Kafka/MinIO TestContainers helpers already in `crates/rockstream-connectors/tests/common/mod.rs:37-79` and `crates/rockstream-storage/tests/minio_backend.rs:174+`).
3. **Typed transcripts (`TST-003`)**: a new `ScenarioTranscript` struct — deliberately **not** named `Transcript` alone, because `docs/adr/0003-transcript-ownership.md` already fixes "transcript" to mean a checked-in documentation command-transcript owned by its executable doc test, and `capabilities.toml`'s `behavior[].statement` prose (e.g. "reflected in the same SELECT transcript") uses the word informally. `ScenarioTranscript` is a distinct, additional typed artifact and must not be conflated with either existing usage.
4. **Independent oracles (`TST-004`)**: one `Oracle` trait unifying the three existing, currently-fragmented oracle implementations: `crates/rockstream-oracle/src/harness.rs:30` (`assert_oracle_noop`), `crates/rockstream-test-support/src/external_harness.rs:48,95` (`ProcessIsolationAuditor`, `MultisetOracle`), and `crates/rockstream-sim/src/qualification/oracle_auditor.rs:27` (`OracleAuditor`). The unification must encode, as an enforced contract test, the exact failure mode this project already found and fixed once: `sign-offs/scalability-value-review-v0.59.7.md` (RED) documents `MultisetOracle`'s original test as self-referential — it "validat[ed] a small in-memory aggregate fixture by passing its own expected result back to the oracle, not output from a running engine process." That review was resolved in v0.59.8 (`evidence/r1-local/`), but the *lesson* — an oracle must compute ground truth from an independently sourced input, never echo back the value under test — has never been made an enforced, generic rule. This version makes it one.
5. **Capability proof levels (`TST-005`)**: extend the existing `[[capability]]` schema in `capabilities.toml` (currently: `id, kind, name, tier, reachability, dispatch, proof, documentation, behavior[]` with per-behavior `paired_proof` already used for LFS+MinIO pairing, e.g. lines 144/161/193) with `proof_levels_achieved` (list) and `min_proof_level` (derived from `tier`). Extend `scripts/check-capability-contract.py`/`.sh` (the existing v0.57.1 gate, DoD-listed in `sign-offs/v0.59.13.md`) to enforce that every `tier = "Core"` capability's `proof_levels_achieved` is a superset of its `min_proof_level` set.
6. **Differential and metamorphic suites (`TST-006`)**: differential — compare a RockStream scenario's `ScenarioTranscript` against an independently obtained reference transcript (a real PostgreSQL instance for the 8 SQL-surfaced Core capabilities; the real source/sink system itself for the 3 connector/sink Core capabilities). Reuse whichever Postgres image each existing suite already pins (`postgres:14-alpine`/`16-alpine` in `driver_matrix_tests.rs`, `postgres:11-alpine` for CDC in `connectors/tests/common/mod.rs:42`) — **do not** adopt v0.59.19's forthcoming `postgres:18.0@sha256:...` pin early; that pin and its rationale belong to v0.59.19 (`NEW_ROADMAP.md:1843`), and pulling it forward would be scope creep and a duplicate source of truth. Metamorphic — define relations (delta-order commutativity, replay idempotence, filter-superset containment) checked over the same scenario corpus.
7. **Reproducibility artifacts**: extend `crates/rockstream-sim/src/soak.rs`'s existing `SeedCorpus`/`RegressionSeed` (lines 19-145) — described in-source as holding "minimized failing seeds from previous soak runs that block release until all replay cleanly" — to also capture minimized, replayable scenario-mismatch artifacts, not only `SimRuntime` fault-seed regressions.

**Out of scope** (explicitly, so it is not silently expanded or silently dropped):
- No new SQL language surface, no new admitted types — that is v0.59.19+ (`SQL Semantics, PostgreSQL Compatibility & System Limits`).
- No change to `contracts/sql-type-matrix.toml`'s semantics; it may be *read* as a corpus source for differential scenarios, exactly as `SqlContractContributor` already reads it for `rockstream-docgen` (`.claude/v0.59.13-plan.md`).
- No pinning of the authoritative differential PostgreSQL version/digest — that is v0.59.19's `DOC-*` work; this version reuses the ad hoc images already checked into test files.
- No lifecycle race/restart/recovery closure, no external-client conformance closure, no zero-hidden-skip enforcement — that is v0.59.18 (`TST-007`–`TST-010`).
- No new workspace crate.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk`.
- One binary, one CLI, one config — this version adds no production dispatch surface, so this rule bounds it to: no new crate is linked into the `rockstream` binary; all new code lives in existing test-support crates (`rockstream-oracle`, `rockstream-test-support`, `rockstream-sim`).
- No code path may depend on SlateDB range deletion.
- Unbounded in-memory accumulation is never acceptable — `ScenarioTranscript` and `SeedCorpus`/mismatch-artifact storage need a named upper bound (event count / byte size) and an explicit truncation-or-error behavior, not an unbounded `Vec`.
- Do not weaken, skip, or delete tests to make a build pass; no `--no-verify`.
- Make only changes this version's Scope requires.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this Scope (see §1).

### Matrix A: Proof-Level Legend (defined by this version)

| Level | Proves | Backend | Driver | Existing precedent |
|---|---|---|---|---|
| L0 — Unit | In-process assertion of the capability's own behavior | Unit | `InProcessDriver` | Already present for all 11 Core capabilities (`capabilities.toml` `proof` field) |

8. **Metamorphic suite (`TST-006`, part 2).** Define and implement the metamorphic relations (delta-order commutativity, replay idempotence, filter-superset containment) against the same corpora. One metamorphic test per Matrix B row.
9. **Reproducibility artifacts.** Extend `crates/rockstream-sim/src/soak.rs`'s `SeedCorpus`/`RegressionSeed` to also capture minimized scenario-mismatch artifacts (not only `SimRuntime` fault-seed regressions); add the mutation tests in Matrix D, including a `SimRuntime`+`buggify!()` seeded scenario test with new fault IDs registered in `fault_model.rs`.
