## 1. Deferred-Item Audit

Audited all prior sign-offs (`sign-offs/v0.1.md` through `sign-offs/v0.51.10.md`):

1. **Overlapping Scope Pickups for v0.51.11**:
   - **Live Per-Operator Statistics for `EXPLAIN INCREMENTAL ANALYZE` (Area C)**: In `v0.45` / `v0.45.1`, `EXPLAIN INCREMENTAL ANALYZE` was stubbed in `crates/rockstream-gateway/src/server.rs` by instantiating a fresh, empty `ControlService(TopologyCatalog::new())` and calling `collect_operator_stats(0)`, returning empty/zero stats. This version (v0.51.11) explicitly picks up live per-operator statistics collection from running topologies/metrics registry and wires it end-to-end to `EXPLAIN INCREMENTAL ANALYZE <view>`.
   - **Pipeline Stall Diagnostics & Wire Localization (Area C)**: In `v0.20`–`v0.31` / `v0.45`, pipeline frontiers were recorded internally per operator/shard, but an operator could not query why an epoch $N$ was stalled across shards/operators without inspecting Rust source code or log tracebacks. This version (v0.51.11) explicitly exposes per-operator/per-shard frontier positions, the slowest-advancing input, and the operator holding back the committed frontier over PGWire (`SHOW PIPELINE STALLS`, `SHOW FRONTIERS`) and `/metrics`.
   - **Read-Only Intermediate Arrangement Peek (Area C)**: In `v0.25` / `v0.45`, `DbReader` was added for cross-shard snapshot reads, but wire clients had no direct read-only inspection query for intermediate operator Z-set state. This version (v0.51.11) explicitly adds `SHOW ARRANGEMENT <view> <op_id> <key>` via `DbReader` to inspect live intermediate Z-set weights without perturbing execution.

2. **Non-Overlapping Prior Deferrals (Flagged for Follow-up Versions)**:
   - **v0.51.12**: New operational edge-case specs (quota exhaustion edge handling, source failure, object-store brownout, misconfiguration, late data).
   - **v0.51.13**: Genuinely multi-shard and cap-free ad hoc query execution.
   - **v0.55**: Full operator CLI + IVM arrangement debugger (v0.51.11 delivers the runtime data and minimal inspector those tools need).

No undocumented deferral was dropped. All overlapping scope items are fully incorporated into this plan.

## 5. Test Commitments & Oracle Property Tests

- **Op-Stats Oracle Property Test:** For any pipeline run $R$, per-operator stats returned by `EXPLAIN INCREMENTAL ANALYZE` match independently recorded metric snapshots $M(op)$ within a 1% tolerance:
  $$\forall op, \quad \text{Stats}_{\text{Explain}}(op).\text{rows\_per\_s} = M(op).\text{rows\_per\_s}$$
  *Test:* `crates/rockstream-gateway/tests/explain_analyze_opstats_tests.rs`.
- **Stall Localization Oracle Property Test:** For any wedged pipeline state where operator $op^*$ or shard $s^*$ is artificially delayed, the diagnostic surface uniquely identifies $(op^*, s^*)$ as `is_holding_back_commit = true`:
  $$\text{StallReport}() = \{ (op^*, s^*) \mid \text{is\_holding\_back\_commit} = \text{true} \}$$
  *Test:* `crates/rockstream-gateway/tests/pipeline_stall_diagnostics_tests.rs`.
- **Arrangement Peek Oracle Property Test:** For any view key $k$, the weight $W(k)$ returned by `SHOW ARRANGEMENT` via `DbReader` equals the ground-truth Z-set weight $Z(k)$ computed by the reference batch model:
  $$W_{\text{SHOW ARRANGEMENT}}(k) = Z_{\text{Batch}}(k)$$
  *Test:* `crates/rockstream-gateway/tests/arrangement_peek_tests.rs`.
