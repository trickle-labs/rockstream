### S4 — Multi-shard `MultiShardReader` pinned to vector frontier

**Files**: `crates/rockstream-gateway/src/multi_shard_reader.rs`

**Change**:
```rust
pub struct MultiShardReader {
    /// One reader per shard, all opened at `pinned_frontier`.
    shards: Vec<Arc<ShardReader>>,
    /// The ClusterFrontier epoch at which all shard readers are pinned.
    pinned_frontier: u64,
    /// Bound: max rows that can be held in memory across all shards.
    ///
    /// Invariant: `total_rows_in_flight <= max_in_flight_rows`.
    /// Backpressure: if exceeded, `scatter_read` returns `GatewayError::ResultSetTooLarge`.
    max_in_flight_rows: usize,
    /// Fill-level metric: tracks current rows in flight.
    rows_in_flight: Arc<AtomicUsize>,
}

impl MultiShardReader {
    pub fn new(shards: Vec<Arc<ShardReader>>, pinned_frontier: u64, max_in_flight_rows: usize) -> Self
    pub async fn scatter_read(&self, view_name: &str, limit: Option<usize>) -> Result<Vec<RecordBatch>, GatewayError>
}
```

**Bound annotation**: `max_in_flight_rows` is the named upper bound for the in-memory result scatter. Default: 1,000,000 rows. Fill-level is tracked by `rows_in_flight`. Backpressure: returns `GatewayError::ResultSetTooLarge` when exceeded.

Scatter algorithm:
1. Compute per-shard limit = `ceil(limit / shard_count)` to avoid over-fetching.
2. Open a `scan_prefix(view_output/{view_name}/)` on each shard in parallel (`tokio::join_all`).
3. Merge batches (union semantics — view outputs are already partitioned, no dedup needed).
4. Truncate to global `limit`.

**Green gate**: `multi_shard_reader_pinned_to_frontier` test — creates two LFS shards each holding half the view rows, constructs `MultiShardReader`, asserts merged result contains all rows.

### S6 — Isolation level handling + RS-2003

**Files**: `crates/rockstream-gateway/src/session.rs`

**Change**:
Add `SessionState` struct:
```rust
pub struct SessionState {
    /// None = READ COMMITTED (pin per-statement).
    /// Some(epoch) = REPEATABLE READ (pin at BEGIN).
    pub pinned_frontier: Option<u64>,
    pub isolation_level: IsolationLevel,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum IsolationLevel {
    ReadCommitted,
    RepeatableRead,
    Serializable,
}
```

Statement processing:
- `SET TRANSACTION ISOLATION LEVEL READ COMMITTED` → `session.isolation_level = ReadCommitted; CommandComplete("SET")`
- `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ` → `session.isolation_level = RepeatableRead; CommandComplete("SET")`
- `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE` → return `ErrorResponse` with SQLSTATE `25001` (active SQL transaction) and error message `"[RS-2003] isolation.serializable_not_supported: SERIALIZABLE isolation is not supported; use READ COMMITTED or REPEATABLE READ"`
- `BEGIN` → if `RepeatableRead`, pin `session.pinned_frontier = current_published_frontier()`
- `COMMIT` / `ROLLBACK` → clear `session.pinned_frontier`
- Statement execution: if `pinned_frontier.is_some()`, use that; else use current `published_frontier()`

**Green gate**: `proof_serializable_returns_rs2003` passes — `tokio-postgres` client issues `SET TRANSACTION ISOLATION LEVEL SERIALIZABLE`, asserts the returned `DbError` message contains `"RS-2003"`.

### S7 — COPY OUT + Terminate

**Files**: `crates/rockstream-gateway/src/protocol.rs`

**Change**:
1. `COPY <view> TO STDOUT` query → enter COPY OUT mode:
   - Send `CopyOutResponse` (binary or text format; text CSV for v0.23).
   - Stream row data as `CopyData` messages (one row per message, tab-separated).
   - Send `CopyDone` + `CommandComplete("COPY N")`.
2. `Terminate` message → flush pending writes, close TCP connection cleanly.

**Bound annotation**: COPY OUT is streaming — at most one row is buffered per `CopyData` message. No unbounded accumulation.

**Green gate**: `copy_out_streams_view_rows` unit test passes — COPY OUT from a 3-row view returns exactly 3 CopyData messages followed by CopyDone.

## 5. Coordination Slices

New coordination path: multi-shard `scatter_read` pinned to a published `ClusterFrontier` epoch. This is a **read-only** coordination path — the gateway observes an already-committed frontier; it cannot advance or revert it.

| New coordination path | `buggify!()` site | `SimRuntime` test |
|---|---|---|
| Multi-shard read at pinned frontier (reads from N shards simultaneously) | No new buggify needed — reads are idempotent and use an already-committed frontier. No fault injection path exists here. | `multi_shard_reader_pinned_to_frontier` (S4) verifies that two shards with partial data each return their subset, and the merged result is complete and causally consistent at the pinned epoch. |

No new distributed-coordination protocol is introduced (no election, no 2PC, no fence). The existing `buggify!()` annotations in `rockstream-runtime` and `rockstream-connectors` continue to cover the write path.
