## Key Design Decisions

**Storage key format** (DESIGN.md §6.7):
```
Input arrangement:
  [0x01 (OpState)][0x57,0x4E ('WN')][op_id:8][part_key_bytes][order_key_bytes][row_id:16]
  → input row bytes

Output cache (OpIndex, for retraction on next recompute):
  [0x02 (OpIndex)][0x57,0x4E ('WN')][op_id:8][part_key_bytes][row_hash:16]
  → output row bytes
```
`order_key_bytes` encodes i64 columns sort-preserving (XOR `0x8000_0000_0000_0000`, big-endian),
so a prefix scan over `[0x01][WN][op_id][part_key]` returns rows sorted by order_key naturally.

**Recomputation strategy**: partition-based recomputation for ALL functions in v0.11
(PartitionRecompute). When any row in a partition changes: read all rows via arrangement
prefix scan, apply delta to in-memory view, sort by order_key, evaluate window function
batch-wise, diff against output cache, emit retract+insert deltas, persist new state.
`SlidingAggregate` (segment-tree) is reserved for a future optimization pass.

**Named bound**: `WINDOW_PARTITION_THRESHOLD: usize = 10_000` rows per partition.
- `fill_level()` = total rows across all partitions in the arrangement.
- `oversized_partition_keys()` = Vec of partition key bytes that exceeded threshold.
- Backpressure: epoch-level backpressure from scheduler (same as existing ops).
- `RS-5023`: NOTICE emitted in EXPLAIN when any partition exceeds threshold at runtime.

**Window functions in scope** (v0.11): ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD,
SlidingSum, SlidingAvg. `Ntile` is defined but returns `RS-1016` unsupported in v0.11.

**SQL lowering RS codes**:
- `RS-1016`: unsupported window function
- `RS-5023`: oversized partition NOTICE in EXPLAIN

### Slice 2 — WindowOp core + all window functions
**File**: `crates/rockstream-ops/src/window.rs`

```rust
pub const WINDOW_PARTITION_THRESHOLD: usize = 10_000;

pub struct WindowOp {
    schema: SchemaRef,
    window_exprs: Vec<WindowExpr>,
    db: Option<(Arc<Db>, u64)>,          // (db, op_id) — None = in-memory
    fill_level: Arc<AtomicUsize>,
    oversized_partitions: Vec<Vec<u8>>,  // partition keys that exceeded threshold
}
```

- `WindowOp::new(schema, window_exprs) -> Self` — in-memory (no db)
- `WindowOp::new_with_db(schema, window_exprs, db, op_id) -> Self` — LFS-backed
- `WindowOp::process_epoch(&mut self, delta: ZSet, epoch: u64) -> Result<ZSet, OpError>`
  - Collect affected `part_key` bytes from delta rows (from partition_by columns)
  - For each affected partition:
    1. Read existing arrangement rows (`window_arr_partition_prefix`)
    2. Apply delta (insert/delete rows by row_id)
    3. Sort remaining rows by order_key
    4. Evaluate each `WindowFunc` batch-wise → compute output column values
    5. Read previous output (`window_prev_output_partition_prefix`)
    6. Diff: retract previous output, emit new output
    7. Persist updated arrangement rows
    8. Persist new output cache (delete old, write new)
    9. If partition size > WINDOW_PARTITION_THRESHOLD: record in oversized_partitions
  - Update `fill_level` = total rows across all partitions
- `fill_level() -> usize`
- `oversized_partition_keys() -> &[Vec<u8>]`

Window function batch evaluator `eval_window_batch`:
- **RowNumber**: 1-based sequential row position in sorted partition
- **Rank**: 1 + # rows with strictly smaller order_key (ties get same rank, next rank has gap)
- **DenseRank**: as Rank but consecutive (no gaps)
- **Lag { offset }**: value at position (i - offset); NULL/zero if out of bounds
- **Lead { offset }**: value at position (i + offset); NULL/zero if out of bounds
- **SlidingSum { frame_rows }**: sum of `val` over rows at positions [i - frame_rows + 1, i]
- **SlidingAvg { frame_rows }**: average of `val` over same frame (integer division)

Cost model (in docstring): O(|P| × log|P|) per affected partition P per epoch.
Not O(total_rows) — only affected partitions recompute.

**Unit tests** (in `window.rs` or `crates/rockstream-ops/tests/window_unit.rs`):
- `window_row_number_basic` — 5 rows, one partition, verify RN = 1..5
- `window_rank_with_ties` — 6 rows, 2 tied on order_key, verify rank assignment
- `window_dense_rank_with_ties` — same as above, verify no gaps
- `window_lag_basic` — 4 rows, offset=1, verify NULL on first row
- `window_lead_basic` — 4 rows, offset=1, verify NULL on last row
- `window_sliding_sum_basic` — 5 rows, frame=3, verify rolling sum

PlanNode::Window { input, window_exprs } => {

        inputs: vec![input_id],

}

### Slice 7 — SQL lowering
**File**: `crates/rockstream-sql/src/lower.rs`

Replace the `LogicalPlan::Window(_) => "Window"` error string with a real lowering:

```rust
LogicalPlan::Window(w) => {
    let input_node = lower_logical_plan(&w.input, catalog)?;
    let window_exprs = w.window_expr.iter()
        .map(|e| lower_window_expr(e, w.input.schema()))
        .collect::<Result<Vec<_>, _>>()?;
    Ok(PlanNode::Window {
        input: Box::new(input_node),
        window_exprs,
    })
}
```

`lower_window_expr(e: &DfExpr, schema: &DFSchema) -> Result<WindowExpr, LowerError>`:
- Extract `DfExpr::WindowFunction(wf)` → map `wf.fun` to `WindowFunc`
- Map `window_def.partition_by` → column indices
- Map `window_def.order_by` → column indices
- Supported mappings:
  - `BuiltInWindowFunction::RowNumber` → `WindowFunc::RowNumber`
  - `BuiltInWindowFunction::Rank` → `WindowFunc::Rank`
  - `BuiltInWindowFunction::DenseRank` → `WindowFunc::DenseRank`
  - `BuiltInWindowFunction::Lag` → `WindowFunc::Lag { offset: 1 }` (default)
  - `BuiltInWindowFunction::Lead` → `WindowFunc::Lead { offset: 1 }`
  - `AggregateFunction::Sum` over `WindowFrameBound::Preceding(n)` → `WindowFunc::SlidingSum { frame_rows: n }`
  - `AggregateFunction::Avg` similarly → `WindowFunc::SlidingAvg`
  - Other → `LowerError::UnsupportedWindowFunction("RS-1016: ...")`

### Slice 10 — Cost documentation (satisfies Proof obligation 2)

**In `crates/rockstream-ops/src/window.rs` module docstring**:

Document cost model:
```
//! ## Cost Model
//!
//! Recomputation cost per epoch = Σ_{affected partitions P} O(|P| × log|P|)
//!
//! Only partitions with at least one row in the input delta are recomputed.
//! Unchanged partitions are not touched. This means:
//! - Sparse deltas (few partitions changed): near-constant cost.
//! - Dense deltas (many partitions changed): proportional to total relation size.
//!
//! Bound: WINDOW_PARTITION_THRESHOLD = 10_000 rows.
//! Metric: `fill_level()` = total rows in arrangement; `oversized_partition_keys()`
//! = partitions exceeding the threshold (RS-5023 NOTICE in EXPLAIN).
```

**In oracle tests**: oracle harness records `max_partition_size` and `recomputed_row_count / delta_row_count` ratio; asserts ratio ≤ `n_partitions × max_partition_size / delta_size`. This is logged with `eprintln!` (visible with `--nocapture`).

Proof obligation 2 is met by: code docstring + oracle cost assertions + `window_partition_recompute_cost_bounded` unit test (Slice 2).
