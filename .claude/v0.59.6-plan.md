# v0.59.6 Plan — Durable Shared Arrangement Fabric

## Scope and Boundary

v0.59.6 implements the Durable Shared Arrangement Fabric of the Pre-v1 Performance Architecture track (`NEW_ROADMAP.md` v0.59.6, `rockstream-pre-v1-scalability.md` Section 2):

1. **Canonical `ArrangementSpec` and Stable `ArrangementId`**:
   - Define a comprehensive canonical specification `ArrangementSpec` with all 12 mandatory constituent components:
     ```rust
     pub struct ArrangementSpec {
         pub tenant_id: TenantId,
         pub security_policy_digest: [u8; 32],
         pub source_identity: SourceIdentity,
         pub source_schema_generation: u64,
         pub key_expressions: Vec<CanonicalExpr>,
         pub key_types: Vec<DataType>,
         pub value_projection: Vec<CanonicalExpr>,
         pub predicate: Option<CanonicalExpr>,
         pub null_semantics: NullSemantics,
         pub decimal_scale: Option<u8>,
         pub collation_identifier: CollationId,
         pub collation_version: CollationVersion,
         pub time_domain: TimeDomainSemantics,
         pub merge_law_id: MergeLawId,
         pub merge_law_version: MergeLawVersion,
         pub partitioning: PartitioningSpec,
     }
     ```
   - Implement deterministic AST/expression canonicalization: eliminate no-op type casts, normalize commutative operand ordering where safe, canonicalize projection aliases, and standardize key encodings.
   - Hash `ArrangementSpec` with domain-separated BLAKE3 into a deterministic, stable 64-bit/128-bit `ArrangementId`.
   - Enforce strict multi-tenant and security isolation: any variation in `tenant_id`, `security_policy_digest`, predicate, collation version, decimal scale, schema generation, merge-law version, null semantics, or time domain yields a distinct `ArrangementId` and never shares physical state.

2. **Durable Arrangement Catalog & Reference-Counted Lifecycle**:
   - Introduce `ArrangementCatalog` in control and storage layers tracking registered arrangements, canonical specs, manifest locations, and active consumer references (`consumer_count`).
   - Implement reference-counted lifecycle: registering a new view/query that canonicalizes to an existing arrangement increments refcount; dropping a view decrements refcount.
   - Implement safe deferred reclamation: dropping the last consumer marks the arrangement as unreferenced and triggers garbage collection of catalog entry, trace batches, storage state, and cache blocks only after all reader epochs and compaction horizons clear.

3. **Immutable Consolidated Trace Batches & Per-Consumer Read Frontiers**:
   - Implement differential-style immutable trace layout:
     - Compacted base snapshot through frontier $F$.
     - Sequence of immutable sorted delta batches ($F+1, F+2, \dots$).
     - Per-consumer read frontiers ($F_c$ for each active view/shard reader).
   - Each epoch commit writes one consolidated, sorted delta batch into the shared trace.
   - Readers access state as: `base_snapshot_F + deltas(F .. requested_frontier)`.

4. **Compaction Frontier Derived from Slowest Live Consumer**:
   - Compute dynamic compaction frontier: $F_{\text{compaction}} = \min_{c \in \text{live\_consumers}} F_c$.
   - Enforce compaction safety invariant: background compaction merges trace delta batches into the compacted snapshot up to $F_{\text{compaction}}$, strictly never compacting or deleting deltas beyond the slowest live consumer's read frontier.
   - Reclaim obsolete trace batches and delta files once compaction advances.

5. **Frontier-Safe Zero-Rescan New-View Installation**:
   - Implement view attachment protocol:
     1. Pin shared arrangement frontier $F$.
     2. Obtain or read the compacted trace snapshot through $F$.
     3. Subscribe to and buffer incoming deltas arriving after $F$.
     4. Build only the view-specific downstream pipeline/state.
     5. Attach the view into live execution at cluster frontier without rescanning the underlying source relation, with zero visibility gaps and zero duplicate records.

6. **Worker-Wide Shared Storage Context & Cache Reuse**:
   - Move decoded-block cache, index block cache, and object caches from per-shard/per-view silos into a unified worker-wide `WorkerStorageContext` (`SharedStorageContext`).
   - Enable multiple shards and views to reuse cached blocks and index structures under explicit, configurable memory budgets (`storage.cache_budget_bytes`).
   - Tag and partition cache keys by `tenant_id` and `security_policy_digest` to guarantee that cross-tenant and row-security data are strictly unobservable across isolation boundaries.

7. **Storage Format Versioning (V3), Migration, Rollback & Fail-Closed**:
   - Introduce `StorageFormatVersion::V3` (`V3SharedTrace`) and versioned trace manifests (`TraceManifestHeader`).
   - Implement deterministic online and offline migration from v0.59.5 V2 delta-native private state to V3 shared trace format.
   - Define mixed N/N+1 cluster read/write policy: N+1 workers read V2 private state and emit V3 shared traces; unsupported or corrupt formats fail closed with `RS-5001` / `RS-5002` / `RS-5003`.
   - Validate clean rollback boundaries and disaster restore from independent exports.

8. **Introspection & `EXPLAIN INCREMENTAL`**:
   - Extend `EXPLAIN INCREMENTAL` and `SHOW VIEW STATUS` to report:
     - `arrangement_id`: deterministic stable arrangement identity.
     - `consumer_count`: number of views/queries sharing the physical arrangement.
     - `shared_state_bytes`: physical byte volume of the shared trace.
     - `bytes_saved_by_sharing`: calculated byte reduction achieved via arrangement reuse.
     - `compaction_frontier`: minimum consumer read frontier governing retention.

9. **Formal M2 Model Extension & SimRuntime Crash Chaos**:
   - Extend `formal/m2_frontier_agg.fizz` with shared-consumer read frontiers, frontier-pinned view attachment, compaction frontier derivation, and reference-counted trace reclamation.
   - Formally verify invariants: M2-S1 (Meet correctness), M2-S2 (Pessimistic staleness), M2-S3 (Single publisher safety), M2-S4 (Stale write rejection), M2-S5 (Slowest consumer compaction safety), M2-S6 (Attach frontier completeness without gaps/duplicates), M2-S7 (Trace reclamation safety), M2-L1 (Publication progress), M2-L2 (Failover progress), M2-L3 (Reclamation progress).
   - Verify 100% paired Rust runtime assertions (`assert!`) via `scripts/check-invariant-pairs.sh`.
   - Implement SimRuntime tests with `buggify!()` chaos injecting crashes during attachment, compaction, and reclamation.

10. **Scale Proof (20 Views Sharing + 21st Attach)**:
    - 20 semantically equivalent views with harmless syntax/cast differences canonicalize to 1 physical arrangement, producing oracle-identical output with memory and state storage growing with arrangements rather than view count.
    - Installing the 21st view attaches at a declared frontier without source rescan or visibility gap.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

### Slice 3 (S3): Immutable Consolidated Trace Batches & Multi-Consumer Compaction
- **Goal**: Implement `SharedArrangementTrace` maintaining a base compacted snapshot through frontier $F$, an immutable sequence of sorted delta batches, and per-consumer read frontiers, with compaction derived from the slowest live consumer.
- **Implementation**:
  - Implement `SharedArrangementTrace` in `crates/rockstream-storage/src/trace.rs`:
    - Base snapshot through $F$.
    - Appended immutable sorted delta batches tagged with epoch frontiers.
    - Active consumer read frontier registry ($F_c$).
  - Implement `commit_trace_batch(id, frontier, delta_batch)`: appends one consolidated sorted delta batch to the trace.
  - Implement `read_trace_snapshot(id, target_frontier)`: returns iterator merging base snapshot with deltas up to `target_frontier`.
  - Implement `compact_trace(id)`: computes $F_{\text{compaction}} = \min_{c} F_c$; merges delta batches up to $F_{\text{compaction}}$ into the base snapshot; reclaims obsolete delta files. Compaction is strictly blocked from advancing past the slowest live consumer.
- **Green Test Commitments**:
