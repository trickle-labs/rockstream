# v0.51.20 Plan — Long-Duration Real-Process Resource-Leak Soak

## Contract

| Field | Commitment |
|---|---|
| Focus | Long-duration real-process resource-leak soak. |
| Scope | A nightly, approximately four-hour TestContainers run drives the shipped unified `rockstream` binary through sustained abnormal pgwire connection churn, real source pause/resume churn, and continuous materialized-view refresh. It samples RSS, open file descriptors, and open sockets at regular intervals, rejects an upward trend outside documented generous tolerances, and publishes an artifact and job summary. |
| Proof | The full run reports flat resource use for all three OS-level measures; the same trend gate rejects an injected connection-teardown deregistration leak. |
| Backends | Unit, LFS, MinIO, SimRuntime, TestContainers. The soak adds no commit, replay, checkpoint, compaction, or WAL implementation path; existing lifecycle paths are exercised rather than changed. |
| Previous sign-off | `sign-offs/v0.51.19.md:3-18` is `✅ Done`, records its proof and exit checks, and declares no required deferral. |

The soak must use the one shipped binary from `Dockerfile:5,9-10`, never an in-process gateway substitute. Its sample history is bounded (`MAX_SAMPLES = duration / sample_interval + 1`), records its fill level in the summary, and fails before writing beyond that bound; it must not introduce a queue, buffer, or unbounded scan.

No aggregate, type, join, or window capability is added; those feature matrices are not applicable. The equivalent required matrix is resource kind × workload condition × backend. Every cell below needs a named test or assertion.

| Complete workload behavior | bounded sampler fill-level / threshold-unit tests | `tcp_level_kill_of_many_connections_shows_zero_session_state_growth` plus real-binary churn | `source_pause_resume_checkpoint` LFS, MinIO, and seeded SimRuntime lifecycle tests plus real-binary churn | exact `REFRESH MATERIALIZED VIEW` command-complete assertion plus active-view result check | test-only teardown-deregistration fault hook causes the identical trend assertion to fail |

The trend decision is deterministic and explicit: retain the initial warm-up window, then require each resource's final rolling median and every subsequent rolling median to remain at or below `baseline + tolerance`; tolerate documented fixed startup noise but reject a positive slope or sustained step above the band. Unit tests assert the complete rendered summary for flat, tolerated-step, and monotonically growing sequences, not counts. Test-only leak injection is gated by an explicit environment/config switch that cannot be enabled in the shipped release workflow; the negative CI invocation enables it and must fail at the same assertion with the exact resource and threshold diagnostic.

## Vertical test-first slices

### S1 — Bounded resource-series gate and artifact contract

- **Owned files:** `crates/rockstream-sim/tests/resource_leak_soak_tests.rs`, plus a focused sampler/summary module under `crates/rockstream-sim/src/` if test visibility requires it.
- **Failing tests first:** `resource_series_accepts_flat_rss_within_band`, `resource_series_accepts_flat_fd_within_band`, `resource_series_accepts_flat_socket_within_band`, and the three exact monotonic-leak rejection tests. Each asserts the entire Markdown/JSON summary including units, baseline, tolerance, samples collected/capacity, slope verdict, and failing resource diagnostic.
- **Implementation:** define bounded samples, `/proc/<pid>/status` RSS, `/proc/<pid>/fd` FD, and `/proc/<pid>/net`/socket inspection helpers; use a fixed cadence, named tolerances, no range deletion, and write `resource-leak-soak-summary.{json,md}` under `ROCKSTREAM_RESOURCE_SOAK_ARTIFACT_DIR`.
- **Proof:** a reproducible algorithm distinguishes flat real-world noise from an unbounded leak, and the artifact reports its bound/fill level.

### S2 — Real-binary churn harness across all required backends

- **Owned files:** `crates/rockstream-sim/tests/resource_leak_soak_tests.rs`; narrowly shared setup only in `crates/rockstream-sim/tests/real_cluster_chaos_soak_tests.rs` if it avoids duplicated TestContainers startup without changing existing proof semantics.
- **Failing tests first:** `resource_leak_soak_real_binary_lfs_churn_is_flat`, `resource_leak_soak_real_binary_minio_churn_is_flat`, and `resource_leak_soak_source_lifecycle_sim_seed_<seed>_preserves_progress`. The LFS and MinIO tests use the short, configurable duration but execute the same real-binary workload; the scheduled TestContainers invocation sets the full four-hour duration. The SimRuntime test uses a fixed seed and `buggify!()` lifecycle interleaving to prove pause/resume transitions continue progressing, then hands the process-level proof to TC.
- **Implementation:** start the unified Docker image with LFS/local storage and MinIO variants; create a live source and materialized view; drive a bounded-concurrency pool of raw pgwire connections through setup/query/drop (including TCP-level abnormal disconnect); repeatedly pause/resume the source and refresh the view; assert exact command tags and active result values. Reuse lifecycle semantics from `source_runtime.rs:121-153` and cleanup behavior from `abnormal_disconnect_cleanup_tests.rs:165-205`, not a mock.
- **Proof:** all listed backends exercise the same production-facing workload, while the full schedule has a genuine OS process to measure.

### S3 — Nightly four-hour workflow, publication, and leak-detection proof

- **Owned files:** `.github/workflows/long-duration-resource-soak.yml`, `scripts/sample-resource-leak-soak.sh`, `scripts/sample-resource-leak-soak.test.sh`, and only the artifact-path configuration required by S2.
- **Failing tests first:** shell self-tests feed exact flat and leaked samples to the sampler/assertion script; the positive test asserts exact summary output, and the deliberate teardown-deregistration leak test exits nonzero with the same gate's exact diagnostic. The TestContainers workflow must run both a short scheduled-contract test and the full-duration target; no PR trigger is permitted.
- **Implementation:** schedule nightly plus `workflow_dispatch`, build the real image, run the four-hour test with a 60-second cadence and explicit time budget under the six-hour runner limit, upload the complete JSON/Markdown/TSV artifact even on failure, and append its Markdown to `$GITHUB_STEP_SUMMARY`. The script samples only named running container PIDs, enforces `MAX_SAMPLES`, and fails closed on missing `/proc` data or a disappeared target process.
- **Proof:** every nightly run leaves a visible SLO-style record and a deliberately introduced deregistration leak fails the same CI gate rather than a separate synthetic check.
