# Implement v0.51.9 — Phase 2 Plan: Real Native Ingestion Connectors & `CREATE SOURCE` DDL

**Version**: `v0.51.9`  
**Target Scope**: Close Area D — the reviewer's "the system relies on SQL interfaces for ingestion." Replace mock source connectors (`kafka_source.rs`, `s3_source.rs`) with production `rdkafka`-backed Kafka consumer source (consumer-group offsets, partition assignment, backpressure) and real `aws-sdk-s3`/`object_store`-backed S3/GCS object-arrival source, both reusing the M3 exactly-once 2PC state machine. Add `CREATE SOURCE <name> TYPE kafka|s3 (...options...) FORMAT json|avro|csv`, `ALTER SOURCE <name> {PAUSE|RESUME|DROP}`, and `SHOW SOURCES`/`SHOW SOURCE STATUS` over pgwire, wired into the unified data plane so ingested rows become real operator-DAG input. Reference credentials by name (deferring envelope-encrypted `CREATE SECRET` to v0.56) without logging plaintext secrets. Reposition v0.28 "First-Party Source Connectors [Done]" claim honestly in lineage note.

## ⚡ Ground Rules (non-negotiable)

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` must remain runnable through it at the end of this version.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters, and a test must assert this.
- Unbounded in-memory accumulation is never acceptable. Every new queue, buffer, or scan window needs a named upper bound, a fill-level metric, and a backpressure or error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- Make only changes this version requires. No speculative features, no drive-by refactors, no scope outside the two pillars (IVM engine + Postgres wire layer).
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals.** Scan every previous `sign-offs/v*.md` for items marked deferred, postponed, or out-of-scope that overlap this version's Scope.

## 4. Vertical Slices

### Slice 1: Real Dependencies & Source Catalog Data Structures
- **Goal**: Add `rdkafka` and `aws-sdk-s3` (or `object_store` S3 feature) to `Cargo.toml` (`crates/rockstream-connectors/Cargo.toml` and workspace `Cargo.toml`), and implement `CatalogSourceEntry` + source tracking methods in `crates/rockstream-gateway/src/catalog_stubs.rs`.
- **Implementation**:
  - Add `rdkafka` and `aws-sdk-s3` dependencies.
  - Implement `CatalogSourceEntry` struct in `catalog_stubs.rs` with `name`, `source_type`, `options`, `format`, `status` (`OK`, `PAUSED`), `live_offset`, `live_lag`.
  - Add `add_source`, `get_source`, `update_source_status`, `remove_source`, `list_sources` in `CatalogStubs`.
- **Verification**: `cargo test -p rockstream-connectors` & unit test in `catalog_stubs.rs` verifying source catalog registrations.

### Slice 2: Production `rdkafka`-Backed Kafka Source Connector
- **Goal**: Replace mock logic in `crates/rockstream-connectors/src/kafka_source.rs` with a production Kafka consumer using `rdkafka`.
- **Implementation**:
  - Implement real partition assignment, consumer-group offsets, poll loop, watermark tracking, and backpressure bounded by `KAFKA_SOURCE_BUFFER_LIMIT`.
  - Integrate with M3 2PC exactly-once state machine for offset commits on checkpoint/epoch boundary.
  - Ensure credentials (SASL passwords, etc.) are handled securely without plaintext logging.
- **Verification**: Unit tests in `kafka_source.rs` with mock/real brokers and offset state serialization test.

### Slice 3: Production `aws-sdk-s3` / `object_store`-Backed S3 Source Connector
- **Goal**: Replace mock logic in `crates/rockstream-connectors/src/s3_source.rs` with a production S3 object-arrival reader using `aws-sdk-s3` / `object_store`.
- **Implementation**:
  - Implement real object listing, offset/byte-range polling, format decoding (`json`, `avro`, `csv`), and backpressure bounded by `S3_SOURCE_BUFFER_LIMIT_BYTES`.
  - Integrate with M3 2PC state machine for file marker / byte offset checkpoint durability.
- **Verification**: Integration test against MinIO / local object store reading real object drops.

### Slice 4: Pgwire DDL Dispatch Wiring & Protocol Integration
- **Goal**: Wire `CREATE SOURCE`, `ALTER SOURCE`, `SHOW SOURCES`, `SHOW SOURCE STATUS` into `crates/rockstream-gateway/src/server.rs`.
- **Implementation**:
  - Add DDL parsers `parse_create_source_ddl`, `parse_alter_source_ddl`.
  - Wire dispatch branches in `dispatch_async_with_conn` handling `CREATE SOURCE`, `ALTER SOURCE {PAUSE|RESUME|DROP}`, `SHOW SOURCES`, `SHOW SOURCE STATUS`.
  - Connect ingested rows directly to the unified data plane (v0.51.3) operator DAG.
- **Verification**: `source_ddl_tests.rs` running `CREATE SOURCE`, `ALTER SOURCE`, `SHOW SOURCES` over pgwire returning expected result sets.
