# v0.59.9 plan: SLO-adaptive runtime and storage

## Scope and boundary

This version replaces the worker's single execution queue with bounded,
shard-owned actors. It adds stateless-stage fusion, byte and time based
morsels and exchange credits, physical commit grouping behind logical
visibility epochs, a bounded freshness controller, foreground and compaction
isolation, changelog checkpoints, and reserved barrier capacity.

It adds no SQL keyword, CLI command, configuration key, pgwire message, or
new relational operator. The optional S5 mechanisms stay absent unless the
named measurement proves the matching S5 admission condition.

## Dispatch-wiring audit

parser, SQL dispatcher, executor-dispatch, or response-encoder path to add.
`crates/rockstream-runtime/src/client.rs:869` only receives an already
validated internal `ControlMessage::Execute`; it is not SQL or pgwire

CLI, config, or wire feature without a separate complete parser-to-response
audit. If a scope change introduces such a feature, that feature is

## Vertical slices

1. **Shard actors and stateless fusion.** Replace the global `execute_tx`
   queue at `crates/rockstream-runtime/src/client.rs:647` with one bounded
   mailbox per leased shard. The receive path at `client.rs:869` routes only
   to the current lease owner's actor. Fuse adjacent stateless stages inside
   that actor without changing the pipeline result. Each mailbox has byte and
   message limits, a fill-level metric, and refusal or backpressure when full.
   `shard_actor_morsel_tests` proves complete aggregate, join, and window
   multisets equal the batch oracle under interleaving and revocation.

2. **Morsels, exchange credits, and physical commit groups.** Make actor work
   items bounded by encoded bytes and elapsed compute time. Replace fixed
   queue capacity as the control input with byte and time credits. Keep each
   `RuntimeExchangeMessage.epoch` a logical visibility epoch. A physical group
   may flush multiple complete logical epochs, but it must not acknowledge or
   publish any member before `ViewSinkOp::write_epoch` at
   `crates/rockstream-ops/src/sink.rs:261`, state persistence, and
   `ShardDb::flush` at `crates/rockstream-storage/src/shard_db.rs:667` succeed.
   Extend `formal/m1_epoch_commit.fizz` and pair every new formal invariant
   with a runtime assertion.

3. **Freshness control and compaction isolation.** Replace the static SLO
   derivation at `crates/rockstream-control/src/config_deriver.rs:12` with a
   bounded controller that consumes source lag, compute time, queue age,
   memory, checkpoint cost, compaction debt, and object-store latency. It may
   adjust only morsel limits, credits, physical-group bounds, checkpoint mode,
   and admission within declared min/max values. A dedicated, budgeted
   compaction worker cannot consume foreground actor capacity. Tests cover
   step, burst, and oscillating load, and require convergence without an
   unbounded queue or a correctness change.

4. **Changelog checkpoints and barrier reservation.** Build checkpoints from
   the v0.59.5 mutation stream instead of scanning live state. Extend
   `CheckpointCoordinator::begin_checkpoint` at
   `crates/rockstream-control/src/checkpoint.rs:205` so barriers use reserved
   capacity while data credits are exhausted. The existing aligned mode stays
   the default. A checkpoint commits only after every shard's durable
   changelog contribution and manifest confirmation. Cleanup remains
   scan-and-delete or snapshot-safe filtering. It must never use SlateDB range
   deletion.

5. **Optional S5 admission gate.** Add measurements, not an optional
   mechanism by default. The gate records one of: barrier alignment does not
   breach its bound and unaligned checkpoints remain absent; ordinary rebuild
   does not breach its bound and localized arrangement rebuild remains absent;
   or ordinary query p99 does not breach its concurrency bound and
   frontier-pinned replicas remain absent. A measured breach admits only its
   matching mechanism, with a separate crash, recovery, resource-bound, and
   global-commit proof.

6. **Qualification and freeze.** Re-run the v0.59.5 matrix through the
   external harness with raw before and after samples. It must record useful
   CPU attribution, lock time, p50/p95/p99 freshness, byte credits, mailbox
   fill, logical and physical write amplification, checkpoint duration,
   changelog growth, compaction debt, recovery, and worker-loss results. A
   passing matrix freezes this physical architecture.

## Durability and coordination commitments

The grouped-commit path has LFS and MinIO durability tests. The changelog
checkpoint path has the LFS and MinIO tests named above. The compaction path
adds `compaction_isolation_lfs_tests::restart_preserves_exact_multiset` and
`compaction_isolation_minio_tests::restart_preserves_exact_multiset`. Each
test must include a crash after mutation staging, after physical flush, after
per-shard checkpoint durability, and after manifest commit. It must compare
the complete recovered multiset with the independent oracle.

The three seeded SimRuntime files named above are mandatory coordination
tests. Their `buggify!()` sites cover duplicate or reordered group delivery,
data-saturated barrier injection, compaction pressure, controller action
delivery, worker loss, and recovery. Each run asserts the final output,
published frontier, and resource-bound transcript exactly.
