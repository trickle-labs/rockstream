## RS-Code Note

The roadmap row for v0.25 says `AS OF EPOCH` outside retention returns `RS-2005`.
However `error_code.rs` defines:

| Code | Meaning |
|------|---------|
| RS-2005 | Query rate limit exceeded |
| RS-2006 | Historical query references an epoch before the checkpoint retention window |

RS-2006 is the correct code for epoch-before-retention (it is already defined
and tests will use it). RS-2012 (`session.wait_for_timeout`) and RS-2020
(`subscribe.consumer_too_slow`) are new and must be added to `error_code.rs`.

## Buffer Bound Declarations

| Buffer / Queue / Window | Upper Bound | Fill Metric | Backpressure / Error |
|-------------------------|-------------|-------------|----------------------|
| `ViewChangeLog` per-table entry count | `CHANGE_LOG_MAX_ENTRIES` (configurable, default 10 000 entries) | `changelog_entry_count` gauge | Entries older than `CHANGE_RETENTION` are evicted; further-behind consumer gets RS-2020 |
| Subscribe backlog per subscriber | `SUBSCRIBE_BACKLOG_MAX` epochs (default = CHANGE_LOG_MAX_ENTRIES) | `subscribe_backlog_epochs` gauge | RS-2020 `subscribe.consumer_too_slow` when backlog > limit |
| Session wait-for wait queue | Bounded by `session_wait_for_timeout` (default = pipeline freshness SLO, e.g. 5 s) | `session_wait_for_triggered_total` counter | RS-2012 `session.wait_for_timeout` on expiry |

### S1 — `ViewChangeLog` + new RS codes

**Files:** `crates/rockstream-gateway/src/change_log.rs` (new),
`crates/rockstream-types/src/error_code.rs`

**What:** In-memory bounded change log for a single table. Records
`(epoch: u64, row_key: Bytes, mz_diff: i8, encoded_row: Bytes)`. Evicts
entries older than `CHANGE_RETENTION` (default 1 hour of epochs). Exposes:

```rust
pub struct ViewChangeLog {
    entries: VecDeque<ChangeEntry>,
    /// Named upper bound.
    max_entries: usize,
    /// Number of entries currently held (fill-level metric).
    entry_count: Arc<AtomicUsize>,
}
impl ViewChangeLog {
    pub fn push(&mut self, entry: ChangeEntry);
    pub fn since_epoch(&self, epoch: u64) -> Vec<&ChangeEntry>;
    pub fn earliest_epoch(&self) -> Option<u64>;
    pub fn entry_count(&self) -> usize;
}
```

Add to `error_code.rs`:
- `RS_2012`: `session.wait_for_timeout` — wait-for deadline exceeded
- `RS_2020`: `subscribe.consumer_too_slow` — subscriber fell behind retention window

**Green gate:** `view_change_log_push_poll_bound` (unit test: push > max_entries, assert eviction; `since_epoch` returns only retained entries)

### S2 — Subscribe SQL parser

**Files:** `crates/rockstream-gateway/src/server.rs` (dispatch), or new
`crates/rockstream-gateway/src/subscribe_parser.rs`

**What:** Parse `SUBSCRIBE <view> [AS OF NOW WITH SNAPSHOT | AS OF EPOCH <n>]
[WHERE <pred>] [(<col1>, <col2>, ...)]` in the gateway's `do_query` dispatch.
Produces a `SubscribeRequest` value type (no I/O yet).

```rust
pub struct SubscribeRequest {
    pub view_name: String,
    pub start: SubscribeStart,     // NowWithSnapshot | Epoch(u64)
    pub where_clause: Option<String>,
    pub projection: Option<Vec<String>>,
}
pub enum SubscribeStart { NowWithSnapshot, Epoch(u64) }
```

**Green gate:** `subscribe_parse_as_of_now_with_snapshot`,
`subscribe_parse_as_of_epoch`, `subscribe_parse_where_projection` (unit tests on
parse output; no shard I/O)

### S3 — Subscribe snapshot path (`AS OF NOW WITH SNAPSHOT`)

**Files:** `crates/rockstream-gateway/src/server.rs`,
`crates/rockstream-gateway/src/subscribe_handler.rs` (new)

**What:** On `SUBSCRIBE orders_mv AS OF NOW WITH SNAPSHOT`:
1. Scan `view_output/{view_name}/` via `ShardDb::scan_prefix` (current snapshot).
2. Emit each row as a pgwire `CopyData` row with columns
   `(mz_timestamp=current_epoch, mz_diff=+1, <projected cols>)`.
3. Enter live-tail loop (S4).

**Green gate:** `subscribe_snapshot_delivers_current_state` — write N rows via
DML, subscribe, assert the snapshot batch contains exactly N rows with
`mz_diff=+1`.

---

### S4 — Subscribe live tail

**Files:** `crates/rockstream-gateway/src/subscribe_handler.rs`,
`crates/rockstream-gateway/src/server.rs`

**What:**
- `GatewayHandler` gains a `Arc<SubscribeRegistry>` — a shared map from
  `table_name → Arc<Mutex<ViewChangeLog>>`. `handle_commit` pushes to every
  registered log for the committed table.
- Subscribe handler polls the log for entries with `epoch > last_sent_epoch`
  (100 ms poll interval), emitting each as a `CopyData` row.
- Named upper bound: `SUBSCRIBE_BACKLOG_MAX`; fill metric: `subscribe_backlog_epochs`;
  backpressure: RS-2020 when consumer is behind by more than `max_entries`.

**Green gate:** `subscribe_live_tail_emits_deltas` — write row, assert subscriber
receives `mz_diff=+1`; delete row, assert subscriber receives `mz_diff=-1`.

---

### S5 — Subscribe restart survival (`AS OF EPOCH <n>` / RS-2006)

**Files:** `crates/rockstream-gateway/src/subscribe_handler.rs`

**What:**
- `AS OF EPOCH <n>`: replay from `ViewChangeLog::since_epoch(n)`, then live-tail.
- If `n < ViewChangeLog::earliest_epoch()` (outside CHANGE_RETENTION):
  return RS-2006 `history.epoch_before_retention`.

**Green gate:**
- `subscribe_restart_replays_from_epoch` — write 5 rows (epochs 1–5), subscribe
  from epoch 3, assert only epochs 3–5 replayed.
- `subscribe_as_of_epoch_outside_retention_returns_rs2006` — set `max_entries=3`,
  push 10 entries, `AS OF EPOCH 1` returns RS-2006.

### S6 — Server-side `WHERE` and column projection

**Files:** `crates/rockstream-gateway/src/subscribe_handler.rs`

**What:**
- Apply `SubscribeRequest::where_clause` as a simple equality/comparison filter
  against the encoded row columns before sending (parsed by existing SQL
  infrastructure or a light inline evaluator).
- Apply `SubscribeRequest::projection` to select only the requested column
  indices from the row before encoding.
- Bound: filter is stateless; no per-subscriber buffer beyond current row.

**Green gate:**
- `subscribe_where_filters_rows` — write 10 rows, subscribe with
  `WHERE id > 5`, assert only 5 rows received.
- `subscribe_projection_selects_columns` — view has (id, name, value),
  subscribe with `(id, value)`, assert `name` column absent in CopyData output.

### S7 — Freshness token on query responses + `last_written_epoch` upgrade

**Files:**
- `crates/rockstream-gateway/src/session.rs` — upgrade
  `last_written_epoch: Option<u64>` → `Option<FreshnessToken>`
- `crates/rockstream-gateway/src/server.rs` — after SELECT, emit freshness
  token as a pgwire `ParameterStatus` message (`rockstream.freshness_token`
  = JSON-encoded token)
- `crates/rockstream-gateway/src/server.rs` — on COMMIT success, build a
  `FreshnessToken { source_progress: {table_source_id → source_epoch}, cluster_frontier_hash }` and store in `session.last_written_epoch`

**Green gate:**
- `last_written_epoch_upgraded_to_freshness_token` — after COMMIT, assert
  `session.last_written_epoch` is `Some(FreshnessToken)` with correct source epoch.
- `freshness_token_emitted_on_select` — assert that a `SELECT` response includes
  a `ParameterStatus` carrying the current frontier as a `FreshnessToken`.

### S8 — `wait_for=<token>` explicit read-your-writes + RS-2012

**Files:** `crates/rockstream-gateway/src/server.rs`,
`crates/rockstream-gateway/src/session.rs`

**What:**
- `SET rockstream.wait_for = '<json>'` deserializes a `FreshnessToken`.
- Before the next `SELECT`, the gateway polls `ShardDb::last_epoch()` until
  `current_epoch >= token.source_epoch_for(table)` or
  `session_wait_for_timeout` expires.
- On timeout: return RS-2012 `session.wait_for_timeout`; proceed at current
  frontier (do not abort the query).
- Bound: timeout is the only bound; no additional buffer.

**Green gate:**
- `wait_for_resolves_when_frontier_advances` — write a row (epoch E), build
  token for E, assert that a subsequent SELECT with that `wait_for` token sees
  the written row.
- `wait_for_timeout_returns_rs2012` — construct a token for epoch
  `u64::MAX`, set short timeout (1 ms), assert RS-2012 notice is emitted and
  query returns (at current frontier).

---

### S9 — Session-scoped automatic read-your-writes

**Files:** `crates/rockstream-gateway/src/server.rs`,
`crates/rockstream-gateway/src/session.rs`

**What:**
- After every successful `COMMIT`, `session.last_written_epoch` holds the
  `FreshnessToken` for that write (set in S7).
- Before every `SELECT` (unless session_wait_for is off), automatically apply
  `wait_for = session.last_written_epoch` (reuses S8 path).
- `SET rockstream.session_wait_for = off` clears the auto-apply flag for this
  session.
- Metrics: `session_wait_for_triggered_total` counter,
  `session_wait_for_satisfied_ms` histogram,
  `session_wait_for_timeout_total` counter.

**Green gate:**
- `session_ryw_after_commit_sees_own_write` — single connection: COMMIT a row,
  then SELECT without explicit `wait_for`, assert the row is visible.
- `session_ryw_opt_out` — same scenario with `SET rockstream.session_wait_for =
  off`, assert SELECT proceeds immediately (does not wait).

---

### S10 — Oracle property test + LFS proof tests

**Files:** `crates/rockstream-gateway/tests/gateway_proof_tests.rs`

**What:**
- Oracle: `oracle_subscribe_incremental_equals_batch` — N sequential 1-row
  COMMITs produce the same cumulative Z-set (net `mz_diff` sum per key = 1) as a
  single N-row batch COMMIT on the subscribe stream.
- LFS proof: `proof_subscribe_snapshot_then_deltas_lfs` — create view, write
  rows, subscribe AS OF NOW WITH SNAPSHOT, assert snapshot + live deltas match.
- LFS proof: `proof_subscribe_no_gaps_restart_lfs` — write rows, record epoch
  E, close and reopen ShardDb, reconnect subscribe AS OF EPOCH E, assert no gaps.
- LFS proof: `proof_ryw_resolves_within_slo_lfs` — COMMIT a row, session SELECT
  sees it without explicit wait_for token; verify round-trip time < 100 ms.
- TC proof: `proof_subscribe_no_gaps_restart_tc` — same as LFS proof but with
  TestContainers gateway restart (stop gateway process, restart, reconnect).

## Coordination Slices

Subscribe and read-your-writes are gateway-local (single-connection, no new
consensus path). No new FizzBee model is required. Existing M1–M4 models cover
the underlying epoch-commit and frontier-advance protocols. Paired runtime
`assert!`s from M1 (`committed_epoch` non-decreasing) already gate the
`handle_commit` path used by all RYW logic.
