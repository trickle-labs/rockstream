## 1. Resolved Contract Choices

1. **Seven Independent Health Dimensions (Step 1, V071-01, UIE-M6-02)**:
   - Evaluated and reported independently across all nodes and workloads:
     1. `liveness`: Process is running, event loops tick, heartbeats pulse. (Evaluation rule: heartbeat age $\le$ 5s).
     2. `readiness`: Process can accept external client traffic (PGWire, RPC). Fails closed during startup, unrecovered catalog replay, or graceful drain.
     3. `availability`: Data query paths can respond to queries for active views without error.
     4. `freshness`: Materialized view published frontier is within configured `freshness_slo_ms`. Fails/degrades if `freshness_lag_ms > freshness_slo_ms`.
     5. `durability`: Storage backend (SlateDB / Object store) is reachable, readable, and writable. Storage write failures degrade durability independently while liveness remains true.
     6. `capacity`: Memory and disk consumption relative to configured limits (`memory_budget_bytes`, disk headroom). Flags warning at 80% and failure/shedding at 100%.
     7. `degradation`: Composite health code and reason explaining any dimension impairment.
   - **Grounding Rule**: A live process with unavailable storage MUST remain live while reporting `durability: FAIL` and `availability: FAIL`. Liveness alone NEVER produces workload health.
   - **Stale Observation Policy**: Observations older than `stale_observation_threshold = 15s` are marked `is_stale: true` and downgraded to `UNKNOWN` rather than reporting false healthy zeros.

2. **Status Model & Authoritative Field Semantics (Step 2, V071-02, UIE-M6-01)**:
   - Standardized `ViewStatus` contract:
     ```text
     ViewStatus {
         state: ViewState,                    // Active, Paused, Recovering, Degraded, Failed
         published_frontier: Option<u64>,     // Durably committed epoch visible to readers
         input_frontier: Option<u64>,         // Highest ingested source epoch
         freshness_lag: Option<Duration>,     // input_frontier - published_frontier in ms
         freshness_slo: Option<Duration>,     // Configured SLO target
         state_bytes: Option<u64>,            // SlateDB + RAM arrangement footprint
         memory_bytes: Option<u64>,           // Current RSS / arena memory attributed to view
         assigned_shards: Vec<ShardAssignment>,// Shard IDs and owning worker IDs
         degradation_reason: Option<DegradationReason>, // WaitingOnSource, WorkerPressure, CompactionLag, StorageUnavailable
         blocking_operation: Option<OperationId>,      // In-flight migration or checkpoint blocking progress
     }
     ```
   - **Explicit Missing Semantics**: Missing values strictly report one of: `known`, `unknown`, `stale`, `unavailable`, `not_applicable`. No synthetic zeros for missing observations.
   - **Commit Boundary**: Published frontier advances ONLY when epoch durability in SlateDB is fully acknowledged.

3. **`rockstream doctor` Real Bounded Probes Matrix (Step 3, V071-03, UIE-M6-04)**:
   - Exactly twelve non-destructive diagnostic checks executed with bounded concurrency and timeouts:
     1. `config.parse_and_semantic`: Validates TOML syntax, semantic bounds, and rejects illegal options.
     2. `storage.filesystem_and_object_store`: Probes LFS directory or S3/MinIO bucket access (read, write, delete probe file).
     3. `network.endpoints`: Validates listen addresses and DNS resolution of configured endpoints.
     4. `network.pgwire_connectivity`: Probes PGWire server handshake and protocol negotiation on port 5432.
     5. `control.connectivity`: Probes Control Raft RPC reachability and election status on port 9200.
     6. `worker.connectivity`: Probes Worker DataPlane RPC and gossip channels on port 9100.
     7. `connector.connectivity`: Probes configured Kafka broker / PostgreSQL CDC source endpoints with bounded timeout.
     8. `tls.certificate_validity`: Validates file existence, expiration date ($\ge 30$ days), and private key match.
     9. `storage.format_compatibility`: Verifies format magic bytes, schema compatibility, and flags obsolete versions.
     10. `catalog.recovery`: Probes ability to read and rebuild catalog definitions from `ShardDb` snapshot.
     11. `system.port_conflicts`: Detects port collisions across standard ports (5432, 9090, 9100, 9200).
     12. `system.resource_limits`: Validates open file limits (`RLIMIT_NOFILE >= 1024`) and memory baseline ($\ge 512$ MB).
   - **Distinctions & Redaction**: Strict `PASS`, `WARN`, `FAIL`, `SKIP` statuses. Bounded timeout: 5s per check, 30s overall. Credentials, passwords, SASL tokens, and secrets are strictly redacted in summaries, details, and remediation text.

4. **Canonical SQL Catalog Relations (`rockstream_catalog.*`) (Step 4, V071-04, V071-10, UIE-M4-01)**:
   - Provide authoritative virtual relations accessible via standard SQL `SELECT`:
     - `rockstream_catalog.namespaces`
     - `rockstream_catalog.tables`
     - `rockstream_catalog.nodes`
     - `rockstream_catalog.shards`
     - `rockstream_catalog.operations`
     - `rockstream_catalog.views`
     - `rockstream_catalog.sources`
     - `rockstream_catalog.workloads`
     - `rockstream_catalog.checkpoints`
   - **Query Execution & Lineage**: Handled natively in gateway `CatalogStubs::handle_query` and SQL execution engine. No parallel catalog, no synthetic or hallucinated rows.
   - **Authorization & Bounds**: Authorization checked before pagination and count accumulation. Capped scan rows (`MAX_CATALOG_SCAN_ROWS = 1000`) and bounded lineage DAG depth (`MAX_LINEAGE_DEPTH = 16`).

5. **Structured Logging & Correlation Identifier Propagation (Step 5, V071-05)**:
   - Canonical 7-tuple correlation context:
     $$\text{LogContext} = (\text{request\_id}, \text{operation\_id}, \text{workload\_id}, \text{view\_id}, \text{shard\_id}, \text{worker\_id}, \text{epoch})$$
   - Carried across asynchronous tasks, Tokio spawn boundaries, RPC exchanges, and retries.
   - Schema explicitly marks non-applicable fields as `null` / `None` rather than fabricating IDs. Bounded log ring buffer (`MAX_STRUCTURED_LOG_EVENTS = 4096`) with exposed dropped counter.

6. **Production Metrics Classes, Provenance & Units (Step 6, V071-06, UIE-M6-03)**:
   - 12 authoritative metric classes exported via `/metrics`:
     1. Ingest throughput: `rockstream_ingest_rows_total`, `rockstream_ingest_bytes_total` (counter, rows/bytes)
     2. Execution rows: `rockstream_execution_rows_total` (counter, rows)
     3. Epoch duration: `rockstream_epoch_duration_seconds` (histogram, seconds)
     4. Frontier lag: `rockstream_frontier_lag_seconds` (gauge, seconds)
     5. State size: `rockstream_state_bytes` (gauge, bytes)
     6. Worker memory: `rockstream_memory_bytes` (gauge, bytes)
     7. Exchange throughput: `rockstream_exchange_bytes_total` (counter, bytes)
     8. Exchange backpressure: `rockstream_exchange_backpressure_ratio` (gauge, 0.0-1.0)
     9. Checkpoint duration: `rockstream_checkpoint_duration_seconds` (histogram, seconds)
     10. Migration progress: `rockstream_migration_rows_copied_total` (counter, rows)
     11. Connector lag: `rockstream_connector_lag_records` (gauge, records)
     12. Errors: `rockstream_errors_total{code="RS-XXXX"}` (counter, occurrences grouped by stable RS code)
   - Bounded label cardinalities ($\le 64$ distinct series per metric). Counter reset rules tied to process restart epoch.

7. **Seven Planned Degraded Release Scenarios (Step 7, V071-07)**:
   - Planned test suite validating exact diagnosis before, during, and after 7 faults:
     1. `source_disconnected`: Ingestion paused, health reports `degraded`, reason `WaitingOnSource (RS-3701)`, remediation instructions emitted.
     2. `worker_unavailable`: Heartbeat lost, shards marked `Orphaned`, control initiates re-lease, availability degraded.
     3. `migration_active`: Active shard migration reported in `blocking_operation`, operation state visible in SQL and CLI.
     4. `state_budget_exceeded`: Worker state exceeds memory budget, capacity flags `FAIL`, backpressure paused.
     5. `view_recovering`: View replaying WAL/checkpoints, lifecycle `recovering`, readiness `503`.
     6. `connector_lagging`: High upstream offset delta exceeding SLO, freshness flags `FAIL`, lag metrics accurate.
     7. `storage_unavailable`: SlateDB I/O fault injected, durability flags `FAIL`, liveness remains `PASS`.
