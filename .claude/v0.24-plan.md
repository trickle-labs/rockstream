### S1 — `WriteBuffer` struct + `RS-2019` error code

**Files**:
- `crates/rockstream-gateway/src/write_buffer.rs` (new)
- `crates/rockstream-types/src/error_code.rs` (add `RS_2019`)

**WriteBuffer design**:
```rust
pub const WRITE_BUFFER_LIMIT_BYTES: usize = 64 * 1024 * 1024; // 64 MiB

pub enum DmlOp {
    Insert { table: String, cols: Vec<String>, values_tsv: String },
    Update { table: String, old_row_key: String, old_tsv: String, new_tsv: String },
    Delete { table: String, row_key: String },
}

pub struct WriteBuffer {
    ops: Vec<DmlOp>,
    byte_count: usize,
    limit_bytes: usize,   // named upper bound: WRITE_BUFFER_LIMIT_BYTES
}

impl WriteBuffer {
    pub fn new() -> Self { ... }
    /// Returns Err(RS-2019) when limit_bytes exceeded.
    pub fn push(&mut self, op: DmlOp) -> Result<(), GatewayError> { ... }
    pub fn drain(&mut self) -> Vec<DmlOp> { ... }
    pub fn clear(&mut self) { ... }
    pub fn byte_count(&self) -> usize { ... }  // fill-level metric
    pub fn is_empty(&self) -> bool { ... }
}
```

**Bound**: `WRITE_BUFFER_LIMIT_BYTES = 64 MiB` (named, constant, referenced in error message).  
**Fill-level metric**: `WriteBuffer::byte_count()` → surfaces as `direct_write_pending_bytes{shard_id}` in the gateway metric collector.  
**Backpressure/error path**: `RS-2019 write.shard_backpressure` returned from `push()` when `byte_count + op_bytes > limit_bytes`.

**Error code addition** (`error_code.rs`):
```rust
pub const RS_2019: ErrorCode = ErrorCode::new(2019);
// description: "Shard write buffer full — backpressure"
// next_steps: "Wait for downstream IVM processing to drain, then retry COMMIT."
```

**Green gate**: `write_buffer_push_drain_clear` and `write_buffer_limit_returns_rs2019` unit tests.

### S3 — DML parsing → WriteBuffer accumulation

**Files**:
- `crates/rockstream-gateway/src/server.rs` (add INSERT/UPDATE/DELETE dispatch)
- `crates/rockstream-gateway/src/lib.rs` (export `write_buffer` module)

**GatewayHandler** gets two new fields:
```rust
write_buffers: Arc<DashMap<String, WriteBuffer>>,  // key = conn_id
shard_db: Arc<ShardDb>,
```

**`GatewayServer::new`** / `GatewayServer::with_catalog` gain a `shard_db: Arc<ShardDb>` parameter.

**Connection ID**: On any write DML `do_query` call, extract `conn_id = client.metadata().get("_rs_conn_id").cloned()`. If absent, generate a UUID v4, insert via `client.metadata_mut()`, and seed the `DashMap` entry.

**INSERT parsing**:
- `INSERT INTO <table> [(cols)] VALUES (v, v, ...)` — positional or named columns, one row.
- Values are serialized to tab-separated string for the `view_output/{table}/{row_key}` storage.
- `row_key` = deterministic UUID from row hash (so retries are idempotent within the buffer).

**UPDATE parsing**:
- `UPDATE <table> SET col = val [, ...] WHERE col = val` — simple single-key WHERE only in v0.24.

**DELETE parsing**:
- `DELETE FROM <table> WHERE col = val` — simple single-key WHERE.

**Green gate**: `insert_accumulates_in_write_buffer` and `delete_accumulates_in_write_buffer` unit tests.

### S4 — COMMIT → atomic WriteBatch flush (next `source_epoch`)

**Files**:
- `crates/rockstream-gateway/src/server.rs`

**COMMIT handler** (replaces the trivial current handler):

1. Look up `conn_id` in `write_buffers`.
2. If buffer is empty → return `COMMIT` (no-op).
3. Check idempotency (see S6 — if not set, reject with RS-2007).
4. Allocate next epoch: `epoch = shard_db.last_epoch.fetch_add(1, SeqCst) + 1`.
5. Build `WriteBatch`:
   - For each `DmlOp::Insert`: `batch.put(view_output_key(table, row_key), tsv_bytes)`
   - For each `DmlOp::Update`: `batch.delete(view_output_key(table, old_key))` +
     `batch.put(view_output_key(table, new_key), new_tsv)`
   - For each `DmlOp::Delete`: `batch.delete(view_output_key(table, row_key))`
   - `ShardDb::put_idempotency_key(&mut batch, shard_id=0, key_hash, epoch)` (with timestamp)
   - `batch.put(ShardKeyEncoder::frontier_key(), epoch.to_be_bytes())`
6. `shard_db.write_batch(batch).await` → atomic commit.
7. Clear write buffer for `conn_id`.
8. Return `Response::TransactionEnd(Tag::new("COMMIT").with_rows(affected_count))`.
9. Set `session.last_written_epoch = Some(epoch)` (for future read-your-writes in v0.25).

**Source epoch key**: `view_output/{table}/{row_key}` where `row_key` encodes values as
`{col1}={val1}|{col2}={val2}` (stable, deterministic per row).

**No range-delete assertion**: `WriteBatch` uses only `Put` and `Delete` ops — no range-delete
path exists. Asserted by `commit_write_batch_uses_no_range_delete` test.

**Green gate**: `commit_flushes_rows_scannable_via_view_prefix` unit test.

### S6 — Idempotency enforcement

**Files**:
- `crates/rockstream-gateway/src/session.rs` (extend `SessionState`)
- `crates/rockstream-gateway/src/server.rs` (SET handling, COMMIT check)

**SessionState additions**:
```rust
pub idempotency_key: Option<[u8; 16]>,       // MD5 of user-supplied key string
pub source_epoch_envelope: Option<u64>,       // SET rockstream.source_epoch = N
pub last_written_epoch: Option<u64>,          // for read-your-writes (v0.25)
```

**`SET` parsing** (add to `dispatch_sync`):
- `SET rockstream.idempotency_key = 'str'` → `MD5::digest(str)` → store in session
- `SET rockstream.idempotency_key = DEFAULT` / `NULL` → clear
- `SET rockstream.source_epoch = N` → parse N as u64, store in session

**COMMIT idempotency check** (step 3 of S4):
```
if session.idempotency_key.is_none() && session.source_epoch_envelope.is_none() {
    return RS-2007 "[RS-2007] write.idempotency_key_required: ..."
}
if let Some(key_hash) = session.idempotency_key {
    if let Some(prev_epoch) = shard_db.get_idempotency_epoch(shard_id=0, key_hash).await? {
        // idempotent replay: already committed
        buffer.clear();
        return COMMIT tag with 0 rows (no-op);
    }
}
```

**Time-bounded idempotency-key table**: the idempotency key value stores `[epoch:8][timestamp_ms:8]`
(16 bytes). A `cleanup_expired_idempotency_keys(shard_db, retention_ms)` function
(called lazily at COMMIT or on a periodic interval — default retention 86400000 ms / 24 h)
does a bounded `scan_prefix(idempotency_prefix)` → point-deletes expired entries.
This is scan-and-delete; no range-delete path. Asserted by a dedicated test.

**Green gate**: `missing_idempotency_key_returns_rs2007`, `idempotent_replay_is_noop`, and
`idempotency_key_expiry_cleanup_no_range_delete` unit tests.

### S7 — `INSERT … RETURNING`

**Files**:
- `crates/rockstream-gateway/src/server.rs`

**Parsing**: After `dispatch_async` identifies an `INSERT … RETURNING …` statement:
1. Execute as normal INSERT → WriteBatch flush (but on `INSERT … RETURNING`, COMMIT is implicit
   — the statement is auto-committed for single statements outside a transaction).
2. After `write_batch`, collect the written rows from the `WriteBatch` ops (not a re-read — the
   rows were computed in memory during S4, so return them directly from the `DmlOp` list).
3. Build a `QueryResponse` with the table schema columns and the written row values.

**Multi-row `INSERT … SELECT … RETURNING`**:
- Parse sub-select source: `INSERT INTO t SELECT … FROM source WHERE …`.
- In v0.24, the source must be a literal `VALUES (…), (…)` or a constant sub-select
  (no joins). Unsupported shape → `RS-2013 session.returning_unsupported_shape`.
- Each inserted row is returned in the `RETURNING` result set.

**Green gate**: `insert_returning_returns_written_rows` and
`insert_select_returning_multi_row` unit tests.

## 5. Coordination Slices

v0.24's direct-write connector is single-connection local: no new distributed coordination
path is introduced (COMMIT writes to a single base-table shard without any shard reassignment,
leader election, or cross-shard protocol). The existing M1–M4 FizzBee models cover the
`commit_epoch`/frontier advance path already validated in v0.18–v0.22. No new
`SimRuntime`/`buggify!()` test is required by the ground rules for this version.
