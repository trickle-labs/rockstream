# v0.45.3 Plan — Coverage-Gate Expansion, Lint-Suppression Cleanup & Scheduled Dependency Audit

## Deferred-Item Audit

Scanned every `sign-offs/v*.md`. No prior version left an item marked
deferred/postponed/out-of-scope that overlaps this version's Scope (coverage
gates, `Makefile`/CI drift, gateway lint suppression, or dependency-audit
scheduling). The only related note is `v0.42.3.md`'s NUM_SHARDS-scoping
out-of-scope item, which is unrelated to coverage/lint/dependency tooling.

This version's Scope itself originates from a **self-documented gap**, not a
sign-off deferral: `DEPENDENCY_POLICY.md`'s Enforcement section already states
"Scheduled to be made real at v0.45.3," and the roadmap row states the
original wording of the coverage-crate rollout deferred a group of crates to
an unscheduled future version — this plan closes both gaps in full, now.

**Scope-completeness catch:** the roadmap row's prose names 11 non-gateway
crates explicitly (`rockstream-diff`, `-ops`, `-storage`, `-runtime`, `-sql`,
`-control`, `-connectors`, `-types`, `-plan`, `-sim`, `-cli`), but the Proof
column says *"thirteen workspace crates."* The workspace has 13 members total:
those 11 + `rockstream-gateway` (already gated since v0.42) + `rockstream-oracle`
(not named in the prose). Since nothing may be deferred, **`rockstream-oracle`
is in scope** and gets the same coverage gate as the other 11 — otherwise the
Proof's "thirteen" claim would be false with only 12 gated.

## Vertical Slices

Each slice ends in a green, CI-runnable check (test, `cargo llvm-cov`, or
`cargo clippy` command). Order follows the roadmap's stated priority: hot
path first, then the rest, then cross-cutting lock/lint/dependency work.

### S1 — Baseline measurement (prerequisite for S2/S3)
For each of the 12 ungated crates (`rockstream-diff`, `-ops`, `-storage`,
`-runtime`, `-sql`, `-control`, `-connectors`, `-types`, `-plan`, `-sim`,
`-cli`, `-oracle`), run `cargo llvm-cov --package <crate> --summary-only`
to record current line % and region %. This produces the per-crate floor
table used by S2/S3:
  - floor = max(70, floor(measured %)) — i.e. never below 70%, and never set
    below whatever the crate already achieves (no loosening).
  - Any crate currently below 70% must get real tests added in S2/S3 to
    cross 70% before its gate step is added to CI (a gate can never be added
    below the baseline it's supposed to enforce).
Ends green when: a recorded baseline table exists and every floor value is
decided (checked into the plan/evidence file, not committed to source).

### S2 — Hot-path crates: `rockstream-diff`, `rockstream-ops`, `rockstream-storage`, `rockstream-runtime`
For each crate: (a) add tests if needed to clear its 70% floor, (b) add a
`cargo llvm-cov --package <crate> --fail-under-lines <N> --fail-under-regions <N>`
step pair to the `coverage` job in `ci.yml`, (c) add the matching
`cargo llvm-cov --package <crate> --fail-under-lines <N> --fail-under-regions <N>`
lines to the Makefile `coverage-gate` target.
Ends green when `cargo llvm-cov --package <crate> --fail-under-lines <N> --fail-under-regions <N>`
exits 0 locally for all four crates.

### S3 — Remaining crates: `rockstream-sql`, `rockstream-control`, `rockstream-connectors`, `rockstream-types`, `rockstream-plan`, `rockstream-sim`, `rockstream-cli`, `rockstream-oracle`
Same treatment as S2, one crate at a time. Ends green the same way, for all
eight crates.

### S4 — Fix `Makefile`/`ci.yml` drift + add the permanent lock test
Replace the stale `coverage-gate` target (currently gateway-only,
`--fail-under-lines 90` / `--include-files ... --fail-under-branches 85`,
which doesn't match what CI actually enforces) with the real, CI-enforced
flags for **every** gated crate (gateway included): `--fail-under-lines 70`
and `--fail-under-regions 70`, one pair per crate, matching S2/S3's per-crate
floors exactly (floors above 70 for crates whose baseline already exceeds it).
Add a new test mirroring `test_coverage_gate_config_is_present`'s parsing
style (extend `crates/rockstream-gateway/tests/conformance_doc_tests.rs`, or
a new sibling test file if a more central location is more appropriate):
`test_makefile_coverage_gate_matches_ci_yml` — parses both `Makefile` and
`.github/workflows/ci.yml`, extracts the `--package`/`--fail-under-lines`/
`--fail-under-regions` triples from each, and asserts (1) the same 13 crate
names appear in both, and (2) each crate's numeric floor is identical in both
files.
Ends green when that test passes.

### S5 — Gateway lint-suppression cleanup
Remove `#![allow(clippy::all, unused_variables, dead_code)]` from
`crates/rockstream-gateway/src/lib.rs`. Measured today: 57 lib warnings + 6
additional test-target warnings surface (unused variables/params, one dead
method, missing `Default` impls, `or_insert_with`→`or_default`, manual
prefix-stripping, `matches!`-style match simplification, collapsible `if`,
loop-variable indexing, overly complex types, etc.). Fix each with a real
code change where the lint is correct; where a lint is a genuine false
positive, replace it with a narrow, item-level `#[allow(clippy::specific_lint)]
// reason` — never crate- or module-wide.
Ends green when `cargo clippy --workspace --all-targets -- -D warnings`
passes with zero blanket allow remaining in gateway's `lib.rs`.

### S6 — Scheduled dependency-audit workflow
Add `.github/workflows/dependency-audit.yml`, mirroring
`simulation-soak.yml`'s cron pattern (`schedule:` + `workflow_dispatch:`,
independent of `pull_request`/`push` triggers), running `cargo deny check`
against `main` daily. Leave the existing PR-triggered `cargo deny` step in
`ci.yml` untouched (fast PR feedback stays; the new workflow adds the
missing "runs even when nothing touches the repo" coverage).
Add a detection test proving the mechanism actually works: temporarily
remove one existing `ignore` entry from a copy of `deny.toml` (e.g.
`RUSTSEC-2025-0141`) in a temp dir, run `cargo deny check advisories
--config <tmp>/deny.toml`, and assert non-zero exit — proving an
un-ignored/newly-disclosed advisory is caught. Add a config-presence test
asserting the new workflow file has a `schedule:`/`cron:` trigger with a
period ≤24h.
Ends green when both new tests pass locally.

### S7 — Real `dependabot.yml` + policy doc cleanup
Add `.github/dependabot.yml`: `version: 2`, one `updates` entry with
`package-ecosystem: "cargo"`, `directory: "/"`, `schedule.interval: "weekly"`.
Add a structural test asserting the file parses as valid YAML with those
exact fields. Update `DEPENDENCY_POLICY.md` to remove the "Not yet true"
caveat now that both `dependabot.yml` and the scheduled audit workflow exist.
Ends green when the structural test passes. The Proof's "opens a real
version-bump PR in a fork smoke-test" clause is **not unit-testable**; it is
a one-time manual verification to be performed and recorded as Prove-phase
evidence (a link to the actual fork PR), not silently dropped.

## Test Commitments / Durability Slices / Coordination Slices — N/A, explicitly

This version adds no new IVM operator, no new durability path (commit,
replay, checkpoint, compaction, WAL), and no new distributed-coordination
path. It is CI/tooling hardening only (per the roadmap's own Phase 12.6
annotation: "no new coordination protocol"). No oracle property tests,
SlateDB/MinIO durability tests, or `SimRuntime`/`buggify!()` seeds are owed
by this version. The SlateDB-range-deletion and unbounded-accumulation
ground rules are respected trivially: no code path touched here allocates
storage, buffers, or queues.
