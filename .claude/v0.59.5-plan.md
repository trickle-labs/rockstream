# v0.59.5 Plan — Delta-Native State Foundation

## Scope and Boundary

v0.59.5 executes the core state-architecture transformation of the Pre-v1 Performance Architecture track (`NEW_ROADMAP.md` v0.59.5, `rockstream-pre-v1-scalability.md` Section 1):

1. **Long-Lived Worker Process Service Plumbing**:
   - Refactor `rockstream start --role worker` from an ephemeral run into a long-lived service that runs independently, accepts an explicit `--worker-id <u64>` (or generates a deterministic stable ID), and listens for OS shutdown signals (SIGTERM/SIGINT) with clean drain.
   - Establish bidirectional control-plane connectivity: worker registers with explicit `WorkerId`, location, and capabilities, sends periodic heartbeats, acquires authoritative shard leases, and executes streaming dataflow partitions.
   - Ensure the control plane independently tracks worker heartbeats, shard leases, and health without synthetic single-process shims.

2. **External Benchmark & Oracle Harness (S1 Baseline Capture)**:
   - Establish an independent benchmark and oracle test harness that imports **no RockStream internal crate**, interacting strictly through external process boundaries (CLI, PGWire, TCP/HTTP, and Kafka/Postgres connectors).
   - Enforce process isolation validation: harness strictly requires distinct OS process IDs (PIDs) or cgroup identities and distinct `WorkerId`s for multi-worker evaluations (1, 2, 4, 8 workers); missing multi-worker capability is reported as `UNAVAILABLE`, never simulated by task handles or duplicate IDs.
   - Implement an independent multiset oracle computing expected query and aggregation results from raw event streams without engine code.
   - Capture a reproducible v0.59.5 S1 pre-optimization baseline against unchanged v0.59.4 full-state persistence for uniform aggregation, high-cardinality aggregation (1K, 100K, 10M groups), and joins across 1, 2, 4, and 8 real worker processes.
   - Record exact candidate SHA, artifact digests, environment specs, throughput, p50/p95/p99 freshness, CPU profiles, lock time, RSS, network bytes, SlateDB storage bytes, object-store requests, and logical vs. physical write amplification.

3. **Delta-Native State Representation (`StateMutation`, `OperatorEpochResult`, `EpochStateDelta`)**:
   - Introduce first-class state mutation primitives:
     ```rust
     pub enum StateMutation {
         Merge {
             key: Vec<u8>,
             law: MergeLawId,
             law_version: MergeLawVersion,
             operand: Bytes,
         },
         Put {
             key: Vec<u8>,
             value: Bytes,
         },
         Delete {
             key: Vec<u8>,
         },
     }
     ```
   - Introduce `EpochStateDelta` containing per-operator mutations, dirty key counts, and logical delta bytes.
   - Introduce `OperatorEpochResult`:
     ```rust
     pub struct OperatorEpochResult {
         pub output_delta: ArrowZSet,
         pub state_mutations: Vec<StateMutation>,
         pub metrics: OperatorEpochMetrics,
     }
     ```
   - Upgrade `MergeOperatorRegistry` with versioned law tags, typed associative merge functions, and **checked arithmetic** (`i128` intermediate accumulation for sum/count with overflow detection emitting `RS-1002` rather than silent wrapping).
   - Retain ordered/replacement updates where no associative merge law exists.

4. **Operator Delta Tracking & Hot-Path O(1) Group Commit**:
   - Refactor all stateful operators (`AggregateOp`, `DistinctOp`, `JoinOp`, `WindowOp`, `TopKOp`, `IndexArrangeOp`) to incrementally track dirty keys and emit only changed entries per epoch.
   - Modify the epoch commit path (`GroupCommit`, `ShardDb::write_batch`) to consume `EpochStateDelta` directly without rescanning live in-memory maps or walking unchanged arrangement state.
   - Proof guarantee: a 1-key insert/update/delete against arrangements containing 1,000, 100,000, and 10,000,000 groups produces approximately constant state mutations and logical write bytes (O(1) write amplification).

5. **State & Manifest Versioning, Migration, Rollback, and Fail-Closed**:
   - Introduce `StorageFormatVersion` (`V1SnapshotFull`, `V2DeltaNative`) and version every state value and checkpoint manifest.
   - Implement deterministic online/offline migration from v0.59.4 snapshot state to v0.59.5 delta-native format.
   - Define mixed N/N+1 read/write policy: N+1 workers can read V1 snapshots and emit V2 deltas; unsupported or corrupted formats fail closed with `RS-5001` / `RS-5002` / `RS-5003`.
   - Document and verify rollback boundaries: state committed in V2 format cannot be silently corrupted by V1 binaries; clean rollback paths are validated.

6. **Formal M1 Model Re-Proof & SimRuntime Crash Chaos**:
   - Update `formal/m1_epoch_commit.fizz` with the delta-state variant modeling mutations, tombstones, and migration boundaries.
   - Formally verify invariants: M1-S1 (write batch atomicity), M1-S2 (frontier monotonicity), M1-S3 (CALM commit monotonicity), M1-S4 (verifiability), M1-S5 (idempotent replay under delta state), M1-S6 (tombstone non-resurrection), M1-S7 (atomic migration), and M1-L1 (epoch progress).
   - Ensure all paired runtime assertions (`assert!`) are present across `rockstream-storage`, `rockstream-runtime`, and `rockstream-control` and verified by `scripts/check-invariant-pairs.sh`.
   - Implement SimRuntime tests exercising crashes at every step of format migration, delta commit, and recovery.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` remains runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window has a named upper bound, fill-level metric, and backpressure/error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix the root cause.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

## 4. Vertical Slices

  - In `run_start`, when `role == "worker"`, assign explicit `WorkerId` (or deterministic ID if omitted), connect to control plane, register worker, spawn periodic heartbeat loop, and block on termination signals instead of exiting immediately.
  - Enhance `rockstream-control` and `rockstream-runtime` to observe independent worker heartbeats, shard lease assignment, and clean worker drain.

### Slice 2 (S2): External Benchmark / Oracle Harness & S1 Baseline Capture

  - Implement multiset oracle: independently consumes raw inputs, calculates exact materialized view multisets, queries PGWire, and compares results.
  - Capture S1 baseline: run 1, 2, 4, and 8 worker processes under uniform and high-cardinality aggregation (1K, 100K, 10M groups) and joins, recording throughput, p50/p95/p99 freshness, CPU profiles, lock time, RSS, network bytes, SlateDB storage bytes, and write amplification.

### Slice 3 (S3): Delta-Native State Primitives & Checked Merge Laws
- **Goal**: Introduce `StateMutation`, `EpochStateDelta`, and `OperatorEpochResult` types, and equip `MergeOperatorRegistry` with versioned law tags and checked overflow arithmetic.
- **Implementation**:

### Slice 4 (S4): Stateful Operator Delta Tracking & O(1) Group Commit Integration
- **Goal**: Refactor stateful IVM operators to track dirty keys incrementally and emit delta mutations directly into the atomic group-commit `WriteBatch`, eliminating full arrangement scans on the commit hot path.
- **Implementation**:
  - Refactor `AggregateOp` in `crates/rockstream-ops/src/aggregate.rs`: track dirty keys during epoch processing; emit `StateMutation::Merge` (or dirty `Put`) only for changed group keys; emit tombstone `Delete` / zero identity when count reaches zero.
  - Refactor `DistinctOp` in `crates/rockstream-ops/src/distinct.rs`: track dirty distinct keys; emit point mutations only for changed multiplicities.
  - Refactor `JoinOp` in `crates/rockstream-ops/src/join.rs`: track dirty row keys per side; emit point `Put`/`Delete` mutations only for changed join entries.
  - Refactor `WindowOp`, `TopKOp`, and `IndexArrangeOp` in `rockstream-ops`: replace full state persistence with dirty-journal delta emission.
  - Update `GroupCommit` in `crates/rockstream-ops/src/group_commit.rs` and `crates/rockstream-ops/src/live_exec.rs`: merge `OperatorEpochResult` state mutations directly into the epoch's atomic SlateDB `WriteBatch`.
