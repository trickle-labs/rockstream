## Key Design Decisions

**TUMBLE window storage key format** (DESIGN.md §6.9):
```
Partial state:
  [0x01 (OpState)][0x54 0x57 ('TW')][op_id:8][window_id:8 BE ms][group_key:var]
  → partial_state_bytes

Watermark state (MaxRegister semilattice):
  [0x06 (ShardMeta)][0x57 0x4D ('WM')][op_id:8]
  → watermark_ms:8 BE
```
`window_id = (event_time_ms / window_size_ms) * window_size_ms` — aligns event time to
window start epoch. Key sort order: window_id ascending = lowest window_id first in scan.

**Top-K storage key format** (DESIGN.md §6.10):
```
Top-K buffer (value-descending sort):
  [0x01 (OpState)][0x54 0x4B ('TK')][op_id:8][partition_key:var][value_desc_bytes:8][row_id:16]
  → row_bytes

  value_desc_bytes = (!((v as u64) ^ 0x8000_0000_0000_0000)).to_be_bytes()
  → lexicographic scan order = highest value first per partition
```
`scan_prefix(partition_prefix).take(K)` returns top-K in O(K + log N). Buffer size = K + ε (ε = K).

**Late-data policy**: `drop` (default) — rows with `event_time_ms < watermark_ms` are
silently discarded before reaching the window arrangement. Policy is recorded per-operator.

**Compaction filter rule**: state for `window_id W` may only be removed when BOTH:
1. `W + window_size_ms + allowed_lateness_ms < watermark_ms` (event-time TTL satisfied)
2. The input frontier has advanced past `W + window_size_ms` (correctness gate)

Named bound: `TUMBLE_WINDOW_STATE_LIMIT: usize = 100_000` window × group_key pairs per operator.

## Vertical Slices

### TUMBLE Window (IVM-8)

**TW-1: Storage key encoding**  
Add `TW_DISCRIMINATOR = [0x54, 0x57]`, `WM_DISCRIMINATOR = [0x57, 0x4D]`, `TK_DISCRIMINATOR = [0x54, 0x4B]`
to `rockstream-storage/src/keys.rs`. Add `tumble_window_key(op_id, window_id, group_key)`,
`tumble_window_op_prefix(op_id)`, `tumble_window_window_prefix(op_id, window_id)`,
`watermark_key(op_id)`, and value_desc sort helpers.  
**Green test**: `tumble_window_key_roundtrip` — encode/decode round-trip; two keys with different
`window_id` sort in ascending `window_id` order.

**TW-2: `TumbleWindowOp` skeleton**  
`rockstream-ops/src/time_window.rs`: struct `TumbleWindowOp` with `process_epoch` that assigns
`window_id`, accumulates weighted partial state per `(window_id, group_key)`, diffs against
previously-emitted state, emits retract+insert deltas for changed windows.  
**Green test**: `tumble_window_basic_assignment` — two input epochs; rows in window 0 and window 1;
verify output contains correct `window_id` column and weighted rows. No persistence.

**TW-3: Watermark tracking**  
Add `WatermarkState` (MaxRegister: `max(a, b)` merge law, idempotent), `load_watermark`,
`persist_watermark` to `time_window.rs`. Watermark advances drive window-close decisions.  
**Green test**: `tumble_window_watermark_merge_idempotent` — merge(w, w) = w; merge(w1, w2) = max.

**TW-4: Late-data `drop` policy and frontier-gated window close**  
Window is considered closeable when `watermark_ms > window_id + window_size_ms`. Rows with
`event_time_ms < watermark_ms` are dropped (policy = `drop`). Window state is only emitted
once and flagged as finalized after close.  
**Green test**: `tumble_window_late_data_dropped` — insert row, advance watermark past window end,
insert same-window row; second row must NOT appear in output.

**TW-5: Frontier-aware compaction filter (no-early-eviction)**  
`CompactionFilter` struct: `may_delete(key)` returns false unless both TTL and frontier gate pass.
Test asserts state survives when only TTL is met but frontier has not advanced.  
**Green test**: `tumble_window_compaction_filter_no_early_eviction` — set watermark past TTL but
hold frontier before window_end; verify `may_delete` returns false for window state key.

**TW-6: Diff pass arm**  
Add `PlanNode::TumbleWindow { .. }` arm in `rockstream-diff/src/lib.rs` that emits
`OpKind::TumbleWindow { window_size_ms, late_data_policy }`.  
**Green test**: `diff_tumble_window_emits_tumble_window_op` — differentiate a TumbleWindow plan;
assert output contains exactly one `OpKind::TumbleWindow`.

**TW-7: LFS durability**  
`rockstream-ops/tests/lfs_time_window.rs` with four tests:
- `lfs_tumble_window_state_persists` — partial state (window buckets) survive ShardDb close/reopen
- `lfs_tumble_window_crash_replay` — write to WAL, drop without flush, reopen; output bit-identical
- `lfs_tumble_window_no_range_delete` — WriteBatch for `persist_window_state` has no DeleteRange
- `lfs_tumble_window_no_early_eviction` — advance watermark but hold frontier; scan confirms
  window state key still present after would-be compaction point

**TW-8: MinIO durability**  
`rockstream-ops/tests/minio_time_window.rs` — skips if Docker unavailable:
- `minio_tumble_window_late_data_and_ttl` — late rows dropped; partial state not evicted on
  MinIO backend until both TTL and frontier gate are satisfied

### Top-K (IVM-9 per roadmap)

**TK-1: Storage key encoding**  
Add `topk_key(op_id, partition_key, value, row_id)` and `topk_partition_prefix(op_id, partition_key)`
to `keys.rs`. The value_desc encoding inverts `window_sort_key` so highest value = first scan hit.  
**Green test**: `topk_key_scan_order` — insert keys for values [10, 5, 20, 1]; prefix scan returns
them in descending order [20, 10, 5, 1].

**TK-2: `TopKOp` skeleton — insert and emit**  
`rockstream-ops/src/topk.rs`: struct `TopKOp` with `K+ε` buffer (ε=K). Insert new row:
if buffer has room, add it; if new row outranks current K-th, emit displacement delta.  
**Green test**: `topk_basic_insert_and_emit` — insert K+2 rows in random order; output contains
exactly K rows (highest K values); buffer holds K+ε.

**TK-3: Delete-refill correctness**  
Delete any row ranked ≤K: scan buffer past K for the next candidate; emit delta retracting
the deleted row and inserting the replacement. If buffer is exhausted below K, emit only retraction.  
**Green test**: `topk_delete_refill_all_positions` — K=3, insert 6 rows; delete rank-1, rank-2,
rank-3 rows individually (three separate runs); verify replacement row is always the next-best.

**TK-4: Displacement delta on new top-K entry**  
New row with value > current K-th row: retract the current K-th row from output, insert new row.  
**Green test**: `topk_displacement_delta_emitted` — insert K rows, then insert a row that outranks
the K-th; output delta contains exactly one retraction (old K-th) and one insertion (new row).

**TK-5: Diff pass arm**  
Add `PlanNode::TopK { .. }` arm in `rockstream-diff/src/lib.rs` that emits
`OpKind::TopK { k, rank_col, partition_by }`.  
**Green test**: `diff_topk_emits_topk_op` — differentiate a TopK plan; assert output contains
exactly one `OpKind::TopK` with correct k and rank_col.

**TK-6: Oracle property test**  
`rockstream-oracle/src/topk_oracle.rs`: `TopKOracle` batches all inserts/deletes and computes
reference output as `sort_desc(rows).take(K)`. Compare against `TopKOp` incremental output.  
**Green test**: `oracle_topk_incremental_matches_batch` — 1,000-iteration random test: random
insert/update/delete sequences; K ∈ {1, 3, 5, 10}; multiple partition keys; incremental ==
batch reference for every epoch.

**TK-7: LFS durability**  
`rockstream-ops/tests/lfs_topk.rs`:
- `lfs_topk_state_persists` — arrangement (buffer) survives ShardDb close/reopen
- `lfs_topk_crash_replay` — WAL replay; output bit-identical to non-crash path
- `lfs_topk_no_range_delete` — WriteBatch has no DeleteRange

**TK-8: MinIO durability**  
`rockstream-ops/tests/minio_topk.rs` — skips if Docker unavailable:
- `minio_topk_random_changes` — random insert/update/delete sequence on MinIO backend;
  result after each epoch matches batch oracle
