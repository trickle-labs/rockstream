# v0.43 Plan — FizzBee Cold-Tier Protocol Model & Simulator Fidelity

Source: `NEW_ROADMAP.md` row (Phase 12, v0.43) and `DESIGN.md` §17.8 gaps 1–3.
Prerequisite confirmed: `sign-offs/v0.42.3.md` is complete (all boxes
checked) and explicitly states it "unblock[s] Phase 12 (v0.43), which
requires a working `make verify` gate for its new M5 model."

**Scope is model + simulator fidelity only — no new cold-tier sink
implementation.** `object_store_sink.rs` and `kafka_sink.rs` (both landed
v0.21) already implement the 2PC exactly-once protocol M5 formalizes; v0.43
hardens their simulation coverage and proves the protocol in FizzBee ahead
of v0.44's Iceberg/Delta-specific sinks reusing the same protocol.

## 2. Vertical Slices

Each slice ends in a green test before the next begins.

1. **S1 — `formal/m5_cold_tier_sink.fizz` authored and green** (binding
   pre-implementation gate; must land before S2–S4 touch any sink code).
   Models the existing `object_store_sink.rs` 2PC protocol: roles
   `SinkConnector` (pre_commit → `_pending/{epoch}/` → atomic rename to
   final), `ExternalObjectStore` (with a `partial_write` crash-yield point
   during the rename/PUT), `ControlPlane`/`CheckpointCoordinator` (checkpoint
   coupling, reusing M3's pattern). Safety: M5-S1 (no duplicate final
   output), M5-S2 (no data loss — every committed row survives), M5-S3
   (manifest-pointer atomicity — the final-prefix pointer is never observed
   in a partially-written state). Liveness: M5-L1 (`committed_epoch` always
   advances after a bounded number of crashes, mirroring M1/M3's
   `MAX_CRASHES` pattern). Add `m5_cold_tier_sink` to `Makefile`'s `verify`
   and `verify-relaxed` targets and to `.github/workflows/ci.yml`'s
   "Formal verify — smoke, M1, M2, M3, M4 (hard gate)" step (rename to
   include M5, no `continue-on-error`, matching the v0.42.3 hard-gate
   contract). Add a `### 3.5 M5 — Cold-Tier Exactly-Once Sink` section to
   `FIZZBEE_TEST_PLAN.md` (renumbering the existing 3.5/3.6 to 3.6/3.7) and
   an M5 row in Appendix A's spec inventory.
   Green test: `fizz formal/m5_cold_tier_sink.fizz` passes locally and via
   `make verify`.

2. **S2 — gap 1: partial object writes.** Add
   `partial_write_probability: f64` to `SimObjectStore`'s fault model
   (same `buggify!()`-gated pattern as `check_rate_limit`, e.g.
   `crate::buggify!("object_store.partial_write", p)`), truncating bytes on
   `put` when triggered mid-write. Register a new
   `object_store.partial_write` entry in `crates/rockstream-sim/src/law_faults.rs`
   ("`PartialWriteRecoveryTest`" per the roadmap wording) with its own
   `FaultCategory::Io` entry and inclusion in `LAW_FAULT_IDS`. Add a paired
   runtime `assert!` in `rockstream-connectors` — new
   `assert_commit_pointer_atomic` in `sink_connector.rs` alongside the
   existing `assert_no_duplicate_delivery` / `assert_no_lost_delivery_after_checkpoint`
   — asserting the final-prefix pointer is never visible half-written, called
   from `object_store_sink.rs`'s commit path.
   Green test: new `crates/rockstream-connectors/tests/partial_write_recovery_tests.rs`
   with `test_partial_write_recovery_lfs` (LocalFileSystem `object_store`
   backend) and `test_partial_write_recovery_minio_tc` (MinIO via
   `testcontainers`, following `source_proof_tests.rs`'s `MinIO2024` /
   `start_minio` helpers), each injecting `partial_write_probability=0.5`
   and asserting zero duplicate/missing rows in committed output.

3. **S3 — gap 2: Kafka transactional broker timeout.** Add
   `kafka_tx_timeout_probability: f64` fault parameter to the Kafka
   connector's simulator hook (mirrors real `transaction.timeout.ms`
   aborting an open transaction). On trigger, `kafka_sink.rs`'s open
   transaction is force-aborted before commit, forcing the `CheckBeforeCommit`
   recovery path (query topic → absent → re-commit) on the next attempt.
   Register `kafka.tx_timeout` in `law_faults.rs` (or a new
   `kafka_faults.rs` module registered from `lib.rs`, matching
   `coord_faults.rs`'s pattern, if scope warrants a dedicated module).
   Green test: extend/add a Kafka sink test exercising
   `kafka_tx_timeout_probability` and asserting the `CheckBeforeCommit`
   recovery path delivers exactly once (no duplicate, no loss).

4. **S4 — gap 3: `list_staleness_epochs`.** Add
   `list_staleness_epochs: u64` fault parameter to `SimObjectStore` (stale
   `list()` results for N epochs after a `put`). Confirm and assert (per
   DESIGN.md's own note that this gap is "informational only") that no
   RockStream correctness property depends on LIST — CALM epoch manifest
   reads are direct-key reads, never LIST-based. Add a targeted
   `SimObjectStore` unit test proving LIST staleness does not affect any
   `assert_*` in `sink_connector.rs`.

5. **S5 — close the loop.** Update all three DESIGN.md §17.8 gap statuses
   from `[UNMITIGATED — scheduled for v0.43]` to `[MITIGATED]` with a
   one-line evidence pointer to the new tests. Run full
   `cargo test --workspace` and `make verify`.
   Green test: full workspace suite + `make verify`, both green.

6. **S6 — sign-off.** Write `sign-offs/v0.43.md` mapping every Proof claim
   to its test (Phase 2 §6 mapping below, promoted to evidence with actual
   command output).

## 4. Durability Slices

New durability path: **cold-tier sink commit protocol under partial-write
faults** (the `_pending/{epoch}/` → final atomic-rename commit in
`object_store_sink.rs`, now exercised under `partial_write_probability`).

- **SlateDB/LFS test**: `test_partial_write_recovery_lfs` — LocalFileSystem
  `object_store` backend, `partial_write_probability=0.5`, asserts recovery
  reaches a consistent committed state with no duplicate output (matches
  roadmap's "cold-tier recovery test passes without duplicate output").
- **MinIO (S3, TestContainers) test**: `test_partial_write_recovery_minio_tc`
  — same fault injection against a real MinIO container via
  `testcontainers`' `AsyncRunner`, following the existing
  `MinIO2024`/`start_minio` helper pattern in
  `crates/rockstream-connectors/tests/source_proof_tests.rs`.

No other new durability path (no new commit/replay/checkpoint/compaction/WAL
surface) is introduced this version — the Kafka and LIST-staleness fault
additions harden simulator fidelity for *existing* durability paths (M3's
2PC sink, already covered by prior LFS/MinIO tests); they do not open new
ones requiring their own paired LFS+MinIO slice.

## 5. Coordination Slices

New distributed-coordination-adjacent fault surfaces requiring a seeded
`SimRuntime` test with `buggify!()`:

- **`object_store.partial_write` fault** (S2): seeded `SimRuntime` test in
  `crates/rockstream-connectors/tests/partial_write_recovery_tests.rs`
  driving multiple epochs through `ObjectStoreSink` with
  `buggify!("object_store.partial_write", p)` active, asserting
  `assert_no_duplicate_delivery` / `assert_no_lost_delivery_after_checkpoint`
  / new `assert_commit_pointer_atomic` all hold across seeds.
- **`kafka.tx_timeout` fault** (S3): seeded `SimRuntime` test driving
  `KafkaSink` through pre_commit/commit with the fault active, asserting the
  `CheckBeforeCommit` recovery path (`profile: CheckBeforeCommit` branch in
  `kafka_sink.rs`) reaches exactly-once delivery.
- **`list_staleness_epochs` fault** (S4): seeded `SimObjectStore` unit test
  proving no `assert_*` regresses when LIST results are stale (informational
  gap, still requires a regression seed per the "law-faults corpus" audit
  trail convention in `law_faults.rs`).

The M5 FizzBee model itself (S1) is the formal (non-`SimRuntime`) half of
this coordination proof; `COV-M5` (coverage) is the FizzBee-side commitment,
and the three bullets above are its paired runtime/simulator commitments.
