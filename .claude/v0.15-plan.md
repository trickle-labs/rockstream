## 2. Vertical Slices

### Slice 1: Unified Binary Role Flags and Command-Line Interface
- **Goal**: Support `--role=control|worker|gateway|all` and optional/required `--control=<url>` flag on the unified `rockstream` entrypoint.
- **Changes**:
  - [main.rs](file:///Users/grove/projects/rockstream/crates/rockstream-cli/src/main.rs): Modify `Command::Start` arguments to parse `control: Option<String>` and pass it through `StartOptions`.
  - [lib.rs](file:///Users/grove/projects/rockstream/crates/rockstream-cli/src/lib.rs): Add `control: Option<String>` to `StartOptions`. Update `run_start` validation to verify `--control` is present for remote worker/gateway roles.
- **Test**: CLI unit tests asserting that invalid roles are rejected and valid ones parse successfully.

### Slice 2: Control Service Daemon & Live Audit Logging
- **Goal**: Start `ControlService` as a background TCP daemon, auditing all connection, registration, and lease events.
- **Changes**:
  - [lib.rs](file:///Users/grove/projects/rockstream/crates/rockstream-cli/src/lib.rs): Add control plane startup logic inside `run_start`. When running in `control` role, instantiate `FileAuditLog` at `storage/audit.jsonl` and start the `ControlService` on the default or specified bind address.
- **Test**: Integration test starting the `ControlService` and checking that worker registration logs a structured `worker.registered` event to the audit log.

### Slice 3: Worker Node Registration and Heartbeat Client
- **Goal**: Implement worker daemon client loop to self-register, send heartbeat telemetry, and maintain active connection.
- **Changes**:
  - [lib.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/lib.rs): Add worker runtime lifecycle loop. It connects to the control plane TCP address, registers itself, and schedules a recurring background task to send heartbeat messages carrying updated capacity headroom.
- **Test**: Integration test of worker registration and heartbeats over real TCP sockets.

### Slice 4: Capacity-Aware Lease Acquisition & SlateDB Fencing
- **Goal**: Implement dynamic worker lease acquisition, and ensure SlateDB's manifest writer epoch fences out old writers.
- **Changes**:
  - [shard_db.rs](file:///Users/grove/projects/rockstream/crates/rockstream-storage/src/shard_db.rs): Ensure opening `ShardDb` handles SlateDB `Fenced` write errors and maps them to a storage-level error.
  - [lib.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/lib.rs): Ensure worker runtime tracks its assigned shards, performs `FenceWrite` validations, and immediately detaches its local `ShardDb` instances if a fence check fails or lease is revoked.
- **Test**: SlateDB LFS and MinIO fencing tests demonstrating that opening a second writer fences out subsequent writes from the first writer.

### Slice 5: Worker Failure and Lease Reassignment
- **Goal**: Verify that control plane detects worker disconnects, revokes their leases, and reassigns them cleanly via the Shard Scheduler.
- **Changes**:
  - [service.rs](file:///Users/grove/projects/rockstream/crates/rockstream-control/src/service.rs): Ensure disconnects trigger lease cleanup and trigger `TopologyChanged` notifications to surviving workers.
- **Test**: Integration test simulating worker termination and verifying reassignment of leases.
