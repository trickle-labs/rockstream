# v0.55.1 Plan — Secrets Management & Envelope Encryption

## Scope and Non-Negotiable Invariants

This version implements first-class secrets management and envelope encryption for RockStream, building upon the v0.55 internal mTLS and node-identity substrate (DESIGN.md §14.18; [ROCKSTREAM_PROJECT_FOCUS.md](ROCKSTREAM_PROJECT_FOCUS.md) §5.3; [NEW_ROADMAP.md](NEW_ROADMAP.md) v0.55.1 row).

1. **First-Class Secret Lifecycle & DDL**:
   - `CREATE SECRET <name> (TYPE = '<type>', [KEY = 'VAL', ...])`
   - `ALTER SECRET <name> SET (KEY = 'VAL', ...)`
   - `DROP SECRET <name>`
   - `SHOW SECRETS`
   - Enforce envelope encryption for all stored secret payloads in SlateDB under key prefix `catalog/secrets/` (`0x01 0x0B namespace_id(16) secret_name(var) → encrypted_blob`).
2. **Envelope Encryption & KEK Provider Substrate**:
   - Per-secret Data Encryption Key (DEK) encrypts credential payload using authenticated AEAD (`AES-256-GCM`).
   - DEK is wrapped by cluster's Key Encryption Key (KEK).
   - `KekProvider` trait with two `Core` backends:
     - `env`: KEK loaded from `RS_SECRET_KEK` environment variable on control plane.
     - `aws_kms`: Envelope encryption via AWS KMS key ARN with real client and local test harness.
   - `gcp_kms` and `vault` are deferred by decision to post-v0.55.1 per `NEW_ROADMAP.md`.
   - Dynamic KEK rotation: re-wraps every DEK with new KEK while leaving all existing secrets readable.
3. **Worker-Side Short-Lived Secret-Token Resolution**:
   - Workers never read raw secret values from the control database.
   - At pipeline startup or source initialization, worker requests a short-lived *secret token* over the v0.55 authenticated mTLS control channel.
   - Control plane issues a short-lived token (encrypted blob containing decrypted credential, encrypted to requesting worker's `NodeIdentity`, with a bounded TTL).
   - Worker decrypts token using node key derived from its mTLS certificate and holds credential in memory only for the lifetime of connector process.
   - Asserted that raw values are completely absent from worker on-disk state and all APIs reachable by workers.
4. **Source & Sink Integration & Zero-Restart Rotation**:
   - `CREATE SOURCE ... (..., secret = '<name>')` and `CREATE SINK ... (..., secret = '<name>')` replace inline plaintext credentials.
   - `ALTER SECRET <name>` updates the encrypted blob; active Kafka and PostgreSQL CDC connectors receive a rotation notification and acquire fresh tokens on their next epoch boundary without restarting the pipeline and with zero failed batches.
5. **Universal Redaction & Complete Audit Coverage**:
   - Every secret lifecycle event (`secret.created`, `secret.altered`, `secret.dropped`, `secret.token_issued`, `secret.rotated`) is recorded in the audit log with actor, timestamp, and target secret name.
   - Plaintext secret values NEVER appear in logs, audit events, `SHOW SECRETS` output, error messages, or support bundles.
   - Asserted by scanning every emitted artifact for the secret's literal bytes across all subsystems (`secrets_redaction_tests.rs`).
6. **One Binary, Durability & Coordination**:
   - Single `rockstream` binary remains runnable across all roles.
   - No SlateDB range deletion; cleanup uses scan-and-delete or point delete.
   - Durability verified across SlateDB LFS and MinIO (TestContainers).
   - Distributed coordination verified with seeded `SimRuntime` tests with `buggify!()` annotations.

## Test Commitments & Oracle Invariants

1. **Redaction & Secrecy Invariance**:
   - $\forall s \in \text{Secrets}$, $\forall a \in \{\text{Logs}, \text{AuditLogs}, \text{ShowOutputs}, \text{ErrorMessages}, \text{SupportBundles}, \text{WorkerDiskState}\}$: $\text{contains}(a, s.\text{plaintext\_bytes}) = \text{false}$.
2. **Worker Memory-Only Resolution Invariance**:
   - $\forall w \in \text{Workers}$, $w$ holds only decrypted secret tokens in memory during active pipeline execution; $w.\text{disk\_state}$ contains 0 secret bytes.
3. **Live Rotation Zero-Disruption Invariance**:
   - For any active connector $C$ undergoing `ALTER SECRET`:
     - $\text{epochs\_lost}(\text{rotation\_window}) = 0$.
     - $\text{pipeline\_restarts}(\text{rotation\_window}) = 0$.
     - $\text{failed\_batches}(\text{rotation\_window}) = 0$.
4. **KEK Provider Interchangeability & Rotation Invariance**:
   - Both `env` and `aws_kms` providers satisfy the same `KekProvider` test contract.
   - For any KEK rotation $K_1 \to K_2$: all existing secrets remain readable and decrypt to identical plaintext credentials.
5. **SlateDB Range Deletion Prohibition**:
   - Zero code paths use SlateDB range deletion; secret cleanup uses point delete or scan-and-delete.
