# v0.66 Phase 2 plan: real management plane

Committed scope: `docs/implementation-plans/v0.66.md` at `Status: Planned`.
Roadmap source: `ROADMAP.md` section 12. Exit IDs: `V066-01` through
`V066-08`. This is a plan only. It makes no product claim.

## Resolved contract choices

- Add one shared `rockstream-management-proto` crate. It owns
  `proto/management/v1/management.proto`, generated tonic code, and protocol
  compatibility tests. `rockstream-control` implements the server and
  `rockstream-cli` uses its client. This keeps the public management protocol
  separate from `rockstream-types/src/topology.rs` worker messages, row
  exchange, and PostgreSQL.
- Add `management_addr` to the v0.62 `NodeConfig`. It binds a tonic listener
  separate from the worker control listener and the HTTP
  `--metrics-addr` listener. The HTTP `/live`, `/ready`, and `/health`
  endpoints remain probes, not a management API.
- Protocol package and version are `rockstream.management.v1`. A request and
  response carry `protocol_version = 1`; unsupported versions fail with a
  typed `FAILED_PRECONDITION` response naming both ranges. Unknown resources
  return `NOT_FOUND`; unavailable dependencies return `UNAVAILABLE` with a
  coded detail. No successful response is synthesized from a probe or fixture.
- Read lists default to 50 and cap at 100 items. Responses cap at 1 MiB,
  requests cap at 64 concurrent calls, and operation admission caps at 1,000
  non-terminal records and 10,000 retained terminal records. Expose the three
  fill levels. Invalid page tokens and every full limit fail deterministically
  with `INVALID_ARGUMENT` or `RESOURCE_EXHAUSTED`.
- A compound response has `observed_at` and source-version fields. Each field
  identifies its authoritative runtime, catalog, lease, checkpoint, or durable
  operation record. A missing observation is `unknown` with a reason, never
  zero, healthy, or complete.
- Operation records are versioned and durable before acceptance. They retain
  `Pending`, `Running`, `Waiting`, `Succeeded`, `Failed`, or `Cancelled`, plus
  `started_at`, `updated_at`, `progress`, `phase`, `error_code`, and
  `next_steps`. Terminal states are immutable. Allowed transitions are
  `Pending -> Running|Waiting|Failed|Cancelled`,
  `Running -> Waiting|Succeeded|Failed|Cancelled`, and
  `Waiting -> Running|Failed|Cancelled`.
- An idempotency key binds protocol version plus canonical request bytes to a
  SHA-256 digest and the durable operation ID before effects start. Exact
  retries return that record. A changed request returns `ALREADY_EXISTS` with
  the original operation ID. Keys are accepted for 24 hours; an older key is
  rejected as expired and cannot start an effect. Terminal operation records
  remain queryable for seven days or until the 10,000-record cap. Expiry never
  silently reruns an accepted request.
- Cancellation is durable. It succeeds only before the executor's declared
  irreversible boundary: before a drain starts handoff, before a migration
  transfers the lease, and before a backup writes its commit marker. After the
  boundary, `CancelOperation` returns `FAILED_PRECONDITION` and leaves the
  truthful active or completed record intact.
- Configuration summaries omit secret values and replace declared secret
  fields with `redacted: true`. No credential, token, certificate content, or
  connection password appears in a management response, CLI output, error, or
  evidence transcript.

## Dispatch-wiring audit

Current code has no management protobuf, tonic server, generated client, or
operation query path. `ControlMessage` and `WorkerMessage` are private
line-delimited JSON worker protocol in `rockstream-types/src/topology.rs:273`
and `:772`; they cannot become the management API. The only current typed-like
status path is `main.rs:49-52` -> `run_cluster_status`
(`lib.rs:1264-1270`) -> `RemoteTopologyClient` (`transport.rs:777-785`) -> the
private `ClusterStatusQuery` worker message. It reports only a control-node
leadership response and is not a v0.66 route.

Every completed route must be:

`CLI parser -> ManagementClient -> generated ManagementService client ->`
`ManagementService RPC handler -> authoritative state or executor -> typed`
`response -> CLI renderer`.

## Vertical slices

1. Create the shared v1 protobuf crate and the `management_addr` configuration
   path. Implement only version negotiation, unavailable-service failure, and
   generated client/server registration. Green tests:
   `management_v1_contract_has_all_fourteen_methods` and
   `management_v1_rejects_incompatible_versions`. Covers `V066-01`, `V066-08`.
2. Add the read-only service mapper from `TopologyCatalog`, shard state,
   effective configuration, capabilities, lifecycle, and the future operation
   store. Define the field-to-authority table in the test fixture and mutate
   each real owner. Green tests: `management_read_methods_return_exact_records`,
   `management_health_reports_unknown_not_synthetic_healthy`, and
   `management_read_failures_return_exact_typed_errors`. Covers `V066-02`,
   `V066-07`.
3. Add one durable, versioned operation store and lifecycle validator in
   `rockstream-control`; do not add a CLI-local registry. Persist acceptance
   before executor dispatch and reconcile a record after restart. Green tests:
   `management_operation_lifecycle_has_exact_state_records` and both LFS and
   MinIO operation-store reopen tests. Covers `V066-03`, `V066-05`.
4. Add shared idempotency admission around that store. Canonicalize before
   hashing, serialize conflicting shard and backup identities, and reject
   changed payloads. Green tests: `management_idempotency_retries_return_one_exact_record`
   and `management_idempotency_conflict_and_restart_preserve_exact_state`.
   Covers `V066-04`.
5. Route a real two-worker drain through the operation executor. Persist the
   acceptance, emit the actual worker lifecycle, and test early versus late
   cancellation without inventing a success response. Green tests:
   `management_drain_accepts_once_and_moves_a_real_worker` and
   `management_cancel_at_safe_boundary_returns_exact_record`. Covers
   `V066-01`, `V066-03`, `V066-06`.
6. Route a real supported shard move through the same operation executor. A
   stale owner, invalid destination, unavailable worker, and post-transfer
   cancellation return typed failure. The success case moves the actual shard
   lease. Green test: `management_migrate_moves_a_real_shard_once`. Covers
   `V066-01`, `V066-04`, `V066-06`.
7. Route backup creation through the same operation executor. Success writes a
   real committed backup; a store write failure rejects acceptance or records
   failure, never success. Green test:
   `management_backup_creates_and_records_a_real_backup`. Covers `V066-01`,
   `V066-05`.
8. Replace the production CLI routes with `ManagementClient` calls and add
   `shard show`, `admin operation list`, `admin operation show`, `config
   summary`, `capabilities`, and `health`. Retire private worker RPC and local
   storage-admin usage from the covered paths. Green test:
   `management_cli_transcripts_use_only_management_rpc`. Covers `V066-08`.
9. Freeze and test every bound, then run release binaries in standalone and
   multi-process clusters. Add executable documentation transcripts and collect
   the evidence artifact. Green tests:
   `management_limits_overflow_and_recovery_are_exact` and
   `management_release_process_transcripts_are_exact`. Covers `V066-02`,
   `V066-07`, `V066-08`.

## Durability and coordination commitments

The operation store, idempotency mapping, durable cancellation request, and
backup-operation record are new durability paths. Each gets both tests in
`crates/rockstream-control/tests/management_operation_durability_tests.rs`:

- `accepted_operation_and_idempotency_survive_lfs_process_restart`
- `accepted_operation_and_idempotency_survive_minio_tc_process_restart`
- `storage_write_failure_never_acknowledges_management_acceptance`
- `restarted_management_executor_reconciles_exact_operation_and_effect_state`

The MinIO test is required TestContainers qualification. Missing Docker is
blocked evidence, never a passing skipped test.

Drain and migration add coordination paths. Add
`crates/rockstream-control/tests/management_operation_sim_tests.rs` with
`seeded_management_operation_accept_cancel_and_reconcile_is_exact`. It uses a
fixed `SimRuntime` seed, registers
`management.acceptance.before_effect`, `management.cancel.safe_boundary`, and
`management.reconcile.after_effect` in the fault model, and annotates the
three production boundaries with `buggify!()`. It asserts the whole durable
operation transcript and final worker, lease, and backup state. This does not
replace the real multi-process proof.
