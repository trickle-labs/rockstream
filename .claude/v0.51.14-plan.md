# v0.51.14 Plan — Real Postgres CDC and HTTP Webhook/Push Sources

Roadmap: `NEW_ROADMAP.md:1059`. This version adds keyed PostgreSQL logical
replication CDC and push-driven HTTP webhooks through the existing source
contract. One `rockstream` binary remains: `--role=gateway` serves pgwire and
the webhook HTTP listener on separate configured ports.

## 4. Vertical Slices

1. **Typed source configuration and runtime registration.** Extend DDL
   validation; store credential references only; atomically register catalog
   and runtime source. Exit:
   `source_ddl_postgres_webhook_tests::create_source_rejects_bad_options_and_redacts_credentials`.

2. **Postgres CDC decoder.** Add `PostgresCdcSource`, packed-LSN token, native
   watermark, stable primary-key row identity, and pgoutput/wal2json decoders.
   `POSTGRES_CDC_MAX_IN_FLIGHT_BYTES` and
   `POSTGRES_CDC_MAX_IN_FLIGHT_RECORDS` bound the queue; fill-level metrics and
   zero-credit socket-read pause are mandatory. Exit: all six CDC matrix tests.

3. **Real replication and M3 commit/replay.** Use the `tokio-postgres`
   replication protocol to snapshot then subscribe; durably persist an LSN with
   its source epoch before acknowledging upstream; restart from the highest
   committed LSN only. Exit:
   `postgres_cdc_exactly_once_tests::worker_restart_resumes_committed_lsn_with_exact_keyed_cdc_output`.

4. **CDC failure and slow-subscriber handling.** Classify dropped/invalidated,
   publication-missing, timeout, and WAL-retention-loss slots as `BLOCKED`;
   perform bounded automatic resnapshot/re-subscribe or a documented bounded
   error. Publish recovery fill levels, `postgres_cdc_wal_lag_bytes`, and pause
   at a named lag/credit threshold before unbounded primary retention. Exit:
   `postgres_cdc_failure_and_slow_subscriber_tests::invalidated_slot_resnapshots_and_slow_subscriber_pauses_before_retention_growth`.

5. **Gateway HTTP listener and source.** Add a separate HTTP listener to the
   existing gateway roles, route only `POST /webhook/<source_name>`, authenticate
   constant-time tokens, cap request bytes, and decode JSON/CSV into source
   epochs. `HTTP_WEBHOOK_LOCAL_BUFFER_MAX_EPOCHS` and
   `http_webhook_buffered_epochs` are the queue bound and fill metric; full
   capacity returns 429 before enqueue. Exit the two first-delivery webhook tests.

6. **Webhook exactly-once and watermark.** Persist bounded delivery-id/digest
   dedup with the source epoch, acknowledge only after commit, implement
   `ExternalHint` plus `ADVANCE WATERMARK`, and prove failed/429 retries are not
   double-applied. Exit:
   `http_webhook_backpressure_tests::full_buffer_returns_429_then_recovery_retry_has_exact_output`.

7. **Live lifecycle/status and cleanup.** ALTER drives the actual connector and
   route; SHOW reads live status; all cleanup is scan-and-delete or a
   snapshot-safe compaction filter, never SlateDB range deletion. Exit both DDL
   matrix tests and
   `source_cleanup_tests::source_drop_uses_no_range_delete_and_leaves_exact_live_sources`.

8. **Real-system proof and regressions.** Run Postgres 18 Testcontainers,
   gateway pgwire+HTTP, LFS/MinIO durability, and the seeded simulation below.
   Existing Kafka/S3 source suites remain green unmodified.

## 5. Oracle, Durability, and Coordination Commitments

The pre-implementation oracle is:

`incremental materialized-view Z-set after source epochs == batch application of the same snapshot and ordered source mutations`.

CDC batch input contains keyed INSERT/UPDATE/DELETE and proves the exact
retract/reinsert identity. Webhook batch input contains accepted deliveries in
commit order: duplicate delivery IDs/digests count once; rejected and 429
deliveries count zero.

New commit/replay/checkpoint paths require both substrates:

| Substrate | Test commitment |
| --- | --- |
| SlateDB LocalFileSystem | `source_durability_lfs_tests::postgres_lsn_and_webhook_delivery_replay_after_crash_match_exact_oracles` |
| MinIO/S3 via Testcontainers | `source_durability_minio_tests::postgres_lsn_and_webhook_delivery_replay_after_crash_match_exact_oracles` |

The source-owner/epoch-commit/failover path is distributed coordination.
`source_coordination_sim_tests::seeded_cdc_and_webhook_failover_buggify_preserves_exactly_once`
uses a recorded seed and `buggify!()` before ownership acquisition, between
prepare/commit, after slot acknowledgement, and between HTTP acceptance and
acknowledgement. It asserts exact output, one committed token per epoch, no
duplicate delivery, and every queue fill level within its named bound.
