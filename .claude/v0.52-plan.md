## 4. Vertical Slices

- **Slice 1: DLQ Data Model & `rockstream_catalog.dead_letter_queue` SQL Surface**
  - Extend `DlqEntry` in `crates/rockstream-types/src/dlq.rs` and catalog storage.
  - Wire `SELECT * FROM rockstream_catalog.dead_letter_queue` in `crates/rockstream-gateway/src/catalog_stubs.rs` with filtering by `source_name`, `error_code`, and time bounds.
  - End-state: `dlq_catalog_query_tests.rs` passing against pgwire surface.

- **Slice 2: Connector Decode Failure Quarantine & Atomic M3 Epoch Commit**
  - Modify `KafkaSource`, `PostgresCdcSource`, `S3Source`, and `WebhookSource` to catch decode errors (`RS-1003`), construct `DlqEntry`, and write to DLQ inside the same M3 commit advancing `OffsetToken`/LSN.
  - Verify exact-once semantics: crash/restart (`kill -9`) recovers with neither lost DLQ entries nor re-applied offsets.
  - End-state: `dlq_connector_tests.rs` passing (LFS + MinIO + real-broker TC).

- **Slice 3: `ALTER SOURCE ... REPLAY DEAD_LETTER_QUEUE` Dispatch & Execution**
  - Extend `parse_alter_source_ddl` in `crates/rockstream-gateway/src/server.rs` for `REPLAY DEAD_LETTER_QUEUE [SINCE <ts> UNTIL <ts>]`.
  - Implement replay executor: re-decodes selected records, re-ingests them into the pipeline, and increments `replay_attempt`.
  - End-state: `dlq_replay_command_tests.rs` passing.

- **Slice 4: `ALTER SOURCE ... DISMISS DEAD_LETTER_QUEUE` & Retention Enforcer GC**
  - Extend `parse_alter_source_ddl` for `DISMISS DEAD_LETTER_QUEUE WHERE <condition>`.
  - Implement background DLQ retention GC in control plane (`DLQ_RETENTION` / `dlq_retention_days`), purging expired rows so disk storage stays flat.
  - End-state: `dlq_retention_tests.rs` passing (LFS + MinIO).

- **Slice 5: Backpressure, Threshold Alerting (`RS-1004`), and `BLOCKED` State Degradation**
  - Wire `dlq_warn_threshold` rate checker; emit `RS-1004 connector.dlq_growing` `NOTICE` and increment `rockstream_connector_dlq_growing_total`.
  - Enforce bounded memory: source producing continuous undecodable records past threshold degrades to `BLOCKED` state with `RS-1004` rather than buffering infinitely in memory.
  - End-state: `dlq_backpressure_threshold_tests.rs` passing.

## 5. Test Commitments

1. **`dlq_connector_tests.rs`**:
   - **Oracle Property Test**: Asserts `incremental == batch` oracle property for valid records while malformed records are durably placed in `rockstream_catalog.dead_letter_queue`.
   - Real Kafka broker and real Postgres CDC stream integration test (TestContainers).
   - Injected `kill -9` at every prepare/commit boundary of quarantine write.
2. **`dlq_catalog_query_tests.rs`**:
   - Validates `SELECT * FROM rockstream_catalog.dead_letter_queue` over raw pgwire returns expected columns (`arrived_at`, `source_name`, `source_offset`, `error_code`, `error_message`, `raw_bytes_hex`, `replay_attempt`).
3. **`dlq_replay_command_tests.rs`**:
   - Validates `ALTER SOURCE ... REPLAY DEAD_LETTER_QUEUE SINCE .. UNTIL ..` re-ingests exact matching records and increments `replay_attempt` across repeated replays.
   - Validates `ALTER SOURCE ... DISMISS DEAD_LETTER_QUEUE WHERE ...` removes exactly matching rows and nothing else.
4. **`dlq_backpressure_threshold_tests.rs`**:
   - Validates exceeding `dlq_warn_threshold` emits `RS-1004` `NOTICE` and metric.
   - Validates source quarantining continuously past threshold degrades to `BLOCKED` state.
5. **`dlq_retention_tests.rs`**:
   - Validates background GC purges entries past `DLQ_RETENTION` and keeps table on-disk size flat.
