# v0.53.2 Plan — IVM Arrangement Debugger: Addressability, User-Level Key Decoding & Non-Perturbing State Inspection

## Scope and Non-Negotiable Invariants

This version implements the IVM arrangement debugger split out of v0.53 by the 2026-08-12 realism review (DESIGN.md §14.7.1). It provides operators with deep inspection of intermediate Z-set state when a view produces a *wrong answer* (not just a slow one), solving three fundamental engine capabilities:

1. **Addressability (`rockstream explain <view> --op-ids`)**:
   - Compiles the SQL pipeline and outputs stable, deterministic `OperatorId`s for each stateful (and stateless) stage.
   - Surfaces operator types, schemas, and connection graph so an operator can identify which operator to inspect.
   - Supports both human-readable annotated text and structured `--json` output.

2. **User-Level Key Decoding & Encoding**:
   - `rockstream debug arrangement <view> <op_id> <key> [--epoch=N]` accepts and formats *user-level* keys (e.g. `"product_id=42"`, `"k1=1, k2=2"`, `"category=books"`).
   - Reverses and round-trips every arrangement key encoding used by the engine:
     - `GroupKeyPacker` composite surrogates
     - `Utf8ColumnPacker` / `Utf8KeyPacker` string columns
     - Window operators (`TumbleWindowOp`, `HopWindowOp`, `SessionWindowOp`)
     - Join side keys (`JoinOp`, `OuterJoinOp`, `JoinPipeline`)
     - Single-column primitive keys (`Int64`, `Int32`, `Float64`, `Utf8`, etc.)
   - Where a family cannot be reversed, cleanly refuses with an enumerated code (`RS-1021`) naming that family by name, never printing raw, indecipherable bytes.

3. **Non-Perturbing Snapshot Reads & Historical Epoch Inspection**:
   - Live reads use `DbReader` / `ShardReader` snapshot reads pinned to the latest committed frontier without taking pipeline locks or advancing frontiers.
   - Historical inspection via `--epoch=N` reads historical state within checkpoint retention. If outside retention window, cleanly refuses with `RS-2006`.
   - Continuous polling of loaded pipelines verifies zero freshness-lag regression.

4. **Correctness Verification via DataFusion Oracle**:
   - Verified across all supported stateful operator families (`Aggregate`, `MinMax`, `Join`, `TopK`, `Distinct`, `TumbleWindow`, `HopWindow`, `SessionWindow`) against the DataFusion batch oracle.

### Ground Rules & Engine Constraints
- **One binary, one CLI, one config**: All subcommands are built into the single `rockstream` binary. `main` remains runnable across all roles.
- **Prefix every shell command with `rtk`**: Enforced in all workflows.
- **No SlateDB range deletion**: All storage scans and reads use point-get or bounded prefix scans (`scan_prefix_bounded`).
- **Bounded buffers & metrics**: Scan windows and debug buffers have named caps (`DEBUG_ARRANGEMENT_MAX_BYTES` = 64MB).
- **No deferrals**: All scoped items are implemented this version.

## Vertical Slices

1. **Slice 1 — Error Code Registration & Models (`RS-1020`, `RS-1021`, `ArrangementDebugInfo`)**:
   - Register `RS-1020` (`operator_not_found`) and `RS-1021` (`arrangement_key_decode_failed`) in `crates/rockstream-types/src/error_code.rs`.
   - Define `ArrangementDebugInfo`, `ExplainOpIdInfo`, `OperatorKindInfo` in `crates/rockstream-cli/src/output.rs` with `--json` schema and human-readable text formatters.
   - Test: `test_debugger_output_models_and_error_codes`.

2. **Slice 2 — Addressability: `rockstream explain <view> --op-ids`**:
   - Add `--op-ids` flag to `Command::Explain` in `crates/rockstream-cli/src/main.rs`.
   - Implement `explain_view_op_ids` in `crates/rockstream-ops` and wire into `run_explain_view` in `crates/rockstream-cli/src/lib.rs`.
   - Print stable `OperatorId`s for all operators in the pipeline with their type, inputs, and schema.
   - Test: `test_cli_explain_view_op_ids_text_and_json`.

3. **Slice 3 — Key Encoding & Decoding Engine (`rockstream-ops::debugger`)**:
   - Implement reverse decoding for `GroupKeyPacker` (composite `GROUP BY` surrogates).
   - Implement reverse decoding for `Utf8KeyPacker` and `Utf8ColumnPacker`.
   - Implement reverse decoding for time-window operators (`TumbleWindowOp`, `HopWindowOp`, `SessionWindowOp`).
   - Implement reverse decoding for join arrangements (`JoinOp`, `OuterJoinOp`).
   - Implement strict refusal by family name (`RS-1021`) when key cannot be reversed.
   - Test: `test_arrangement_key_packer_decoders_and_refusal`.

4. **Slice 4 — Non-Perturbing Storage & Checkpoint Epoch Inspector (`ShardReader`)**:
   - Extend `ShardReader` to support reading arrangement state for given `OperatorId` and key bytes.
   - Support historical checkpoint reading via `--epoch=N`, verifying retention window and refusing with `RS-2006` if pruned.
   - Assert point reads and bounded prefix scans without SlateDB range deletion.
   - Test: `test_arrangement_shard_reader_snapshot_and_epoch_reads`.

5. **Slice 5 — `rockstream debug arrangement` CLI Command & Transport**:
   - Add `Command::Debug` and `DebugCommand::Arrangement` to `crates/rockstream-cli/src/main.rs`.
   - Implement `run_debug_arrangement` in `crates/rockstream-cli/src/lib.rs` and `CatalogClient` / `StorageClient`.
   - Support both human text (DESIGN.md §14.7.1 format) and `--json` structured output.
   - Test: `test_cli_debug_arrangement_command_e2e`.

6. **Slice 6 — Stateful Operator Families Verification vs Batch Oracle (`arrangement_debugger_tests.rs`)**:
   - Create `crates/rockstream-cli/tests/arrangement_debugger_tests.rs`.
   - Verify Z-set weights and intermediate state values for all 8 stateful operator families (`Aggregate`, `MinMax`, `Join`, `TopK`, `Distinct`, `TumbleWindow`, `HopWindow`, `SessionWindow`) against DataFusion batch oracle.
   - Test: `test_debug_arrangement_all_stateful_operators_batch_oracle`.

7. **Slice 7 — Historical Epoch Bit-Identical Inspection & Retention Bounds**:
   - Assert that `--epoch=N` inside retention returns bit-identical historical state.
   - Assert that `--epoch=N` outside retention returns `RS-2006`.
   - Test: `test_debug_arrangement_epoch_retention_and_historical_consistency`.

8. **Slice 8 — Non-Perturbing Polling & Freshness-Lag Invariance**:
   - Run a continuous polling loop of `debug arrangement` against a loaded live pipeline.
   - Assert zero freshness-lag regression and 0 pipeline stalls compared to a control run without polling.
   - Test: `test_debug_arrangement_continuous_polling_non_perturbing`.

9. **Slice 9 — Durability & Coordination (LFS, MinIO, SimRuntime Faults)**:
   - Verify arrangement debugger reads against SlateDB Local File System (LFS) and MinIO (S3, via TestContainers).
   - Verify deterministic behavior under simulated storage stalls and worker transitions in `rockstream-sim`.
   - Test: `test_debug_arrangement_durability_lfs_and_minio`, `test_debug_arrangement_sim_faults`.

10. **Slice 10 — Documentation & Golden Output Conformance**:
    - Update `docs/cli.md` documenting `rockstream explain <view> --op-ids` and `rockstream debug arrangement <view> <op_id> <key> [--epoch=N]`.
    - Update `crates/rockstream-cli/tests/cli_doc_coverage_tests.rs` to assert 100% documentation coverage.
    - Test: `test_docs_cli_conformance_and_coverage`.
