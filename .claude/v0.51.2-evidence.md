## Oracle / property note

Per plan §4, no new IVM/DBSP operator is introduced by this version (Slices
1–4 reuse `view_materializer.rs`'s existing DataFusion `MemTable` pattern
read-only at query time; Slice 5's backfill is a one-time scan, not a
continuously-maintained operator). The `incremental == batch` oracle property
test therefore does not apply; the "oracle-matching" claims for JOIN/GROUP
BY/subquery/CTE are instead proven by the hand-computed-expected-result-set
tests above (`ad_hoc_*_matches_oracle`), which is the standard this codebase
already applies to `view_materializer.rs`'s own batch-recompute correctness.

## Coordination / SimRuntime note

Per plan §6, no `SimRuntime`/`buggify!()` test is owed — all v0.51.2 work is
single-shard, gateway-local (hardcoded shard `0`), no cross-shard/cross-node
coordination path introduced.
