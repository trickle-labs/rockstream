### Slice 4 — Source-Epoch Registry with Persisted Partition→Offset Map

**Goal**: Implement per-connector `source_epoch` with the persisted
`connector/{id}/epoch_map/{source_epoch} → { partition_id → committed_offset }`
map (DESIGN.md §8.1.1). This is required for exactly-once source-side recovery.

**Changes**:
- [MODIFY] `crates/rockstream-connectors/src/`: Add
  `SourceEpochRegistry` that:
  1. Maintains a strictly-increasing `source_epoch` per connector.
  2. On epoch commit: writes `connector/{id}/epoch_map/{source_epoch}` →
     `{ partition_id → OffsetToken }` atomically with the epoch `WriteBatch`.
  3. On recovery: reads the highest committed `source_epoch`, retrieves its
     partition→offset map, and resumes from those offsets.
- [MODIFY] `crates/rockstream-control/src/`: Expose
  `connector/{id}/epoch_map/` prefix for recovery reads by the source connector.
- [MODIFY] `crates/rockstream-connectors/src/`: Update `ConnectorContext` to
  include `source_epoch` field; propagate through the connector contract
  (`commit_offset(epoch, offset: OffsetToken) -> IdempotentResult`).

**Test**: Unit test: connector commits 10 epochs with distinct offset maps,
simulates crash, recovers, and resumes from the correct offset. Verified on
LFS.

### Slice 5 — Kafka Sink (CheckBeforeCommit Profile)

**Goal**: Implement a transactional Kafka sink that uses the
`CheckBeforeCommit` idempotency profile. Kafka uses producer transactions
(`initTransactions` / `beginTransaction` / `commitTransaction` /
`abortTransaction`). The `check` step queries Kafka for the latest committed
offset for the output topic-partition before deciding whether to commit.

**Changes**:
- [NEW] `crates/rockstream-connectors/src/kafka_sink.rs`: `KafkaSink` struct.
  - `idempotency_profile()` → `CheckBeforeCommit`.
  - `pre_commit(epoch, rows)`: begins Kafka producer transaction; writes rows
    with epoch-tagged headers; stages the producer handle in `sink_state/`.
  - `commit(epoch, handle)`: calls `commitTransaction`; updates `sink_state/`
    to `Committed`.
  - `abort(epoch)`: calls `abortTransaction`.
  - `recover(epoch, CheckBeforeCommit)`: queries Kafka topic for epoch marker;
    if present → already committed, mark `Committed`; if absent → re-run
    `pre_commit → commit` against a new transaction.
  - Bounds: `local_buffer_max_epochs` applies to the per-connector staging
    buffer; fill-level metric `kafka_sink_staged_epochs_count` emitted.
    Backpressure returned when buffer full.
- [MODIFY] `crates/rockstream-connectors/src/`: Wire `KafkaSink` into the
  connector registry.

**Test**: Unit tests for pre/commit/abort/recover state machine (all three
crash points). `test_kafka_sink_exactly_once` integration test via
TestContainers (Kafka container): delivers rows exactly once under injected
broker faults (broker restart mid-commit).

### Slice 6 — Object-Store Sink (NativeIdempotent Profile)

**Goal**: Implement an object-store sink using `NativeIdempotent` profile.
Writes to `_pending/{epoch}/...` during pre-commit; atomically renames to
final path at commit. Re-commit of the same epoch checks `If-None-Match`
and is a no-op if already committed (S3 conditional PUT semantics).

**Changes**:
- [NEW] `crates/rockstream-connectors/src/object_store_sink.rs`:
  `ObjectStoreSink` struct.
  - `idempotency_profile()` → `NativeIdempotent`.
  - `pre_commit(epoch, rows)`: writes rows to `_pending/{epoch}/part-{n}`;
    records `pending_handle` in `sink_state/`.
  - `commit(epoch, handle)`: atomically renames `_pending/{epoch}/` → final
    path prefix; uses object-store conditional copy + delete. Updates
    `sink_state/` to `Committed`.
  - `abort(epoch)`: deletes `_pending/{epoch}/` (scan-and-delete, no range
    delete).
  - `recover(epoch, NativeIdempotent)`: if `_pending/{epoch}/` exists and
    final path does not → re-run rename; if final path exists → already done.
  - Bounds: `object_store_sink_pending_epochs_count` fill metric; backpressure
    when `> max_pending_epochs` (default 5).
- [MODIFY] `crates/rockstream-connectors/src/`: Wire `ObjectStoreSink` into
  the connector registry.

**Test**: Unit tests for all crash points (pre, between, during). LFS and
MinIO tests: crash mid-rename, verify idempotent recovery (final path appears
exactly once, no duplicates).

### Slice 7 — Worker Self-Fencing on Control-Plane Partition (DESIGN.md §11.6)

**Goal**: When a worker cannot deliver a heartbeat to the control plane for
`self_fence_after` seconds (default 30 s = `2 × dead_after`), it proactively
terminates itself, stopping new epoch processing the moment control-plane
contact is lost.

**Changes**:
- [MODIFY] `crates/rockstream-runtime/src/` (worker heartbeat path):
  - Track `last_control_contact: Instant`.
  - On each failed heartbeat: if `now - last_control_contact >= self_fence_after`
    → call `self_fence()` (flush metrics, stop accepting new epoch credits,
    shut down process).
  - Stop processing new epochs immediately when `can_reach_control == false`
    (before the deadline, to avoid advancing shard state that the new owner
    will overwrite).
  - On reconnect: re-register as a new worker identity, not the old one.
- Assert: `self_fence_after > dead_after` and
  `self_fence_after < 2 × shard_recovery_budget` enforced at startup with
  `RS-3005` error if violated.
- [MODIFY] `crates/rockstream-runtime/src/`: Add runtime `assert!` pairs for
  M4-S2 (self-fence precedence): assert that when `SelfFenceGuard::must_self_fence()`
  returns `true`, no new epoch commit is accepted. (M4-S2 was implemented in
  v0.20; this slice wires the M3 compose: M3-S3 requires the partitioned worker
  self-fences before the new owner's first sink commit.)

**Test**: `test_partitioned_worker_self_fences_before_sink_commit` (SimRuntime):
  injects `can_reach_control=false` for `> self_fence_after`; asserts
  partitioned worker terminates before the new owner performs its first sink
  `commit`. Verifies M3-S3 × M4-S2 composition.

### Slice 8 — Object-Store Brownout Buffering + Backpressure (DESIGN.md §11.7)

**Goal**: During an object-store brownout, workers stall at epoch commit
(WAL flush blocks), accept connector credits up to `local_buffer_max_epochs`
(default 10), then apply backpressure; source consumption pauses; pipeline
transitions to `STRESSED` → `BLOCKED(RS-3003)`. On recovery, buffered epochs
commit in order with no loss and no duplicates.

**Changes**:
- [MODIFY] `crates/rockstream-runtime/src/` (epoch commit loop):
  - Add `brownout_buffer: VecDeque<EpochBatch>` with capacity
    `local_buffer_max_epochs`. Named bound; fill-level metric
    `worker_brownout_buffer_epochs_count`.
  - When WAL flush fails with `ObjectStoreUnavailable`: push epoch to
    `brownout_buffer`; if buffer full → stop granting upstream source credits
    (backpressure). Transition worker state to `STRESSED` at 50% fill,
    `BLOCKED(RS-3003)` at 100% fill.
  - On WAL flush success after outage: drain `brownout_buffer` in epoch order
    before accepting new epochs. No-op re-flush if WAL segment already exists
    (idempotent).
  - `cluster_storage_stalled = true` published to metrics and degraded-state
    channel during brownout.
- Assert: re-flushing the same `WriteBatch` is idempotent (WAL segment already
  exists → skip, not error). This is the no-duplicate guarantee.

**Test**:
- Unit: `test_brownout_buffer_bounded` — fills buffer to `local_buffer_max_epochs`,
  asserts no further epochs accepted; asserts `RS-3003` state.
- `test_object_store_brownout_50epochs` (SimRuntime / MinIO): injects 50-epoch
  object-store blackout; resumes; verifies zero loss and zero duplicates in
  sink output.
