## Post-Evidence Fix: Full-Row Multiplicity in Compiled Views

During final sign-off, a full `cargo test --workspace` run (broader than the
per-crate proof suites above) caught a real regression not exercised by this
version's own new tests: `crates/rockstream-gateway/src/server.rs`'s
`GatewayHandler::try_compile_view()` hardcoded `PlanNode::ViewSink { pk:
vec![0] }`, so every compiled view — including a bare passthrough like
`CREATE VIEW q0 AS SELECT * FROM bid` — silently upserted on column 0 as an
implicit primary key, collapsing multiple rows sharing that column's value
instead of preserving `bid`'s full append-only Z-set bag. Caught by
`rockstream-oracle`'s pre-existing `test_nexmark_q0_q3_retraction_lfs`,
`test_nexmark_q0_q9_retraction_minio`, and `test_nexmark_retraction_100_seeds_lfs`.

Fixed: compile views with a full-row `pk` (all output columns), track
materialized compiled-view state as `(row, multiplicity)` counts, emit
multiplicity deltas on recompute, and expand multiplicities back to
duplicate rows on `SELECT`. Added `compiled_view_state_preserves_full_row_multiplicity`
unit test in `server.rs`.

Re-verified after the fix:
- `cargo test --package rockstream-oracle --test nexmark_retraction` → **6 passed**
- `cargo test --package rockstream-gateway --test gateway_proof_tests` → **107 passed, 1 ignored** (same pre-existing ignore as above)
- `cargo test --package rockstream-gateway --test unified_data_plane_tests` → **2 passed**
- `cargo test --package rockstream-gateway --test unified_data_plane_oracle_tests` → **2 passed**
- `cargo test --package rockstream-ops --test sink_multi_type_tests` → **3 passed**
- `cargo fmt --check` → clean
- `cargo clippy --workspace --all-targets -- -D warnings` → clean

## Full Workspace Verification

`cargo test --workspace` (every crate, full suite) was run twice: once before
this fix (surfacing the `q0` regression above), and once after, confirming
zero regressions. The only remaining failure in the post-fix run,
`rockstream-sql`'s `test_nexmark_ingestion_lfs`, was verified via `git
stash`/A-B testing to fail identically (same "person row count mismatch
left: 1 right: 10" panic) with none of v0.51.3's changes applied — it is a
pre-existing test-assertion bug from v0.50 (`crates/rockstream-sql/tests/

COUNT(*)`, which always returns exactly one row, instead of parsing the
count value out of that row), wholly unrelated to v0.51.3's Gateway↔Runtime
unification scope. Not a regression introduced by this version.
