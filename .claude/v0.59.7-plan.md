# v0.59.7 Plan — Factorized & Filtered IVM

## Scope and Boundary

Implement the v0.59.7 roadmap row: canonical key capsules; factorized PK/FK
join-to-algebraic-aggregate maintenance; bounded star-join payload trees; a
per-operator Delta Amplification Governor; frontier-versioned, join-safe
predicate transfer; and deterministic classic-versus-factorized selection at
compile/deploy time.

This adds no SQL keyword, CLI command, configuration surface, live plan
replacement, distributed switch generation, or new coordination protocol.
CREATE [MATERIALIZED] VIEW AS SELECT ... JOIN ... remains the sole public
surface. The compiler records one immutable plan choice for that view; a
runtime budget breach returns a coded refusal before unbounded work, rather
than replacing a live graph.

Ground rules for every slice:

- Reuse one KeyCapsule { typed_bytes, stable_hash } for arrangement lookup,
  partitioning, shuffle, skew accounting, and persisted keys. It has an
  explicit type tag, length framing, and NULL representation; no second
  serializer or hasher may be introduced at a consumer.
- Reuse the existing stable hashing style and shared-arrangement storage. A
  capsule is a value representation, not a second catalog or cache.
- Each payload tree has named MAX_FACTOR_PAYLOAD_ROWS and
  MAX_FACTOR_PAYLOAD_BYTES bounds, exports row/byte fill levels, and refuses
  the epoch before either bound is exceeded. Governor budgets are named per
  operator and expose all six counters.
- Cleanup remains point deletion or scan-and-delete only. No path may use
  SlateDB range deletion; new persistence tests must assert that fact.
- Every factorized operator is exact under positive and negative weights, and
  gets an incremental == DataFusion batch oracle test before implementation.

## 4. Vertical Slices

### S1 — Canonical Key Capsule

Add the smallest shared value type beside existing arrangement types and replace
duplicated join-key serialization/hash consumption sites. The capsule owns typed
framing and a deterministic hash; it is created once per input row and passed by
reference through lookup, partition, shuffle, skew, and storage encoding. Reuse
the existing stable-hash style; do not add a dependency. Extend
ShardKeyEncoder::join_arr_key only to accept capsule bytes. Add the complete
S3.1 matrix tests and a no-range-delete assertion.

Green: every consumer receives the same bytes/hash; composite and NULL cases
are exact; unsupported types fail closed.

### S2 — Factorized PK/FK Join-to-Algebraic-Aggregate Path

Extend compile.rs::try_compile_join_shape to recognize only a PK/FK inner join
directly consumed by one SUM, COUNT, or AVG. It creates a factorized payload
operator rather than JoinOp plus a materialized aggregate. The operator
maintains keyed multiplicities and aggregate contributions, emits only aggregate
deltas, and atomically applies inserts, updates, deletes, and retractions.
Every other shape continues through classic execution.

Commit the six S3.2 DataFusion-oracle tests first.

Green: no high-fan-out joined intermediate is emitted; accumulated factorized
output equals batch output after every epoch.

### S3 — Bounded Star Payload Tree

Generalize only the admitted inner PK/FK shape to a two- and three-dimension
star tree. Store compact payload nodes, never an enumerated fact×dimension cross
product. Define MAX_FACTOR_PAYLOAD_ROWS and MAX_FACTOR_PAYLOAD_BYTES; export
factor_payload_rows and factor_payload_bytes; reject before append on either
bound. Persist nodes and capsule keys in the atomic write batch that contains
view output and frontier.

Green: the star oracle is exact for insert/update/delete/retraction/NULL cases;
byte and row limits leave no partial epoch state.

### S4 — Delta Amplification Governor and Compile-Time Selection

Add one per-operator governor that records input deltas, probes, shuffled bytes,
intermediate tuples, output deltas, and state writes. Its selection rule is
immutable for a compiled view:

1. Factorize only an admitted PK/FK inner algebraic aggregate when the
   compile/deploy estimate is within all named budgets.
2. Otherwise select classic.
3. After deployment, if any actual counter would cross its pre-append bound,
   return one coded refusal and leave committed frontier and payload unchanged.

Persist selected strategy and rule version with compiled-view metadata so
recovery uses the same graph. Do not add a live adaptive switch.

Green: each budget dimension has a complete-output test proving classic
selection or atomic refusal, and shadow comparison proves recorded choice
follows the declared rule.

### S5 — Frontier-Versioned Predicate Transfer

When the compiler recognizes a selective predicate, attach it with the view
frontier/version to the safe pre-join input. Inner joins may transfer a
column-local predicate to either side. Left/right joins transfer only a predicate
on the preserved side; full joins transfer no post-join predicate; NULL-sensitive
and null-supplying-side predicates remain after the join. Retractions carry the
same predicate version as insertion and use the same rule.

Green: S3.3 matches DataFusion for insertions, updates, deletes, retractions,
NULLs, and outer-join null extension, while probes and shuffle bytes fall for
the selective inner workload.

### S6 — Durability, Recovery, and Range-Deletion Audit

Persist capsule-keyed factor payloads, immutable plan choice, governor state
needed for a retried epoch, and predicate version in existing atomic
commit/replay. Restore through recover_compiled_views; clean up only by
scan-and-delete/point delete. Add both required backend suites:

- crates/rockstream-ops/tests/factorized_join_durability_lfs_tests.rs for
  commit, replay, checkpoint, recovery, retraction, and scan-and-delete on
  SlateDB LFS.
- crates/rockstream-ops/tests/factorized_join_durability_minio_tests.rs for
  identical cases on MinIO S3 via TestContainers.

Green: crash/reopen returns the exact complete batch-oracle output; the test
asserts no range-deletion API/path is used.

### S7 — Wire E2E, Shadow Benchmark, and Formal Path Coupling

Add a pgwire E2E CREATE MATERIALIZED VIEW high-fan-out test through simple and
extended query paths; it sees the existing command tag and exact view rows.
Extend the external benchmark harness to run classic and factorized alternatives
from the same v0.59.6 shared arrangements in shadow mode, compare each to its
independent batch oracle, and publish join amplification, filter selectivity,
CPU, memory, and freshness deltas.

Add a path-coupling test that fails if live cutover/switch generation/dual
active graph is introduced without the future dedicated formal model. No new
distributed-coordination path exists, so no new SimRuntime protocol test is
needed; existing M1/M2 models plus oracle equivalence remain the proof boundary.

Green: wire E2E, benchmark evidence, and path coupling are green; no production
live replacement code exists.

## 5. Test Commitments

### 5.1 Oracle Properties

Before S2, S3, or S5 implementation, add these exact complete-output tests:

1. factorized_join_aggregate_oracle_tests: every S3.2 cell and every
   insert/update/delete/retraction/NULL epoch sequence accumulates to its
   DataFusion batch result.
2. factorized_star_join_oracle_tests: two- and three-dimension star aggregate
   output equals DataFusion batch output and the forbidden materialized cross
   product has exactly zero intermediate tuples.
3. predicate_transfer_tests: transferred and non-transferred plans each produce
   the complete DataFusion multiset for every S3.3 cell.
4. key_capsule_tests: asserts exact capsule byte values and hashes at all
   consumers, rather than counts or merely equal hashes.

### 5.2 Durability Commitments

factorized_join_durability_lfs_tests and factorized_join_durability_minio_tests
each prove complete output after commit, replay, checkpoint, crash recovery, and
compaction equals the batch oracle. Both assert point/scan cleanup and no
SlateDB range deletion.

### 5.3 Coordination Commitment

There is no new distributed coordination path: strategy selection is
compile/deploy-time and immutable, while a runtime breach is local atomic
refusal. The required guard is
crates/rockstream-sim/tests/factorized_plan_path_coupling_tests.rs, which
asserts no live switch generation, dual active graph, or cutover action exists.
If any such action is added, a dedicated formal model and seeded SimRuntime
tests with buggify! annotations are mandatory.

### 5.4 Dispatch Commitment

crates/rockstream-gateway/tests/factorized_view_wire_e2e_tests.rs drives the
public pgwire path: CREATE MATERIALIZED VIEW, DML on both join sides, SELECT the
view, restart/recover, and SELECT again. It asserts the exact command tag and
complete returned rows for classic and factorized selection.
