# v0.62.1 Plan — Worker Memory Budgets

**Version**: v0.62.1  
**Phase**: Phase 4 — Prove (Complete)  
**Target Scope**: Wire the existing `WorkerStorageContext` into production shard creation. Pass worker-owned block and metadata caches into every `ShardDbBuilder`; account for their shared allocations once. Include SlateDB write buffers, operator state, source and exchange buffers, queries, checkpoints, and migrations in the worker budget. Enforce byte limits and admission control before allocation. Propagate pressure to sources, and bound retries and waiters. Reserve capacity for foreground maintenance and reads while limiting compaction, backfill, and migration concurrency. Prove bounded RSS and queue age under sustained overload with many shards, including shard creation and removal. Use a bounded local disk cache for object-store data through the pinned SlateDB version's supported API (`Settings.object_store_cache_options`). Validate cache identity and lifecycle across shards. Shared block caches primarily share a resource budget; cross-instance download reuse belongs in the object-store cache.

Committed implementation plan reference: `docs/implementation-plans/v0.62.1.md`.  
Shared implementation and evidence rules reference: `docs/implementation-plans/README.md`.

v0.62.1 establishes production worker memory control across configuration, shared storage contexts, comprehensive budget accounting, admission control, foreground reservation, bounded disk caching, and many-shard overload qualification:

1. **Production Shard Construction & Shared Storage Context Injection**:
   - Inventory every production shard construction site: startup, restore, addition, and migration destinations.
   - Wire `WorkerStorageContext` from `crates/rockstream-storage/src/storage_context.rs` into every `ShardDbBuilder` in `crates/rockstream-storage/src/shard_db.rs`.
   - Pass worker-owned block and metadata cache instances into every `ShardDbBuilder`, replacing isolated per-shard cache instances.
   - Charge shared block and metadata cache allocations exactly once against the worker budget ledger.
   - Strictly isolate cache key identities across tenants, security policy digests, arrangements, shards, and backend objects.

2. **Comprehensive Worker Budget Ledger & Accounting**:
   - Build a unified `WorkerBudgetLedger` accounting for actual byte allocations across all 8 canonical categories:
     1. SlateDB Write Buffers (active WAL and memtable buffers across all hosted shards)
     2. Block and Metadata Caches (shared worker caches charged once)
     3. Operator State (in-memory arrangement state, aggregation accumulators, join hash tables)
     4. Source Buffers (CDC transaction buffers, poll credits, webhook input queues)
     5. Exchange Buffers (shuffle send and receive buffers, network frames)
     6. Query Work Memory (in-flight ad-hoc queries, sort buffers, intermediate projections)
     7. Checkpoint Staging (snapshot memory, serialization buffers, flush staging)
     8. Migration Buffers (state transfer chunks, deserialization staging)
   - Incorporate explicit headroom accounting for transient allocation copies and allocator overhead; logical state bytes alone do not guarantee RSS containment.
   - Expose real-time telemetry gauges and fill metrics for every ledger category.

3. **Byte Permits, Prospective Admission Control & Error Reclaim**:
   - Obtain byte permits via `WorkerQuotaManager::try_acquire_permit` *before* allocating memory across any subsystem.
   - Return an explicit drop-safe `MemoryPermit` (or `QuotaGuard`) that automatically decrements the category and ledger on drop or cancellation.
   - Reject oversized requests exceeding category or worker budget with `RS-5003` (`state_budget_exceeded`) or `RS-9001` (`quota_limit_exceeded`).
   - Propagate backpressure upstream to ingestion sources (reducing poll credits, pausing stream pulls) when memory approaches the budget limit.
   - Enforce bounded retry counts (max 20 attempts) and bounded waiter queues (max 1,024 waiters with 1.0s maximum queue age) before failing requests cleanly.
   - Audit all internal caches to guarantee entries larger than capacity are rejected or bypassed without untracked memory consumption.

4. **Capacity Reservation for Foreground Reads & Maintenance with Background Governors**:
   - Reserve dedicated capacity (configurable via `foreground_reservation_bytes`, default 20% of worker budget) exclusively for foreground reads and maintenance.
   - Protect foreground read execution and transaction commits from starvation under heavy background ingest.
   - Independently limit background concurrency:
     - `max_compaction_concurrency` (default 2)
     - `max_backfill_concurrency` (default 1)
     - `max_migration_concurrency` (default 1)
   - Fail configuration validation before port bind if declared partitions or reserves are mutually impossible (e.g. reserves exceed total budget).

5. **Bounded Local Disk Cache for Object-Store Data (Pinned SlateDB 0.13 Integration)**:
   - Configure SlateDB's native object-store disk cache via `slatedb::config::Settings.object_store_cache_options`.
   - Explicitly configure disk cache parameters: `root_folder`, `max_cache_size_bytes`, `part_size_bytes` (4 MiB), `scan_interval` (3600s), and `max_open_file_handles`.
   - Guarantee strict isolation across shards and tenants within the disk cache hierarchy.
   - Clean up cached artifacts upon shard deletion or worker termination without orphaned files.
   - Enforce disk occupancy upper bounds; eviction occurs deterministically when capacity is reached.

6. **Many-Shard Overload Qualification & Bounded RSS Verification**:
   - Stress-test workers hosting 20+ concurrent shards under sustained write and query overload.
   - Verify shard addition, deletion, and restart under active load without memory leaks or unbounded backlog.
   - Inject simulated storage latency and verify that memory permits and waiter queues remain strictly bounded.
   - Prove that process RSS does not exceed the frozen budget contract plus documented allocator tolerance.
   - Compare all committed output and recovered state against the oracle to prove zero data corruption or lost updates.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag or config property on the same `rockstream` binary. `main` remains runnable through it.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters, asserted by test.
- Unbounded in-memory accumulation is never acceptable. Every new queue, buffer, or scan window needs a named upper bound, a fill-level metric, and a backpressure or error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix root causes.
- Make only changes this version requires. No speculative features outside IVM engine + Postgres wire layer.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals.**
