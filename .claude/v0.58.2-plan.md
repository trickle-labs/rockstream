# v0.58.2 Plan — Storage-Pressure Admission Signals & the SLO Auto-Tuning Lock

## Scope and Boundary

v0.58.2 implements storage-pressure admission signals and completes the SLO auto-tuning lock per `ROCKSTREAM_PROJECT_FOCUS.md` §5.5 and `NEW_ROADMAP.md` v0.58.2.

Per the 2026-08-12 realism review split:
- **v0.58**: Failure matrix enumeration and deterministic `SimRuntime` coverage across all 11 production failure modes.
- **v0.58.1**: Real-backend failure proofs, per-cell time budgets, and published recovery baselines.
- **v0.58.2 (this version)**:
  1. Extend the controller built in v0.45.1 and wired to state bytes in v0.51.23 with five storage-pressure admission signals:
     - L0 backlog (`l0_backlog`)
     - Pending compaction bytes (`pending_compaction_bytes`)
     - Flush latency (`flush_latency_ms`)
     - Write amplification (`write_amplification`)
     - Object-store latency and failure rate (`object_store_latency_ms`, `object_store_failure_rate`)
  2. Enforce the documented shedding order:
     - **Step 1**: Throttle backfills (v0.52.1) first
     - **Step 2**: Reduce source ingestion second
     - **Step 3**: Refuse parallelism increases that would worsen compaction debt third
     This guarantees that a large backfill can never make already-running views indefinitely stale by overwhelming the storage layer.
  3. Lock the auto-tuner to the IVM freshness SLO contract: the auto-tuner is a means to the freshness contract, not an elasticity product surface; no new user-facing tuning knob or control surface ships here (asserted by a configuration-surface lock test).
  4. Retain **separately attributable and individually exported** signals: the proposed single composite `storage_debt` scalar is explicitly rejected; every degradation names its dominant cause through v0.54.1 dominant-cause attribution.
  5. Prove convergence: the control loop converges rather than oscillates under both a sustained pressure step and an oscillating one over a documented settling window (≤ 3 cycles).
- **v0.58.3**: Unscoped reachability, dispatch-wiring & silent-wrong-answer sweep.

### Non-Negotiable Ground Rules
- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary. `main` must remain runnable.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable. Every queue, buffer, or scan window needs a named upper bound, fill-level metric, and backpressure or error path.
- Do not weaken, skip (`#[ignore]`), or delete tests.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

### Slice 1: Storage Pressure Signal Definitions & Attribution Modeling
- **Deliverables**:
  - Extend `crates/rockstream-types/src/metrics.rs`:
    - Add `StoragePressureSignals` struct capturing the 5 signals (`l0_backlog`, `pending_compaction_bytes`, `flush_latency_ms`, `write_amplification`, `object_store_latency_ms`, `object_store_failure_rate`).
    - Add atomic collectors and metric export functions for each signal individually.
  - Extend `crates/rockstream-types/src/view_lifecycle.rs`:
    - Extend `DominantContributor` with granular storage pressure variants:
      - `StoragePressureL0Backlog`
      - `StoragePressurePendingCompaction`

      - `StoragePressureWriteAmplification`
      - `StoragePressureObjectStoreLatency`

- **Test**: `rtk cargo test -p rockstream-types` and `crates/rockstream-sim/tests/storage_pressure_admission_tests.rs::test_sp_signal_definitions_and_dominant_attribution`.

### Slice 2: Documented Shedding Engine & Admission Controller Integration
- **Deliverables**:
  - Extend `crates/rockstream-gateway/src/admission.rs`:
    - Define `StoragePressureSheddingEngine` implementing the 3-step shedding hierarchy:
      1. Throttle / reject backfills via `BackfillAdmissionController::reserve` under storage pressure.
      2. Signal source ingestion reduction via backpressure advice.
      3. Signal refusal of parallelism expansion / shard split requests.
    - Implement adaptive evaluation in `AdmissionController::evaluate_and_admit_with_storage_pressure`.
    - Integrate with `FileAuditLog` for structured audit logging of each shedding transition.
- **Test**: `rtk cargo test -p rockstream-gateway --lib admission`.

### Slice 3: Auto-Tuner Storage Pressure Integration & Parallelism Lock
- **Deliverables**:
  - Update `crates/rockstream-sim/src/auto_tuner.rs`:
    - Update `adjust_parallelism` to take current `StoragePressureSignals` into account: strictly veto / refuse scale-up when storage pressure is detected (Step 3).
    - Update `adjust_source_throttle` to take storage pressure severity into account (Step 2), applying source throttling before buffer exhaustion.
    - Add deterministic convergence logic with bounded settling windows (≤ 3 cycles) and hysteresis to prevent oscillation under square-wave inputs.
- **Test**: `rtk cargo test -p rockstream-sim --lib auto_tuner`.

### Slice 4: Independent Signal Induction & Dominant-Cause Attribution Suite (LFS & MinIO/TC)
