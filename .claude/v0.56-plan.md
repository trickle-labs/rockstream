# v0.56 Plan — Version Compatibility Gates & Rolling-Upgrade Drill

## Scope and invariants

Implement the storage-format gate, the actual gRPC protocol-version gate, the
offline `rockstream migrate --from=N --to=M --storage=<url>` command, and the
mixed-version assignment/upgrade proof from the v0.56 roadmap row.  Disaster
recovery remains v0.56.1 and is not part of this plan.

- `rockstream` remains the only production binary and `main` remains runnable.
- `RS-5001` is the only storage-format incompatibility result.  `RS-5002`
  remains unknown-merge-law.  The wire rejection is reassigned from the
  unshipped `RS-5003` model to `RS-5021`.
- Format metadata is one byte at a fixed shard-meta key.  A missing key means
  format 1, preserving existing populated shards; every subsequent open
  validates the stored value against the binary's inclusive supported range
  before reads or writes.
- The migration is offline and resumable: it processes one shard/object stream
  at a time, writes a durable per-shard completion marker only after the new
  layout is durable, and repeats safely after interruption.  Its named bound
  is `MAX_MIGRATION_OBJECTS_IN_FLIGHT = 1`; it exports current/maximum work as
  a fill-level metric and returns an error rather than retaining an unbounded
  object or key list.
- Migration cleanup is point-delete after copy/verification; neither
  production nor test code may use SlateDB range deletion.  A regression test
  asserts this exact property.
- No IVM operator, SQL grammar, aggregate, join, or window behavior changes.
  Consequently no incremental-equals-batch operator oracle applies.

The synthetic 1→2 fixture changes a real fixture state layout, not merely the
marker: migration copies each fixture state entry to its version-2 encoding,
verifies the complete bounded stream, point-deletes its version-1 counterpart,
then commits the one-byte format marker.  Its oracle compares the full sorted
logical `(key, value, weight)` query vector before migration and after a fresh
format-2 reopen.

   - Implement only the streaming 1→2 fixture transform plus durable progress

   - Cover completed and interrupted/restarted migration through LFS and fresh
     MinIO/TestContainers, including the complete logical-result oracle.
   - Green: `rtk cargo test -p rockstream-storage --test format_migration_lfs_tests` and `rtk cargo test -p rockstream-storage --test format_migration_minio_tests`.

     executor → storage migration engine and exact text/JSON response.

5. **Live protocol header and compatibility-aware assignment**
   - Put the shared protocol version in all shuffle requests; validate it at

6. **Two-binary TestContainers rolling drill and documentation**
