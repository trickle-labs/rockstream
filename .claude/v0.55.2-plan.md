# v0.55.2 Plan — Security Hardening & Independent Review Remediation

## Scope and non-negotiable constraints

This version hardens the current product surface; it adds no IVM operator, SQL
feature, connector, service, configuration file, or binary. The existing
rockstream binary remains the only CLI and every role remains a flag on it.

- Write a machine-checked threat model for auth, RBAC, secrets, internal mTLS,
  pgwire SQL injection, TLS rotation, and connector credentials.
- Gate both cargo audit and cargo deny in PR CI and scheduled dependency CI,
  with documented, reviewed exceptions.
- Fuzz every remaining live network-facing decoder and replay every checked-in
  corpus input on normal test runs.
- Enforce and prove unauthorized refusal plus one audited denial for every
  mutating CLI and pgwire-dispatch surface.
- Triage and remediate every received P0/P1 review finding. The engagement is
  commissioned, but no report artifact is present at planning time.

No cleanup path may use SlateDB range deletion. This work adds no production
queue, buffer, or scan. The expanded corpus replay must not retain an
unbounded Vec: it streams entries under named per-target file and byte caps,
reports corpus-files and corpus-bytes, and fails clearly when either cap is
exceeded.

There are no aggregate, type, join, window, durability-protocol, or distributed
coordination features in scope. Therefore no incremental-equals-batch operator
oracle, LFS/MinIO durability slice, or SimRuntime buggify slice is applicable
except the audit-persistence tests committed below.

## Vertical slices

1. Threat model and proof linker
   - Add docs/threat-model.md with the nine boundary rows above, each naming
     assets, trust transition, control, exact RS behavior where applicable, and
     a single passing proof link.
   - Add scripts/check-threat-model-links.sh and its self-test. The checker
     rejects missing boundaries, missing controls, missing tests, or dangling
     test links.
   - Green test: scripts/check-threat-model-links.test.sh.

2. Dependency advisory gate
   - Add cargo audit alongside cargo deny to PR CI and the daily workflow.
   - Document exception owner, RustSec advisory, rationale, expiry/review date,
     and removal condition in DEPENDENCY_POLICY.md; keep deny.toml only as the
     machine-readable enforcement configuration.
   - Add a checked-in known-vulnerable lockfile fixture and
     scripts/check-dependency-audit.test.sh. The self-test proves both tools
     reject it and proves an expired/missing exception record is rejected.
   - Green test: scripts/check-dependency-audit.test.sh.

3. Complete bounded decoder fuzzing
   - Add the four missing targets and one seed corpus directory per target.
   - Refactor only the current replay helper in
     fuzz_corpus_regression_tests.rs to stream bounded inputs and to assert
     exact target/directory agreement; do not add a fuzz framework.
   - Register all targets in fuzz/Cargo.toml and include replay in fuzz-soak CI.
   - Green test: replay_all_fuzz_corpora plus cargo check --package
     rockstream-fuzz.

4. Shared mutation authorization and audit policy
   - Add the smallest central policy table needed by the gateway dispatch and
     CLI command dispatch; it supplies operation name, minimum role, and audit
     action. It is the sole enumeration consumed by production dispatch and
     tests.
   - Route actual transport/session identity into CLI clients, replacing
     ClientIdentity::default() on mutating paths.
   - Thread conn_id/principal through the existing gateway mutation handlers,
     check AclStore before side effects, and append the denial before encoding
     its exact error response.
   - Green tests: the CLI matrix, pgwire simple/extended matrix, and
     multi-statement bypass test.

5. Audit durability and review remediation
   - Run LFS and MinIO/TestContainers reopen tests for an unauthorized pgwire
     mutation and verify the full persisted audit event is identical.
   - For each received P0/P1 report item, add a narrow fix, a regression test,
     and a row in docs/threat-model.md or a review-findings appendix linking
     the issue identifier, fix, and test. No generic remediation bucket.
   - Green tests: gateway_mutation_authorization_lfs and
     gateway_mutation_authorization_minio_tc.
