### Slice 3: Connection Pool and Stream Multiplexer
- **Goal**: Pool worker-to-worker connections and multiplex all shuffle traffic over a single bidirectional stream per peer.
- **Changes**:
  - [NEW] [pool.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/exchange/pool.rs): Implement `ShuffleClientPool` to establish and cache exactly one gRPC client connection to each peer worker.

- **Test**: Assert that exchange streams are correctly merged and routed, and that the connection count is bounded by the number of active workers, not the number of physical shards.

### Slice 4: Same-Worker Loopback Routing and Outbox/Inbox Persistence
- **Goal**: Implement the `Loopback` path routing over in-process channels, and ensure both loopback and direct paths persist outbox/inbox metadata to SlateDB.
- **Changes**:
  - [MODIFY] [exchange.rs](file:///Users/grove/projects/rockstream/crates/rockstream-types/src/exchange.rs): Implement exchange path classifier (`elided`/`loopback`/`direct`/`durable`).
  - [NEW] [loopback.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/exchange/loopback.rs): Implement same-process loopback routing using bounded tokio channels.
  - [NEW] [persistence.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/exchange/persistence.rs): Ensure that even on the loopback path, `shuffle_outbox/` (0x05) and `shuffle_inbox/` (0x04) metadata/bytes are written to the respective shard databases in SlateDB, matching the distributed path crash-replay semantics.
- **Test**: LFS durability test verifying that loopback writes outbox and inbox metadata keys to SlateDB, and crash-replay reads them correctly.

### Slice 5: Credit-Based Flow Control & Backpressure
- **Goal**: Implement sender-side credits and receiver-side acknowledgments to restrict memory allocation and apply backpressure upstream.
- **Changes**:
  - [NEW] [flow_control.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/src/exchange/flow_control.rs): Implement window credit logic: senders start with `OPERATOR_CHANNEL_CAPACITY` (=16) credits per target. Sending consumes 1 credit; receiving `ShuffleAck` restores 1 credit. 0 credits blocks the sender.
- **Test**: Unit test verifying sender suspension and resumption upon receiving credits/acknowledgments.

### Slice 6: Multi-Worker Shard Cluster Verification (Integration Proof)
- **Goal**: Verify end-to-end multi-worker exchange over a 16-shard cluster running a partitioned query subset.
- **Changes**:
  - [NEW] [exchange_integration.rs](file:///Users/grove/projects/rockstream/crates/rockstream-runtime/tests/exchange_integration.rs): Spin up a multi-worker cluster running a partitioned TPC-H subset. Assert connection constraints and bit-identical loopback vs. direct gRPC outputs.
- **Test**: Run the new TestContainers integration test target.

## 3. Test Commitments & Proof Mapping

### Oracle / Property / Simulation Tests
- **Loopback Parity Test** (`test_loopback_vs_direct_grpc`): Verify that loopback routing produces identical results compared to direct gRPC routing with zero network calls.
- **Flow Control Credit Test** (`test_credit_backpressure`): Validate that senders correctly suspend when credits are exhausted and resume upon receiving ACKs.

### Durability / LFS / TestContainers Tests
- **SlateDB Exchange Durability Test** (`test_exchange_metadata_durability`): Verify that `0x05` and `0x04` keys are correctly written to SlateDB LFS for both loopback and direct paths.
- **Multi-Worker 16-Shard TPC-H Test** (`test_distributed_tpch_connections_bounded`): TestContainers integration test checking connection limits and correctness.
