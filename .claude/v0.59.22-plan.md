# v0.59.22 Plan — Supported Platforms & Deployment Profiles

## Scope and Boundary

Roadmap row (`NEW_ROADMAP.md:1846`): *"Publish supported CPU architectures, Linux distributions and libc expectations, OCI image and `docker run`/Compose profiles, non-root container behavior, ports, storage and object-store requirements, resource recommendations, upgrade-safe configuration, and reference systemd and Kubernetes deployment profiles with a minimal Helm chart. Classify environments as `Supported`, `Compatible, unverified`, or `Unsupported`; `rockstream doctor` warns for the middle category and startup rejects only known unsafe or incompatible combinations."* Proof: *"Clean-machine runs pass for each supported profile; x86-64 and ARM64 binaries and multi-architecture images start the same smoke workload; container, systemd, and Kubernetes profiles run as non-root with documented persistence and networking; the matrix distinguishes tested versions from protocol-compatible but unverified S3-compatible, PostgreSQL, and Kafka versions, and rejects only known incompatibilities."* Backends: `Unit, LFS, MinIO, Postgres, Kafka, TC`. Dependencies: `v0.59.4, v0.59.21` (proof deps: `v0.59.14, v0.59.21`) (`NEW_ROADMAP.md:77`).

v0.59.22 delivers a comprehensive, production-hardened platform support matrix, deployment profiles, container packaging, and environment classification contract across all RockStream roles (`gateway`, `worker`, `control`, `frontier`, and standalone `all`):

1. **Environment & Platform Classification Contract (`Supported`, `Compatible, unverified`, `Unsupported`)**:
   - Establish formal environment classification tiers across host CPU architectures, operating systems, Linux distributions, libc runtimes, and storage filesystems in `contracts/platform-matrix.toml` and `crates/rockstream-types/src/platform.rs`:
     - **`Supported`**: Formally qualified in CI across automated integration suites. Operates with zero diagnostic warnings.
     - **`Compatible, unverified`**: Protocol-compatible or POSIX-compliant environments not continuously qualified in release gates (e.g. S3-compatible storage like Cloudflare R2 / Ceph, PostgreSQL 12–13, non-LTS Linux distributions, alternative 64-bit architectures). `rockstream doctor` and node startup emit clear, actionable informational warnings explaining the unverified status, but allow execution.
     - **`Unsupported`**: Known incompatible, unsafe, or deprecated environments (e.g. 32-bit architectures, glibc < 2.31, PostgreSQL < 12 CDC, NFS/SMB mounts lacking `O_DIRECT`/POSIX file locking for SlateDB WAL). Node startup and `rockstream doctor` fail fast and reject execution with documented diagnostic codes (`RS-0002` / `RS-0003` / `RS-3024`).

2. **Multi-Architecture OCI Image & Non-Root Container Profiles**:
   - Update `Dockerfile` to produce multi-architecture OCI images (`linux/amd64`, `linux/arm64`) with standardized OCI labels (`org.opencontainers.image.*`).
   - Enforce non-root execution by default using dedicated service user `rockstream` (UID 10001, GID 10001).
   - Standardize exposed network ports: `5432` (PGWire SQL), `9090` (Management HTTP / `/live`, `/ready`, `/health`, `/metrics`), `9100` (Worker RPC / DataPlane), `9200` (Control Plane Raft/RPC).
   - Configure persistent volume mount `/data` with proper non-root ownership.
   - Support read-only root filesystem execution (`--read-only --tmpfs /tmp`) with all transient state isolated to `/tmp`.
   - Provide reference `docker run` invocations and modular Docker Compose profiles (`standalone`, `distributed`, `kafka`, `postgres-cdc`) with healthcheck probes.

3. **Production-Grade Systemd Service Profiles**:
   - Deliver reference systemd unit files in `deploy/systemd/`:
     - `rockstream.service` (All-in-one standalone daemon)
     - `rockstream-gateway.service` (Stateless query gateway)
     - `rockstream-worker.service` (Stateful stream processing worker)
     - `rockstream-control.service` (Raft-backed control plane node)
   - Implement Linux security sandboxing directives: `User=rockstream`, `Group=rockstream`, `ProtectSystem=strict`, `ProtectHome=yes`, `NoNewPrivileges=yes`, `PrivateTmp=yes`, `MemoryDenyWriteExecute=yes`, `CapabilityBoundingSet=`, `LimitNOFILE=65536`.
   - Integrate systemd readiness and watchdog notifications (`WatchdogSec=30`, `ExecStartPost` polling `/ready`).

4. **Reference Kubernetes Manifests & Minimal Helm Chart**:
   - Deliver production-ready Kubernetes deployment manifests in `deploy/kubernetes/`:
     - Gateway `Deployment` with Horizontal Pod Autoscaler (`HPA`) based on active queries and CPU.
     - Worker `StatefulSet` with `volumeClaimTemplates` for dedicated SlateDB LFS / NVMe cache storage.
     - Control Plane `StatefulSet` (3 replicas) for Raft consensus with persistent storage.
     - Service definitions for PGWire (5432), Management/Metrics (9090), Worker RPC (9100), Control RPC (9200).
   - Enforce Kubernetes Pod Security Standards (`restricted` profile):
     - `securityContext`: `runAsNonRoot: true`, `runAsUser: 10001`, `runAsGroup: 10001`, `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `capabilities: { drop: ["ALL"] }`, `seccompProfile: { type: "RuntimeDefault" }`.
   - Configure container lifecycle probes wired to v0.59.21 management endpoints:
     - `livenessProbe`: HTTP GET `/live` on port 9090.
     - `readinessProbe`: HTTP GET `/ready` on port 9090.
     - `startupProbe`: HTTP GET `/ready` on port 9090 with failure threshold.
   - Deliver a minimal, clean Helm chart in `deploy/helm/rockstream/` (`Chart.yaml`, `values.yaml`, templates) supporting standalone and distributed deployment topologies.

5. **External Backend Compatibility & Verification Contract**:
   - Publish authoritative compatibility matrix for external storage, databases, and event brokers:
     - **Storage**: Local NVMe/SSD `LFS`, AWS S3, MinIO (`Supported`); Cloudflare R2, Google Cloud Storage (S3 API), Azure Blob (S3 API), Ceph S3 (`Compatible, unverified`); NFS/SMB without POSIX lock/O_DIRECT semantics (`Unsupported`).
     - **PostgreSQL**: PostgreSQL 14, 15, 16, 17, 18 (tested against pinned `postgres:18.0` reference) (`Supported`); PostgreSQL 12, 13, Neon, Supabase, AWS Aurora PostgreSQL (`Compatible, unverified`); PostgreSQL < 12 (`Unsupported`).
     - **Kafka**: Apache Kafka 3.x, Redpanda 23.x/24.x (`Supported`); Apache Kafka 2.8+ (`Compatible, unverified`); Apache Kafka < 2.8 / proprietary non-Kafka message brokers (`Unsupported`).

6. **Environment Diagnostics in `rockstream doctor` & Startup Rejection**:
   - Extend `rockstream doctor` to execute comprehensive platform classification and deployment readiness checks:
     - Check host architecture, OS distribution, kernel version, and libc runtime against `contracts/platform-matrix.toml`.
     - Check non-root container execution and read-only rootfs status.
     - Verify network port availability for required role listeners.
     - Inspect storage filesystem semantics (testing POSIX locking and write durability).
     - Probe configured external backends (S3/MinIO, PostgreSQL, Kafka) and classify their compatibility tier.
   - Wire startup validation: startup automatically classifies the environment, logs classification details, emits warnings for `Compatible, unverified`, and fails immediately with `RS-3024` / `RS-0002` if an `Unsupported` environment is detected.

7. **Upgrade-Safe Configuration & Resource Sizing Guidance**:
   - Document zero-downtime rolling upgrade sequencing: Control plane first -> Workers (drain one-by-one with shard lease migration) -> Gateways.
   - Define exact resource recommendation profiles (Development, Minimum Production Worker, Standard Production Worker, Gateway, Control Plane).
   - Generate authoritative single-source documentation: `docs/platforms.md`, `docs/deployment-profiles.md`, and update `docs/limits.md`.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag on the same `rockstream` binary.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters.
- Unbounded in-memory accumulation is never acceptable: all buffers, client sessions, probe checks, and diagnostic histories have named bounds and metrics.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass; no `--no-verify`. Fix root causes.
- Make only changes this version requires.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals** overlapping this scope.

### Explicitly Out of Scope

- No capacity planning estimator calibration or cost formula freezing — that is `v0.59.23` (`Capacity Planning & Estimator Calibration`).
- No final multi-worker RC benchmark qualification runs — that is `v0.59.24` (`Final Horizontal Scale & Performance Qualification`).
- No new SQL syntax, query operator, or engine execution changes.
- No new workspace crates.

## 6. Durability and Coordination Commitments

**Durability (LFS & MinIO Across Deployment Profiles)**:
- Persistence volume `/data` must survive container restarts, systemd service reloads, and Kubernetes pod recreations without state corruption or data loss.
- Non-root UID 10001 permissions on `/data` must be preserved across restarts and host volume re-attachments.
- SlateDB memtable flushes, WAL syncs, and SST compaction must succeed cleanly on container volume mounts and Kubernetes PersistentVolumeClaims across ext4, xfs, and MinIO backends.

**Coordination & Upgrade Safety**:
- Rolling upgrades must execute deterministically in declared order: Control Plane -> Workers -> Gateways.
- Workers draining during rolling upgrades must release shard leases cleanly to surviving or newly upgraded peer workers without query interruption.
- Gateway nodes must route client queries to available workers and gracefully handle transient node transitions during rolling deployment updates.
