### Slice 2 — `auth.rs` — New AuthMode variants and SCRAM crypto
**Files**: `src/auth.rs`

- `AuthMode`: add `Scram` and `Md5` variants; `from_str` handles `"scram"` / `"md5"`
- `Principal`: add `Principal::ScramUser { username: String }`; `identity()` returns the username
- `AuthError`: add `AuthError::InvalidPassword` — maps to RS-2401 / SQLSTATE `28P01`
- SCRAM crypto primitives (RFC 5802 §3, using sha2 + hmac):
  - `scram_hi(password: &[u8], salt: &[u8], iterations: u32) -> [u8; 32]` — PBKDF2-HMAC-SHA256 implemented via iterative HMAC loop
  - `scram_stored_key(salted_password: &[u8]) -> [u8; 32]` — HMAC-SHA256(SaltedPassword, "Client Key") → SHA256
  - `scram_server_key(salted_password: &[u8]) -> [u8; 32]` — HMAC-SHA256(SaltedPassword, "Server Key")
  - `scram_client_signature(stored_key: &[u8], auth_message: &str) -> [u8; 32]` — HMAC-SHA256(StoredKey, AuthMessage)
  - `scram_server_signature(server_key: &[u8], auth_message: &str) -> [u8; 32]`
  - `verify_client_proof(stored_key_from_catalog: &[u8], client_proof_b64: &str, auth_message: &str) -> bool`
- MD5 helpers:
  - `hash_md5_password(user: &str, password: &str, salt: &[u8]) -> String` — returns `"md5" + hex(md5(hex(md5(pw+user)) + salt))`
  - `verify_md5(expected_hash: &str, user: &str, salt: &[u8], client_response: &str) -> bool`
- **Green gate**: `auth.rs` unit tests `test_scram_crypto_rfc_vectors` (RFC 5802 Appendix B test vectors for SCRAM-SHA-256), `test_md5_password_hash_roundtrip`

### Slice 5 — `server.rs` — SCRAM-SHA-256 server flow in `on_startup`
**Files**: `src/server.rs`

Extend `impl StartupHandler for GatewayHandler::on_startup`:

**`AuthMode::Scram` + `PgWireFrontendMessage::Startup`**:
1. `save_startup_parameters_to_metadata`
2. Assign `conn_id` (CONN_ID task-local), create `SessionState` in `sessions`
3. Send `Authentication::SASL(vec!["SCRAM-SHA-256".to_owned()])` via `client.send(...).await?`
4. Set `session.scram_auth_state = ScramAuthState::Idle`
5. Return Ok — do NOT call `finish_authentication` yet

**`AuthMode::Scram` + `PasswordMessageFamily::SASLInitialResponse(r)`**:
1. Decode the client-first-message from `r.message`
2. Parse: extract `gs2_header`, `client_first_bare` (everything after gs2 prefix), `client_nonce` (from `r=` attribute)
3. Look up username (from session metadata `METADATA_USER`) in `RoleCatalog` — not found → RS-2401/28P01 immediately
4. Generate `server_nonce = client_nonce + random_nonce()` (24 base64 chars)
5. Retrieve `scram_salt` and `scram_iterations` from the role entry
6. Build `server_first = format!("r={server_nonce},s={salt_b64},i={iterations}")`
7. Set `session.scram_auth_state = ScramAuthState::ServerFirstSent { salted_password, server_nonce, auth_message: format!("{client_first_bare},server_first={server_first}"), username }`
   - Wait — the auth_message is: `client_first_message_bare + "," + server_first_message + ","`, built at this point
8. Send `Authentication::SASLContinue(server_first_bytes)`

**`AuthMode::Scram` + `PasswordMessageFamily::SASLResponse(r)`**:
1. Read session state — must be `ServerFirstSent`; otherwise protocol error
2. Parse client-final-message: extract `channel_binding` (c=), `nonce` (r=), `client_proof_b64` (p=)
3. Verify nonce matches `server_nonce` — mismatch → RS-2401/28P01
4. Build `client_final_message_without_proof = "c={channel_binding},r={nonce}"`
5. Complete `auth_message = stored_auth_message + "," + client_final_message_without_proof`
6. Call `verify_client_proof(stored_key, client_proof_b64, &auth_message)` — fail → RS-2401/28P01
7. Compute `server_signature_b64 = base64(scram_server_signature(server_key, &auth_message))`
8. Send `Authentication::SASLFinal(Bytes::from(format!("v={server_signature_b64}")))`
9. Set `session.principal = Principal::ScramUser { username }`
10. Call `finish_authentication(client, &GatewayServerParameterProvider::default()).await?`
11. Reset `scram_auth_state = ScramAuthState::Idle`

- **Green gate**: integration test `tests/gateway_proof_tests.rs::test_scram_auth_flow_unit` — end-to-end SCRAM handshake via tokio-postgres client against in-process gateway with `AuthMode::Scram`

### Slice 6 — `server.rs` — MD5 password fallback in `on_startup`
**Files**: `src/server.rs`

**`AuthMode::Md5` + `PgWireFrontendMessage::Startup`**:
1. `save_startup_parameters_to_metadata`
2. Assign conn_id, create session
3. Generate 4-byte random salt: `rand::random::<[u8; 4]>()`
4. Store in `session.md5_auth_salt = Some(salt)`
5. Send `Authentication::MD5Password(salt.to_vec())`

**`AuthMode::Md5` + `PasswordMessageFamily::Password(p)`**:
1. Get username from session metadata
2. Look up role in `RoleCatalog` — not found → RS-2401/28P01
3. Get `salt = session.md5_auth_salt.expect("MD5 salt missing")`
4. Call `verify_md5(role.md5_hash.as_deref().unwrap_or(""), username, &salt, &p.password_str())`
5. Fail → RS-2401/28P01; success → set `Principal::ScramUser { username }`, call `finish_authentication`

- **Green gate**: integration test `tests/gateway_proof_tests.rs::test_md5_auth_flow_unit` — MD5 connect via tokio-postgres with `password` config option against `AuthMode::Md5` server

### Slice 8 — `server.rs` / `session.rs` — GUC round-trip (SET / SHOW)
**Files**: `src/server.rs`, `src/session.rs`

- `dispatch_sync` currently calls `catalog_stubs.handle_query` for SET commands (returns `CommandComplete("SET")`)
- Move SET parsing out of `catalog_stubs` into `dispatch_sync` in `server.rs`:
  - Parse `SET <key> [=|TO] <value>` with a simple regex/split
  - Store in `session.guc_params[key.to_lowercase()] = normalized_value`
  - Also update specific `SessionState` fields for known keys:
    - `search_path` → `session.search_path = normalized_value`
    - `application_name` → `session.application_name = normalized_value`
    - `statement_timeout` → `session.session_wait_for_timeout_ms = parse_ms(value)`
  - Return `CommandComplete("SET")`
- Parse `SHOW <key>` in `dispatch_sync`:
  - Look up in `session.guc_params` → return value
  - Fall back to known defaults (UTF8 for encodings, current `session.search_path`, etc.)
  - Return `RowDescription + DataRow + CommandComplete`
- **Green gate**: `tests/gateway_proof_tests.rs::test_guc_round_trip` — SET search_path → SHOW search_path returns same value; SET/SHOW for client_encoding, timezone

### Slice 9 — `server.rs` — search_path-aware view resolution
**Files**: `src/server.rs`, `src/catalog_stubs.rs`

- When `dispatch_sync` receives an unqualified `SELECT * FROM <name>` (no schema prefix), parse the name; check `session.search_path` schema list in order
- `CatalogStubs::resolve_view(name: &str, search_path: &[&str]) -> Option<CatalogView>`: iterate schemas, return first match
- All existing views stored with schema = `"public"` — unqualified name resolves if `"public"` in search_path
- For schema-qualified `schema.name`: bypass search_path entirely
- `SET search_path = 'app'; SELECT * FROM my_view` where my_view is in public → RS-2000 (42P01 — relation not found)
- `SET search_path = 'app, public'; SELECT * FROM my_view` → resolves via public fallback
- **Green gate**: `tests/gateway_proof_tests.rs::test_search_path_view_resolution` — create view in public schema, verify resolution with various search_path settings
