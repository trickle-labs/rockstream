# v0.59.8 Plan — Shared Windows & Skew-Aware Execution

## Scope and boundary

The roadmap row requires shared time slices, law-aware rolling maintenance,
heavy/light aggregate and join planning, deterministic power-of-two routing,
and frontier-safe micro-migration. Phase 3a implements the first four internal
slices. It adds no SQL keyword, CLI command, or wire protocol.

The existing v0.59.7 factorized operator and governor remain the join executor;
this version supplies the skew-aware selection and routing inputs around them.
Phase 3b owns bounded copy chunks, migration-epoch dual routing, committed
frontier cutover, delayed reclamation, and decayed heat in leases.

## Vertical slices

1. **Shared time-slice identity and fabric** — canonicalize the source,
   partitioning, time column, physical slice width, predicate digest, and merge
   law; attach different logical window widths to one bounded physical store.
2. **Law-specific rolling state** — maintain checked SUM/COUNT deltas per slice,
   including retractions, with a bounded query scan and fill-level metric.
3. **Heavy/light planning** — normalize composable hot-key splits to a power of
   two and retain the existing spill fallback for non-composable laws.
4. **Deterministic power-of-two routing** — route the same key to the same
   bucket using the existing stable hash; use the helper in bucketed aggregate
   execution without changing the existing rendezvous compatibility API.
