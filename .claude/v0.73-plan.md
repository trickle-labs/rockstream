# v0.73 Security Coherence — Working Plan

Baseline: `9a912e1c` (`main`). Scope owners: issues #301–#307. The
release remains incomplete until every criterion below has assembled public
endpoint evidence and the required durable restart checks.

## Adopted source-plan profile

The user-approved decisions are recorded in the [v0.73 authorization policy
profile](../docs/implementation-plans/v0.73-authorization-policy.md) and are a
source-plan amendment, not runtime evidence. Keep #301–#307 open until their
implementation and release qualification pass.

- Qualify SCRAM-SHA-256, OIDC/RS256, and external mTLS in supported enabled
  configurations. Run all ten required negative cases through release
  endpoints; startup rejection cannot replace a missing case. Failed auth or
  wrong-node identity creates no session. An insufficient-role denial in an
  existing session preserves the session unless protocol, revocation, or
  security policy requires closure.
- Use the profile's exact action/scope and preset matrix. Keep verified legacy
  grants in explicit versioned mappings; caller role flags never grant
  authority. Operator alone grants no business-data, secret-value, or grant
  access. Bootstrap through trusted offline preprovisioning; reject online
  last-administrator removal, disablement, or downgrade, with offline recovery.
- Freeze RS256 only; token size ≤16 KiB; JWKS ≤1 MiB and 100 keys per issuer;
  cache TTL ≤60 seconds; 5-second fetch timeout; one in-flight refresh per
  issuer; one transient retry after 250 ms; and the 10,000-entry/60-second
  authorization cache. Keep the 60-second revocation bound.
- Retain audit for 90 days up to 1 GiB with synchronous mutation coupling and
  fail-closed capacity behavior. Limit artifacts to 10 MiB each, 10 minutes of
  availability, and 100 MiB aggregate storage; delete expired/temporary data
  within 60 seconds, including startup recovery before listeners open.
- Require a client UUID in `Idempotency-Key` before security mutations; bind
  actor/scope/request digest, reconcile via authorized `GET /operations/{id}`,
  and retain the original result for 90 days. Never retry as a new mutation.
- Preserve secret-reference input and canonical persistence, next-epoch
  connector continuity, KMS/KEK recovery semantics, and in-flight internal
  certificate rollover. Keep unsupported Kafka rotation routes, bootstrap
  fixtures, independent envelope inspection, and client-visible response-loss
  seams blocked until real evidence exists.
