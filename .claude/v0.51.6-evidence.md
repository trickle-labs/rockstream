## Regressions found and fixed during Prove (schema-change fallout, not deferred)

Fixing `avg_v`'s output type (`Int64` → `Float64`) broke two pre-existing
tests that hard-coded the old `Int64` column type for `AggregateOp`'s output
column 3. Per ground rules ("nothing may be deferred"), both were fixed as
part of this version rather than left broken or ignored:

- `crates/rockstream-ops/tests/virtual_bucket_state_durability_tests.rs` —
  `extract_rows()` downcast column 3 as `Int64Array`; updated to
  `Float64Array` and the row tuple type to `(i64, i64, i64, f64, i64)`.
  Verified: `cargo test -p rockstream-ops --test virtual_bucket_state_durability_tests`
  → `4 passed; 0 failed`.
- `crates/rockstream-sql/tests/tpch_soak_e2e.rs` — the TPC-H mini-interpreter
  unconditionally downcast `AggregateOp`'s column 3 as `Int64Array` for
  every aggregate (`Sum`/`Count`/`Avg`), panicking even on non-`Avg`
  queries; updated to `Float64Array` with the `Avg` arm rounding to `i64` to
  preserve the rest of the i64-typed comparison pipeline (no TPC-H query in
  this file actually exercises `AVG`, so this is a compile/shape fix only).
  Verified: `cargo test -p rockstream-sql --test tpch_soak_e2e`
  → `5 passed; 0 failed`.
