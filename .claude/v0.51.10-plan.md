## 1. Deferred-Item Audit

Audited all prior sign-offs (`sign-offs/v0.1.md` through `sign-offs/v0.51.9.md`):

1. **Overlapping Scope Pickups for v0.51.10**:
   - **Worker-Side Prospective Quota Enforcement (Area B)**: In `v0.27` / `v0.45.1`, state budgets were implemented in `crates/rockstream-types/src/state_budget.rs` and gateway `catalog_stubs.rs` (`budget.try_acquire`), but runtime worker operators allocated arrangement state without prospective checks (resulting in reactive `OverBudgetRelaxed` status). This version (v0.51.10) explicitly picks up prospective worker-side quota ledger consultation before arrangement/state allocation and prospective batch shedding/rejection (`OverBudgetRejected`).
   - **Consensus-Replicated Lease HA Leader-Kill Drill (Area A)**: In `v0.45.2`, shard-lease failover was verified only in a single-process `SimRuntime` scenario, and `ShardManager` lease grants remained in an in-memory `HashMap` without durable cross-control-node consensus replication. This version (v0.51.10) explicitly picks up full consensus replication of shard-lease grants through Raft (`RaftPersistentStore` / `RaftHandle::require_leader()`) and proves leader failover against real, separate processes under SIGKILL (`lease_ha_leader_kill_tests.rs`).

2. **Non-Overlapping Prior Deferrals (Flagged for Follow-up Versions)**:
   - **v0.51.12**: New operational edge-case specs (quota exhaustion edge handling, source failure, object-store brownout, misconfiguration, late data).
   - **v0.51.13**: Genuinely multi-shard and cap-free ad hoc query execution.

No undocumented deferral was dropped. All overlapping scope items are fully incorporated into this plan.

## 5. Test Commitments & Oracle Property Tests

- **Worker Quota Oracle Property:** For any batch sequence $B$, prospective worker-side rejection decision matches exact quota budget state $Q(B) > L_{\text{workload}}$ before allocation, and $L_{\text{well\_behaved}}$ latency is invariant to hostile tenant load:
  $$\text{Latency}(\text{WellBehaved} \mid \text{HostileActive}) \le \text{LatencySLO}(\text{WellBehaved})$$
  *Test:* `tests/distributed_quota_enforcement_tests.rs::test_cross_worker_quota_coordination`.
- **Lease HA Oracle Property:** For any leader failover transition $L_1 \xrightarrow{\text{SIGKILL}} L_2$, shard lease mapping $M(S)$ is strictly monotonic in fencing token $T(S)$ and continuous:
  $$M_{L_2}(S) = M_{L_1}(S), \quad T_{L_2}(S) > T_{L_1}(S), \quad \text{DualWriters} = 0$$
  *Test:* `tests/lease_ha_leader_kill_tests.rs::test_leader_sigkill_follower_takeover_lease_continuity`.
