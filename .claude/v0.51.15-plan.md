# v0.51.15 Plan — Durable Source Runtime Foundation

Roadmap: `NEW_ROADMAP.md:1061`. This version makes the existing source DDL and
HTTP listener a durable runtime. It adds no relational IVM operator and no new
SQL grammar; the single `rockstream` binary remains the gateway and webhook
listener.

## 1. Deferred-Item Audit

### Must implement this version

All prior `sign-offs/v*.md` were searched for `deferred`, `postponed`, and
`out-of-scope`. No signed-off deferred item overlaps source checkpoints,
source ownership, source lifecycle, or webhook acknowledgement. In particular,
`v0.51.9` through `v0.51.13` defer nothing. Older connector, IVM, aggregate,
and shard-count items are outside this scope.

The v0.51.14 source surface was superseded rather than signed off
(`NEW_ROADMAP.md:1064`). Its unshipped runtime gaps are undocumented deferrals
and therefore **must implement this version**:

| Required gap | Current evidence | v0.51.15 commitment |
| --- | --- | --- |
| Durable source epoch and offset | `SourceEpochRegistry` is explicitly in-memory at `source_epoch.rs:58-60`; `SourcePollLifecycle::commit` only mutates it at `source_connector.rs:240-255` | Persist a prepared/committed epoch record and opaque token in the M3 input `WriteBatch`, recover only the highest committed record, and retain a bounded durable history. |
| Correct prepare/commit/ack order | `SourcePollLifecycle::commit` calls upstream `commit_offset` before local epoch publication at `source_connector.rs:246-255` | Enforce `prepare durable input → M3 commit → mark source checkpoint committed → upstream acknowledgement`; crashes at each transition never acknowledge uncommitted input. |
| Live owner and coordination | Catalog runtime has only `status`, `live_offset`, and `live_lag` at `catalog_stubs.rs:243-247` | Add fenced owner lease, live checkpoint, lag, bounded-buffer level, and blocked reason; failover recovers the durable checkpoint before ownership becomes active. |
| Durable webhook delivery identity | `HttpWebhookSource` has process-local pending/committed sets at `webhook_source.rs:151-179`; handler calls `commit_next` before its response at `server.rs:1690-1702` | Bind delivery identity and payload digest to the M3 input transaction, return success only after that transaction commits, and restore deduplication from the committed checkpoint. |
| Lifecycle cleanup | `ALTER SOURCE` currently changes catalog/maps at `server.rs:5113-5155` | PAUSE, RESUME, and DROP fence/stop the owner, remove only the named source's durable runtime records with scan-and-delete, and make the post-action live status exact. |
| Required observability | `SHOW SOURCE STATUS` emits only catalog status/offset/lag/options at `catalog_stubs.rs:854-879` | Report owner, committed checkpoint/token, lag, buffer fill, and blocked state from the live durable runtime; redact credential references and tokens. |

### Out-of-scope — flag for follow-up version

None from prior sign-offs overlap this scope. PostgreSQL replication workers,
pgoutput/wal2json decoding, JSON/CSV row conversion, and production webhook
source semantics remain explicitly scheduled for v0.51.16; this version only
provides their durable runtime foundation.

## 4. Vertical Slices

1. **Durable checkpoint model and storage adapter.** Define a versioned source
   checkpoint containing source identity, epoch, opaque token, state, and
   delivery identity/digest where applicable. Persist prepared and committed
   records through the source's M3 `WriteBatch`; read the highest committed
   record at recovery. Bound persisted history to a named
   `SOURCE_CHECKPOINT_HISTORY_MAX_ENTRIES` and publish
   `source_checkpoint_history_entries`. Exit: the five LFS matrix tests.

2. **S3 durability parity.** Run the identical checkpoint transaction and
   restart scenarios against TestContainers MinIO. Exit: the five MinIO matrix
   tests, with byte-for-byte identical expected committed records to Slice 1.

3. **Runtime ownership and strict acknowledgement ordering.** Add a fenced
   per-source owner registration and coordinator. It must prepare input, commit
   M3 plus checkpoint, then acknowledge upstream; errors pause/block without
   advancing the checkpoint. The in-flight source work queue has named bound
   `SOURCE_RUNTIME_MAX_IN_FLIGHT_EPOCHS`, metric
   `source_runtime_in_flight_epochs`, and zero-credit/error backpressure.
   Exit: first three SimRuntime ownership/fault tests.

4. **Lifecycle and live status wiring.** Rewire CREATE/ALTER/SHOW to the
   coordinator so catalog visibility, owner state, PAUSE/RESUME/DROP, and live
   status cannot diverge. Status exposes exact owner, checkpoint, lag, buffer,
   and blocked reason but no credential/token. DROP uses a bounded prefix scan
   (`SOURCE_CLEANUP_SCAN_PAGE_LIMIT`) plus point deletes, reports
   `source_cleanup_scan_pages`, and never range deletion. Exit: all five
   lifecycle/status tests.

5. **Webhook M3 ingress.** Replace process-local `commit_next` success with a
   durable source-input transaction. Preserve the pre-enqueue request and
   buffer bounds, expose `http_webhook_buffered_epochs`, respond `429` at the
   configured bound, and emit `202` only after committed M3 input is durable.
   Exit: both LFS/MinIO webhook-ack tests and the seeded retry/failover test.

6. **Race and cleanup proof sweep.** Inject all prescribed ownership/lifecycle
   races and prove scan-and-delete cleanup leaves no named source records while
   preserving unrelated sources. Exit: final SimRuntime lifecycle-race test
   and `source_cleanup_tests::drop_scan_deletes_only_named_source_runtime_without_range_delete`.

## 5. Operator and Durability Commitments

No new relational operator is introduced, so an `incremental == batch`
operator oracle is not applicable. The corresponding source-runtime oracle is
mandatory: for every crash point, replayed committed
`(epoch, token, input-delta, delivery-id)` output equals a no-crash batch
oracle exactly and in order. The commit-boundary matrix supplies that oracle on
both required storage backends.

All new durability paths—prepared source input, M3 commit, source checkpoint
replay, webhook deduplication, and lifecycle cleanup—have both LFS and MinIO
TestContainers tests in the matrices above. All new coordination paths have
the seeded SimRuntime tests above with active `buggify!()` annotations.
