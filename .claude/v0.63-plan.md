# v0.63 Plan — Durable Catalog

## Scope and Boundary

Roadmap reference (`ROADMAP.md` §9: `v0.63 — Durable Catalog`):
> **Focus**: Make database metadata as durable as maintained state.
> **User outcome**: After an ungraceful process death, RockStream still knows which tables and materialized views exist.
> **Required Proof**: Black-box crash test:
> 1. Start RockStream.
> 2. CREATE TABLE.
> 3. CREATE MATERIALIZED VIEW.
> 4. INSERT rows.
> 5. Verify result.
> 6. SIGKILL process.
> 7. Start a completely new process from the same data directory.
> 8. Query pg_catalog.
> 9. Query the materialized view.
> 10. Verify definitions and exact result.
> Repeat with:
> - index,
> - workload assignment,
> - source metadata where supported.

Committed implementation plan reference: `docs/implementation-plans/v0.63.md`.
Apply the shared implementation and evidence rules: `docs/implementation-plans/README.md`.

v0.63 eliminates ephemeral in-memory catalog storage, replacing it with a durable, versioned, transaction-logged catalog store:

1. **`CatalogStore` Unified Ownership (`crates/rockstream-storage/src/catalog/`, `crates/rockstream-gateway/src/catalog_stubs.rs`)**:
   - Introduce `CatalogStore` backed by the configured durable storage backend (`file://` or `s3://`).
   - Single authoritative owner for all metadata categories: databases, namespaces, tables, columns, materialized views, inline views, view dependencies, indexes, workloads, sources, sinks, roles/grants, and compiled-plan metadata.
   - Projections (`pg_catalog`, `information_schema`, `rockstream_catalog`) derive strictly from the durable catalog revision; no independent in-memory catalog truth is permitted.
   - Define supported vs. inapplicable object matrix: creation of unsupported objects (`CREATE TRIGGER`, `CREATE PROCEDURE`, `CREATE FOREIGN TABLE`, `CREATE DOMAIN`, `CREATE SEQUENCE`) fails explicitly with `RS-1001` / `RS-2001`.

2. **Versioned Record Envelope & Durable Identity (`crates/rockstream-types/src/ids.rs`, `crates/rockstream-storage/src/catalog/envelope.rs`)**:
   - Every catalog record is serialized in a canonical versioned envelope containing:
     - `catalog_format_version: u32` (current format = 1).
     - `record_version: u32` (per-entity schema version = 1).
     - `object_id: u128` (or 128-bit strong ID).
     - `catalog_revision: u64` (monotonic sequence revision).
     - `checksum: u32` (CRC32 checksum of serialized body).
   - Compatibility engine: strict closed validation; unsupported combinations fail fast with `RS-1002` / `RS-1003`.
   - Durable domain IDs (`TableId`, `ViewId`, `IndexId`, `SourceId`, `WorkloadId`) remain immutable across restart, rename, compaction, and backup/restore.
   - Monotonic durable ID generator: allocated from storage with high-water mark tracking; restored IDs never collide with new allocations.

3. **Atomic Logical Transactions (`CatalogTxn`) (`crates/rockstream-storage/src/catalog/txn.rs`)**:
   - DDL changes execute as atomic logical catalog transactions:
     - `revision: u64`
     - `operation_id: u64`
     - `mutations: Vec<CatalogMutation>`
     - `checksum: u32`
   - Every metadata modification (`CREATE TABLE`, `CREATE MATERIALIZED VIEW`, `DROP VIEW`, `CREATE INDEX`, `ALTER WORKLOAD`, etc.) routes exclusively through `CatalogStore::commit_txn`.
   - All mutations in a transaction commit atomically or none do.
   - Replay deduplication: repeated replay of `operation_id` skips previously committed mutations without duplicate side effects.

4. **Snapshot-Plus-Log Metadata Retention & Compaction (`crates/rockstream-storage/src/catalog/log.rs`, `snapshot.rs`)**:
   - Storage layout under documented catalog namespace:
     - `catalog/log/<start_revision>_<end_revision>.log`
     - `catalog/snapshots/<snapshot_revision>.snap`
   - Catalog recovery rule: `latest valid snapshot + subsequent valid log entries = current catalog state`.
   - Snapshot confirmation before log deletion: old log records are compacted only after the durable snapshot is confirmed fsync'd/persisted.
   - Bounded scan windows: scans bounded by page limits (1,024 records), exposing progress and continuing to completion rather than treating a page boundary as EOF.

5. **Compiled-Plan Identity & Safe Gateway Reconstruction (`crates/rockstream-plan/src/identity.rs`, `crates/rockstream-gateway/src/server.rs`)**:
   - Materialized view definitions persist 7 required compiled-plan identity fields:
     1. `sql`: original SQL query text.
     2. `ast_hash`: SHA-256 hash of parsed SQL AST.
     3. `logical_plan_hash`: SHA-256 hash of normalized DataFusion logical plan.
     4. `compiler_version`: semantic version of compiler/lowering engine.
     5. `state_layout_version`: layout format version of operator arrangements.
     6. `output_schema`: complete serialized Arrow Schema (field names, types, nullabilities).
     7. `dependency_ids`: complete list of prerequisite `TableId` and `ViewId` dependencies.
   - Refactor `GatewayHandler::recover_compiled_views`:
     - Load all views and compiled plans from `CatalogStore`.
     - Validate compatibility of state layout and schemas; return mandatory errors on mismatch.
     - Recovery must never replace failed state restoration with an empty successful view.
     - Failed view restoration sets component state to `Fatal` and prevents `Ready`.

6. **Public Projections & Exact Projection Replay (`crates/rockstream-gateway/src/catalog_stubs.rs`)**:
   - `pg_catalog.pg_tables`, `pg_catalog.pg_views`, `pg_catalog.pg_class`, `pg_catalog.pg_attribute`, `pg_catalog.pg_namespace`, `pg_catalog.pg_type`, `pg_catalog.pg_index` derive directly from `CatalogStore` snapshot.
   - `information_schema.tables`, `information_schema.columns` derive from `CatalogStore`.
   - Projection caches are keyed by `catalog_revision` and invalidated atomically on revision advance.
   - Pre-commit validation: check for dependency cycles, missing referenced objects, and drop cascade rules before committing a transaction.

7. **Crash Verification & Black-Box Proof (`crates/rockstream-gateway/tests/`, `crates/rockstream-cli/tests/`)**:
   - End-to-end crash proof: Start release binary, CREATE TABLE, CREATE MATERIALIZED VIEW, INSERT data, verify query results, SIGKILL the process, start a fresh process from identical storage directory, query `pg_catalog`, query materialized view, assert bit-identical results.
   - Repeat crash proof for indexes, workload assignments, and Kafka/Postgres sources.
   - Negative testing: corrupted record envelopes, broken plan layouts, failed storage appends, and exhausted budgets cleanly fail closed without partial state corruption.

### Non-Negotiable Ground Rules

- Prefix every shell command with `rtk` (e.g. `rtk cargo test`, `rtk git status`).
- One binary, one CLI, one config: every role is a flag or config property on the same `rockstream` binary. `main` remains runnable through it.
- No code path may depend on SlateDB range deletion. Cleanup is scan-and-delete or snapshot-safe compaction filters, asserted by test.
- Unbounded in-memory accumulation is never acceptable. Every new queue, buffer, or scan window needs a named upper bound, a fill-level metric, and a backpressure or error path.
- Do not weaken, skip (`#[ignore]`), or delete tests to make a build pass. Do not use `--no-verify`. Fix root causes.
- Make only changes this version requires. No speculative features outside IVM engine + Postgres wire layer.
- **Nothing may be deferred to a later version.**
- **Pick up all prior deferrals.**

## 2. Dispatch-Wiring & Public Surface Audit

This version makes all catalog mutations route through `CatalogStore::commit_txn`, persists versioned record envelopes to durable storage, reconstructs catalog state on node startup, and derives all public catalog queries (`pg_catalog`, `information_schema`, `rockstream_catalog`) from the durable catalog revision.

| Public Surface / SQL Command | Parser & Recognition | Dispatcher & Router | Executor / Storage Implementation | Response & Failure Invariant | Status |

| `DROP TABLE <name>` | `rockstream-sql/src/frontend.rs:DdlStatement` | `server.rs:dispatch_sync` | `CatalogStore::commit_txn` -> validates zero dependent views, writes drop mutation | Rejects drop if dependent views exist (`RS-1002`); survives restart | **MUST REFACTOR** |
| `CREATE [OR REPLACE] [MATERIALIZED] VIEW <name> AS ...` | `rockstream-sql/src/frontend.rs:DdlStatement` | `server.rs:handle_create_view` | `CatalogStore::commit_txn` -> writes `CatalogTxn` with `ViewId`, 7 compiled-plan fields | Commits atomic view definition or none; survives SIGKILL; visible in `pg_views` | **MUST REFACTOR** |
| `DROP VIEW <name>` | `rockstream-sql/src/frontend.rs:DdlStatement` | `server.rs:handle_drop_view` | `CatalogStore::commit_txn` -> validates zero dependent views, deletes view records | Rejects drop if dependent views exist (`RS-1002`); atomic deletion | **MUST REFACTOR** |
