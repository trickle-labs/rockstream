# v0.49 Plan — Zero-Copy IPC, AZ-Aware Shuffle & Shuffle Compression

Prerequisite phases 0–1 complete: `sign-offs/v0.48.md` is fully checked off
(`**Nothing deferred.**`), and the orchestrator already verified the full
v0.48 sign-off / proof chain plus the all-history deferred-item sweep.
NEW_ROADMAP.md row read (line 921, Phase 14 — Zero-Copy IPC, AZ-Aware Shuffle &
Shuffle Compression). This plan therefore starts from the verified v0.48
baseline and only re-checks the current code / recent sign-offs needed to scope
v0.49 precisely.

## Proof obligations (restated as checkable assertions)

1. Same-host, different-worker exchanges no longer traverse the TCP/gRPC payload
   path on the hot path: when both peers advertise the v0.49 same-host IPC
   capability and share the same host identity, the runtime uses Arrow
   Flight-style shared-memory transport and the profiled copy count on the
   sender/receiver path is zero; if shared memory cannot be established,
   delivery falls back once to the existing direct path with no duplicate
   delivery.
2. Exchange routing becomes real, not aspirational: the doc-only
   `exchange_direct_threshold_bytes`, `exchange_spill_threshold_mb`,
   `exchange_domain_size`, and `exchange_force_durable` knobs exist in
   `RockstreamConfig`, `ExchangeAnn` is consumed by a concrete classifier, and
   the classifier chooses `Elided` / `Loopback` / `Direct` / `Durable` plus the
   concrete transport / codec from worker locality (`same worker`, `same host`,
   `same AZ`, `cross AZ`), health, and batch size.
3. Cross-AZ worker-to-worker shuffle traffic drops to near zero during shuffle
   phases because AZ-mismatched peers are never left on the direct gRPC path:
   same-host peers use shared memory, same-AZ peers may stay direct, and
   cross-AZ traffic is routed through the durable object-store path / AZ-aware
   hierarchical domains instead.
4. Shuffle payload encoding is actually implemented, path-specific, and rolling
   upgrade safe: direct-network and persisted fast-path payloads use LZ4,
   durable shuffle objects and cluster-checkpoint manifests use ZSTD, the
   elided path still skips serialization entirely, and every v0.49 decoder
   accepts both the legacy raw Arrow IPC bytes and the new framed payloads.
5. On a representative wide-shuffle workload (TPC-H and/or Nexmark via the
   existing oracle harness), measured cross-worker network bytes fall by at
   least 40% with zero divergence from the oracle / uncompressed baseline.
6. Direct-path compression stays within the per-epoch SLO budget; if it does
   not, the existing auto-tuner concept (not a one-off ad hoc flag) disables
   direct-path compression for the affected exchange until hysteresis says it is
   beneficial again.
7. Ground rules: no new persistence or cleanup path uses SlateDB range
   deletion; every new bounded structure (same-host shared-memory segment pool,
   compression-tuner state, any route/domain cache) has a named capacity,
   fill-level metric, and fallback/backpressure path; no existing test is
   weakened; `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D
   warnings`, `cargo test --workspace`, `bash scripts/check-error-codes.sh`,
   `bash scripts/check-invariant-pairs.sh`, and `make e2e` all pass.

## 1. Deferred-Item Audit

The orchestrator already completed the all-history audit across
`sign-offs/v0.1.md` through `sign-offs/v0.48.md` and confirmed the strong
result this plan needs: **no prior version has an outstanding deferred item that
overlaps v0.49's exchange / shuffle / network-efficiency scope.** I still
spot-checked the recent sign-offs most likely to contain exchange-adjacent work:

- `sign-offs/v0.45.4.md` closes with "No item from this version's Scope has
  been deferred" after the benchmark-gate work landed completely.
- `sign-offs/v0.45.5.md` closes with the same "No item ... deferred"
  confirmation for the conformance-lock/documentation sweep.
- `sign-offs/v0.45.7.md` is the most relevant overlap check because it touched
  the durable-shuffle code family directly (`durable.rs`, `multiplexer.rs`,
  `serialization.rs`, `loopback.rs`, `RS-3011`–`RS-3018`): its Notes section
  explicitly says no item from scope was deferred and that every tightly-coupled
  exchange-shuffle bare-error site was fixed alongside the named files rather
  than postponed.
- `sign-offs/v0.46.md`, `sign-offs/v0.47.md`, and `sign-offs/v0.48.md` each
  explicitly state `**Nothing deferred.**`

That clears the true deferred-item question. What **does** overlap v0.49, and
must be reconciled in-scope, is pre-existing scaffolding / doc drift:

- **DESIGN.md §7.2 already names four exchange-routing knobs, but no code or
  config surface exists for any of them.** `exchange_direct_threshold_bytes`,
  `exchange_spill_threshold_mb`, `exchange_domain_size`, and
  `exchange_force_durable` are documented, but `crates/rockstream-types/src/
  config.rs` has no exchange block and grepping `crates/` finds no code hits.
  v0.49 cannot keep this gap: compression is explicitly "selected automatically
  by the same path classifier," and AZ-aware domains literally depend on
  `exchange_domain_size`, so these knobs become in-scope now.
- **`ExchangePath` / `ExchangeAnn` / `ExchangeClassifier` are half-built
  scaffolding, not live behavior.** `crates/rockstream-types/src/exchange.rs`
  says the planner attaches `ExchangeAnn` and a runtime classifier consumes it,
  but the types are never constructed or read anywhere else in `crates/`.
  v0.49 must wire this existing enum family into a real classifier rather than
  inventing a second, competing routing vocabulary.
- **The current `LoopbackRouter` serialize→persist→deserialize round-trip is
  real but is not the roadmap's same-host target.** DESIGN.md §7.5's existing
  `Loopback` means same worker / different shard; the roadmap's same-host
  zero-copy target is different worker processes co-located on one host. The
  plan below keeps that distinction explicit so the zero-copy proof is attached
  to the correct path.
- **Cluster-checkpoint persistence is specified in DESIGN.md §11.2, but the code
  still has only an in-memory `CheckpointCoordinator` plus an external
  `commit_manifest` callback.** There is no shared manifest codec/store yet.
  Because the roadmap now requires ZSTD-compressed cluster checkpoints, v0.49
  has to centralize that persistence path instead of hand-compressing
  individual call sites.
- **The absence of `tonic` transport-compression features is evidence of the
  gap, not the fix.** Enabling gzip/zstd on tonic would not satisfy DESIGN.md
  §7.3 because the durable object-store path and `shuffle_outbox/` /
  `shuffle_inbox/` values also need the same codec framing. v0.49 therefore
  needs application-level payload codecs and capability-gated decode logic, not
  just a transport-level knob.

**Conclusion: deferred-item audit is complete. Nothing from a prior version is
deferred into v0.49. The only carry-over is scoped reconciliation of existing
exchange scaffolding / DESIGN.md drift (`ExchangeAnn`, missing config knobs,
missing checkpoint manifest store), and those are resolved in the slices below.**

  `crates/rockstream-runtime/src/client.rs`, and
  `crates/rockstream-runtime/src/exchange/pool.rs`.

  decode cleanly during rolling upgrade.
- Add a real `exchange` block to `crates/rockstream-types/src/config.rs`
  (`ExchangeConfig` or equivalent), containing the already-documented
  `exchange_direct_threshold_bytes`, `exchange_spill_threshold_mb`,

  `same_host_shm_segment_bytes`, `same_host_shm_segments_per_peer`, and

- Wire these fields into the existing single-binary startup surface in
  `crates/rockstream-cli/src/main.rs` / `rockstream start` rather than inventing

- Tests:
  `worker_registration_roundtrip_preserves_location_and_capabilities`,
  `legacy_worker_registration_defaults_location_and_capabilities`,
  `topology_catalog_persists_location_and_capabilities`,
  `config_exchange_defaults_roundtrip`.

#### Slice A2 — Turn orphaned `ExchangeAnn` scaffolding into the single real route model

  `crates/rockstream-runtime/src/exchange/classifier.rs`.
- The classifier consumes the existing `ExchangeAnn`, peer locality
  (`same worker`, `same host`, `same AZ`, `cross AZ`, `unknown`), peer
  capabilities, reachability, and the new `ExchangeConfig` thresholds. Its
  outputs are the concrete transport, codec, and optional domain id. This is
  the place that finally makes DESIGN.md §7.2/§7.5 executable instead of
  aspirational.
- Update `DESIGN.md` in the same slice: §7.2/§7.5 gain explicit v0.49
  subsections for locality/capability-gated routing, same-host shared memory,
  and AZ-aware hierarchical domains, each marked in the repo's normal
  `**Ships**: v0.49` style so the implementation and the design text stay
  aligned.
- `crates/rockstream-runtime/src/exchange/mod.rs`,
  `multiplexer.rs`, and `loopback.rs` are updated to call the classifier
  instead of hard-coding "always gRPC unless same worker".
- Register the next exchange-family error codes in
  `crates/rockstream-types/src/error_code.rs` for the new failure modes:
  shared-memory segment unavailable, unknown codec / decompression failure, and
  missing/stale locality metadata fallback warnings. Continue the existing
  30xx exchange block directly after `RS_3018`.
- Tests:
  `classifier_consumes_exchange_ann_instead_of_ignoring_it`,
  `classifier_selects_same_host_shared_memory_before_grpc`,
  `classifier_selects_durable_for_cross_az_peers`,
  `classifier_honors_exchange_thresholds_and_force_durable`.

### Track B — Same-Host Zero-Copy IPC

#### Slice B3 — Add the shared-memory transport, bounded from day one
- Add `arrow-flight = "58"` to the workspace/root dependency set and the
  runtime crate, then introduce
  `crates/rockstream-runtime/src/exchange/shared_memory.rs`.
  This module owns the same-host transport's bounded shared-memory segment pool
  (Arrow IPC written once into a memfd/mmap-backed segment, then exposed through
  a Flight ticket/descriptor model on the same worker service endpoint).
- `crates/rockstream-runtime/src/exchange/service.rs` serves the Flight service
  alongside the existing `ShuffleService`; `pool.rs` caches the extra client
  handle per peer worker; `multiplexer.rs` chooses it only when the classifier
  resolves to `ExchangeTransport::SharedMemory`.
- The shared-memory pool is bounded by the named config values from Slice A1.
  Fill-level metrics are exported (`shuffle_shm_bytes_used`,
  `shuffle_shm_segments_in_use`), and the error path is **not** "grow without
  bound": segment-allocation failure, pool exhaustion, or handshake failure
  logs the registered code and falls back to the existing direct route.
- Tests:
  `same_host_shared_memory_fast_path_delivers_exact_rows`,
  `same_host_shared_memory_never_opens_a_grpc_payload_stream`,
  `shared_memory_segment_pool_enforces_bound_and_falls_back_to_grpc`.

#### Slice B4 — Preserve existing outbox/inbox durability and exactly-once semantics on the SHM fast path
- Same-host zero-copy is a transport optimization, not a replay model rewrite.
  `crates/rockstream-runtime/src/exchange/multiplexer.rs`,
  `service.rs`, and `persistence.rs` are updated so the SHM fast path still
  writes the canonical outbox/inbox entries before ACK, uses the existing inbox
  dedupe key on replay, and deletes outbox state exactly once on successful ACK.
- The critical constraint here is that same-host IPC must not become a
  durability special case: a crash after segment publication but before ACK must
  recover from the persisted inbox/outbox path, not from a dead segment handle.
- Tests:
  `same_host_shared_memory_ack_deletes_outbox_once`,
  `same_host_shared_memory_duplicate_delivery_is_deduped_by_inbox`,
  `same_host_shared_memory_replay_uses_persisted_inbox_after_restart`.

### Track C — Codec Framing, Durable Shuffle Compression, and Checkpoint Manifests

#### Slice C5 — Introduce backward-compatible payload framing once, centrally
- Add `lz4_flex = "0.14"` and `zstd = "0.13"` to the workspace dependency set;
  add `lz4_flex` + `zstd` to `crates/rockstream-runtime/Cargo.toml`, and `zstd`
  to `crates/rockstream-control/Cargo.toml` for checkpoint manifests.
- Extend `crates/rockstream-runtime/src/exchange/serialization.rs` with a small
  framed payload header (`codec`, `wire_version`, `uncompressed_len`) so
  decoders can distinguish:
  1. legacy raw Arrow IPC bytes (today),
  2. codec-framed LZ4 payloads, and
  3. codec-framed ZSTD payloads.
- This slice is where rolling-upgrade safety is locked in: the new decoder must
  accept both old and new bytes; the encoder uses new codecs only when the peer
  capability floor says it is legal. No wire-protocol-breaking `ShuffleFrame`
  change is required.
- Tests:
  `legacy_raw_arrow_ipc_decodes_under_codec_v1`,
  `lz4_shuffle_payload_roundtrip_is_exact`,
  `zstd_shuffle_payload_roundtrip_is_exact`,
  `unknown_shuffle_codec_returns_registered_error`.

#### Slice C6 — Apply codecs by path: LZ4 on direct/persisted fast paths, ZSTD on durable objects
- Wire the classifier output through
  `crates/rockstream-runtime/src/exchange/loopback.rs`,
  `multiplexer.rs`, `service.rs`, and `durable.rs`:
  - `Elided` => no serialization/compression.
  - `Loopback` => persisted outbox/inbox bytes are LZ4-framed.
  - `Direct + SharedMemory` => transport is zero-copy, but the canonical
    persisted outbox/inbox bytes are still LZ4-framed.
  - `Direct + Grpc` (same AZ, different host) => payload bytes are LZ4-framed.
  - `DurableObject` => object-store payload bytes are ZSTD-framed.
- Capability gating is explicit: if the peer cluster floor is still legacy, the
  sender writes raw IPC bytes and the decoder still accepts them. That keeps the
  upgrade contract from DESIGN.md §5.5 intact.
- Tests:
  `loopback_persistence_writes_lz4_payloads`,
  `direct_grpc_writes_lz4_payloads_when_codec_capability_is_present`,
  `durable_shuffle_writer_writes_zstd_payloads`,
  `legacy_peer_receives_raw_ipc_until_capability_floor_advances`,
  `mixed_legacy_and_compressed_shuffle_frames_replay_exactly_once`,
  `exchange_codec_gc_uses_scan_and_delete_not_range_delete`.

#### Slice C7 — Centralize and compress the cluster-checkpoint manifest path
- Add a real checkpoint manifest store in
  `crates/rockstream-control/src/checkpoint_store.rs` and thread it into
  `crates/rockstream-control/src/checkpoint.rs` instead of leaving checkpoint
  persistence as an arbitrary external closure forever.
- The store owns `control: checkpoints/{checkpoint_id}` exactly as DESIGN.md
  §11.2 describes. Its decode path accepts legacy plain JSON manifests and new
  ZSTD-framed manifests; its encode path writes ZSTD only once the cluster's
  control-plane capability floor permits it, otherwise it stays on legacy JSON.
- `DESIGN.md` §11.2 / §11.3 are updated in the same slice to say this
  explicitly: cluster checkpoints stay backward-decodable during rolling
  upgrade, then switch to ZSTD once the capability floor advances.
- This slice also gives the checkpoint path the same no-range-delete proof the
  rest of the repo requires: point `put` for manifest writes, explicit retention
  scan/delete for old checkpoints, never a range delete.
- Tests:
  `checkpoint_store_roundtrip_zstd_manifest`,
  `legacy_json_checkpoint_manifest_still_loads`,
  `checkpoint_store_uses_put_and_scan_delete_not_range_delete`.

#### Slice C8 — Extend the existing auto-tuner concept to compression decisions
- Add the direct-path compression policy to the already-existing tuning surface
  instead of inventing a one-off flag. Concretely:
  `crates/rockstream-types/src/config.rs` extends `AutotunerConfig` with direct
  compression budget knobs; `crates/rockstream-sim/src/auto_tuner.rs` grows a
  small compression decision loop; and
  `crates/rockstream-runtime/src/exchange/compression_tuner.rs` keeps a bounded
  per-exchange state map keyed by `exchange_id`.
- This state map is explicitly capped by `max_exchange_compression_states`; the
  fill-level metric is `shuffle_compression_state_entries`; the fallback path on
  exhaustion is "do not compress this exchange" rather than unbounded growth.
- `crates/rockstream-types/src/metrics.rs` gains the compression/network proof
  counters needed later in Track D:
  `shuffle_lz4_bytes_saved_total`, `shuffle_zstd_bytes_saved_total`,
  `shuffle_cross_az_direct_bytes_total`, `shuffle_direct_bytes_total`,
  `shuffle_compression_disabled_total`, alongside the SHM fill-level gauges from
  Slice B3.
- Tests:
  `compression_tuner_disables_lz4_when_cpu_budget_exceeded`,
  `compression_tuner_holds_disable_until_hysteresis_clears`,
  `compression_state_map_never_exceeds_bound`.

### Track D — AZ-Aware Domains, Placement Hints, and Proof Workloads

#### Slice D9 — Make hierarchical exchange domains AZ-aware, and keep placement changes narrow
- Extend `crates/rockstream-control/src/placement.rs`,
  `crates/rockstream-control/src/scheduler.rs`, and the drain-selection logic in
  `crates/rockstream-control/src/service.rs` so locality is used narrowly and
  intentionally:
  - same-AZ candidates win ties / near-ties when capacity headroom is otherwise
    equivalent,
  - drain recipients prefer same-AZ workers before cross-AZ workers,
  - hierarchical exchange domains are built as `(availability_zone, domain_idx)`
    instead of a flat worker count only.
- The runtime side in `crates/rockstream-runtime/src/exchange/classifier.rs` and
  `pool.rs` then uses those AZ-grouped domains to keep direct traffic inside an
  AZ and to choose the durable object-store path for cross-AZ traffic. No
  speculative global rescheduler is introduced.
- Tests:
  `placement_prefers_same_az_on_headroom_tie`,
  `drain_prefers_same_az_recipient_before_cross_az`,
  `hierarchical_domains_group_workers_by_az`,
  `cross_az_peers_never_open_direct_grpc_streams`.

#### Slice D10 — Prove the headline roadmap claims on real wide-shuffle workloads
- Extend `crates/rockstream-runtime/benches/exchange_bench.rs` so it measures
  the three concrete performance claims this roadmap row makes:
  1. same-host shared-memory path copy count / CPU profile,
  2. direct LZ4 per-epoch CPU overhead against the baseline, and
  3. compressed-vs-raw network bytes.
- Add an oracle-driven workload proof file (new
  `crates/rockstream-oracle/tests/shuffle_transport_oracle.rs`, reusing
  `src/tpch_gen.rs` and the existing Nexmark harness patterns) that runs the
  same representative wide shuffle under legacy raw IPC, same-AZ direct+LZ4,
  same-host SHM, and cross-AZ durable+ZSTD routes and asserts identical
  observable output after every epoch.
- This is the slice that turns "≥40% bytes saved", "near-zero cross-AZ direct
  traffic", and "zero divergence from the oracle" into checked artifacts rather
  than hand-waved expectations.
- Tests / proof benches:
  `oracle_shuffle_transport_modes_match_tpch_batch`,
  `oracle_shuffle_transport_modes_match_nexmark_batch`,
  `proof_wide_shuffle_network_bytes_drop_over_40_percent`,
  `proof_cross_az_direct_bytes_drop_to_near_zero`,
  `proof_same_host_shared_memory_cpu_profile_reports_zero_copies`.

## 3. Test Commitments (oracle property tests, pre-committed before writing operators)

v0.49 adds **no new SQL operators**. The new mechanisms are transport,
encoding, and locality decisions, so the oracle property is not "new SQL
operator incremental == batch"; it is **transport choice is observationally
transparent**: same rows, same weights, same frontiers, same checkpoint
recovery result as the raw-IPC/gRPC baseline.

| New operator / mechanism | Oracle property test | Property |
|---|---|---|
| Same-host shared-memory direct route | `oracle_shuffle_transport_modes_match_tpch_batch` + `oracle_shuffle_transport_modes_match_nexmark_batch` (new, `rockstream-oracle`) | For the same input deltas and shard mapping, replacing legacy same-host gRPC with SHM produces identical observable output after every epoch |
| LZ4 direct / loopback persisted payload codec | `oracle_shuffle_transport_modes_match_tpch_batch` (same file) | Replacing raw IPC bytes with LZ4-framed payloads changes network/storage bytes only; row-level results and weights remain identical |
| ZSTD durable shuffle payloads + cluster checkpoint manifests | `oracle_shuffle_transport_modes_match_nexmark_batch` + checkpoint recovery assertions in the new durability tests | Durable replay and checkpoint recovery from ZSTD-framed payloads/manifests reconstruct exactly the same logical state as legacy raw/JSON encoding |
| AZ-aware classifier / hierarchical domain reroute | `oracle_shuffle_transport_modes_match_tpch_batch` + `oracle_shuffle_transport_modes_match_nexmark_batch` | Changing route selection from location-agnostic direct gRPC to same-host SHM / same-AZ direct / cross-AZ durable is observationally transparent: no dropped, duplicated, or mutated results |
